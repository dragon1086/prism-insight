## 1. 무엇을 했나

설계 문서 검토로 시작해서 **프로토콜 설계 → 구현 → 실 API 검증 → 서버 배포**까지 갔다.

시작은 `git pull` 로 받은 OTD 설계 문서 하나를 리뷰하는 것이었다.
검토 과정에서 리더보드를 무의미하게 만드는 구멍들이 나왔고, 고치다 보니
프로토콜 자체를 다시 설계하게 되었으며, 결국 돌아가는 서비스가 되었다.

## 2. 설계에서 뒤집은 것들

### 2.1 처음 리뷰에서 찾은 치명적 구멍

**신고 단가가 공짜 조작 옵션이었다.** 참여자가 신고한 단가가 실측가 ±1% 안이면
그 값을 인정하고 밖이면 조용히 실측가로 대체했다. **벗어난 데 대한 벌칙이 없었다.**
그러면 매수 시 항상 0.9% 낮게 신고하는 것이 최적이 된다. 맞으면 이득, 틀리면 원복.
**왕복 1.8% 를 공짜로 얻는 비대칭 옵션**이었고, 설계가 스스로 강조한
"거래세 0.18% 만으로 순위가 뒤집힌다" 의 10배였다.

→ **가격 필드를 아예 삭제**했다. 유인이 없으면 감시가 필요 없다.

**해시체인이 채점값을 봉인하지 못했다.** 해시가 INSERT 시점에 계산되는데
그때 체결가·상태·자산은 전부 비어 있었다. 채점을 좌우하는 값이 봉인 밖이었다.

→ **원장과 계산장부를 테이블로 분리**했다.

**현금 파킹으로 1등을 할 수 있었다.** Sortino 의 분모는 하락 변동성이라,
99% 현금으로 두고 소액 매매를 반복하면 분모가 0 에 수렴해 지수가 폭발한다.
그러면서 커버리지 70%·거래 20건 요건을 전부 통과한다.
설계는 레버리지(과대 위험)만 막고 **과소 위험은 전혀 다루지 않았다.**

### 2.2 논쟁 끝에 바꾼 것

**투자비중 게이트를 넣었다가 뺐다.** 처음엔 "평균 투자비중 30% 이상" 을 요건으로 걸었는데,
지적을 받고 다시 보니 **PRISM 이 현금 90~100% 라 첫 참여자부터 탈락**이었다.

근본적으로 하락장에서 현금으로 빠지는 것은 오답을 피한 게 아니라 정답을 고른 것이다.
**판단 리더보드가 특정 판단을 금지하면 자기모순이다.**

시뮬레이션으로 확인한 결과 게이트 없이 **하락편차 하한 0.05%/일** 만으로 충분했다.
게이밍 전략은 세 국면 모두 중위권이고, 정상 방어 전략이 항상 이긴다.

그 과정에서 더 큰 것도 확인했다 — **중립적인 단일 지표는 존재하지 않는다.**
절대수익 기반은 저노출을 구조적으로 우대하고(방어 전략이 세 국면 모두 1위),
초과수익 기반은 국면에 따라 노출 방향에 베팅하게 된다(상승장에서 PRISM 이 바닥권).

→ **채점을 코어에서 빼고 교체 가능한 프로파일로 분리**했다.

**제출률 요건도 뺐다.** 거래일 기준 70% 를 요구하면
주간 리밸런싱 20%, 월간 5%, 이벤트 기반 7% 로 **매일 돌지 않는 시스템이 전멸**한다.
게다가 제출률이 막으려던 조작("지는 날 생략")은 목표비중 방식에서
**구조적으로 불가능**하다 — 생략해도 포지션이 유지되어 손실이 그대로 반영된다.

### 2.3 크립토를 점검하다 자산군을 분리했다

`Costs.for_market("CRYPTO")` 를 한 줄 넣어둔 것이 성급했다.
규칙 5개를 대입해보니 **코어 규칙 ①("가격은 서버가 정한다")이 크립토에서 깨진다.**
거래소마다 가격이 다르고 김치프리미엄이 수 %다. 권위가 존재하지 않는다.

→ 채점과 같은 패턴으로 **시장 프로파일을 분리**하고,
v1 정식 지원을 **현물 주식(KRX·NASDAQ·NYSE)** 으로 못 박았다.

## 3. 최종 설계

```
Layer 2  리더보드 (구현체) · 신원 정책
Layer 1  채점 프로파일 stance-score/1  +  시장 프로파일 markets.py
Layer 0  선언 프로토콜 ★코어★ — 자산군도 채점도 모른다
```

**코어는 메시지 2개와 규칙 5개가 전부다.**

```json
{ "protocol": "stance/1", "strategy": "prism-kr-gpt5", "seq": 42,
  "symbol": "005930", "target_weight": 0.10 }
```

목표 비중이 지금보다 크면 사는 것, 작으면 파는 것, `0` 이면 청산이다.
**매수와 매도라는 구분이 없다.**

규칙 — 가격은 서버가 정한다 · 자산은 1.0 에서 시작한다 · 비중 합은 1.0 을 넘을 수 없다 ·
기록은 고치거나 지울 수 없다 · 현실에서 불가능한 체결은 인정하지 않는다.

## 4. 구현

| 영역 | 내용 |
|---|---|
| **원장** | `stances` · `quotes` · `daily_marks` · `market_events` 넷. SQLite 트리거로 UPDATE/DELETE 차단 + 해시체인 |
| **엔진** | 순수 함수. DB·네트워크를 모른다. 같은 입력 → 같은 출력 |
| **서비스** | HTTP 를 모른다. 그래서 FastAPI 없이 로직 28개를 검증한다 |
| **HTTP** | `POST /stances` · `/strategies` · `GET /portfolio` · `/leaderboard` · `/markets` · `/health` |
| **마감** | 하루 종가를 원장에 봉인. 채점의 시간축을 만든다 |
| **대시보드** | Stance 탭 신설. 전인구 실험실 탭과 대시보드 측 로직 제거 |

`stance/` 는 PRISM 을 import 하지 않는다. `tests/test_boundary.py` 가
**ast 로 모든 소스를 훑어 강제**한다 — 함수 안의 지연 임포트도 잡는다.
연동은 루트의 세 파일(`stance_adapter` · `stance_server` · `stance_mark`)만 담당한다.

## 5. 검증이 잡아낸 실제 버그 5개

문서 검토만으로는 나오지 않았던 것들이다.

**① SQLite 스레드 바인딩** — 커넥션은 만들어진 스레드에서만 쓸 수 있는데
웹 서버는 동기 핸들러를 스레드풀에서 돌린다. **운영에서 첫 요청부터 터졌을 것이다.**
HTTP 계층 테스트를 붙이자마자 전부 실패해서 발견했다.

**② 일별 마킹이 아예 없었다** — 실 KIS 로 서버를 띄워 선언을 넣어보니
`/portfolio` 는 투자비중 35% 인데 `/leaderboard` 는 0% 였다.
`apply_mark()` 를 서버에서 **단 한 번도 부르지 않았다.** 데모와 테스트에만 있었다.
일별 마킹은 채점의 시간축이라 없으면 운영일수·투자비중·위험지표가 전부 0 으로 남는다.
**리더보드가 구조적으로 죽어 있었다.**

**③ 경계가 이미 새고 있었다** — `marker.py` 의 CLI 가 `prism_core` 와 `trading` 을
import 하고 있었다. 내가 세운 규칙을 내가 어긴 것이다.
그 상태로 `subtree split` 하면 떼어낸 저장소가 깨진다.

**④ 거래세가 옛 세율이었다** — `0.0018` 은 인상 전 값이다.
2026-01-01 부터 코스피 0.05% + 농특세 0.15% = **0.20%**, 코스닥 0.20% 다.

**⑤ 세율을 고치고도 안 고쳐졌다** — `models.Costs` 기본값만 바꾸고
`markets.py` 의 KRX 프로파일에 하드코딩된 값을 놓쳤다.
엔진은 프로파일의 costs 를 쓰므로 **실제 채점은 계속 0.18% 로 돌고 있었다.**
테스트는 프로파일 없이 엔진을 만들어 기본값을 타서 통과했다.
**운영 서버의 리더보드 JSON 을 눈으로 확인하다 발견했다.**

⑤ 는 특히 뼈아프다. 테스트가 통과하는데 실제로는 틀린 값으로 돌고 있었다.
지금은 프로파일 세율을 검증하는 테스트가 있다.

## 6. 실 KIS 검증 (2026-08-10 정규장)

읽기 전용으로만 호출했다. 매매 함수는 건드리지 않았다.

- 인증 → 시세 조회 → Quote 변환 → 장부 반영 → 마감 → 리더보드까지 실제 값으로 확인
- 삼성전자 232,000 (상한 300,000 / 하한 162,000), SK하이닉스 1,442,000 (1,848,000 / 996,000)
- **상한가 판정에 추가 API 가 필요 없었다** — 현재가 응답에 이미 상한가·하한가가 있었다.
  `get_current_price()` 매핑에서 빠져 있었을 뿐이라 두 필드를 추가했다
- 방향을 나눴다 — 거래정지는 양방향, **상한가는 매수만, 하한가는 매도만** 막는다.
  하나로 뭉치면 상한가에서 매도까지 막게 되는데 그건 틀렸다

## 8. ⚠️ 하지 않은 것 — 실 매매 연동

**PRISM 매매는 Stance 로 흘러가지 않는다.** 이유가 있다.

배포하다 알게 된 사실이 있다. 실제 매매 cron 은
**`/Users/rocky/work/prism-subscriber`** 에서 돈다. 같은 저장소의 **별도 체크아웃**이고
커밋 `57ca1b8` 에 머물러 있으며, **`stance_adapter.py` 도 `stance_quotes.py` 도 없다.**

즉 내가 `ExecutionService` 에 붙인 훅은 그 런타임에 존재하지 않는다.
켜려면 **아직 병합되지 않은 브랜치를 실 매매 체크아웃에 배포**해야 하는데,
그건 실제 주문을 실행하는 코드를 바꾸는 일이라 PR 승인 없이 할 일이 아니라고 판단했다.

훅 자체는 준비되어 있고 안전장치도 걸려 있다.

- **기본 꺼짐.** `STANCE_ENDPOINT`/`API_KEY` 둘이 다 있어야 켜진다
- 주문이 끝난 뒤 호출한다. 주문을 지연시키지 않는다
- 모든 예외를 삼킨다. 리포터가 터지든 잔고 조회가 깨지든 주문 결과는 그대로다
- 스레드에서 돌리고 타임아웃 3초 (기존 10초는 주문 경로에 너무 길다)

`tests/test_stance_execution_hook.py` 10개가 이를 고정하고,
**기존 매매 테스트 164개는 회귀 없이 통과**한다.

### 켜는 순서

1. PR #577 병합
2. `prism-subscriber` 에서 `git pull`
3. 그쪽 실행 환경에 `~/prism-stance/strategy.env` 주입
4. 첫 매매 후 `curl localhost:8800/portfolio -H "Authorization: Bearer $KEY"` 로 확인

## 9. 남은 것

**바로 필요한 것**

- 실 매매 연동 (위 §8)
- Phase 0 자가 대결 — 모델만 바꾼 인스턴스 추가 등록 (`prism-kr-sonnet46` 등)
- 대시보드 배포 — Stance 탭은 만들었으나 빌드·배포는 하지 않았다

**설계상 열려 있는 것**

- 상한가 **잠김**(매도 잔량 0) 판정 — 지금은 "도달" 까지만. 호가 API 필요
- 동시호가·장 마감 후 체결 규칙 — 설계는 정했으나 미구현
- 기업행위 자동 감지 — 엔진은 처리하지만 감지 주체가 없다
- 요청 한도 — `RateLimit` 은 있으나 API 에 미연결
- 결제 주기 T+2 · 유상증자 · 서머타임 — v1 범위 밖으로 명시
- 크립토 시세 권위 — 정해지기 전에는 `EXPERIMENTAL` 을 벗을 수 없다

**공개 전 확인**

- `stance` 는 흔한 단어다. PyPI·npm 패키지명 충돌을 정식으로 확인할 것
- 저장소 분리 — `stance/` 는 PRISM 을 import 하지 않으므로
  `git subtree split` 으로 이력째 떼어낼 수 있다. Phase 2 개방 시점이 자연스럽다
