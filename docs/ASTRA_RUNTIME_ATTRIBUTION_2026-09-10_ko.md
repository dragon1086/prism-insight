# Astra 정규 배치 지연 계측

## 확인한 장애

2026-09-09 미국 정규 배치는 KST 23:15:05에 시작해 다음 날 00:10:42에 끝났습니다.
BUY 3건은 각각 약 240초, SELL 3건 중 2건은 각각 약 120초 후 기존 백엔드로
넘어갔습니다. 성공한 SELL 1건은 95.88초, MCP 호출 8회였습니다.
이는 배치 완료 증거이지 Astra 안정화 증거가 아닙니다.

## 이번 변경의 범위

`cores/llm/codex_oauth_fast_backend.py`에서 JSONL 진행 내용을 읽어 다음을
허용 목록 기반으로 기록합니다.

- 호출별 임의 상관 ID와 모델·effort·프로필·제한시간
- 첫 이벤트, MCP 시작·완료·오류 수와 개별 조회 시간
- 모델 최종 메시지와 turn 완료, 실패 시 마지막 관측 단계
- 제한시간 초과·출력량 초과·프로세스 정리 결과

프롬프트, MCP 인자·결과, 원문 오류, 계좌 식별자, 비밀값은 기록하지 않습니다.
호출 예외 문자열에도 원문 stderr와 경로를 포함하지 않습니다.
stdout/stderr 동시 배수와 호출이 만든 프로세스 그룹 정리를 유지합니다.

계측 한계는 명시합니다. 출력량 제한은 통신 폴링 시 검사하므로 순간 메모리 사용량의
절대 상한은 아닙니다. 단계 계측은 긴 줄과 과도한 이벤트를 제한하며, 기록되지 않은
내부 모델 연산 시간과 서버 측 큐 시간은 구분하지 못합니다.

## 바꾸지 않은 것

- 모델, effort, Fast 설정 및 BUY/SELL 제한시간
- 매수 병렬 수, 기존 백엔드 전환과 매매·손절 규칙
- 운영 원장, 계좌, crontab, app-server

## 검증 상태와 다음 판정

관련 회귀 테스트와 독립 코드 검토를 통과한 정확한 commit만 배포합니다.
배포 후 정상 배치의 단계 기록으로 실제 병목을 확인하기 전까지 원인은 미확정입니다.
간이 빈 포트폴리오 테스트를 정규 배치와 동등하다고 부르지 않습니다.
별도 무주문 재현 환경에서도 실제 보고서·포트폴리오·도구 구성이 다른 부분을 기록합니다.
정규 한국·미국 배치의 성공 증거가 모일 때까지 운영 안정성은 **관측 대기**입니다.

## 되돌리기

계측 변경에 문제가 있으면 해당 변경만 별도 revert PR로 검증한 뒤 ff-only 배포합니다.
원장·runtime 데이터·계좌 설정을 Git으로 복원하거나 삭제하지 않습니다.
기존 제한시간과 백엔드 전환은 그대로이므로 계측 배포가 새 거래 정책을 활성화하지 않습니다.
