# BTC 주요 구간 연속 평가 수리 (M2.6 / M4)

## 수정 전 검토

1. 유형과 기준선: M2.6 측정 오류 수리와 M4 판단 프레이밍 후보를 별도 PR로 다룬다. 기준선은 origin/main 7b3f1c9c의 BTC 소스이며, 앞선 V7은 7곳의 대표시점과 후속시점만 평가했다. 7/7 모델 실행은 연속 파동 포착 검증의 완료가 아니다.
2. 가설과 반증: 같은 7개 고정 하락구간의 시작 직전 정상 판단과 구간 내 30분 간격 재평가를 이어가면 관망 후 진행·반전을 측정할 수 있다. 후보는 현재 추세 지속 근거를 반전 확인과 혼동하지 않고 판단한다. 진입만 증가하고 비용 차감 수익·손절 비용·낙폭이 악화하면 후보를 채택하지 않는다. 사후 선정 개발 표본이며 상승·횡보 반례와 독립 검증이 없으면 수익성 입증으로 승격하지 않는다.
3. 호환성: HistoricalScenarioData → ScenarioRuntime → 실제 DRAFT/SELECT → 계산·실행·보호·정산을 사용한다. 15분봉부터 분석하며 30분 주축·1시간 방향이다. 분석봉과 판단 간격을 구분한다. 회복 첫 관찰, 동시 수렴, 원래 목표, 비용·수량·손실 예산·하드스톱은 유지한다. 사이 구간은 기존 native 보호·체결만 재생하며 연속5분 운영과 같다고 말하지 않는다.
4. 비교: 원 V7의 7개 구간 경계를 고정하고 각 시작 5분 전 및 시작~끝 30분마다 판단한다(버전당44판단, 초안/선택 최대88HTTP). 기준/후보는 같은 일정·1만USDT 가상 회복계좌·가격·비용·OHLC 경로를 사용한다. 별도 계좌로3일 연속 상태를 보존하며 강제 종료·가짜 이전 손익·관찰 응답을 넣지 않는다. 비용2배 결과와 미청산을 별도 보고한다. 실제 양안 호출은 기존48회 한도를 넘으므로 사용자 응답 전에는 실행하지 않는다.
5. 진단과 판정: 미예정·미실행·호스트 차단·첫 관찰 강제WAIT·자율WAIT·후보 거절·미체결·체결·청산을 구분한다. 스케줄 결측, 모델·입력 오류, 원문 재생 불일치, UNKNOWN·예산 위반은 기술 중단이다. 가짜 전체 실행과 별도 프로세스 재생이 먼저다. 승률/건수·승리/손실 평균 수익률·손익비·순손익·낙폭과 진입 지연을 보고하며, 좋은 1거래만으로 전환하지 않는다. M5 판정 기준은 바꾸지 않는다.
6. 현재 결정: 측정 수리는 오프라인 검증 후 PR로 반영한다. 경제 변경은 DRAFT 한 계층만 수정한 사전등록 후보이며 실제 비교 전 운영 반영하지 않는다. SELECT·보유·복구·실행의 바이트·권한 계약을 대조한다. 실패 시 원 기준선을 유지하며 자동 SHADOW/LIVE·실자금 활성화는 없다.

## 구현 범위

- 기존 재생 모듈에 고정 구간의 연속 판단 일정 생성 함수를 추가하고 등록서와 실제 일정이 같은지 검증한다.
- coverage의 기술적 완료와 모델 판단 기록 유무·전체 기간 평가 여부를 별도 필드로 보고한다.
- DRAFT의 기존 readiness 문장을 현재 근거·반대 증거·재평가 조건을 구분하는 문장으로 교체하는 후보를 준비한다. 새로운 진입 강제·수치 문턱·위험 기본값을 추가하지 않는다.

## M2.6 로컬 검증

수정 전 새10개 검사가 실패했고, 수정 후 일정·잘못된 경계·샘플과 전체 구분·native 경제 재생·독립 프로세스 관련31개 검사가 통과했다. 기존 기본계약은 바꾸지 않으며 새 coverage는 기록 유무를 세고 실제 유료 호출 수로 가장하지 않는다. `slots_without_model_review`에는 호스트 차단도 포함되므로 해당 슬롯의 runtime outcome과 함께 읽는다. 전체44판단 모의 실행·실제 호출·CI·배포·M5는 별도 증거다.
