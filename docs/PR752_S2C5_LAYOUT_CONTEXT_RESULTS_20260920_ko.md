# S2c-5 결과: 표의 제목·기간·단위·각주 연결

## 검증 범위

회사명이나 표 번호에 따른 운영 분기 없이 작은 layout table의 명시적 문법을 인식합니다. 원문 table record를 삭제·변환하지 않고 `layout_role`, `context_paths` 및 조건 불완전 상태를 추가합니다. 해당 layout은 독립 금융 사실로 중복 선택하지 않습니다. source/표/문서/최종 입력 예산은 유지합니다.

새 동작은 제한된 문맥 연결입니다. 중첩 표 지원이나 모든 wide table의 예산 내 전달, 금융 품질 합격이 아닙니다. 기존 prose-only 각주도 누적 한도를 초과하면 불완전 표를 제외하는 의도적 안전 변경이 있으므로 모든 기존 HTML 동작이 동일하다고 주장하지 않습니다.

## 설계·구현·검증 피드백

1. 사전 설계 리뷰에서 각주 초과 후 부분 수치 전달, native caption/셀 밖 조건 유실, unknown scope의 명시적 범위, structured 경로 우회를 보완한 뒤 OKAY를 받았습니다.
2. 최초 실제 감사는 실패했습니다. 실제 caption의 빈 colgroup이 초기 허용 문법에서 빠져 있었습니다. 같은 해시 원문을 확인하고 단일 colgroup/일치하는 빈 col/숫자 width만 허용하도록 설계 재검토와 RED 회귀를 거쳤습니다. 임의로 parser 결과를 성공 처리하지 않았습니다.
3. 독립 코드 리뷰에서 layout→prose 각주 한도 우회, 초과 후 후속 각주의 독립 전달, 빈 추가 tr의 위장을 재현했습니다. 혼합 각주에 공통 한도, 불완전 묶음 유지, 정확한 row_count를 적용했습니다. 후속 각주 원문 record도 보존하고 후보에서만 제외하도록 추가 피드백을 반영했습니다. spacer·거절된 표·빈 일반 표에서 불완전 상태가 해제되지 않습니다.
4. DOM 감사에는 context XPath의 원문 위치·순서·text 변조 5건을 RED로 고정했습니다. 원문 td가 표보다 앞에 있고 원래 순서와 문자열을 유지하는지 검사하며 최종 provenance에도 같은 경로가 있어야 합니다. 이 검사는 금융적 연관성을 독립 인증하지 않습니다.

## S3는 여전히 불합격

동일 선택 원문으로 packet을 재구성했습니다. **실제 네트워크 실행 replay가 아니라 선택된 source의 오프라인 재구성**이며 이전 실제 결과와 candidate 수가 달라졌음을 명시합니다.

- 최종 news/overview/status: 2/3/3개, 5,931/5,851/5,823 UTF-8바이트.
- 필수 표 781/1018은 후보에 존재하고 문맥은 복구됐지만 최종 입력에는 둘 다 없습니다. 연간 자식의 최종 전달도 없습니다.
- 표 781의 excerpt 자체가 7,957바이트입니다. 표 1018은 1,229바이트지만 순서·주제별 후보 한도에서 밀립니다. 아직 6,000바이트 필수 근거 합격을 주장할 수 없습니다.

기준선의 앞 news 후보는 회계정책이 아니라 담보제공자산의 caption/data/비교기간 반복이었습니다. HTML 경로에 Markdown의 우선순위·가족별 다양화가 없고 앞 24개를 먼저 자르는 구조가 원인 중 하나입니다. 다음 단계는 특정 회사의 열 번호를 고정하지 않는 조건 보존 열 투영, 손실 없는 표현, 일반적 후보 정렬입니다. 승소·해소 같은 반대근거를 불리한 내용과 동등하게 보존해야 합니다.

## 변경 파일과 남은 게이트

`filing_html.py`, `material_filing_selection.py`, `filing_report_evidence.py`, `report_insight_prefetch.py`, DOM 감사 도구, 관련 회귀와 CI를 변경했습니다. 기존 기하 파서와 provenance compact/expand 구조를 재사용했으며 새 의존성은 없습니다. 보유기간·손절·재진입·주문 정책은 수정하지 않았습니다.

최종 연구 입력 회귀 1,953개가 통과했습니다(기존 경고 4개). 신규 layout 67개, DOM 감사 12개를 포함하며 독립 재리뷰는 APPROVE입니다. 리뷰어가 별도로 3개 경계 × material 모드 2개를 실제 packet까지 확인해 불완전 각주 전달 0건을 검증했습니다. 변경부 Ruff·구문·diff 검사도 통과했습니다. Python 전용 타입 검사 완료 주장은 하지 않습니다.

기존 LG·카카오·HMM·POSCO의 strict replay가 요청 순서를 모두 소비했습니다. layout-only 제외와 문맥 보존으로 원래 capture 요약과는 네 회사 모두 달라졌습니다. 최종 news/overview/status 바이트는 LG 5,593/5,190/5,832, 카카오 5,839/5,550/4,879, HMM 5,677/5,215/5,801, POSCO 5,754/5,639/5,782입니다. 여전히 primary만 전달하며, 전체 최신성은 INCOMPLETE입니다. candidate/record 수 감소를 품질 개선으로 단정하지 않습니다.

정확한 HEAD CI는 push 후 별도 확인합니다. 머지·배포는 하지 않습니다. S3 금융 gold, 새 KR 검증군, 미국 공식 원천 검증과 실제 모델/PDF/BUY/SELL 검증이 남습니다.
