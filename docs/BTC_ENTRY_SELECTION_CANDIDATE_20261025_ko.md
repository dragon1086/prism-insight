# 신규 진입 선택 선호 후보: 운영 미배포

## 구현 전 고정 계획

- M3/M4 calculated DRAFT/SELECT 지침 한 계층만 바꾼다. 기본 목적은 추세 참여이며 진입·무효화 SL·목표를 시장 구조로 먼저 정한다.
- 신규 flat OPEN에서 호스트 whole_plan_payoff가 AVAILABLE일 때 추세 참여 계획의 2:1을 명시적으로 비교한다. 미달이면 더 나은 구조 후보 또는 WAIT를 우선 검토하되 강제 자격 차단은 추가하지 않는다.
- 제한구간 계획은 원 premise/goal과 MA35 경계를 보존한다. regime/goal 이름만으로 목적을 단정하거나 이름을 바꿔 기준을 피하지 않는다. 유형별 승률·기대값 근거가 없으면 confidence로 대신하지 않는다.
- 비용 UNKNOWN이나 실행 가능한 TP_STOP 부재는 비율 0/2 통과가 아니다. 자동 WAIT 규칙도 아니다. 미가격 잔량의 미래 수익을 발명하지 않는다.
- 기존 보유 ADJUST/REDUCE/FAILED EXIT, schema/enum, 자격·위험예산, 10배, 시간봉 우선순위·15분 금지, 계획/경로/연장 응답 형식은 유지한다.

## 검증 계획과 실패 기준

1. 지침 범위와 금지사항 회귀를 먼저 작성해 기존 버전에서 실패를 확인한다.
2. 실제 호스트 계산의 LONG/SHORT 1.99/2/2.01 경계에서 자격·위험·원문·해시 결박을 확인한다. 비용 UNKNOWN·목표 없음·최소수량 미달·보유 경계를 기존 테스트와 함께 실행한다.
3. 실제 호출에 조립된 프롬프트와 출력 schema를 검사하고 기존 100KB 방어·무손실 입력·재생 회귀를 실행한다. 프롬프트 핀은 새 내용의 SHA로만 갱신한다.
4. 모델이 실제로 선호를 따르는지는 오프라인 가짜 응답으로 입증할 수 없다. 주문 없는 사전등록 실모델 검증과 독립 검토는 부모 작업이며 여기서는 실콜하지 않는다.

## 검토와 한계

연구교훈의 모델 판단/호스트 산술 분리와 원문·실패 기록 보존을 따른다. 23개 과거 진입은 이미 사용한 개발 자료로 holdout이나 고승률 입증이 아니다. 이 후보는 수익 개선을 보장하지 않으며 현재 UNKNOWN 사건이 미해소인 동안 배포 보류다. 이번 작업은 서버·주문·commit/push를 하지 않는다.

- 신규 지침 회귀의 최초 결과는 2 FAIL/7 PASS였다. 초기 경계 fixture의 tick 정렬 오류를 수정한 뒤 제품 변경 전 실패가 새 문구 두 건에 한정됨을 확인했다.
- 구현 후 신규 9개를 포함한 관련 10개 파일 274개가 통과했다. 네트워크 시도 0회, 165.669초다. 결과는 작업공간 `btc-entry-preference-regression-20261025.json`에 보존했다.

- Ruff, py_compile, git diff --check가 통과했다. HEAD와 두 프롬프트 문자열을 제외한 AST가 완전히 같아 실행 코드·schema·enum의 변경이 없음을 별도로 확인했다.

### 독립 검토 후 잔량 스트레스 해석 보강

TP_STOP은 미가격 잔량을 hard SL에서 종료하는 스트레스 경로이므로 낮은 비율만으로 추세 잔량을 버리거나 전량 고정 TP를 선호할 수 있다는 위험을 확인했다. 신규 2:1 선호 문단 안에서 완전 가격화된 목표 계획과 이 스트레스를 구분하도록 연결했다. 의도된 최소수량 이상 미가격 잔량이 비율을 낮춘 경우 숫자만으로 WAIT/전량 TP를 우선하지 않고 추세 참여·무효화 구조를 별도로 비교한다. 미가격 상승여력을 2:1 통과로 발명하거나 dust/기계적 runner 추가로 비교를 피하는 것도 금지한다.

새 범위 회귀는 수정 전 1 FAIL/9 PASS였다. 보강 SELECT SHA는 `fdb8576b0d36d1a4626dae7cce646146c4f27afe4ed14c1eab3fb71ef8af9799`다. 같은 관련 10개 파일의 최종 275개가 통과했다(네트워크 시도 0회, 162.333초). Ruff·컴파일·diff-check도 통과했다. 최종 결과는 작업공간 `btc-entry-runner-preference-regression-20261025.json`에 보존했다.

후속 주문 없는 실모델 검증은 실행 전에 고정해야 한다. 일부 TP+의미 있는 runner, bounded MA35, 비용 UNKNOWN, 강한 즉시 진입 또는 조건부 진입을 포함하고 이 보강의 기회 보존·설명 정합성을 평가한다. 이는 수익 증거가 아니며, 실제 단일 cancel 결과 110001 이후에도 기존 UNKNOWN이 유지되므로 운영 배포는 HOLD다.

이 결과는 프롬프트 내용·기존 동작 보존의 기능 증거다. 실제 모델의 선택 개선이나 수익성 증거가 아니다. 실모델 호출, 서버 접근, 주문, commit/push, 배포는 하지 않았다. 독립 검토·정확한 최종 HEAD 전체검증·사전등록 판단 비교가 남았으며 운영 배포는 보류한다.
