# BTC 스윙 진입 복구·운영 경보 교정

## 범위와 확인 근거

로드맵 M0(진입 체결·보호·정산) 및 M3(운영 경보) 결함 수정이다. 전략 신호,
손절폭·위험 예산·주문 반올림 규칙·실자금 활성화는 변경하지 않는다.

2026-09-15 09:02 KST 스윙 진입 의도는 원시 수량 0.08904303700823521을 기록했지만
기존 주문 직렬화는 0.089 BTC를 전송했다. 거래소 주문은 Filled, 체결량·실제 포지션은
0.089 BTC, 체결가 78,188.2, 네이티브 손절은 76,569.1이었다. 원장은 수량을 원시 값과
엄격 비교하여 반영하지 못했고 09:12 이후 반복 tick이 복구 대기 상태로 멈췄다.
단순한 거래소 지연으로 단정하거나, 기다리면 해결된다고 안내하지 않는다.

완전 페이지 조회를 추가 검증하자 두 번째 차단 원인도 확인했다. 포지션 첫 페이지는
활성 0.089 BTC지만 마지막 페이지는 같은 종목의 수량 0·방향/가격/보호/생성·갱신시각/상태가
전부 빈 자리표시 행이었다. 독립적인 첫 페이지 재조회는 원래 활성 수량·보호·시각과 일치했다.
따라서 수량 수정만으로 복구 완료라고 보고하지 않는다.

## 수정·검증 계획

1. 원시 소수 수량→기존 전송 수량의 불일치를 격리 테스트로 재현한다.
2. 새 진입은 기존 직렬화를 한 번 적용한 수량을 승인·의도 저장·전송·체결 확인에 함께 쓴다.
   0으로 반올림되는 수량은 주문 전에 거부한다. 반올림 방식 자체를 바꾸지 않는다.
3. 기존 pending은 같은 직렬화로 전송했을 수량만 인정한다. 주문 ID/link·종목·방향·
   주문 유형·가격·전체 체결·보호 확인은 유지한다. 수량 허용 오차를 넓히지 않는다.
4. 이상 경보는 기존 모니터링 채팅/봇 경로로 분리한다. 정상 진입·청산 공개 알림은 유지하되
   이상 경보를 공개 채널·Firebase·FCM으로 전파하지 않는다. 누락된 설정을 성공으로 처리하지 않는다.
5. 반올림 내림/올림·0·잘못된 lot·부분체결·재시작·멱등성과 private/public 전달 경계를 검사한다.
   페이지 예외는 정확한 BTCUSDT 단방향 단일 포지션과 명시적으로 빈 마지막 행에만 적용한다.
   독립 조회가 수량·방향·보호·생성/갱신시각·정상 상태와 모두 일치할 때만 활성 행을 보존한다.
   실제 flat·변경된 노출·헤지·타종목·오류·누락 필드·순환·다중 행은 여전히 UNKNOWN이다.
   이는 원자적 거래소 snapshot이나 체결 자체의 증명이 아니며 기존 체결·보호 게이트는 유지한다.
6. 읽기 전용 거래소 상태를 확인하고, 검증한 복구 코드 배포 후 기존 tick에서 정확한
   근거에 따라 원장이 복구되는지 확인한다. 미확정 pending을 수동 삭제하거나 재진입 주문을 하지 않는다.

운영 변경은 Bybit demo 범위다. 보호 주문이 존재한다는 사실과 실제 미래 손절 체결을
보장한다는 주장은 다르다. 코드·시험·배포·자연 복구 관측을 분리해 기록한다.

## 검증 증거

- 수량 내림/올림 회귀는 수정 전 2건 실패, 수정 후 통과했다. 잘못된 다른 lot는 계속 거부한다.
- 실제 API의 활성→빈 마지막 행→같은 활성 응답을 재현했다. 수량 수정만으로는 복구되지
  않았고, 좁은 자리표시 행 검증을 추가한 뒤 전송·노출 대조가 통과했다.
- 실제 거래소 GET 11회와 메모리 전용 원장으로 전체 기존 pending 복구를 시험했다.
  0.089 BTC, 진입 78,188.2, 손절 76,569.1, 수수료 3.82731239가 정확히 반영됐으며
  브로커 변경 요청과 운영 DB 쓰기는 0회였다. 운영 원장 복구 완료를 뜻하지는 않는다.
- 기존 모니터링 봇의 getChat으로 대상이 '프리즘 인사이트 테스트/모니터링'임을 확인했다.
  환경변수·자격증명을 복사하거나 변경하지 않았다. 공개/Firebase 경로는 경보에 사용하지 않는다.
- 일반 Python 3.14에서는 기존 연구 지표 커널 호환성 검사 9건이 실패했다. 지정된
  .venv-bt Python 3.12에서는 해당 연구를 포함한 2,215개 통과/1개 skip, 네트워크 시도 0회였다.
  이후 추가한 자리표시 행 검증을 포함한 최종 검증과 배포 결과는 별도로 확인한다.
- 최종 지정 런타임 전체 회귀는 2,230개 통과/1개 skip, 네트워크 시도 0회였다.
  슬롯·보호·원장·재시작 회귀를 함께 수행했고, 마지막 정적 검사 후 관련 60개를 재확인했다.
