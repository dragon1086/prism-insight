# 대형 근거 배치 개선: 전체 셀의 위치 중복만 제거

사용자는 대형 근거 배치 개선 → 새로운 한국 사례와 최종 보고서 검증 → 통과 후 미국 순서를 승인했습니다. 이번 구현은 첫 단계이며 운영 예산6,000, 실험 최대32,000, 후보24개, 기존 순서·gold·원문 조건을 바꾸지 않습니다.

## 원인과 선택

POSCO의 지급보증 표443과 PF 표447은 tuple excerpt만 각각21,519/20,435바이트입니다. 단순 우선순위 변경은 다른 중요한 표를 밀어내므로 해법으로 채택하지 않습니다. 행·열 좌표와 기본 span을 셀마다 반복하는 표현을 줄이는 일반적인 전체 셀 grid 표현을 추가합니다. 비공개 원문에서 단순 크기 측정은 각각10,005/9,971바이트였으며 실제 packet 성공은 별도 검증합니다.

## 구현 계약과 순서

1. 실패 회귀를 먼저 작성합니다. `html_cell_grid_v1`은 shape, rows, spans를 갖습니다. rows의 배열 인덱스는 원문0-based 좌표이며 문자열은 실제 원본 셀 anchor, null은 원본 셀이 없는 위치입니다. 빈 문자열·0·대시를 null로 바꾸지 않습니다. spans는 기본1×1이 아닌 원본 span만 명시합니다. 헤더·합계·조건을 선택적으로 삭제하거나 문자열을 축약하지 않습니다.
2. 기존 tuple/legacy 인코더와 decoder 계약을 유지하고 grid를 추가합니다. 기존 기하·문자·확장 바이트 검증을 재사용합니다. JSON 전처리 깊이/노드/구분자 제한을 무조건 확대하지 않고 새 구조가 기존 한계에서 처리되는지 검증합니다. 타입/중복키/불법 span/겹침/순서/과대 입력은 static error로 거절합니다.
3. material HTML 표에서만 실제 직렬화된 전체 block 비용이 더 작을 때 선택합니다. 기존 tuple/projection 판단을 먼저 끝낸 뒤 여전히 전체 셀을 유지하고 excerpt가2,400바이트를 넘는 표만 비교합니다. 따라서 기존 projection 시도·선정·retrieval 분류는 바뀌지 않습니다. schema marker를 정확히 붙이고 감사 도구는 표시와 실제 schema의 불일치를 거절합니다. 기존 partial projection은 별도이며 full-grid에 projected 상태를 부여하지 않습니다.
4. 기존 셀 원문·provenance 감사, 모든 private corpus 셀 roundtrip, 6/12/24/32k 비교와 동일예산 재실행, 소비자 guard를 검증합니다. PF뿐 아니라 앞선 지급보증 및 기존 필수 근거의 공동 보존 여부를 확인합니다. 원문은 Git/Telegram에 전달하지 않습니다.
5. 독립 검토, 연구 회귀·provider 호환·정적 검사 및 정확한 HEAD CI를 실행합니다. 압축 복원 성공과 실제 모델 해석 성공을 구분합니다. 새 한국 사례/실제 모델 품질이 확인되지 않으면 미국으로 넘어가지 않습니다.

## 영향 경계

수정 대상은 HTML codec, report evidence adapter, provenance audit와 테스트입니다. 새 의존성·매매 규칙·운영 호출부·배포는 범위 밖입니다. 구조를 이해하기 어려워지는 위험은 원문 복원 시험만으로 해소되지 않으며 후속 실제 모델 소비 검증이 필요합니다.

## 최초 실험에서 발견한 역효과와 보수적 수정

grid만 적용한 최초 실험에서는 삼성생명12,000의 기존 G3가 빠졌습니다. 원인은 압축으로 앞서 탈락했던 다른 큰 표가 새로 들어가면서 뒤쪽 기존 근거를 밀어낸 순차 packing의 비단조성입니다. POSCO도 새로 들어간 표443 때문에447은 여전히 빠졌습니다. 이 실패를 숨기거나 gold를 변경하지 않습니다.

따라서 기존 표현으로 **최종 metadata 정리까지 끝낸 실제 채택 집합을 먼저 고정**합니다. 그 집합을 압축해 유지한 뒤, 같은24개 후보 안의 탈락 항목을 기존 round-robin 순서로 재시도합니다. 원문·filing·provenance 전체가 같은 근거인지 비교하며 private 원래 표현은 모델 입력에 넣지 않습니다. 최종 결과가 기존 채택 근거를 하나라도 잃으면 전체 baseline packet으로 보수적으로 돌아갑니다. 이 보존 규칙은 모든 예산/담당 섹션에 적용하고 특정 회사·표 번호·금액을 사용하지 않습니다.

이는 기존 근거를 보존하는 안전 개선이지 PF 추가 전달 보장이 아닙니다. POSCO32,000에서 기존 채택 전체를 grid로 바꾼 중간 크기는27,955바이트였으므로, 두 큰 표를 모두 추가하려면 여전히 공간이 부족할 수 있습니다. 추가 전달과 남은 누락을 별도로 측정하고 한도를 자동 확대하지 않습니다.
