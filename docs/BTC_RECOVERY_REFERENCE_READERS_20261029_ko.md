# 복구 요청·응답 중복 제거: reader 선행

## 문제와 범위

계산형 판단은 모델 요청·응답을 review event에 기록한 뒤 같은 내용을 recovery event에도 별도로 기록한다. 서버의 최근 review event 16건을 읽기 전용으로 대조했을 때 같은 slot의 recovery event가 16건 모두 유일하게 일치했다. review 원본을 유지하고 복구 이벤트만 같은 slot·sequence의 review event를 참조하는 가상 형식으로 바꾼 검증에서, 복구 이벤트 저장 크기는 해당 16건 합계 903,645바이트에서 4,248바이트였고 원 JSON 16건이 정확히 복원됐다. 이는 작은 중복 표본의 크기이며 전체 DB 절감률이 아니다.

이 변경은 참조 형식을 **읽는 기능만** 준비한다. 기존 운영 writer는 새로운 참조를 저장하지 않으므로 이 변경만으로 신규 기록이나 기존 DB 크기가 줄어들지는 않는다.

## 보존 계약

- 기존 텍스트와 압축 recovery 이벤트는 현재와 동일하게 읽는다. 새 참조에는 별도의 바이너리 표식을 사용해 기존 모델 응답과 구별한다.
- 새 참조는 같은 slot·sequence의 review 원문과 recovery 원문의 SHA를 보존하며, 누락·중복·변조·압축 손상은 조용히 정상으로 처리하지 않는다.
- 복기 해시, 입력크기 복구 감시, ClickStack exporter 기준점, 독립 외부 백업 수신기가 복원된 원문을 사용한다. 복구 상태 확인 중 누락은 기존 경보를 유지한다.
- review event는 참조 대상이므로 독립적인 90일 삭제나 분리·이동을 하기 전 참조 관계와 보관을 함께 검증해야 한다.

## 검증 상태

관련 로컬 테스트는 기존 형식, 참조 복원, 원본 누락·변경·중복·손상, 감시 fail-closed, 복기 해시, 내보내기 기준점과 독립 백업 수신기를 다룬다. CI, 배포, 첫 정기 실행과 향후 writer의 운영 절감 효과는 별도다. 새로운 모델 호출·거래소 조회·주문·운영 DB 변경은 없다.
