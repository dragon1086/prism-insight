# TradingView 보고서·BUY 매핑과 초분할 LIVE 전환 검토

> 역사적 기록: TradingView는 2026-09-23 사용자 결정으로 자동매매 프로젝트에서 제거합니다.
> 현재 배포 범위는 `US_EVIDENCE_RELEASE_20260923_ko.md`를 따릅니다. 아래 내용은 당시의 조사 기록입니다.

## 범위와 결론

사용자는 TradingView 도구를 최대한 시험하고 보고서와 BUY 매핑을 보강하며, 초분할이 단순하고
허점 없이 구현된다면 별도 SHADOW 기간 없이 적용하도록 조건부 승인했다.
이 문서는 실제 코드·정식 Evidence Packet·읽기 도구 시험을 근거로 작성한 설계다.
보고서 보강의 운영 ON 승인과 미완성 초분할 집행의 즉시 LIVE 승인은 같지 않다.

**초분할의 즉시 LIVE 조건은 현재 충족되지 않는다.** 표본 수가 적어서만이 아니라
비중 원장의 의미, 서로 다른 크기의 분할 매수, 실제 체결, 장중 보호청산의 통합이 남아 있기 때문이다.
기존 매매·프롬프트를 바꾸거나 새로운 위험 한도를 활성화하지 않았다.

## 1. 실제 코드상 초분할은 어디까지인가

- micro_split.py: 순수 상향 목표/정수 수량 투영. 10→30→60→100과 100 초과 피라미딩은 계산 초안이다.
- 현재 KR·US 관측 hook: 실제 적격 신규 진입에서 최초 0→10만 SHADOW로 기록한다.
- pilot_lifecycle.py: 별도 50→100 파일럿을 지원하지만 non-SHADOW를 명시적으로 거절한다.
- 새 strategy_ledger는 비중·체결 상태를 표현하지만 그 표현이 운영 브로커 연결 완료의 증거는 아니다.
- 기존 강세장 피라미딩은 별도 경로다. 최초부터 일부만 진입하는 새로운 초분할과 혼용하면 안 된다.

핵심 근거: prism_core/micro_split.py:39-44,102-128,156-170;
observability/micro_split.py:49-75; prism_core/pilot_lifecycle.py:102-104,133-136,180-193.

## 2. 즉시 적용을 막는 실질적인 통합 공백

### 서로 다른 비중을 기존 보유 행으로 표현할 수 없음

tracking/helpers.py:274-278은 보유 행별 수량 없이 행별 진입가 단순평균을 사용한다.
400-418은 부분 청산 수량을 총수량/남은 행수로 계산한다.
같은 크기의 기존 피라미딩 행을 전제로 한 계약이며 10·20·30·40%의 서로 다른 leg에 맞지 않는다.
예를 들어 10주를100에 사고30주를110에 사면 수량가중 평단은107.5이지 행평균105가 아니다.

### 장중 보호청산에서 빠질 수 있음

tools/hardstop_seller.py:311-316과 tools/trend_exit_seller.py:491-496은 동일 종목 보유 행이
여러 개이면 기존 배치 청산에 맡기고 건너뛴다. 새 leg를 기존 행으로 단순 추가하면 이 경로에 걸린다.
관련 두 회귀 테스트도 그 건너뛰기를 확인한다. 이는 현재 설계 의도이며 무조건 skip을 지우면
기존 피라미딩·수동 보유의 소유수량을 잘못 청산할 위험이 있으므로 소유권까지 함께 고쳐야 한다.

### 목표 비중의 의미가 서로 다름

기존 micro 투영은 현재 평가액 목표, 새 원장은 누적 투입원금 한도다.
같은 target_pct를 두 의미로 사용하면 증액·수익률이 달라진다.
신규 계약은 논리 슬롯의 누적 투입 기준으로 통일하고 과거 기록은 별도 버전으로 보존하는 것이 적절하다.
1슬롯100%와 계좌100%, 기준 주문금액과 실제 체결금액은 서로 다르다.

### 출력 JSON만 고치면 실행되지 않음

prism_core/trading_scenario_contract.py:100-108은 BUY sell_triggers를 기존 SELL 템플릿으로 교체한다.
현재 SELL은 should_sell boolean을 중심으로 해석하며 새 목표비중 필드가 실제 부분매도를 만들지 않는다.
새로운 스키마를 기존 consumer가 읽게 하면 reduce가 전량매도로 처리되는 등 충돌할 수 있다.

### 추가 판단의 신선도·비용 계약

기존 SHADOW pilot은 최신 quote와 AI 증거를120초 이내로 요구한다.
처음 생성한 BUY 계획을 며칠간 재사용하는 결정론적 증액과 같은 설계가 아니다.
초기 plan의 유효기간/무효화 조건을 검증하거나 정규 배치의 새 판단이 있을 때만 증액해야 한다.
옛 판단의 날짜만 바꿔 최신 AI 증거로 취급하지 않는다.

## 3. 제안하는 BUY 계획과 결정론적 제어

LLM은 근거·설정 유형·판단 변경 조건을 제안한다. 서버는 허용 정책·현재 단계·최대위험·실제 수량을 정한다.
다음은 구현된 실행 스키마가 아니라 설계 예시다.

```json
{
  "position_plan": {
    "schema_version": "position_plan_v1",
    "mode": "PROPOSAL_ONLY",
    "allocation_basis": "CUMULATIVE_DEPLOYED_SLOT_BUDGET",
    "policy_id": "SERVER_APPROVED_POLICY",
    "entry_setup": "BREAKOUT",
    "thesis_evidence_refs": ["E1"],
    "counter_evidence_refs": ["E2"],
    "add_rule_id": "LATER_CONFIRMED_WINNING_BREAKOUT",
    "cancel_add_conditions": ["THESIS_INVALID", "RISK_FAILURE", "PLAN_EXPIRED"],
    "exit_rule_id": "EXISTING_FULL_EXIT"
  }
}
```

실제 활성화하려면 별도 v2 consumer가 필요하다. LLM이 임의 수량·위험 한도·정책 ID를 승인하지 않는다.
10→30이면 추가분은20이지30을 더하는 것이 아니다. 다음 단계만 허용하고 같은 근거로 단계 건너뛰기를 금지한다.

결정론적 확인 항목:
- campaign/계정/시장 소유권과 현재 누적 비중, 정책 버전.
- 신규 증거봉·유효 plan·진입 시나리오 유지·현재가와 손절 근거.
- 기존 점수/RR/국면/섹터/슬롯/총위험·현금 한도.
- 기존 주문의 부분체결·미확정·예약금액과 중복 주문 여부.
- 수익 방향의 확인 후 증액. 하락 중 기계적 물타기나 손절 하향으로 공간 만들기 금지.
- 0주이면 주문하지 않되 전략 원장과 브로커 실행 결과는 분리한다.

상태는 전략(부분보유/완전보유/종료), 추가매수 권한(대기/가능/만료/취소),
브로커 집행(접수/부분체결/완료/거절/취소/미확정)을 따로 둔다.
동일 campaign·revision·stage·evidence_bar는 한 번만 전이한다.
매수 대기 중 손절이 오면 잔여 매수 취소와 소유 체결수량의 전량 종료를 우선한다.
기능 OFF는 새 증액만 막고, 기존 캠페인의 청산 소유권은 유지해야 한다.

수수료·세금·환율·수량 반올림을 계정별 실제 체결 원가에 반영해야 한다.
성과 통계도 campaign과 leg를 구분한다. 한 종목을 네 번 나눠 청산했다고 승리 거래 네 건으로
불려서는 안 되며, 기존 전량 거래와 같은 단위로 비교 가능한 별도 계약이 필요하다.

## 4. 매도 프롬프트와의 연결

필수 전달: 초기 thesis, 반대/무효화 근거, 현재 비중, 체결된 leg, 가중 원가, 남은 매수 권한,
손절/총위험, 최근 추가 판단 및 실제 실행 상태.
SELL은 투자 논리 유지/훼손을 판단하고 결정론 코드가 실행 가능 수량과 주문 충돌을 검증한다.

첫 실매매 통합안은 분할 진입과 기존 전량 청산만 연결하는 편이 작다.
부분 익절·부분 위험축소는 후속 별도 계약으로 다룬다. 일부를 팔았다고 동일 캠페인에서 다시
자동 충전되지 않도록 해야 한다. 손절·기업사건·thesis 붕괴의 전량 청산은 삭제할 규칙이 아니다.

프롬프트는 capability에 따라 분기한다.
- 기존 사용자/OFF: 실행 가능한 기존 전량 계약 유지.
- 분할 진입 ON: 서버 승인 정책에 따른 분할 진입과 조건부 증액 가능.
- 부분매도 미구현: 전량 매도 전제를 유지.
따라서 모든 100% 문구를 지금 일괄 삭제하지 않는다.

## 5. 증액 주기와 시장 국면

새 증액 심사는 기존 오전·오후 정규 배치에만 붙이는 방향이 적절하다.
그러나 지금 연속 초분할 증액이 LIVE에서 돌아가고 있다는 뜻은 아니다.
같은 확정 일봉을 오전·오후에 읽었다고 단계가 두 번 올라가면 안 된다.
분봉·장중 이벤트 증거를 별도 정의하지 않는 한, 새 완료봉이 없으면 단계 상승도 없다.
후보로 재선정되지 않은 보유종목의 증액 검토 대상도 명시해야 하며, 시장별 batch당 예산이 필요하다.
장중 보호매도는 정규 배치까지 기다리지 않는다. 기존 피라미딩 경로도 중복 증액하지 않도록 분리한다.

약세/횡보장에서 일부만 진입하면 초기 위험을 줄일 수 있지만 실패 확률·갭·상관손실까지 없어지지는 않는다.
많은 소액 진입의 합산 위험을 봐야 한다. 코드의 국면별 점수 하한은 프롬프트를 적극적으로 써도 남는다.
현재 strong_bear9/moderate_bear8/sideways8, 회복 국면의 제한된 예외가 있다.
비중 정책과 국면 문턱을 동시에 바꾸지 않는다. 먼저 같은 진입 기준에서 분할 정책을 비교한 뒤
기회 확대가 필요한 국면·조건을 별도 사전등록한다. 강세장도 과열 추격·총위험 상한을 유지한다.

## 6. 보고서 구조와 BUY 매핑

기존 번호1~5를 유지하고 선택형 근거 묶음을 앞단에서 한 번 수집한다.

- 1-1 가격·거래량: price_setup, bar_finality, data_delay, price_relative_strength.
- 1-2 수급: 한국 실제 투자자 순매수, 미국 공시 보유량·거래량 대용치를 분리.
- 2-1 기업현황: earnings_actual/consensus/guidance/balance_sheet, 단위·기간·회계 기준.
- 2-2 사업: business_model/competitive_position/peer_comparability, 직접 peer와 생태계 기업 구분.
- 3 뉴스: new_event/contradicting_evidence/thesis_change/next_verification_event.
- 4 시장: macro_event_calendar/sector_context. 실행용 결정론 regime을 덮어쓰지 않음.
- 5 전략: 지지 근거·가장 강한 반대 근거·판단 변경 조건·미확인 사항을 짧게 추가.

BUY CAN SLIM 매핑은 절 번호 + evidence_id + 기준시점을 사용한다.
C/A는 실제 실적과 전망을 구분, N은 새 사건과 반복 보도를 구분, S는 같은 출처/기간 거래량,
L은 주가 상대강도와 사업 우위를 별개로, I는 한국 순매수/미국 보유량 및 proxy를 구분,
M은 주입된 결정론 국면을 기준으로 한다. TV의 Buy 등급을 BUY 승인으로 사용하지 않는다.

US I행의 기관 누적 순매수 표현과 뒤의 flow 교정문은 본문부터 일관되게 정리하는 것이 좋다.
모르는 점을 새로운 자동 탈락 사유로 추가하지 않는다.

실제 BUY는 PDF에서 재추출한 텍스트를 읽는다. 따라서 원문→종합→PDF→BUY까지 evidence ID,
단위·시점·UNKNOWN이 살아남는지 검증한다. 후속 sidecar를 만들면 report hash에 정확히 연결하고
종목+날짜만으로 느슨하게 합치지 않는다.

## 7. 기존 사용자와 비용 보호

기본 OFF, 우리 운영은 검증·이용권한 확인 후 ON이라는 승인 조건을 유지한다.
OFF에서는 새 도구·인증·모델 입력이 없고 기존 경로가 동일해야 한다.
자료를 한번 prefetch해 절별로 필요한 부분만 주고, 원문 전체를 모든 에이전트에 중복 주입하지 않는다.
뉴스·재무·문서 실패 시 기존 경로를 유지하되 실패 때문에 전체 조사를 중복 실행하지 않는다.
US의 Perplexity 미설정 시 뉴스 skip 분기도 선택형 prefetched 근거가 있는 경우에만 보완해야 한다.
허용된 도구·retry·시간·입력 크기·권한별 cache를 코드로 제한한다.

## 실행 우선순위

1. TradingView 실제 읽기 응답·지연·자료 공백을 기록하고 보고서 보강 범위를 선택한다.
2. 기존 도구와 같은 후보로 보고서·BUY 근거 전달 및 비용을 비교한다.
3. 초분할의 단일 원장 의미·체결 소유권·보호청산·중복/부분체결 복구를 먼저 완성한다.
4. OFF 동등성, 주문 없이 격리한 KR/US 실제 모듈, submit 후 timeout/재시작/부분체결/손절 경합을 검증한다.
5. 그 뒤 최소 실행안의 LIVE 조건을 재검토한다. 현재는 조건부 즉시 활성화 승인을 행사하지 않는다.
6. 국면 적극성·부분매도는 분리된 경제적 정책 실험으로 평가한다.

판정: PREREGISTER_REPLAY. 기존 SHADOW는 보존하고 신규 LIVE 전환은 보류한다.
