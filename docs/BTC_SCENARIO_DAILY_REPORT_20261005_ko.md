# BTC 일일 요약의 이전 전략 혼입 교정

## 원인과 범위

2026-10-05 사용자가18:00 KST 발송된 일일 요약에서 ±70점·추세 힘2.0·exchangefill·
거래2건/R0이라는 이전 체제의 설명을 발견했다. 현재 데모 MAIN은 LLM 시나리오를 운영하지만
기존 `live.telegram_reporter`의 정기 실행은 `btc_signal_log`·`btc_trading_history` 등을 그대로 읽었다.
새 매매 알림을 고친 것과 일일 요약 연결은 별개였으며, 이것은 M3의 정보 출처·라우팅 결함이다.

읽기 전용 대조에서 해당 평가액9,611.5082의 기록 시각은10월3일02:10 UTC(11:10 KST),
신호68.33의 기록 시각은10월3일00:00 UTC(09:00 KST)였다. 오늘의 발송 시각을 붙여
이전 값을 현재처럼 보여 준 것이며 매매 엔진이 이전 점수 전략으로 복귀한 것은 아니다.
현재 정규 거래는 시나리오 runner이고 기존 `live.runner`는 shadow 모드임을 확인했다.

운영 기준선은 `089e1ff93b4b1d0fba36459e8f8d26dedf457cb6`이다. 매매 정책·프롬프트·위험·
주문·원장·계좌·스케줄·전송 대상은 변경하지 않는다. 과거 공지 재전송/수정이나 수동 매매를 하지 않는다.

## 변경 계약

1. demo MAIN에 시나리오 제어 상태가 있으면 새 읽기 전용 요약으로 라우팅한다.
   control/binding 손상 시 이전 전략으로 조용히 돌아가지 않고 확인 필요로 표시한다.
   제어 상태가 없는 기존 운영과 shadow/live 경로는 유지한다.
2. 현재 자산·포지션은 검증된 MAIN 계좌의 최근 저장 관측을 사용하고 통화·시각을 붙인다.
   오래된/미확인 관측을0잔량이나 관망으로 바꾸지 않는다. 조회·렌더링 중 거래소 호출이나 DB 변경은 없다.
3. 거래와 누적 손익은 `llm_scenario_settlements`의 확정·체결이 있는 종료 시나리오만 집계한다.
   무체결 취소, 진행 중 부분실현/평가손익, 기존 `btc_trading_history`를 섞지 않는다.
   정산 플래그·유한 수치·순손익 등식·시나리오 ID를 확인하며 결측은 경고한다.
4. 최근 판단은 실제 `llm_scenario_decisions`의 outcome과 기준시각을 함께 사용한다.
   거절된 제안을 실행된 결정으로 표시하지 않는다. 점수±70·추세 힘2.0·112일 누적·R0·
   낙폭을 '잠깐 눌림'이라 축소하는 설명은 시나리오 요약에서 제거한다.
5. 날짜는 KST, 제목·자산·보유·정산·판단을 짧은 이모티콘 블록으로 구분한다.
   raw ID/예외/계좌 원문은 공개하지 않는다. 원장 확인 불가와 체결0건을 구분한다.
6. 설정된 보고 주기는 그대로다. 운영 스모크는 읽기 전용 렌더만 하고 `_send`를 부르지 않는다.
   다음 자연 정기 발송은 별도 확인하며 아직 실행 전이면 미관측으로 보고한다.
7. 실제 CLI도 `mode=ro`·`query_only`·단일 읽기 트랜잭션을 사용한다. 보고 목적으로
   `ensure_schema`나 WAL 설정을 실행하지 않으며, 없는 DB를 만들지 않는다.
   `--preview`는 같은 실제 렌더 경로를 사용하되 전송은 하지 않는다.

## 테스트와 확인

기존 동작을 먼저 잠그고, 시나리오·기존 점수가 충돌하는 fixture에서 오염을 재현한다.
정상/빈 자료/미체결/진행/정산 완료/0손익/오래된 자료/타계좌·손상 제어/거절 판단을
회귀 검사한다. 실제 main→renderer 경로에서 새 양식 라우팅을 검증하고 읽기 전용 DB를 쓴다.
전체 격리 테스트·독립 검토·정확한 head CI 후 정상 PR/ff-only 배포한다.
실제 운영 DB 렌더는 파일로 보존하되 과거 메시지나 주문을 재실행하지 않는다.

## 검증 결과

기존 reporter 관련21개가 먼저 통과했다. 새 경로의 계좌·원장·출처·손상·오래된 자료,
중복 체결 ID 정산·StopLimit 오인·미확정 주문·CLI 읽기 전용·미발송 preview를 회귀로 고정했다.
전체 BTC 테스트는 로컬3,224개 통과/12개 skip, 서버 격리3,235개 통과/1개 skip이며
네트워크 시도는0이다. Ruff·구문·diff 검사와 독립 소스 검토를 통과했다.

실제 운영 DB를 읽는 후보 CLI `--preview`에서 최근 계좌9,602.73 USDT, 보유 없음·진입 대기0건,
시나리오 정산 완료5건·합계−10.54 USDT 및 시각이 붙은 최근 LLM 판단을 확인했다.
이는 해당 관측 시점의 자료이며 고정 값으로 구현하지 않았다. 렌더링 중 발송·주문·DB 변경은 없었다.
과거 점수·추세 힘·R0·exchangefill·112일째 표시는 새 경로에 나오지 않는다.

배포·운영 미발송 스모크는 PR receipt로 별도 기록한다. 다음 자연 일일 발송은 다음18:00 KST에
예정돼 있으며, 실제 발송을 기다리지 않고 스모크를 발송 성공으로 표시하지 않는다.
