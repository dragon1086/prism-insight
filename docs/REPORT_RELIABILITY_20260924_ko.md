# 보고서 장애 및 종합 입력 연결 수정

## 실제 장애

app /report 샘씨엔에스(252990), 2026-09-24 17:38 요청은 DART 심층 입력 ready=False로 17:39 중단됐다. 봇은 생존해 실패 안내를 전달했다. 별개의 이전 종료 로그에는 SIGTERM 시 전체 asyncio task 취소로 발생한 CancelledError가 있었다.

공식 최신 공시 20260814001644의 연결재무제표 본문은 `당사는 보고서 작성기준일 현재 해당사항이 없습니다.`였다. 기존 수집기는 연결 기준만 요구했다. 같은 issuer와 공시의 별도 재무제표·주석은 존재했고, 별도 조회는 4개 source·652개 선택 unit으로 입력 준비를 통과했다.

## 수정 계약

- 공식 연결재무제표 섹션 자체가 명시적으로 해당사항 없음을 밝힌 짧은 본문인 경우만 absence proof를 만든다. HTTP 오류·빈 응답·일반 주석의 '해당사항 없음'은 근거가 아니다.
- 첫 조회에서 최신 후보의 absence proof가 있고 최신 본문을 선정하지 못했을 때만 한 번의 별도 조회를 허용한다. 공식 회사 식별과 같은 최신 공시 ID, 별도 scope가 모두 일치해야 채택한다. 최신성/수집 범위의 기존 한계는 숨기지 않는다.
- 두 단계의 요청·바이트 수를 합산한다. 각 단계의 기존 요청/시간/HTML 예산은 유지한다. 무제한 재시도·보호 검사 우회는 없다.
- 보고서에 별도 기준임과 공식 전환 근거를 표시한다. 연결 실적으로 바꾸어 설명하지 않는다. 유효한 심층 자료가 없으면 정상 완성본 발행을 계속 막는다.

## 종합 단계 수정

KR DART 장과 비교기업 표는 원래도 전략·요약에 들어갔다. 부족했던 것은 정확한 시장 계산표·정량 수급 reference의 명시적 전달, 그리고 KR/US의 뒤늦게 렌더링되던 macro 공개 블록이다.

- 종합용 KR reference에 기존 종목·시장·공시·공개 수급 근거를 함께 넣는다. 전문 agent와 시장 공통 캐시의 범위는 바꾸지 않는다.
- 양국 macro 공개 블록을 전략/요약 이전에 한 번 만들고, 같은 문자열을 최종 본문에도 사용한다. 새 수집이나 모델 단계를 추가하지 않는다.
- 두 종합 prompt는 새 공시·비교기업·공식 가이던스·정량 수급·거시 근거를 검토하고 기간·연결/별도·실적/예상·기준시각을 구분하도록 명시한다. 새 매매 임계값·손절·수량 규칙은 없다.
- 최종 사실 편집이 본문 오류 문단을 고치는데 동일 문단이 읽기 전용 전략에 그대로 남으면 발행을 중단한다. 이는 좁은 동일문단 검사이며 의미가 다른 모든 문장의 진실성 인증이 아니다.
- 일반 KR report service도 DART-depth 캐시 요건을 적용한다. 평가용 cache-only와 US 동작은 유지한다. 기존 캐시 전체를 자동 재작성하지 않는다.

## 종료 처리

SIGTERM은 종료 이벤트만 설정한다. polling → application task 정리 → 진행 중 결과 전송 → HTTP 자원 정리 순서로 종료한다. 전체 task 무차별 취소·loop.stop을 제거했다. 실제 오류·직접 취소를 정상 성공으로 숨기지 않는다. 외부 보고서 worker 전체의 영속 큐/복구 정책은 이번 수정 범위가 아니다.

## 검증과 범위

- 공식 소스만 재조회한 수정 경로에서 ready=True, 연결 미작성 proof와 별도 source 4개, 전체 요청 48회(연결21+별도27)를 확인했다. 모델이나 주문 없이 입력 준비만 검증했다.
- source·fallback·종합·캐시·종료 관련 격리 회귀 282개 통과. 정적 치명 오류 규칙과 diff 검사 통과.
- KR/US 테스트 혼합 시 부모 패키지의 stale child-module 속성이 남아 model mock을 우회할 수 있던 fixture도 수정했다. sys.modules뿐 아니라 부모 속성을 복구하며 실제 네트워크/curl/모델 backend를 차단한다. 순방향·역방향 실행 각각43개 통과.
- 실제 모델 생성·PDF 검수·운영 배포 결과는 별도로 보고한다. 입력 전달 시험을 모델의 완벽한 해석이나 모든 미래 보고서의 무오류 보장으로 바꾸지 않는다.

입력·범위 처리 오류와 데이터 전달 보완이다. 매매 agent의 점수·위험 한도·손절·사이징·SHADOW/LIVE는 변경하지 않는다. DART가 제공되지 않는 기업·새 형식·진짜 공급자 장애는 여전히 명시적인 실패/제한 대상이다.
