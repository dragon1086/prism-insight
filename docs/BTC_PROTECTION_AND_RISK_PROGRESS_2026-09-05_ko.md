## M0.1: 부분 진입 관측 시 보호 — 부분 구현

처음 확인한 실제 노출 수량을 기준으로 pending 주문이 남아 있어도10m/30m 경로에서
보호를 설정합니다. 추가진입은 실제 수량 증가를 확인한 뒤에만 보호를 조정합니다.
보호 미확인 시 진입 잔량 취소를 한 번 요청하고 신규/추가진입을 막습니다.

취소 ACK만으로 pending을 없애지 않습니다. 정확한 주문 ID의 취소/거절,
누적체결0, 전체 체결조회0, 방향·수량·심볼·reduceOnly=false·최근 시각을 확인한
일반 미체결 만료만 자동 해제합니다. 부분/미확인은 보수적으로 유지합니다.

**이는 첫 관측 시 보호이며 체결 순간 즉시 보호가 아닙니다.** 진입에 거래소 native SL을
동반하는 경로, 체결 기반 진입 원장 정합성, 이미 손절선을 넘은 불명확 부분체결은 남습니다.

## M0.2: 스탑 교체 공백 — 코드 보완

공통 reconcile_stop은 완전한 조회→유지/수정/생성→재조회로 구성됩니다.
충분한 stop-market은 변경하지 않고, 소유가 확인된 스탑만 qty와 trigger를
제자리 amend합니다. 취소 선행 방식은 제거하며 더 타이트한 스탑은 보존합니다.
신규 생성은 영속 link ID를 먼저 저장하고, 응답 유실 후에도 같은 ID로 추적합니다.
ACK는 보호 확인이 아니며 실제 주문의 유형·방향·수량·트리거·상태를 검증합니다.

보호 충족(confirmed)과 수정 권한(owned)은 별개입니다. 외부의 충분한 스탑을
보호로 인정할 수 있지만 ID를 봇 소유로 가져와 나중에 수정하지 않습니다.
익절 주문(TP) 교체와 기존 트랜치 전략은 이 수정에서 바꾸지 않습니다.

## M1.1: 공통 위험 계산 — 오프라인 코어만 구현

core/portfolio_risk.py는 실체결 수량, 미체결 잔량, 제안 진입을 분리합니다.
gross는 반대방향도 절대합이며, entry-loss heat와 mark-to-stop giveback을
따로 계산합니다. 수익권 스탑의 이익으로 다른 포지션 위험을 상쇄하지 않습니다.

기본 정책은 메인5%, 스윙1.5%, gross8배, 스윙gross5배입니다. 합산heat6.5%는
현재 예산의 제안 합계이지 별도 검증된 운영 기준이 아닙니다. 수량을 몰래 자르지 않고
reject-only 결과를 냅니다. short에는 gross용 가격 상한과 heat용 체결 하한이 필요합니다.

**운영 주문 경로에는 연결하지 않았습니다.** coherent snapshot, 예약 중복 제거,
durable reservation, 단일 writer lock, 재시작/경합 테스트, 반사실 replay가 선행 조건입니다.
순수 계산 테스트 통과만으로 M1.1을 완료 표시하거나 활성화하지 않습니다.

## 근거 및 남은 작업

로컬 전체 BTC524개, 별도 공통 위험68개 테스트를 검증 대상으로 삼습니다.
실제 배포 결과는 채팅으로 별도 보고합니다. 현재 데모 포지션이 없으므로 실제
부분체결/스탑 amend까지 운영 표본으로 검증한 것으로 보고하지 않습니다.

후속 우선순위는 native entry SL, execution 기반 진입/부분청산 원장,
공통 예약+writer lock, 두 레인 가드 연결 전 replay입니다.
수익률/위험 배수/새 트레일 파라미터/cron은 이번 변경으로 바꾸지 않습니다.
