# BTC 복구 진입 공개 공지 누락

## 원인과 범위

유지보수방에 전송한 것은 신규 진입 신호가 아니라 앞선 장애의 복구 보고였다.
09:02에 실제 체결된 스윙 진입은 정상 `_persist_entry` 경로를 끝내지 못했고,
후속 원장 복구 경로에는 공개 진입 공지를 이어주는 단계가 없었다.
운영 경보를 다시 공개로 돌리지 않고, **확정 매매 기록은 본 채널 / 장애·복구 보고는
모니터링방**이라는 서로 다른 목적을 유지한다. M0/M3 알림 연결 오류 수정이며 전략 변경이 아니다.

## 수정·검증 계획

- 복구된 진입 영수증과 알림 대기를 같은 원장 트랜잭션으로 보존한다.
- 보호·복구 확인 후 공개 공지를 전달하며, 정상 진입 경로와 동일 포지션의 중복 시도를 막는다.
- 전송 전 영속 claim을 기록한다. timeout·응답 유실·전송 중 종료는 자동 재전송하지 않는다.
  이는 도착 exactly-once 보장이 아니라 중복 방지를 위한 제한이다.
- 원래 체결시각·가격·수량·진입 손절만 사용하고 지연 공지임을 명시한다. 현재 시점의
  새로운 매수 신호로 오해하게 만들지 않는다. 과거 모든 포지션을 자동 재공지하지 않는다.
- 이미 청산됐거나 식별/수량이 맞지 않는 포지션은 활성 진입으로 공지하지 않는다.
- 공개/모니터링 경로, 정상/복구 중복, 실제 SQLite 저장·재시작·전송 실패를 격리 검증한다.
- 검증·배포 후 사용자가 지정한 누락 건만 정확한 영수증으로 확인하여 한 번 공지한다.
  실제 매매 배치·재주문·손절 변경을 공지 테스트로 수행하지 않는다.

## 구현 검증

- `swing_entry_notice`는 기존 btc_meta에 포지션별 대기/claim/전송 영수증을 저장한다.
  복구의 원장/영수증 트랜잭션에서 생성하고, 정상 진입 경로도 같은 키를 소비한다.
- 공개 공지는 Telegram Bot의 단일 전송 경로를 사용한다. 비공개 fallback이나
  timeout 후 자동 재전송, 과거 영수증 전체 스캔을 추가하지 않는다.
- 신규 회귀 18개 및 관련 격리 검증 209개 통과, 전체 BTC 검증 2,248개 통과/1개 skip,
  네트워크 시도 0회를 확인했다. 전송 실패·재시작·정상/복구 경합·청산 후 대기 취소를 검사했다.
- CI에 신규 회귀를 연결했다. 실제 본 채널 전달은 배포 후 별도로 수신 영수증을 확인한다.
