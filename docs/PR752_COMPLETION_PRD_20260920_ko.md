# PR #752 잔여 과제 완료 PRD

## 목적과 기준선

사용자 요구는 일부 종목에서 자료를 읽는 수준이 아니라, 한국·미국의 여러 업종에서 정확한 공시·뉴스 근거가 보고서와 매매 소비 경계까지 전달되는 것입니다. 각 작업은 **PRD → 설계 → 구현 → 검증 → 피드백 수정** 순서로 진행합니다. 해결할 근거가 없거나 사용자의 인증·접근 권한·정책 결정이 필요하면 해당 작업을 중단하고 구체적인 지원을 요청합니다.

- 개발 기준선: `1747a59b6b5926f49b95fb286fc53e5426638cba`, 기존 Draft PR #752.
- 개발 위치: 기존 `prism-insight-us-full-validation` worktree. 다른 worktree의 BTC/WIP는 수정하지 않습니다.
- 보유기간·손절·재진입·주문 비중·점수 문턱을 바꾸지 않습니다. 모델·브로커·채널 호출은 명시한 검증 단계 외에는 하지 않습니다.
- TradingView와 새로운 선택형 기능은 기본 OFF입니다. 보고서 입력 개선과 실제 매매 성과 개선을 구분합니다.

## 요구사항

### R1. 한국 수집·파싱

- LG에너지솔루션 주석 범위 탈락, 카카오 연간 주석 우선순위, HMM 전송 실패, POSCO 표 크기 제한을 실제 원문으로 재현합니다.
- 원문 확보를 먼저 검증하고, 원문을 확보하지 못하면 내용이나 원인을 추측해 파서를 고치지 않습니다.
- 개별 2 MiB 초과 섹션은 상한 증가나 문자열 앞부분 절단이 아니라, 공식적인 부분 문서 식별과 문맥 보존 가능성을 설계한 뒤 처리합니다. 안전하게 나눌 수 없으면 미지원으로 남기고 사용자에게 범위 결정을 요청합니다.
- 종목명·종목코드에 따른 파싱·선정 예외는 금지합니다. 수정은 제목 구조·표 구조·기간·범위 등 일반 계약으로 구현합니다.

### R2. 같은 원문 재현과 근거 보존

- 허용된 공개 원문을 Git 밖의 제한된 로컬 fixture에 보존합니다. 문서마다 URL·원문 해시·바이트 수·발행사·공시 식별자·회계기간·범위·관측 시각·기준시점을 기록합니다.
- 인증 토큰·쿠키·헤더·계좌·DB·원문 전체를 로그·모델 프롬프트·공개 커밋·사용자 배포용 요약에 넣지 않습니다.
- fixture는 크기 제한, 새 경로 생성, 덮어쓰기/심볼릭 링크 거절, 엄격한 파일 권한, 해시 검증을 갖춰야 합니다.
- 수정 전후 비교는 같은 fixture 해시에서 수행합니다. 원문이 달라지면 비교 불가 또는 별도 실행으로 기록합니다.

### R3. 최종 예산 내 내용 품질

- 후보 수가 아니라 실제 담당 섹션의 6,000 UTF-8바이트 입력을 평가합니다. 메타데이터·출처·조건도 예산에 포함합니다.
- 기간·발행사·연결/별도·통화/단위·확정/조건부·반대 근거를 보존합니다. 추출된 주장에 붙은 조건을 누락한 경우 해당 주장은 불합격입니다.
- 고정 원문에서 파서 결과를 보지 않고 중요 근거와 원문 위치를 먼저 지정합니다. 필수 항목과 보완 항목을 분리하고, 필수 항목이 누락되면 내용 합격으로 처리하지 않습니다.
- 예산상 필수 항목을 모두 담을 수 없다면 그 사실을 보고하고, 중요도를 사후에 낮추거나 상한을 임의로 높이지 않습니다. 추가 조회나 결과 범위 변경은 별도 설계·사용자 판단 대상으로 올립니다.

### R4. 미국 원천과 문서 범위

- 공식 SEC metadata/본문, Yahoo 제공 사본, yfinance 수치, 뉴스 원문, TradingView 보완 자료를 구분합니다.
- XOM·PLD의 발행사 불일치를 실제 관계 증거 없이 해제하지 않습니다. NVO의 미추출은 문서 구성·태그·포함 문서 여부를 확인하고 일반 규칙으로 해결합니다.
- 공식 기준시점의 제출 시각·정정·서식·기간·발행사 검증이 없는 자료를 최신 공시라고 표시하지 않습니다.
- 수시 공시나 외국 발행사의 부속 문서를 정기보고서의 전면 대체물로 간주하지 않습니다. 읽지 않은 본문은 읽었다고 표시하지 않습니다.

### R5. 실제 생성물과 마지막 소비 경계

- 정상 복구된 기존 계정 OAuth로만 실제 모델 검증을 합니다. 다른 계정 인증 복사·유료 backend 자동 전환은 하지 않습니다.
- 보고서의 사실·의미·조건/한계·후속 확인·출처를 검수하고 Markdown→PDF→텍스트→BUY/요약까지 대조합니다. 고정 응답 전달 시험과 실제 생성 품질을 분리합니다.
- 최신 중요 공시의 KR enhanced/US SELL snapshot은 저빈도 수집·기준시점·만료·누락을 설계하고 실제 소비 메서드로 검증합니다. 고빈도 손절·추세 청산 경로에 수집이나 LLM을 추가하지 않습니다.
- 뉴스 급등 이유는 기사 원문·시간·시세 관계를 대조하고 검색 요약만으로 원인을 확정하지 않습니다. TradingView는 OFF 경로 불변을 먼저 검증하며 권한 미확인 상태에서 활성화하지 않습니다.

## 순차 작업과 진입 조건

1. **S0 전제 확인:** 현재 git 상태, 원천 접근, OAuth 상태를 안전하게 확인합니다. 장애는 단계별로 분리합니다. OAuth 미복구는 실제 모델 단계의 blocker이며 원문 재현 단계까지 불필요하게 막지 않습니다.
2. **S1 한국 재현 기반:** fixture 보존 설계·테스트·구현을 완료하고 LG부터 같은 원문으로 원인을 확인합니다. 카카오/HMM/POSCO로 같은 일반 계약을 검증합니다.
3. **S2 한국 범용 복구:** 파서·표·대형 섹션을 한 종류씩 수정하고 기존 실패/정상 반례를 함께 통과시킵니다. 개발군 검증 후 코드와 표본을 고정해 별도 검증군을 실행합니다.
4. **S3 근거 전달 품질:** 중요 근거 gold를 먼저 고정하고 동일 예산의 선택·출처 압축·조건 보존을 평가합니다. 필수 근거 불충족이면 다음 품질 승인으로 넘어가지 않습니다.
5. **S4 미국 검증:** 발행사 불일치·미지원 문서·공식 최신성·외국 발행사 서식을 순차 검증합니다. 기존 검증군을 수정에 사용하면 회귀군으로 전환하고 새 검증군을 고정합니다.
6. **S5 실제 모델·PDF·BUY/SELL:** OAuth 정상성 확인 후 최소 실제 호출로 시작하고, 인증 실패 시 중단합니다. 실제 경제적 판단에 영향을 주는 변경은 기존 매매 변경 검증 절차를 따릅니다.
7. **S6 통합·운영 게이트:** 기존 snapshot 실패 2건의 변경 이력을 검토하고 회귀·CI·기본 OFF·비용·원문 실패 처리를 점검합니다. 정확한 HEAD로 모든 게이트를 통과한 뒤에만 머지·배포합니다. 배포 후 스모크와 첫 실제 정기 배치는 별도로 확인합니다.

각 단계의 설계에는 변경 파일·입출력·한도·실패 상태·회귀 명령·원복 범위를 명시합니다. 구현 전에 실패를 테스트로 고정하고, 검증 결과에 대한 독립 리뷰의 차단 지적을 수정한 뒤 다음 단계로 이동합니다.

## 합격과 실패의 기록

- 필수 안전 합격: 다른 회사·미래 정보·잘못된 범위/단위 연결 0건, 전달한 모든 근거의 원문 위치 복원 가능, 조건 누락 0건, 제한 초과 시 부분 성공 위장 없음.
- 기능 합격: 지원 대상으로 선언한 표본에서 필요한 본문·필수 근거·최종 소비가 통과합니다. 지원 범위는 결과를 본 뒤 축소하지 않습니다.
- 범용성 합격: 사전 고정한 다업종 개발군과 별도 검증군을 모두 보고하며, 통신 실패·미실행도 분모에 남깁니다. 미실행군이나 새 모델 미검증을 합격으로 세지 않습니다.
- 구현 완료, 오프라인 검증, 실제 공급자 검증, 모델 품질, CI, 배포, 첫 정기 배치 관측을 서로 다른 상태로 기록합니다.

## 중단과 사용자 지원 기준

- 인증·계정 승인·권한·403/429 등 접근 제한은 우회하지 않습니다. 비밀번호·토큰을 채팅으로 요구하지 않습니다.
- 같은 전송 오류가 연속되면 수집기를 중단합니다. 사전에 허용된 정상 재시도·공식 문서 확인·실제 응답 구조 확인으로 해결되지 않으면 더 많은 종목이나 요청량으로 밀어붙이지 않습니다.
- 원문이 없어 원인을 검증할 수 없거나, 설계가 중요한 매매 정책·지원 범위·비용 예산 결정을 요구하면 중단합니다.
- 지원 요청은 ‘막힌 단계 → 확인한 증거 → 이미 시도한 방법 → 사용자에게 필요한 최소 행동 → 재개 검증’ 순서로 작성합니다. 사용자 지원을 받기 전 완료라고 보고하거나 다음 의존 단계를 몰래 진행하지 않습니다.
