# 대형 전체 근거의 표현·배치 안정성 개선 결과

## 판정

전체 셀을 보존하는 grid 표현과 기존 전달 근거 보존 packing을 구현했습니다. **POSCO PF 최종 전달은 아직 실패**입니다. 운영6,000, 실험 최대32,000, 후보24개, 기존 gold·기간·역할·각주 조건은 유지했습니다. 한국 전체 품질이나 미국 진행, 운영 승격·머지·배포 완료가 아닙니다.

## 변경과 단순화

- `prism_core/filing_html_codec.py`: 좌표 네 개를 매 셀마다 반복하지 않고 행 배열과 예외적인 병합 목록으로 표현합니다. 실제 빈 문자열과 원본 셀이 없는 null을 구분하며 원래 좌표·span·전체 문자열을 복원합니다. 기존 tuple/legacy 호환과12,000슬롯·텍스트2MiB·입력/확장8MiB 제한을 재사용했습니다.
- `prism_core/filing_report_evidence.py`: 기존 투영 판단 후 전체 표가 유지되고2,400바이트를 넘는 경우에만 더 작은 grid를 선택합니다. 특정 회사/표/금액 우선순위는 없습니다. 원래 표현은 내부 packing 비교용으로만 유지합니다.
- `prism_core/report_insight_prefetch.py`: 기존 최종 채택 집합을 먼저 고정하고 절약한 공간으로 같은 후보 범위의 다른 근거를 추가합니다. 마지막 metadata 정리 후에도 기존 집합이 보존되는지 검사하고, 실패하면 원래 packet 전체로 돌아갑니다. 운영 예산이나 호출부를 바꾸지 않았습니다. revision은 `bounded-html-v13-full-grid`입니다.
- `prism_core/report_research_context.py`: grid의 행/열, 빈 셀, null, 병합 해석을 명시했습니다. 매매 판단 규칙은 변경하지 않았습니다.
- `tools/evaluate_large_filing_html.py`: schema 표시와 실제 schema 일치를 검사하고, 보수적 fallback도 원본 전체 셀·shape·조건·출처와 대조합니다.
- 신규 codec/delivery/packing 테스트 세 파일과 CI 연구 gate를 추가했습니다. 새 의존성은 없습니다.

## 처음 발견한 회귀도 보존

처음 grid만 적용했을 때는 더 작아진 앞쪽 표가 새로 들어가 뒤의 기존 근거를 밀어냈습니다. 삼성생명12,000의 G3가 다시 실패했고 POSCO도 PF가 빠졌습니다. `grid_greedy_regression_20260921.json`에 실패를 보존했습니다. 기존 전달 집합을 먼저 유지하는 수정 후 G3를 복구했습니다. 기준을 낮추거나 앞선 실패를 삭제하지 않았습니다.

## 실제 원문 기반 재검증

- 기존7개 원문, 네 예산 × 세 담당 섹션의84개 비교에서 **이전 전달 근거 손실0건**입니다. 모든 셀·filing·기간·단위·원문 조건·provenance를 포함한 원래 근거 identity로 비교했습니다. 누적 record 수529→583은 예산별 반복을 합한 값이며 독립 회사 수나 품질 점수가 아닙니다.
- grid로 변환한 **80,151개 원본 셀**을 legacy 전체 셀 표현으로 정확히 복원했습니다. 문서 간 중복 가능성이 있는 검사 누적값입니다. parser record와 후보의 원문 내용·순서·기존 projection 판단은 불변입니다.
-7개 원문의86,480개 source 위치 및 후보/최종 packet 원문 감사 오류0건입니다. 이는 기존 회귀 corpus이며 새로운 한국 홀드아웃이 아닙니다.
- 최종 삼성생명 일반 source 구성:6,000에서 news5,803바이트이며 G1/G2실패·G3통과. **12,000에서는 news10,957바이트, G1/G2/G3 모두 통과**입니다.24,000/32,000에서도 모두 통과합니다. 연간 전체 주석 component 대체도 같은 판정이며 기본/연간 역할은 섞지 않았습니다.
- 표781의83셀, 표1018의14셀을 그대로 유지했습니다. 명시적 실험 injector가 같은 source_material을 온전히 전달하는지 검사했으며, 기본 운영 injector가6,000초과를 거절하는 동작도 유지했습니다. 실제 모델 해석 성공으로 부르지 않습니다.

## 남은 PF 실패와 분기점

POSCO 지급보증 표443은 excerpt21,519→10,005바이트, PF 표447은20,435→9,971바이트로 줄었으며 각주를 잘라내지 않았습니다. 그러나 기존에 전달하던 다른 근거를 보존하면32,000에서도 둘 모두 추가되지 않습니다. PF만 앞으로 옮겨 다른 근거를 밀어내는 방식은 채택하지 않았습니다.

현재 전체 단일 note 예산은 운영6,000/실험최대32,000입니다. **다음 선택지는 총량을 그대로 두고 선정 기준을 재설계하거나, 별도 총량 상한을 정한 분할 전달을 검증하는 것입니다.** 후자는 총입력량/호출 경계가 달라지므로 기존32,000 실험의 자동 연장으로 실행하지 않았습니다. 권장 제안은 운영값을 그대로 둔 채 오프라인에서 최대2개×32,000바이트(총64,000)의 독립 출처 묶음을 비교하는 것입니다. 이 제안은 아직 승인/구현/실행되지 않았으며 모델 호출도 포함하지 않습니다. 특정 근거를 억지로 우대하기보다 공동 보존을 검증할 수 있습니다.

## 코드·안전 검증

- 전체 연구 입력 회귀 **2,352개 통과**, 기존 경고4개입니다.
- 별도 실제 모듈 provider 호환 통합 **46개 통과**입니다. 미국 실제 수집/실행이 아닙니다.
- 독립 리뷰의 관련306개 시험, 변경 Python8개 Ruff·AST 및 diff 검사를 통과했습니다. 시험은 중복 합산하지 않습니다. 리뷰 중 감사기의 scalar 입력 예외와 metadata 정리 변수 충돌을 발견해 수정하고 회귀를 추가했습니다.
- Python 전용 타입 검증 완료는 주장하지 않습니다. LSP 도구는 tsc 기반이었습니다.
- 추가 공시 HTTP·모델·주문 호출은0회입니다. 원격 CI는 최종 commit의 상태를 인수인계에 별도로 기록합니다.

## 다음 품질 검증 준비

기존 frozen KR holdout의 실패/미실행은 품질 통과가 아닙니다. 새 검증군은 원문만 독립 검토해 필수/반대 근거와 위치를 먼저 고정하고 최초 packet 결과를 나중에 공개해야 합니다. 기존 capture CLI는 자동 packet도 생성하므로 source-first 결과 격리가 필요합니다.

실제 모델 검증 전에 전용 tool-free OAuth 경로, 자동 재시도 금지·유한 호출 원장, production PDF의 외부 HTTP(S) 차단 검증이 필요합니다. 실제 BUY 입력 캡처와 별개로 fresh SELL 입력 어댑터도 남아 있습니다. 입력/최종 소비 품질 게이트가 통과하기 전 미국으로 넘어가지 않습니다.
