# BTC 기존 회계 감사 기록의 제한 압축

읽기 호환과 신규 기록 압축이 먼저 배포된 뒤에만 실행한다. 검증된 백업에서 7일 이전 회계 감사의 저장 본문과 복원 원문을 각각 해시로 고정하고, 운영의 같은 행·시간·본문과 참조 복원을 다시 확인한다. gzip 압축 후에도 원문과 ClickStack 내보내기 anchor가 같아야 한다. 하나라도 다르거나 리소스·실행 안전 조건이 깨지면 해당 묶음 전체를 롤백한다. 원문을 삭제하거나 정산 상태를 바꾸지 않는다.

백업 스캔은 최대 1,000행씩 진행하고 실제 압축은 한 묶음 최대 100행·원본 16MB 이하다. 짧은 단발 실행에서 최대 10묶음과 30회 스캔을 수행한다. 대상이 없는 스캔 구간과 백업 끝을 구별하고, 중단된 체크포인트는 기존 계좌 압축과 같은 확인 절차를 따른다. 서버 소스 identity·clean Git commit·백업 증명·봉인된 manifest·백업 비실행·BTC 안전 상태·다음 정기 판단까지 남은 시간을 확인한다. WAL일 때만 검증된 B3 read-only 연결을 허용한다. PR CI가 완료되고 해당 merge가 배포되기 전에는 실행하지 않는다.

10월 29일 검증 백업에서 7일 이전 회계 감사 100건을 메모리에서만 압축한 진단에서는 3,581,371바이트 중 2,891,885바이트가 줄었고 전부 원문과 anchor가 복원됐다. 이 결과는 검증 범위 100건에 한하며 실제 운영 적용이나 파일시스템 공간 반환을 뜻하지 않는다. SQLite 내부 재사용 공간과 실제 디스크 여유는 별도 측정한다.
