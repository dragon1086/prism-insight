# M4 진입 공간 후보: 주문 없는 개발 검증

등록일 2026-10-25. 사용자의 수익성 개선 계속 진행 승인 범위입니다. 실행 복구·보유 감축과
분리해 신규 무포지션 진입 판단 한 계층만 검토합니다. 운영 배포·M5 수익성은 미입증입니다.

## 적합성 검토

1. 기존 23건 개발 표본의 최초 계획을 공통 수수료 가정으로 재계산했습니다. 원래 계획은
   23/23이 2 미만, 전량 마지막 목표 가정에서도 20/23이 2 미만입니다. 수량·목표·손절은
   고정했으며 동적 ADJUST나 러너의 미래 수익을 재생한 결과가 아닙니다.
2. 가설: 비중만 바꾸기보다 구조적 진입 위치·목표 공간·최종 손절을 먼저 비교하는 기존
   미배포 후보의 신규 진입 부분을 검증합니다. 비율 때문에 목표·손절을 꾸미거나 좋은
   돌파를 막으면 기각합니다. 개발 23건은 독립 검증 표본으로 재사용하지 않습니다.
3. baseline `486a4e38`의 DRAFT/SELECT 두 prompt 상수에만 기존 후보 `a046d6c5`의
   진입 문단을 재사용합니다. SELECT는 이미 제공된 eligible 후보/WAIT만 선택합니다.
   보유 약화 프롬프트, 계산·자격·수량·위험·실행·FAILED EXIT·native SL은 변경하지 않습니다.
4. 제한 구간 목표를 임의 연장하지 않습니다. 고승률·기대값·미가격 러너 이익을 발명하지
   않습니다. 미상 수수료나 러너 hard-SL 스트레스만으로 WAIT를 강제하지 않습니다.
5. 기존 계산·수수료·방향·실제 조립 경로를 관련 테스트로 검증합니다. baseline/candidate의
   AST 차이가 두 prompt 상수뿐인지 확인합니다. 모델 원응답은 별도 의미 검토합니다.
6. 신규 모델 비교에서 숫자·권한 오류, 구조 없는 목표 연장·SL 축소, 유효 기회 봉쇄가
   나타나면 HOLD입니다. 전부 WAIT 또는 높은 계산 비율만으로 개선 PASS를 선언하지 않습니다.

## 새 native DRAFT 검증의 사전 범위

기존 `btc-entry-select-native-v2`와 `btc-quality-screen-v1`의 예산·결과는 재개하지 않습니다.
이전 검사는 DRAFT를 고정해 SELECT만 호출했으므로 후보 생성 변화는 미평가였습니다.
새 검사는 원본 등록의 LONG bounded(slot 5976088), SHORT fully priced(slot 5976117)
입력을 그대로 고정하고 BASE→CAND 순서로 실제 DRAFT+SELECT를 비교합니다.

- 최대 8 HTTP(2사례 × 2arm × DRAFT/SELECT), retry 0, 첫 기술 오류에 전체 중단합니다.
- gpt-6.1-sol low, 기존 localhost OAuth만 허용하며 외부 socket·주문·운영 DB 접근은 금지합니다.
- 원 snapshot/context의 논리 시각은 고정합니다. 실제 wall 제한은 arm당 75초입니다.
  과거 가격에 실제 응답 시간만 더하는 이전 실험의 시각 혼용을 반복하지 않습니다.
- 원 등록·입력·양쪽 commit·실행 스크립트 해시를 새 registry에 고정하고 exclusive 시작 표식과
  기존 CallGuard/GuardedModelCall을 사용합니다. 원문 영수증은 새 연구 디렉터리에만 저장합니다.
- 사전 offline 검사에서 저장 DRAFT + 가짜 WAIT를 넣어 계산·schema·guard 연결을 확인합니다.
  실제 실험에서는 저장 DRAFT를 반환하지 않고 새 모델이 생성하게 합니다.
- 실제 DRAFT가 만든 구조와 미가격 잔량, 계산 비율·미상 값, SELECT 근거·권한을 원입력과 대조합니다.
  강한 기회 보존·전체 보유 정책·실현 수익은 두 사례로 입증할 수 없으며 별도 HOLD입니다.

후속 전략 배포는 이 검사의 기술 성공만으로 수행하지 않습니다. 10배·15분봉 제외·기존 위험 한도는 유지합니다.
