## 피드백을 반영한 설계 결정

1. 로그나 최종 packet이 아닌 HTTP transport에서 완성 원문을 보존합니다. 그래야 scope 검사에서 탈락한 원문도 재현할 수 있습니다.
2. `collect_latest`의 진단용 선택형 주입점을 통해 실제 보고서 어댑터를 실행합니다. 진단 도구가 비슷한 packet을 수작업으로 만들어 운영 경계 검증이라고 부르지 않습니다.
3. 부분 수신·압축 거절·전송 오류·취소·저장 실패를 나누며, marker를 먼저 생성하고 성공 확정을 마지막에 합니다. `to_thread`를 취소하면 파일 쓰기도 멈춘다는 가정은 하지 않습니다.
4. 신규 fixture는 Git 밖의 제한된 저장소에 둡니다. 원문은 사용자 배포용 파일에 포함하지 않고 source hash·요약·검증 결과만 제공합니다.

### 실제 검증 피드백: 로컬 capture 한도와 원천 장애 분리

독립 리뷰에서 다음 최소 설계를 승인했습니다. streamed/buffered 모두 `CAPTURE_LIMIT_EXCEEDED` 상태와 개별/누적 한도 정적 코드를 보존하고 manifest summary와 반환값에 같은 코드를 기록합니다. 둘 다 초과하면 둘 다 기록합니다. 일반 ReadError는 STREAM_ERROR를 유지합니다.

실제 adapter가 예외를 흡수하더라도 로컬 한도 코드가 사라지지 않는 실패를 먼저 고정합니다. cap, 예외 흐름, 부분 원문 미저장, marker, replay 거절은 변경하지 않습니다. 기존 삼성생명 fixture를 소급해서 수정하거나 새 결과로 덮어쓰지 않습니다. 한도 확대·초과 chunk 전달·본문 추측 수정은 이번 피드백 범위 밖입니다.

피드백 구현 후 fixture 회귀 68개, 전체 CI 연구 입력 묶음 1,537개가 통과했습니다. 독립 리뷰에서 발견한 테스트 import 순서 1건도 수정하고 Ruff를 다시 통과했습니다. 실제 삼성생명 원문을 다시 수집하거나 초과 본문 복구로 표시하지 않습니다. 기존 KR BUY hash snapshot은 별도 실행에서 2개 실패/7개 통과이며 기대값은 수정하지 않았습니다.

## 사용자 지원 후 재개할 경계

1. 기존 PRISM용 ChatGPT 계정의 재로그인: 만료된 refresh token은 코드로 복원할 수 없습니다. 사용자가 로그인할 수 있을 때 새 인증 절차를 시작하며 만료된 기기 코드를 재사용하지 않습니다. 토큰/비밀번호를 채팅으로 요청하지 않습니다.
2. 삼성생명 대형 원문: 현재 제한 아래에서는 연간 주석 전체가 없어 내용 기반 분할·조건 검증을 할 수 없습니다. 사용자가 공식 원본 HTML/ZIP을 제공하거나 **운영 2 MiB 상한은 유지한 채 별도 비공개 진단 취득만 최대 8 MiB로 허용**할지 정해야 합니다. 승인 전 한도를 올리거나 임의 offset/앞부분을 정상 문서로 처리하지 않습니다. 진단 확대를 승인받아도 별도 설계·보안·자원 회귀 후 1건만 취득합니다.

지원 전 보류 대상은 인증이 필요한 실제 모델 단계와 대형 원문 확보입니다. 나머지 S2c/S3/S4가 완료됐다는 뜻이 아닙니다. 코스맥스는 이번 실행의 미실행으로 남기고 새 재개 실행에서 분리해 기록합니다. 검증군을 향후 튜닝에 쓰면 회귀군으로 전환하고 새 검증군을 먼저 고정해야 합니다.
