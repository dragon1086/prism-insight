# P4b: 공식 DART 목록부터 표지·재무 본문·자료 선택까지

## 목적과 범위

기존 순수 선택기에 실제 공시를 공급하는 읽기 전용 진단 경로를 구현했다.
검색 첫 결과나 회사 IR의 오래된 목록을 최신 정기공시로 가정하지 않는다.
TradingView 데이터와 무관하게 직접 DART 공개 목록·본문을 조회한다.
TV 운영 이용 판단은 `TRADINGVIEW_USAGE_DECISION_20260920_ko.md`에 별도로 기록했다.

기존 보고서/스크리닝/BUY/SELL 호출부·설정·주문·cron은 변경하지 않는다.
이 진단 API를 만든 것과 정규 배치에 적용한 것은 다르다. 명시적 실행 없이 조회하지 않는다.

## 실행 경로

1. DART 회사별 검색 페이지의 실제 form/JavaScript에서 확인한 공개 검색 요청을 사용한다.
   법인코드·시작일·기준일과 정기공시 세 종류를 지정하고 최종본만 보는 필터는 사용하지 않는다.
2. 각 페이지의 법인코드, 실제 접수번호 링크, 접수일, 보고서 종류, 페이지 번호·총건수와
   연속된 행 번호를 대조한다. 오류 화면을 0건으로 바꾸지 않는다.
3. 반환된 링크의 DART main에서 실제 viewer 인자를 읽는다. JavaScript를 실행하지 않고
   허용된 정적 문자열·숫자만 파싱한다. 접수번호를 만들거나 다른 호스트로 이동하지 않는다.
4. 표지의 실제 사업연도 시작·종료일, 회사명, 제출일을 목록과 대조한다.
   제목의 월이나 회계분기만 보고 기간을 만들지 않는다.
5. 요청한 연결/별도 재무 본문을 실제로 읽고 재무상태표 제목·표 구조를 확인한다.
   목차가 있다는 이유만으로 본문을 확보했다고 하지 않는다.
6. 기존 공시 선택기로 최신 기본자료와 연차 보완자료를 구분한다. 새 자료의 수집이 실패하면
   과거 자료를 현재 자료로 조용히 대체하지 않는다. 정정 관계 미확인은 선택을 보류한다.

이 단계는 선택한 재무 section의 확보다. 전체 보고서·주석을 모두 읽었거나 개별 수치의
경제적 의미까지 검증한 것은 아니다. 문서 ID·정확한 URL/인자·본문 hash·크기와 관측시각을 보존한다.
CLI 산출물에서는 원문 HTML과 잘린 미리보기를 제외하여 기술 자료가 본문으로 오인되지 않게 했다.

## 실제 RF 검증

고정 판단시점: **2026-09-18 15:30 KST**. 조회기간: 2025-01-01~2026-09-18.
대상: DART 법인코드01343665. 법인코드를 임의로 KRX ticker와 동일시하지 않는다.

공식 목록의 정기공시 7건을 전부 조회했고 각 표지·연결 재무 본문을 확인했다.

- 기본자료: [2026년 반기보고서](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260814001631),
  기간 2026-01-01~2026-06-30, 제출 2026-08-14.
- 상세 보완: [2025년 사업보고서](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260318001224),
  제출 2026-03-18. 최신 반기를 대신하는 기본자료가 아니다.
- 조회한 기간·공시종류 안에서는 목록 7/7과 본문 7/7을 확보했다. 전 기간·모든 자료 또는
  과거 판단시점 당시 본문과의 동일성을 인증한 것은 아니므로 그 구분을 결과에 남겼다.

최종 단일 실측: **HTTP 22회, 응답 893,033바이트, 1.340269초**.
진단 모듈 자체의 모델 호출은 0회다. 개발·사전 탐색·이전 실패/재실행은 이 단일 실측에서
제외된다. 전체 개발비용이나 보고서 생성비용이 0이라는 의미가 아니며 속도 보장도 아니다.
미국 SEC·다른 업종·다른 DART 서식의 실호출 일반화는 아직 검증하지 않았다.

## 실패·피드백을 포함한 검증

- 최초 실제 실행은 목록 행 번호를 역순으로 가정해 실패했다. 원 응답은 날짜 역순이어도
  행 번호는 1부터 증가했다. 실패 receipt를 보존하고 실제 모양을 회귀로 추가했다.
- 실제 viewer 함수에는 중첩 if가 있어 첫 닫는 괄호까지만 읽는 방법이 실패했다.
  이후 파서 검토에서 반복 스캔의 시간 증가, 주석/템플릿 문자열, 지원하지 않는 대입 연산이
  낡은 인자를 살리는 문제가 드러났다. 제한된 정적 문법으로 거부하도록 수정했다.
- 권한 오류나 빈 컨테이너를 0건으로 오인하지 않도록 정상 0건 화면을 실제 조회해 구분했다.
  정상 화면은 정확한 문구·단일 placeholder 구조이며 pagination이 없는 경우도 있다.
- 최신 연차 실패 시 더 오래된 연차가 보완자료로 대신 들어가는 문제, 잘못된 세 자리 날짜를
  두 자리로 잘라 읽는 문제도 실패 회귀를 먼저 만든 뒤 수정했다.
- 보안·코드 독립 리뷰에서 위 오류를 재현하고 수정 후 다시 검사했다.
  동기 파싱을 asyncio가 선점하는 것은 아니므로 엄밀한 실시간 마감 보장은 하지 않는다.
- 최종 신규 테스트는 수집기 78개·CLI 8개다. 기존 연구/보고서 회귀까지 **916개 통과**,
  기존 deprecation 경고 3건. Ruff·compileall·diff 검사 통과 및 보안·코드 리뷰 승인.
  Python 전용 타입 검사와 의존성 취약점 감사는 도구 미구성으로 완료하지 못했다.

## 변경 파일과 단순화

- `prism_core/dart_public_filings.py`: 고정 출처 수집·정적 파싱·기존 선택기 연결.
- `tools/probe_dart_filings.py`: 명시적 --live 진단, 출력 파일 덮어쓰기 금지, 원문 미리보기 제외.
- 대응 테스트 두 파일과 CI 회귀 등록.
- 기존 `FilingCandidate`·선택기를 재사용했다. 일반 공급자 프레임워크나 새로운 필수 의존성은 추가하지 않았다.

## 재현

```bash
.venv/bin/python tools/probe_dart_filings.py --live \
  --corp-code 01343665 --decision-at 2026-09-18T15:30:00+09:00 \
  --start-date 2025-01-01 --scope consolidated --out /tmp/new_dart_receipt.json
```

기존 파일이 있으면 실행하지 않는다. --live 없이는 수집하지 않는다.
기본 상한은 3페이지·8보고서·28요청·90초, 응답별 2MiB/누적8MiB다.
기존 운영 MCP의 한도를 바꾼 것이 아니라 별도 진단 수집기의 한도다.
후속 단계는 중요 뉴스/Perplexity 복구, 원문 근거의 효율적 재사용·발췌,
서술형 보고서와 실제 PDF→BUY 및 SELL 입력 연결 검증이다. 이번에 완성 투자보고서를 만든 것은 아니다.
