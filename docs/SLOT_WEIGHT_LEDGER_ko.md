# 슬롯·비중 전략 원장 v2

## 범위와 운영 경계

이 모듈은 주문·알림 전송 기능이 없는 검증용 기반입니다. 실거래 원장 연결,
기존 운영 데이터 변환, SHADOW 스케줄 활성화, 50→100 추가 진입 정책 활성화는
포함하지 않습니다. `SHADOW`는 장부 구분값이며 설정만으로 실행을 시작하지 않습니다.

스키마 버전은 **2**입니다. 버전 1 금액 원장은 변경 없이 거부합니다.
원본을 덮어쓰거나 금액을 비중으로 자동 해석하지 않습니다. 별도 파일에 새 장부를
만들어야 하며, 출처가 모호한 과거 행은 실제 포트폴리오로 합산하지 않습니다.
기존 테이블에 버전 행이 빠져 있어도 새 원장으로 채택하지 않고 변경 없이 거부합니다.

## 장부와 캠페인 식별

```python
ledger.create_book("kr-baseline", "KR", max_slots=10,
                   cohort="baseline-v1", mode="VALIDATION")
```

- 필수 입력은 장부 ID와 시장입니다. 기본 용량은 10슬롯이며 1~10을 허용합니다.
- 전략 식별키는 `시장 + 명시적 전략 코호트 + 모드`입니다. 장부 ID는 이 키의
  로컬 별칭이며 같은 식별키에 다른 별칭을 중복 등록할 수 없습니다.
- 실행 프로필, 계좌, 잔고, 주문 거절·체결 여부는 전략 식별키에 포함하지 않습니다.
- 알려지지 않은 과거 코호트는 `cohort=None, mode="VALIDATION_ONLY"`로 격리합니다.
  실행 프로필이 같아도 서로 다른 과거 캠페인을 자동 합치지 않습니다.
- 보유 노출이 남은 캠페인 하나가 슬롯 하나를 차지합니다. 50% 진입도 1슬롯입니다.
  청산 후 같은 종목에 다시 진입하려면 새로운 캠페인 ID를 사용합니다.

## 계산 계약

한 슬롯의 기준 원금을 **1**로 정규화합니다. 이 값은 원화·달러 자산이 아닙니다.

- 목표 `target_pct`는 누적 투입 목표입니다. 증분 배분은
  `(새 목표 − 이전 목표) / 100`이며 모든 시장·레짐에서 누적 100%를 넘지 못합니다.
- 정규화 단위는 `배분 / 체결 기준 가격`입니다. 실제 주문 수량이나 보유 주수가
  아니며, 출력 키는 `normalized_units`입니다.
- `remaining_allocation`은 아직 청산하지 않은 배분 원금입니다.
  `cumulative_deployed_allocation`은 청산 후에도 줄지 않는 누적 투입 배분입니다.
- `marked_exposure = 정규화 단위 × 마지막 가격`입니다. 가격 상승으로 노출이
  커져도 새로운 배분 여력이 생기지 않습니다.
- 잔여 가중평단은 `잔여 배분 원금 / 잔여 정규화 단위`입니다. 매수 가격의
  산술평균을 사용하지 않습니다.
- 투입분 가격수익률은 `마지막 가격 / 잔여 가중평단 − 1`입니다.
- 미실현 1슬롯 기여는 `평가 노출 − 잔여 배분 원금 − 잔여 진입 비용`입니다.
- 실현 1슬롯 기여는 매도 순회수분에서 해당 배분 원금과 진입 비용을 차감합니다.
- 합계 1슬롯 기여는 실현과 미실현 기여의 합입니다. 배분율이 다른 캠페인의
  가격수익률과 혼동하지 않습니다.

예를 들어 100에 50% 진입하면 정규화 단위는 0.005입니다. 가격이 110이면
가격수익률은 +10%, 1슬롯 기여는 +0.05입니다. 같은 캠페인에서 125에 나머지
50%를 추가하면 단위는 0.009, 가중평단은 약 111.1111이며 125 기준 기여는 +0.125입니다.

비용은 `fee_rate`, `slippage_rate`라는 0 이상 1 미만의 무차원 비율로 받습니다.
매수 기준 가격은 `가격 × (1 + 슬리피지율)`, 매도 기준 가격은
`가격 × (1 − 슬리피지율)`입니다. 매수 수수료는 신규 배분에, 매도 수수료는
매도 회수분에 적용합니다. 평단은 슬리피지를 포함한 진입 가격 기준이며 수수료는
가격수익률이 아니라 순기여에 따로 반영합니다.

`sell(..., quantity=...)`의 `quantity`는 기존 호출 이름을 유지한 **정규화 단위**
인수입니다. 실제 주수를 전달하면 안 됩니다. 생략하면 잔여 노출을 전부 청산합니다.
부분 청산은 원금과 진입 비용을 단위 비례로 배분하며 마지막 청산은 잔여액 전부를
정리합니다. 실현 이익을 재투입해 슬롯 한도를 확대하지 않습니다.

한 번이라도 전략 노출을 줄이면 추가 배분 권한은 `CANCELLED_BY_REDUCTION`으로
바뀝니다. 50% 진입 후 25%를 줄였다고 다시 75%를 추가할 수 없습니다.
목표 10→30→60→100은 자료 구조에서 표현할 수 있을 뿐, 자동 실행 정책이 아닙니다.
기존 평균가격 아래 추가 매수 금지, 시간순 적용, 종목 중복·슬롯 한도도 유지합니다.

## 고정 용량 기여와 알림

명시적인 장부에서는 `capacity_normalized_contribution`을
`모든 캠페인의 누적 순기여 합 / 고정 max_slots`로 계산합니다.
분모는 `contribution_denominator_slots`에 함께 표시합니다. 10슬롯 중 한 캠페인이
+0.05 기여하면 고정 용량 기여는 +0.005, 즉 +0.50%입니다. 현재 점유 슬롯 수로
분모를 바꾸지 않습니다. 이는 실제 계좌 수익률이 아닙니다.

격리된 과거 장부에서는 이 값과 분모를 `None`으로 두고 합산을 금지합니다.
전략 메시지는 점유 슬롯, 배분율, 실제 종목 가격, 가격수익률과 순기여를 구분해
보여줍니다. 가상 현금·자산·가상 주식 수는 표시하지 않습니다. 추가 가능 잔여
배분은 조건부이며 추가 매수 일정이나 계좌 현금 확보를 의미하지 않습니다.
실계좌 체결 수량은 별도 집행 증거 구역에만 표시합니다.

## 과거 이벤트 재생

```bash
python tools/replay_strategy_ledger.py --input sanitized.jsonl \
  --ledger isolated-slots.sqlite --message-preview
```

프로필 없이 실행하면 시장과 정확한 포지션 ID로 캠페인을 구분하고 각 캠페인을
격리합니다. ticker·날짜 유사성으로 연결하지 않습니다. 선택 후보나 기록되지 않은
진입은 원장에 만들지 않으며 고아 청산·체결 관측은 재시도 가능 상태로 남습니다.
정책 모드는 명시적인 `normal` 또는 `rebound_pilot`, 배분율은 각각 정확한 1 또는
0.5여야 합니다. 누락·알 수 없는 모드·불리언·비유한 배분율을 100% 진입으로
추정하지 않으며, 미지원 사유를 집계하고 레그를 만들지 않습니다.

검증된 코호트 매핑이 있을 때만 `--slot-profile slots.json`을 추가할 수 있습니다.

```json
{"US":{"max_slots":10,"cohort":"documented-policy-v1","mode":"VALIDATION"}}
```

이 파일의 시장별 매핑은 입력 행 전체에 적용되므로 입력을 같은 전략 코호트로
분류했다는 근거가 있어야 합니다. 근거가 없으면 옵션을 생략합니다.
`--capital-profile` 및 금액 설정은 지원하지 않습니다.

출처 전체 행의 해시는 이벤트 충돌 검증과 실행 관측의 출처에 보존합니다.
계좌 필드가 달라도 전략 장부·캠페인·레그 식별과 계산은 같아야 합니다.
다만 같은 이벤트 ID에 다른 출처 내용을 덮어씌우는 재생은 충돌로 거부합니다.
실행 기록은 독립된 오버레이이며 확인 수량·가격·근거가 없는 체결은 미확인입니다.
출처 로그 자체가 누락 가능한 관측이므로 재생 결과는 비권위적 검증 자료입니다.

## 원자성 및 검증

이벤트 적용은 SQLite 트랜잭션으로 처리합니다. 이벤트 ID와 내용이 같은 재시도는
무효과이며 다른 내용은 거부합니다. 실패한 이벤트와 레그는 함께 롤백합니다.
시간 역행, 초과 청산, 청산 캠페인 재개도 거부하며 이벤트·레그·실행 기록은
수정하거나 삭제할 수 없습니다.

검증 명령: `python -m pytest -q tests/test_strategy_ledger*.py`.
운영 연결이나 데이터 변환은 별도 검증과 배포 범위로 남습니다.
