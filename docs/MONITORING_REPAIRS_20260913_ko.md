# 관측·근거·알림 정비

## 범위와 변경 원칙
2026-09-13 사용자 요청에 따라 운영 결함을 고칩니다. ADX/손절/슬롯/점수/사이징 규칙과 실제 주문 정책은 바꾸지 않습니다. 관측의 누락을 PASS로 만들거나 과거 관측을 가공해서 채우지 않습니다.

## 근거와 한국 관측
- 한국·미국 한/영 프롬프트에서 F4 통과 근거와 보고서의 반대·유보 근거를 대조하도록 했습니다. 시장 지배력 미입증과 구체적인 사업 경쟁우위 부재는 다릅니다. 기존 F1–F4 기준과 JSON 형식은 그대로입니다.
- HPE 운영 보고서에는 GreenLake 고객 효용·통합 제품군 등도 존재했습니다. INCOMPARABLE만으로 매수 오판이라고 확정한 기존 감사는 과도하며, 판정 근거 대조 설명의 부족으로 정정합니다. 프롬프트 변경의 실제 모델 준수는 다음 자연 배치에서 관찰해야 합니다.
- 한국 관심목록·일반 후보에 기존 구조화된 진입품질 관측을 연결했습니다. 한국 피드백 조회와 KR 출처·추출기 표기를 사용하고 미국 기본값은 보존합니다. 없는 지표는 MISSING이며 관측 오류는 매매로 전파하지 않습니다.

## SHADOW 연결
- 미국 실행별 batch_ref를 결정에 연결하고 보고서·PDF 전체 생성과 tracking 성공 때만 핵심 배치 완료를 기록합니다. 번역 완료나 확정 체결이라는 뜻은 아닙니다.
- Packet은 완료 실행과 거래일/오전·오후 고유 세션을 구분합니다. 날짜·모드·실행 참조가 맞지 않는 결정은 연결하지 않으며 20개 완료 세션 미만이면 검토 기준 미달입니다. 기존 과거 이벤트에 완료를 소급 생성하지 않습니다.
- 한국 가상3순위의 기존 16:10 tracker는 연결돼 있었지만 최근 반복 오류로 결과가 비어 있었습니다. KIS 전환 후 실제 날짜별 자료로 기존 tracker를 실행해 성숙 결과 이벤트12건을 복구했고, 재조회에서 추가 생성0·오류0을 확인했습니다. 이는 독립 실험12건이 아닙니다. 실험은 여전히3건·2거래일이며 표본 부족입니다.

## Telegram 전달 불명
- sendMessage는 비멱등 요청이므로 응답 유실 때 같은 내용을 자동 재전송하지 않습니다. 읽기/쓰기 timeout은30초이며, 명시적인 rate-limit 거절만 제한 재시도합니다.
- UNKNOWN은 실제 미전달을 의미하지 않습니다. 일반 알림은 안전한 UNKNOWN 로그, outbox는 DEAD+TelegramDeliveryUnknown으로 수동 확인 대기입니다. 전송 중 프로세스가 사라진 lease도 자동 재생하지 않습니다.
- 성공으로 위장하지 않습니다. 일부 조각 전달 후 후속 조각이 실패한 경우 전체 메시지를 다시 보내지 않도록 보류합니다. 파일 큐의 UNKNOWN도 별도 보류로 분리합니다.
- 이 변경은 전체 독립 배치 재실행을 포함하는 전역 exactly-once 시스템이 아닙니다. 실제 미전달도 보류될 수 있으며 운영 감시에서 수동 확인해야 합니다.
- HDC 알림은 프로그램의 전략 원장 DB 반영 상태와 AI가 제안한 원문을 구분합니다.

## 예약 감시
소스 배포와 별개로 해당 Telegram 채팅의 예약 지침을 보완했습니다. KRX/FDR 복구를 정상 경로로 인정하던 옛 지침을 KIS 단일 경로 기준으로 정정하고, 파일럿50% 예산 상한과 원장 비중을 구분했습니다. 공통 감시는 소유 chat_id를 검증한 예약 실패·쿼터/용량 오류를 추적합니다. 모델 자체가 시작되지 못하면 같은 모델 기반 감시도 실행되지 못하는 한계는 남습니다.

가상3순위 재검토는10월26일에서9월21일로 앞당기고 이후 미충족 시1주 간격으로 점검합니다. 미국 초분할9월19일, BTC 주간월요일09시 예약은 유지합니다. 자동 전략 승격·매매 배치 재실행은 하지 않습니다.

## 검증과 롤백
새 회귀 테스트는 근거 계약/실제 SQLite→이벤트 연결, 실제 파이프라인 메서드의 성공·실패 경계, timeout/명시 거절/부분 전달/만료 lease를 보호합니다. CI에도 이 테스트들을 연결했습니다. 실제 미래 배치의 관측 성공과 소스 테스트 통과는 구분합니다.

롤백은 검증된 수정만 후속 revert PR로 수행합니다. 운영 원장·과거 이벤트를 삭제하지 않습니다. UNKNOWN/DEAD를 일괄 PENDING으로 바꾸거나 보류 파일을 자동 재전송하지 않습니다. 실제 수신 확인과 사람이 선택한 개별 복구가 먼저입니다.
