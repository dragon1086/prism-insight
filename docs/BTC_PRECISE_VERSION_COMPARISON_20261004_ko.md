# BTC 최신 운영 보완의 정밀 전후 비교

## 결론과 비교 범위

**직전 검증 버전 대비 현재 운영 버전의 수익률 차이는 세 조건 모두 0이다.**
이는 수익성 향상 입증이 아니라, 매매 정책을 유지하면서 운영 결함을 고쳤다는 회귀 증거다.
옛 휴리스틱 전략과 새로운 MA/LLM 전략 전체를 비교한 결과는 아니다.

- 이전: `3b5a4a6933bf0f6f934b9e4f5fe3b687bb2221af`
- 현재: `8a53364f1959fb86e5c613d5e23f5833488250e6`
- M2 재생 신뢰성 / M4 비교 평가. 운영 전략·모델·위험·스케줄·주문 변경 없음.
- 해당 구간의 BTC 비테스트 소스 차이는 `scenario_broker.py`, `scenario_accounting.py`,
  `scenario_notice.py`, `scenario_notice_evidence.py` 네 파일뿐이다.
- 프롬프트·진입/비중/SL 제한·주문 집행·런타임·시장 입력·거래소 시뮬레이터는 동일하다.
  펀딩 정산 차단 해소는 실제 신규 진입 가능성에 간접 영향을 줄 수 있지만,
  이를 이 시뮬레이션의 수익률 향상으로 환산하지 않는다.

## 비교 절차

결과 생성 전 `preregister.txt`로 범위를 고정했다. 기존 2026-10-02 00:00 UTC부터
10-03 00:00 UTC까지의 24시간 자료를 사용한다. 이미 본 탐색 구간이지 새 OOS가 아니다.
가상 초기자본 10,000 USDT, 10배, 시나리오 2%/일 4%/3연패 정책을 유지한다.

A는 OHLC 기본 비용, B는 OLHC 기본 비용, C는 OHLC 수수료율·슬리피지 2배다.
각 조건 내부에서 같은 LLM 기록·지연·오류를 고정하고 이전/현재를 각각 실행했다.
각 288개 슬롯, 합계 **864쌍**과 종료시각까지의 전체 경제 결과가 일치했다.
원본 기록 852개에는 오류 기록 1개도 포함되며 **신규 모델 호출·네트워크 시도는 0회**다.

원본 tape/header/record hash를 수정하지 않는다. 연구용 어댑터는 원본 소스와 현재
소스의 manifest를 각각 Git 객체와 대조한 뒤 네 파일의 소스 차이만 명시적으로 허용한다.
그 밖의 데이터·기간·프롬프트·모델·비용·런타임 계약과 모든 판단의 의미적 입력은
기존 native 검증을 통과해야 한다. 불일치는 즉시 중단하고 임의 WAIT/새 LLM 응답으로
보충하지 않는다. 보고서와 sidecar 모두 `CROSS_VERSION_COMMON_RESPONSE_REPLAY`로 표시한다.

5분 슬롯별 상태뿐 아니라 마지막 슬롯 이후의 시장 진행과 최종 정산까지
주문/체결/거래소 상태/자산곡선/낙폭/손익/판단·보호 결과를 대조했다.
소스가 다른 두 보고서의 전체 result hash를 같게 만들지 않는다. 이전 소스 3개 실행은
기존 native frozen result hash와 동일하며, 현재 소스는 경제적 결과의 동일성을 검증한다.

## 회계·시장 자료 독립 대조

운영 DB가 아닌 격리된 모의 DB만 읽기 전용으로 사용한다. exact child/order/execution/
TRADE transaction/settlement ID 연결, 수량·평균가·gross PnL·수수료율·중복 과금 여부와
단일 포지션의 시간순 소유권에 따른 펀딩 귀속을 대조했다. 모호한 동시 체결/펀딩은 거부한다.

보존 시장 bundle의 content hash, 최종 Mark/Last, 8시간 펀딩 일정과 지급액도 대조했다.
최종 Mark close는 84,476.43, Last close는 84,475.90이며 모든 조건에서
`cash + position × (Mark - average)`가 보고된 equity와 일치한다.
종료 정각 펀딩 A -0.43323568/B -0.04641811/C -0.20114514 USDT도 이미 포함돼 있다.
누락 펀딩 조정액은 모두 0이다. 이는 보존 자료 사이의 일관성이지 외부 시장 진위의 독립 인증이 아니다.

잔여 물량을 최종 Last에서 불리한 슬리피지·반 스프레드·taker 수수료로 정리한다고
가정한 전체 순손익 **추정치**는 A +202.43099361/B +223.11002640/C +123.08326288 USDT다.
실제 강제 청산을 실행한 백테스트가 아니며, 호가단위·유동성·지연·추가 펀딩은 재현하지 않는다.
해당 추정치로 원본 미청산 결과를 덮어쓰지 않았다.

## 운영 결함의 별도 재현

기존 시뮬레이터는 정상 Funding execution 및 flat 빈 SL 응답을 충분히 재현하지 못한다.
따라서 historical arm에 몰래 주입하지 않고 6개 합성 장애 형태를 양쪽 코드에 따로 적용했다.

- 정상 펀딩 납부/수취: 이전은 unmatched로 정산 pending, 현재는 각 1회만 정산.
- 충돌한 펀딩 정보/누락된 지급 일정: 양쪽 모두 미확정 또는 거부. 보호 조건은 완화하지 않음.
- flat 빈 SL와 정상/빈 레버리지: 이전은 ValueError로 공지 실패, 현재는 CLOSED 1건 생성,
  반복 조회 시 추가 생성 0건. 실제 채널 발송과 주문은 0건.

이 12개 버전별 사례는 장애 재현이지 시장 성과 표본이 아니다. 수리는 실제 실행 가용성을
개선하지만 그 수익 기여는 이 24시간 자료에서 계량하지 못한다.

## 검증·남은 한계

연구 어댑터/회계 감사의 44개 회귀 테스트, 6개 완주, 12개 장애 사례의 assertions,
Ruff F/E9 및 독립 소스·결과 재검증을 통과했다. 검증 강화를 위한 예비 old A 실행은
보존하되 최종 6개 실행에서 제외했다. 운영 코드를 수정하거나 보류 전략을 활성화하지 않았다.

동일 하루, 조건별 종료 3~4건, 가정한 분봉 내 가격 순서, 호가 대기열·강제청산 미재현,
진행 중 1분봉/실제 tick 부재, 미종료 시나리오가 한계다. 30분/1시간 진행봉은 당시까지
완성된 1분봉으로 구성했으며 미래 완성봉을 사용하지 않았지만 실제 tick 재현은 아니다.
OOS 60건/forward 30건 등 기존 수익성 입증 기준은 충족하지 못했다. 좁은 신뢰구간이나
지속 수익성, 새 MA 전략 전체의 옛 전략 대비 우위를 주장하지 않는다.

**최종 판정: PREREGISTER_REPLAY.** 다음 수익성 검증은 현재 정책을 고정한 새 기간의
다중 시기 평가 및 실제 종료 표본으로 분리하며, 이번 결과를 근거로 위험/공격성을 올리지 않는다.
