# DART 심층 장 및 동종기업 비교 완료 조건

## 실패 원인과 유지할 기준

현재 운영은 공시별 주요 블록을 기존 세 절의 24KB 입력에 배분하고 각 절을 3,000자 이내로 작성한다. 수집기·계산·배포 검증을 보고서 심층분석 완료로 잘못 취급했다. 이 경로를 다시 크게 포장하는 것으로 완료하지 않는다.

기존 최종 개발본의 source-tree 계층 보존, 병합 표 열 정렬·역변환, 일곱 전문 주제 및 plain 숫자·기간 주의 규칙을 재사용한다. V2~V4 구조화 출력 강제 실패 경로, 실험용 별도 시장자료·차트·전체 실행기는 활성화하지 않는다. 최신 운영의 fragment·부모 문맥 검증, 계산·표현·OAuth·원격 시세 경로를 퇴행시키지 않는다.

## 보고서 구조

- 기존 기술·기업·뉴스·시장 절을 보존한다.
- 전략 작성 전에 별도 **DART 주요 재무·사업 위험 분석** 장을 작성한다.
- 일곱 분석 주제를 실적·현금흐름·차입·회계 / 사업·지배구조·자본 / 약정·사건·우발위험의 세 집필 역할로 묶는 안을 우선 계측한다. 이는 새 조합이므로 검증 없이 기존 성공본과 같다고 주장하지 않는다.
- 기존 8개 작성 단계에 3개를 추가하는 안이며 비용·시간이 늘 수 있다. 실제 토큰·시간을 별도로 기록한다. 용량 초과 시 몰래 원문을 자르거나 호출을 늘리지 않는다.
- 집필 결과는 원래 보고서의 합쇼체·문단 중심으로 작성하고 최종 본문에 그대로 보존한다. 전략·요약에는 같은 장을 제공하되 그 요약으로 원래 장을 대체하지 않는다.

## 입력과 내용의 보존

같은 DART 수집에서 검증된 원문을 별도 메모리 경로로 보존한다. 기존 topic-filtered blocks나 24KB 결과를 심층 장의 원문 전체로 간주하지 않는다. 최신 note fragment와 검증된 부모 문맥도 명시적으로 지원한다.

수집 목록, 선택/제외 사유, 집필 입력의 원문 단위 합집합, 최종 문장의 사실·조건 보존을 각각 검사한다. 원문 합집합 해시 일치만으로 최종 내용이 완전하다고 하지 않는다.

SKT 표본에서는 실제 선택 원문에 있는 소송·충당부채·담보·TRS·신종자본증권·AWS 약정·출자약정·차입만기 등을 본문에서 확인해야 한다. 금액·단위·대상 기간·이행 조건·면제/반대 근거와 투자상 의미를 설명해야 하며, 단순한 목록·미확인 안내로 대체하지 않는다. 페이지 수 자체는 성공 지표가 아니다.

## 경쟁사 비교

대상 기업 DART만으로 경쟁사 분석이 완성되지는 않는다. 비교 대상 선정 근거와 동일 기간·정의의 각 회사 자료가 필요하다.

- 실적·재무구조·주석 위험: 각 회사 DART/IR 우선.
- PER/PBR·배당·컨센서스: 동일 공급자·기준일·실적/예상 구분을 갖춘 WiseReport 등 기존 접근 가능한 자료 보완.
- 동일기간 상대수익률: 기존 시세 공급자의 같은 거래일·가격 보정 기준 사용.
- 시장점유율·가입자·ARPU·IDC·AI 사업 우위: 사업 범위와 지표 정의가 맞는 공시/IR/산업 통계가 있어야 판단한다.

Firecrawl은 페이지 수집 도구이지 동종사 선정·숫자 정합성·이용권한을 보증하는 데이터베이스가 아니다. 공개 조회 가능성과 대량 수집·지속 저장 허용 범위를 혼동하지 않는다. 선택한 두세 기업의 평균을 업종 전체 평균이라고 표시하지 않는다.

## 실제 체인과 검증 경계

한국 DART 수집은 스크리닝 이후 보고서 생성 단계에서 시작한다. PDF 전체는 자동 BUY 프롬프트에 전달되지만 보유 SELL은 별도 기업상태·O'Neil·안전망 경로다. DART를 전 종목 스크리닝·SELL에 이미 직접 반영했다고 주장하지 않는다.

새 장을 `section_reports`, 전략용 `combined_reports`, 요약, 최종 PDF에 모두 연결한다. Telegram 평가의 앞30k/뒤10k 절단으로 중간 심층 장이 사라지는 경계도 처리한다. 실제 PDF 후반의 고유 금액·조건이 BUY 양쪽 실행 경로까지 도달하는지 주문 없는 시험으로 검증한다. 점수·손절·게이트·주문 정책을 임의 변경하지 않는다.

## 다음 확인 순서

1. 기존 SKT·롯데·LG 고정 입력으로 원문 보존과 세 묶음 입력 크기를 먼저 검사한다. 이 단계에서는 모델을 호출하지 않는다.
2. 심층 장과 비교 자료의 실제 출력 내용에 대한 수용 기준을 고정한다.
3. 공통 생성·PDF·BUY·평가 경로를 격리 테스트한다.
4. 실제 보고서 1건에서 새로운 사실과 조건이 살아남았는지 대조한다. 기존 실패/원본을 보존한다.
5. 정확한 head CI와 운영 검증 후에만 배포·완료로 보고한다.

## 구현 중 확인한 경계

- 세 묶음의 최종 원문·codec 설명·담당 목록 포함 입력은 SKT 347,284바이트, 롯데 493,225바이트, LG 280,774바이트다. 역할당 220,000바이트·합계 540,000바이트 상한 안에서 선택 단위 보존을 확인했다. 모델 호출 없이 계측했으며 서술 완전성 검증과는 다르다.
- 명확히 빈약한 집필 결과는 길이·문단·제목·제공된 공시 출처 여부로 거절한다. 이 형식 검사는 숫자 진위나 모든 중요 사실의 보존을 증명하지 않는다. 실제 SKT의 주요 항목은 별도로 원문 대조한다.
- 수동 `/report`는 심층 장을 요구하며 입력 준비 실패 시 기존 기본 보고서를 완성본으로 저장하지 않는다. 구형 캐시도 새 심층 요청에서 재사용하지 않는다.
- 기존 정규 배치에는 새 독립 매수 차단 조건을 넣지 않는다. 선택적 심층 입력/작성 실패 시 기본 분석을 보존하되 미완료 범위를 명시하고, 그 산출물을 수동 보고서의 완성본 캐시로 승격하지 않는다.
- 경쟁사 모듈은 확인 가능한 PER/PBR/EPS/배당 등 재무·예상 지표 비교다. 미래 실적 기간·불가능한 월·오래된 시세의 현재 배수 비교를 거절한다. 업종 수요·시장점유·ARPU·IDC 경쟁우위나 업계 순위를 자동 입증하는 모듈이 아니다.
