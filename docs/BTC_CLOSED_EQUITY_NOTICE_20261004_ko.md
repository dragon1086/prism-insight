# BTC 종료 알림의 청산 후 계좌 순자산

## 범위와 계획

M3.1/M3.2 알림 후속이다. 종료 알림의 정산 순손익·시작 계좌 비율은 유지하면서
같은 종료에 연결된 계좌 순자산을 짧게 추가한다. 매매·보호·위험·스케줄은 바꾸지 않는다.

1. 기존 notice/progress 회귀를 먼저 실행한다.
2. producer가 종료 후 자산을 전달하지 않는 실패와 렌더링 누락 실패를 먼저 재현한다.
3. 기존 검증된 flat 스냅샷을 새 CLOSED 이벤트에만 선택적으로 보존한다.
4. 금액과 조회 시각을 표시하고, 미확인 자료를 현재 계좌나 추정값으로 대체하지 않는다.
5. 실제 producer→event→renderer와 plain-text outbox 경계, 중복 발송 금지를 검증한다.
6. 정확한 head CI 이후 ff-only 배포하고 정규 실행과 새 종료 공지 관측을 구분한다.

## 증거·표현 계약

- 종료 체결·정산·잔량 0·주문 종료의 기존 증거 조건은 그대로 유지한다.
- 같은 계좌·같은 종료 관측이며 검증된 포지션 잔량이 0인 자료만 사용한다.
- 계좌 조회 시각은 마지막 청산 체결 시각 이후 120초 이내여야 한다. 이전 시각·오래된
  자료·후속 포지션·다른 계좌·잘못된 수치는 사용하지 않는다.
- 검증된 순자산 0은 표시할 수 있지만 비율의 분모로 사용하지 않는다.
- 기존 시작 순자산 대비 매매 순손익 비율은 계속 시작 순자산을 분모로 쓴다.
- **시작 자산+확정 손익으로 종료 자산을 추정하지 않는다.** 입출금·다른 평가손익·수수료가
  있을 수 있으므로 거래소 계좌 관측값을 별도로 표시한다.
- 예: `💰 종료 후 순자산: 9,647.71 USDT`와 계좌 조회 시각.
- 자료가 없으면 `종료 후 순자산: 미확인` 한 줄을 추가한다. 종료 정산 자체를 버리지 않는다.
- 과거 CLOSED 원본은 불변이다. 새로 조회한 잔고를 소급해 붙이거나 기존 공지를 재발송하지 않는다.
- 지연 복구 알림은 당시 자료가 없는 경우 미확인으로 남긴다.

## 검증과 적용 상태

로컬 구현·검증을 완료했다. 기존 103개 통과 후 신규 회귀 15개 실패를 재현했고,
수정 후 관련 notice/progress/execution 199개와 plain-text outbox 경계를 통과했다.
최종 전체 격리 BTC 테스트: **3,068 passed / 12 skipped / network attempts 0**(Python 3.12.12).
Ruff F/E9·컴파일·diff check와 독립 검토도 통과했다. 별도 타입검사 설정은 없다.
0원 검증은 알림의 금액 표시 계층이다. 운영 계좌 조회의 기존 equity<=0 차단은 변경하지 않았다.

구현·로컬 회귀·CI·운영 Python 검증·첫 정규 실행·새 자연 종료 공지는 각각 확인한다.
이 문서의 사전배포 계획만으로 운영 반영이나 실제 새 종료 공지 발송을 주장하지 않는다.
사용자가 인용한 과거 메시지는 이번 작업으로 새 메시지처럼 다시 보내지 않는다.
