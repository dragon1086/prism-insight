# M4: 근거 있는 진입 대안 생성 → 추세 기회 보존

등록 2026-10-25. 사용자가 승인한 우선순위에 따라 신규 진입 DRAFT만 변경합니다.
운영 baseline은 486a4e38입니다. 이전 2:1 SELECT 선호 후보(#1125)는 HOLD로 보존하며 가져오지 않습니다.

## 변경 적합성 및 완료 조건

1. 병목: 앞선 native 비교에서 양쪽 모두 후보 한 개를 생성했고, 숏의 50/30/20 익절 비중은
   그대로였습니다. SELECT의 거절 선호만 강화해도 더 나은 계획을 만들지는 못했습니다.
2. 가설: 기존 최대 2개 후보 안에서 구조적으로 구별되는 진입 가격 또는 청산 배분 대안을
   생성하면, 현재 자리 하나의 승인/거절보다 의미 있는 비교가 가능해집니다. 두 개를 강제하지 않습니다.
3. 변경 경로는 시장 입력 → DRAFT 문단 → 기존 호스트 계산 → 변경 없는 SELECT입니다.
   schema/후보 수/호출 수/선택 기준/위험/체결/보유/보호 코드는 동일합니다.
4. 같은 수익 공간에 수량만 줄이거나 자신감만 바꾼 것을 좋은 대안으로 보지 않습니다.
   비율 맞추기 목표 연장·SL 축소, 근거 없는 반대 방향·러너·가짜 가격은 금지합니다.
   강한 움직임의 실행 가능한 현재 진입을 대기 주문으로 전부 대체하지 않습니다.
5. 실제 두 후보 계산·변조 거부·입력 한도·형제 보유 지침·15분 제외를 관련 테스트로 확인합니다.
   AST 차이는 DRAFT_PROMPT 하나여야 하며 SELECT는 운영 baseline과 바이트 동일해야 합니다.
6. 사후 높은 비율·전부 WAIT를 성공으로 세지 않습니다. 새 구조가 없거나 계산/권한/시장 근거
   오류가 있으면 HOLD입니다. 합성/offline 검사와 실제 수익 개선·M5 입증은 분리합니다.

## 단계별 신규 검증 (기존 종료 예산 재사용 금지)

- 1단계 생성: 기존 고정 LONG bounded 5976088 / SHORT fully priced 5976117의 동일 원 snapshot/context.
  BASE→CAND, 각 DRAFT+SELECT 1회로 최대 8 HTTP입니다. 적어도 하나의 후보 실행에서 근거 있는
  구별 가능한 두 대안이 생성되고, 두 사례 모두 해석·권한 실패가 없어야 2단계로 진행합니다.
- 2단계 기회 보존: 원자료 23건을 손익 없이 시각순 정렬합니다. entry_contract_version=2,
  1h/30m의 형성 MA10/35 배열·가격 위치가 방향과 일치하고 확정 가격 위치도 같은 방향이며,
  1h 확정 종가 세 개와 형성 가격이 그 방향으로 이어지는 최초 LONG/SHORT를 고정합니다(C08/C11).
  이 기준은 결과를 보지 않는 방향성 대조 사례 선택이며 '반드시 사야 하는 정답'이나 승리 거래 증거가 아닙니다.
  BASE→CAND 각 DRAFT+SELECT로 최대 8 HTTP입니다. 단순히 추가 종가/재시험을 요구하거나,
  근거 없는 대기 주문만 남겨 현재 기회를 제거하면 실패입니다. 시장 반대 근거에 따른 WAIT는 허용합니다.
- 총 상한 16 HTTP, retry 0, arm별 wall 75초, 고정 과거 논리 시각. 첫 기술 실패 시 중단합니다.
- 기존 CallGuard/GuardedModelCall과 immutable git archive를 재사용합니다. 등록·입력·코드·스크립트
  해시를 새로 고정합니다. 원본 세션 기록은 읽지 않습니다. 주문·운영 DB 변경·메시지 전송은 0회입니다.
- 오래된 원 snapshot의 15m는 원본에 보존하되 현재 분석 view에서 제외되는지 검사합니다.
  offline 준비의 저장 DRAFT가 과거 15m changed_evidence를 포함하면 해당 경로만 제거한 fixture로
  따로 기록합니다. 실제 native DRAFT는 원입력의 현재 분석 view로 새로 생성하며 미래 사실을 채우지 않습니다.
- 두 단계의 기능 검사가 통과해도 독립 수익성·강한 기회 전반의 보존은 미입증입니다. 자동 전략 배포는 하지 않습니다.

## 1단계 결과와 오프라인 진단

2026-10-25 생성 비교 8 HTTP는 기술 완료됐으나 BASE/CAND 모두 두 사례에서 후보를 한 개만
생성했습니다. LONG은 양쪽 WAIT, SHORT는 양쪽 진입 선택입니다. 새 지침의 실제 전달과
SELECT 원문 동일성을 확인했습니다. 사전 기준의 '구별되는 두 대안 생성'을 충족하지 못해
HOLD이며 2단계 native 호출은 0회로 남깁니다. 모델 호출 예산을 재개·확대하지 않았습니다.

추가 무호출 진단은 원 DRAFT의 방향·목표·최종 SL·계약·위험 배분을 고정하고, 입력에 이미
있는 primary-frame MA10 가격으로 진입 가격만 대입했습니다. 현행 호스트가 수량을 다시 계산한
결과 LONG 1h MA10 80847.9는 계획 비율 0.2153→0.3849, SHORT 30m MA10 80681.1은
0.7690→2.5129이며 순수 호스트 필터를 통과했습니다. 이 기준 가격은 관측된 MA값일 뿐
지지·저항으로 입증된 값이 아닙니다. 되돌림 도달·체결 확률, 당시 실제 선택, 수익 개선은 미평가입니다.
시장가 진입을 이런 대기 주문으로 대체하거나 운영에 발행하지 않았습니다.

따라서 확인된 것은 '다른 가격을 계산할 수 없어서 후보가 한 개였음'이 아니라,
'숫자상 계산 가능한 다른 기준 가격을 모델이 별도 후보로 검토했다는 증거가 없음'입니다.
다음 보완은 단순히 두 개를 더 강하게 요구하는 것이 아니라, 현재 실행안과 관측 기준 가격의
대안이 각각 어떤 진입 근거·포기 조건·대기 비용을 갖는지 비교 근거를 남기는 DRAFT 계약 검토입니다.
강한 현재 움직임을 버리지 않는 대조와 독립 수익성 검증은 여전히 필요합니다.
