# 매매 에이전트 격리 진단 도구

이 도구들은 주문을 실행하거나 운영 전략을 승격하지 않습니다. 도구 연결 시험,
실제 에이전트 경로 검증, 종단 SHADOW와 자연 발생 성과를 구분합니다.

## 읽기 도구 진단

`tools/prepare_codex_full_stage.py`는 새로운 모델용 디렉터리와 별도의 호스트용
디렉터리를 만듭니다. 기존 디렉터리는 덮어쓰지 않습니다. 운영 DB를 복사하지
않고 합성 SQLite 장부를 사용합니다. 실행은 Linux의 지정된 Python 3.11,
Codex와 bubblewrap을 필요로 합니다.

- 모델에는 읽기 전용 단계 파일과 허용된 읽기 소켓만 제공합니다.
- 호스트 매니페스트와 프로바이더 실행 코드는 모델에 마운트하지 않습니다.
- 호스트 프로바이더는 신뢰한 코드입니다. 호스트 파일을 읽을 수 있으므로
  모델의 파일 격리와 같은 수준의 비밀 격리라고 설명하면 안 됩니다.
- 원본 Node 실행 파일은 읽기 입력으로만 취급하고, 고정 해시와 ELF를 확인한
  별도 소유권의 0700 복사본만 실행합니다. 원본 권한은 바꾸지 않습니다.
- 실행 파일·직접 프로바이더 소스는 고정하지만, 설치된 의존성 전체의 내용까지
  해시로 검증했다는 뜻은 아닙니다.
- 기본 진단 대상은 US입니다. KR은 명시적인 `--kr-public-diagnostic`에서만
  두 소스 환경 변수를 `fdr,naver`로 고정합니다. KIS/KRX 인증 경로를 사용한
  운영 공급자 동등성 시험이 아닙니다.
- KR 공개 경로의 근사 시가총액, 수정주가 처리와 최근 수급 자료의 제한을
  기록합니다. 지원하지 않는 값은 미확인으로 남깁니다.

`tools/probe_codex_trading_runtime.py`의 `--validate-only`는 모델을 호출하지
않습니다. 검토한 단계에서만 `--execute`를 사용합니다. 시장별 필수 서버의
완료 호출이 없거나, 도구 오류·모델의 누락 신고가 있으면 일반 성공으로
분류하지 않습니다. 완료 호출 수는 통신 상태이지 금융 데이터의 정확성이 아닙니다.

## 대체 모델 통신

`tools/isolated_responses_proxy.py`는 별도 감독 프로세스에서만 사용합니다.
원래 Responses 처리기를 재사용하지만 목적지, 요청 형태, 호출 수, 응답 크기와
시간을 제한하고 오류 내용을 정제합니다. 원본 인증 파일을 갱신하지 않습니다.

호스트에만 보관하는 인증 복사본에는 접근 토큰·계정 참조·만료 시각만 남깁니다.
갱신 토큰은 복사하지 않으며, 만료 여유가 부족하면 실행하지 않습니다. 인증
복사본은 어떤 모델 마운트 안에도 두지 않습니다. 기존 파일은 덮어쓰지 않습니다.

네이티브 변환기는 `max_output_tokens`를 제거합니다. 따라서 여기의 시간·횟수·
바이트 제한을 토큰 사용량 상한이라고 설명하면 안 됩니다.

## 아직 별도 검증이 필요한 연결

격리 초기화가 성공해도 실제 매수·매도 경로 또는 종단 SHADOW가 완료된 것은
아닙니다. 다음 경계는 별도로 구현·검토·실행해야 합니다.

1. 쓰기 가능한 가상 장부를 가진 에이전트와 읽기 전용 모델 환경의 분리
2. 감독자가 고정하는 모델 호출과 일관된 장부 스냅샷 연결
3. 취소·연결 단절·감독자 종료 시 자식 정리와 대체 모델 실행 순서
4. 실제 읽기 전용 SQLite 연결을 통한 에이전트·대체 모델의 공통 장부 조회
5. 주문 없는 계좌 증거, 가중 원장, 내구성 있는 테스트 알림의 연결
6. 한국·미국 오전·오후 및 별도 빠른 손절 관측 경로의 종단 실행

운영 모델이나 손절 주기를 이 진단 도구 때문에 자동으로 바꾸지 않습니다.
합성 장부·읽기 진단·관측된 자연 매매는 결과물에서도 별도로 표시합니다.
