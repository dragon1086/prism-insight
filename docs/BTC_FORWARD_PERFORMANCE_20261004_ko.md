# BTC 운영 증거와 비용 포함 오프라인 검증 사전등록

## 범위·선행 조건

사용자는 알림·운영 오류 보완 뒤 남은 실제 거래 흐름과 비용 포함 성과 검증을 승인했다.
기준선은 운영 배포 `3b5a4a6933bf0f6f934b9e4f5fe3b687bb2221af`다.
M3.1 운영 생명주기 증거, M2 재현성, M4 오프라인 평가 범위다.
전략·프롬프트·위험 한도·실계좌·스케줄 변경이나 자동 승격은 하지 않는다.

기존 범용 진입품질 JSONL Packet은 candidate/entry/trade 관측 이벤트용으로,
llm_scenario SQLite 운영 원장을 소비하지 않는다. 두 계약을 혼용하지 않는다.
이번 별도 도구는 운영 증거 감사용이며 진입품질·수익성 승인 Packet이라고 부르지 않는다.

  진단을 이유로 실제 주문을 내지 않는다.

검증 도구 리뷰에서 기간·모델이 서로 다른 실행도 같은 조건으로 잘못 받아들일 수 있는
반례를 확인해 입력 계약 pin을 추가했다. 실행 중 사전 선택을 바꾼 것이 아니라 원래
등록한 Git 소스 3b5a4a69의 BTC Python 129개 파일을 git show로 다시 해시해 A의 실행 전
tape header와 일치함을 확인하고, 자료·프롬프트·소스·Python/pandas/numpy·공통 계약
해시를 registry에 명시했다. 이는 A 시작 뒤 검증 강화를 위해 기록했으며, 기간·조건·
정책·초기자본을 결과에 맞춰 변경하지 않았다.

기본 가정: maker 0.02%, taker 0.055%, 슬리피지 0.05%, 스프레드 0.01%,
직전 확정 1분 거래량 참여율 1%, 주문 5초·취소/정정 2초, 실제 측정해 tape에 보존한 모델 지연.
모델에 제공하는 진행봉은 그 시점까지 확정된 1분봉으로만 집계하며 미래 30분/1시간봉의
완성 값을 넣지 않는다. 미완성 1분/틱·호가 대기열과 강제청산의 실제 재현은 아니다.

## 판정과 한계

이 24시간은 날짜로 고정한 탐색 구간이며 일부가 기존 6시간 실험과 겹친다.
미사용 holdout이나 다양한 장세의 검증으로 부르지 않는다. 모델의 과거 시장 지식도
배제할 수 없다. 조건별 fresh 응답 차이가 있어 차이를 비용/경로의 순수 인과효과로
단정하지 않는다. 기존 6시간·구버전 결과와 새 24시간 결과를 직접 우열 비교하지 않는다.

순손익·비용·펀딩·MTM 최대낙폭·종료 거래 수·승률·PF·최고 수익 거래 제외 결과,
미청산/미정산, 2% 손실 한도 초과, 모델/검증 오류를 함께 기록한다.
OHLC 경로와 신선도·일일 한도·연패 중단이 거래 수에 미친 영향도 구분한다.
기존 입증 계약의 OOS 60건·forward 30건·시점별/비용 스트레스·통계 보정을 완화하지 않는다.
실험을 마쳤다는 것과 수익성이 입증됐다는 것은 다르며 기본 판정은 PREREGISTER_REPLAY다.

## 운영 증거 Packet

운영 DB는 읽기 전용의 일관된 트랜잭션으로 읽는다. exact intent/order/exec/settlement
연결만 사용하고, 순서가 가깝거나 현재 가격이 맞는다는 이유로 과거 기록을 채우지 않는다.
원본 ID는 안정적인 비식별 참조로 바꾸고 계좌 ID·프롬프트·rationale·원응답·인증정보를
내보내지 않는다. exporter 버전과 거래 당시 버전은 구분한다.

보존된 정산과 독립 재계산을 구분한다. 당시 펀딩 일정·정산 확정시각·원본 근거 연결이
없으면 MISSING으로 남긴다. 체결 없는 취소와 미청산 포지션을 완료 거래로 세지 않는다.
이 감사 경계는 2026-10-03 16:46:19 UTC(최근 실행 보완 배포)로 고정하며,
그 전에 시작한 포지션은 carry-in이다. 이 경계가 새 전략의 동결 또는 성과 holdout 시작을
의미하지는 않는다. 거래 당시 소스/정책 hash가 미보존이면 별도 결측으로 표시한다.

운영 Packet은 CONTINUE_CAPTURE, profitability_proven=false, automatic_promotion=false다.
실제 전량 청산이 없으면 기다리는 대신 테스트 주문으로 완료 표본을 만들지 않는다.

## 운영 전진 관측과 수리

실제 demo 원장의 carry-in 거래는 진입 0.1 BTC와 청산 0.1 BTC가 확인됐다. 정상 Funding
execution을 미확인 체결로 취급하던 결함을 #898로 교정하고 09:08:46 KST에 배포했다.
이후 자연 실행에서 저장 정산은 gross -5.40000000, fee 6.35328000,
funding +0.04605927, **net -11.70722073 USDT**로 확인됐다. 수동 정산 성공 처리나
테스트 주문은 없었다. 당시 펀딩 일정·정산 확정시각의 독립 원본 연결은 여전히 결측이다.

정산과 공지는 다른 경계다. flat 응답의 빈 SL을 과거 체결 공지에 붙이면서 종료 알림만
누락되는 두 번째 결함을 #899로 교정했다. 최종 head `8227311d`의 전체 BTC 테스트
2,904 passed / 12 skipped, 운영 Python 격리 123 passed, 양쪽 네트워크 시도 0건,
CI 8개 성공 후 `f513dd84`를 **09:56:19 KST**에 ff-only 배포했다. import smoke 성공,
서버 clean, 기존 cron hash와 서비스 상태를 확인했다. 누락 한 건 복구 CLI는
DRY_RUN_ELIGIBLE이며 전송하지 않았다. 사용자 승인 전 apply하지 않는다.

배포 후 첫 정규 판단 슬롯 **10:00 KST**의 저장 outcome은 WAIT였고 10:00:29 KST의
보호/정산 자료 갱신도 확인했다. 최신 비식별 Packet에는 새 실제 진입 0.18 BTC,
청산 0 BTC가 보존돼 아직 OPEN_OR_UNSETTLED다. 이는 종료/알림 전진 검증 완료가 아니다.
무체결 취소 두 건은 완료 매매 실적으로 세지 않았다. 기존 private SENDING 3건은
전송 여부 불명 상태를 유지하며 재발송하지 않았다. 누락된 과거 CLOSED도 아직 없다.

연구 엔진은 시작 전에 고정한 `3b5a4a69`를 유지했다. 실제 Funding execution 구조와
flat 빈 SL 응답은 이번 시뮬레이터에 충분히 반영되지 않았으므로, 이 수익률을 #898/#899
실행 수리 버전의 완전한 실환경 재현으로 부르면 안 된다. 연구 소스와 배포 소스를 혼합하지 않았다.

남은 검증은 새 자연 거래의 부분 청산→잔여 보호→전량 청산→공지 영수증 연결,
과거 누락 종료 공지의 승인/전송, 원본 펀딩·정산시각 보존, 기존 OOS 60건/forward 30건
계약 충족이다. 현재 정책·프롬프트·위험 예산·스케줄·실계좌는 변경하지 않았다.
