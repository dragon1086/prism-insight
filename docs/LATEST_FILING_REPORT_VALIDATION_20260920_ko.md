# 최신 공시 보고서 연결·섹션 수집 검증

## 범위와 결론

기존 Draft PR #752의 c894284c 이후 작업입니다. 최신 공시를 검색 순서에 맡기던 경로에 **선택형 DART 공식 목록 → 발행사 확인 → 기준시점 선택 → 섹션별 원문 → 보고서 입력** 경로를 연결했습니다. 미국은 별도 프로세스에서 실제 PDF reader → 실제 BUY 메서드까지 전달 계약을 검증했습니다.

**전체 PR 완료·운영 승격 판정이 아닙니다.** 실제 모델 인증이 여전히 실패하고 중요 근거의 누락·독립 표본·SELL 스냅샷 등의 품질 게이트가 남습니다. 보유기간·손절·재진입·주문 비중은 바꾸지 않았습니다.

## 구현

- `dart_identity.py`: 공식 회사 검색과 회사 프로필의 종목코드를 대조합니다. 회사 이름을 법인코드로 추측하지 않습니다. 3회/응답 1 MiB/합계 3 MiB/15초 한도를 두고 오류는 정적 코드로 남깁니다.
- `dart_public_filings.py`: 기본 provenance-only 동작은 유지합니다. `include_section_bodies=True`일 때 검증된 같은 문서의 재무제표와 주석 원문을 별도로 전달합니다. 각 응답 2 MiB, 합계 8 MiB, 최대 28회라는 보고서 호출자의 예산을 유지합니다. 개별 섹션이 너무 크면 잘라 쓰지 않고 누락 사유를 기록합니다.
- `dart_report_evidence.py`: 기존 선택기가 고른 기본 공시와 연간 보완 자료만 처리합니다. 원문 해시·viewer 인자·URL·원문 내 범위를 확인하고 기존 파서·조건 묶음·주제 분류를 재사용합니다. raw DART HTML을 Firecrawl 정제 HTML이라고 표시하지 않습니다.
- `filing_report_evidence.py`: 공통 레코드 변환을 추출하여 기존 Firecrawl 처리와 새 DART 처리가 같은 주제·조건 보존 규칙을 사용하도록 했습니다. 새 의존성은 없습니다.
- `report_insight_prefetch.py`, `report_research_prefetch.py`: 기존 `material_v2`에 별도 `latest_periodic_filings: true`를 지정한 KR만 활성화합니다. OFF·US·structured_v1은 새 HTTP 수집을 하지 않습니다. 검색에서 얻은 미선정 정기 공시는 제외하되 확인 가능한 수시 공시는 기존 검증 경로를 유지합니다.
- `filing_html.py`: 주석 속 회계정책 제목을 최상위 재무제표 제목으로 오인하던 오류를 수정합니다. 확정할 수 없는 범위 전환은 UNKNOWN으로 처리합니다. 캐시 revision은 `bounded-html-v3-note-scope`입니다.

## 시점·최신성·비용 계약

- `decision_at`은 aware datetime이어야 하며 보고서 기준일과 일치해야 합니다. 날짜만 주어진 기존 호출은 한국 시간 해당 날짜 00:00으로 보수적으로 처리합니다. 제출 시각이 없는 당일 공시를 임의로 이미 알았던 자료로 취급하지 않습니다.
- 제출일, 회계기간 말일, 현재 관측 시각을 별도로 남기고 사건일은 확인되지 않으면 UNKNOWN입니다. 연간 보완 자료가 최신 실적을 덮어쓰지 않도록 역할을 전달합니다.
- 조회 범위의 목록이 완전하더라도 전역 최신성을 보증하지 않습니다. 실제 결과는 `INCOMPLETE`, `latest_confirmed=false`, `CATALOG_COVERAGE_UNCONFIRMED`입니다.
- 모델 입력은 담당 섹션별 **6,000 UTF-8바이트** 한도를 유지합니다. 메타데이터도 예산에 포함하고 원문 조건을 잘라 넣지 않습니다.
- 기존 `calls`는 MCP 호출 수입니다. `dart_calls`/`dart_response_bytes`는 별도 HTTP 비용이며 `total_calls_this_run`으로 합계를 표시합니다. 외부 timeout 취소 중에도 공유 계측으로 이미 실행한 요청을 보존합니다. 캐시 적중 시 이번 실행 호출 수는 0입니다.

## 미국 전달 경계

`test_us_material_report_consumer.py`는 독립 subprocess에서 실제 US `cores`·`tracking` namespace를 먼저 연결합니다. 이 연결을 제거한 대조에서는 기존 ImportError가 재현됩니다. 임시 HOME·환경 allowlist·dotenv 차단·socket/브로커/채널 금지를 적용했습니다.

ReportLab으로 만든 고정 PDF를 실제 reader로 읽어 실제 US `_extract_trading_scenario`에 전달했습니다. 기간·연결 범위·약정 미위반 조건·후속 확인·출처가 보존되고 기존 system prompt가 유지됩니다. 모델 응답은 고정 No Entry입니다. **SEC 실수집·모델 생성 품질·BUY 판단의 정확도·SELL 연결을 검증한 것은 아닙니다.**

## 인증과 운영 상태

기존 동일 계정의 인증 파일은 존재하고 권한은 0600이지만 access token이 만료된 상태였습니다. 정상 TokenManager 갱신을 한 번 실행한 결과 **HTTP 401 / ChatGPTAuthExpiredError**였습니다. 비밀값은 출력하지 않았고 다른 계정 자격증명 복사·유료 API 전환·반복 모델 호출은 하지 않았습니다. 모델 호출 0회이며 정식 재로그인이 필요합니다.

db-server는 읽기 전용으로 확인했습니다. `main`, `f586cc9b9a452a76086ef9bbd5485691b107e3fa`, clean이며 실제 서비스명 `crond`가 active입니다. `cron`이라는 다른 이름의 inactive 응답을 장애로 오판하지 않았습니다. 서버 소스·설정·스케줄은 변경하지 않았습니다. 미배포이므로 배포 후 점검과 첫 정기 배치 결과는 미관측입니다.

## 남은 게이트

1. 인증 재로그인 후 실제 모델 본문·출처·최신성·PDF 품질 검증.
2. 최종 고정 예산의 중요 조건·반대 근거 회수율, 연간 보완 전달, 튜닝 전 고정한 독립 기업·업종 표본.
3. 개별 2 MiB 초과 섹션을 문맥을 잃지 않고 수집하는 확장. 지금은 명시적 실패입니다.
4. 최신 중요 공시의 KR enhanced/US SELL 스냅샷. 고빈도 손절 루프에 조회나 LLM을 추가하지 않습니다.
5. 뉴스 급등 이유 원문 기반 검증, TradingView 권한·기본 OFF, 미국 전체 품질.
6. 기존 KR BUY 해시 스냅샷 2개 실패. 이번 재실행도 7개 통과/2개 실패이며 매매 프롬프트나 기대 해시를 임의로 바꾸지 않았습니다.
7. Markdown의 명시적 `###` 회계정책 제목에도 유사한 기존 범위 추정 위험이 있는지 별도 검토가 필요합니다. 이번 raw HTML 수정과 혼동하지 않습니다.

원문 처리·보고서 입력 개선으로 모델 판단이 달라질 가능성은 있습니다. 매매 규칙을 바꾸지 않았다는 사실을 경제적 영향이 전혀 없다는 주장으로 확대하지 않습니다. 전체 게이트가 통과하기 전 머지·배포하지 않습니다.
