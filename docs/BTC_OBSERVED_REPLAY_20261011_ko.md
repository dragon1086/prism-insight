# 보존된 진행봉을 사용하는 오프라인 재생 설계

대상: M2.1/M2.2 입력 시점·체결 가정 검증. 운영 매매·모델·위험·스케줄 변경은 없다.
사용자 요청은 진행봉 재현을 개선하고 같은 정책의 수익을 다시 비교하는 것이다.
기존 동결 실험은 보존하며 비용 설명 H1 등 새 전략은 이번 변경에 섞지 않는다.

## 구현 전 최소 검토 기록

1. 변경 유형: 오프라인 입력 공급·판단 시각·검증 계약 보완이다. 기준 코드는 b453d5d9이며
   운영 A 프롬프트와 기존 미배포 계층 B 프롬프트를 비교 대상으로 유지한다.
2. 가설: 실제 수신한 진행봉과 경계 합성봉의 차이가 판단·성과 비교에 영향을 줄 수 있다.
   결과 차이가 없으면 진행봉 차이가 원인이라는 가설을 지지하지 않는다. B가 좋아질 것을 가정하지 않는다.
3. 연결: 원본 SQLite 읽기 전용 추출 → 정확한 slot·감사 입력 해시 → 시장 전용 packet →
   관측 가용 시각까지 Driver 진행 → 독립 모의 계좌 context → 실제 runtime/LLM/보호/정산.
   실제 계좌의 포지션·손익·복구 상태·주문·판단 결과를 복사하지 않는다. broker/runtime는 수정하지 않는다.
4. 비교: 기존 재구성/보존 관측 입력 × 정책 A/B × OHLC/OLHC 경로를 같은 관측 일정으로 비교한다.
   10/9 12시~10/10 12시는 알려진 개발 자료이며 288slot 중 snapshot 3건이 없어 입력 진단에만 사용한다.
   다음 연속 24시간(10/10 12시~10/11 12시)은 288/288 관측 입력이 있어 사전 완전성 검사 대상으로
   고정한다. 이미 본 운영 기간이므로 untouched holdout이라 하지 않는다. 경제 결과를 보고 기간을 바꾸지 않는다.
5. 중단: 입력 해시·가용 시각·coverage·시장 자료·테이프/회계 검증 중 하나라도 실패하면 모델 호출 전에
   중단한다. 비교 시작 후 실패·거절도 보존하고 재시도·대체 WAIT로 숨기지 않는다. 임의 유리한 부분 구간을 고르지 않는다.
6. 현재 결론: 구현·오프라인 검증 준비. 아직 모델 호출·경제 실험 등록·운영 반영·수익 개선 입증 없음.

## 시간과 격리 계약

- 원본 snapshot의 as_of_ms와 프레임별 observed_at_ms를 바꾸지 않는다.
- 관측 자료는 정확한 decision_input 감사 이벤트의 observed_at 또는 그보다 늦은 검증된 가용 시각에만 공개한다.
  5분 경계로 과거 이동시키지 않는다. 모델 요청 시각이 있으면 별도로 기록하며 서로 같은 것으로 간주하지 않는다.
- 공개 시각은 밀리초 올림으로 보수적으로 잡고 원래 slot 안인지 검사한다. 원본 context.now보다 이르지 않는다.
- snapshot callback은 시계를 진행시키지 않는다. 외부 replay loop가 먼저 관측 시각까지 진행해
  모의 계좌와 시장 입력의 시간 관계를 유지한다. 기존 120초 신선도 검사를 완화하지 않는다.
- 모든 슬롯을 명시한다. 결측이면 다음 입력을 빌려오거나 원래 운영의 WAIT를 복사하지 않는다.
  명시적 결측 시험에서는 독립 보호만 계속되고 신규 모델 판단/진입은 없다. 수익 판정용 coverage는 완전해야 한다.
- 실제 운영 context는 추출 검증에만 사용한다. provider는 시장 snapshot의 독립 복사본만 반환한다.
- 시장 packet·행 집합·판단 일정 해시를 새 계약에 포함하고 변조·중복·자료 누락을 거절한다.
  기존 기본 재생 경로와 동결 schema2 tape는 바꾸거나 재해석하지 않는다.

## 체결 모형의 한계

보존 시장 입력을 쓰더라도 거래소 체결은 여전히 1분 OHLC/OLHC·가정한 유동성·지연의 모형이다.
이는 HYBRID_OBSERVED_INPUT_ASSUMED_EXECUTION이며 실제 체결 패리티가 아니다.
forming.close는 Last 기반이고 Mark로 바꾸지 않는다. 실제 context.mark_price의 관측 시각은
account_captured_at이다. 이를 snapshot 완료 시각의 동시 가격이라고 하지 않는다.
입력 교체 효과를 보기 위해 Driver 가격·체결 용량을 관측값으로 덮어쓰지 않는다.
관측 Mark와 가정 경로의 차이를 별도 진단하고, 경제 비교가 현실 체결의 입증인 것처럼 보고하지 않는다.
OHLC/OLHC에서 후보 상대 성과의 부호가 바뀌면 경로 민감으로 분류한다. 두 경로 일치도 모든 실제 경로 보장은 아니다.

## 필수 검증

- 관측 시각 이전 접근, 미래·오래된 프레임, 잘못된 slot, 중복·누락·해시 변조 거절.
- 보존 시장 입력과 원본 감사 해시 일치, 가능한 경우 실제 모델 요청을 복원한 시장 입력과 일치.
- 운영 계좌 값은 provider 출력에 없고 반환값 수정이 다음 호출을 오염시키지 않음.
- 양방향·두 봉내 경로에서 fixture fresh/frozen의 입력·체결·자산곡선 동일.
- 비정렬 관측 시각에 도달한 뒤 모의 context 생성, callback 내부 시각 이동 없음.
- 기존 기본 재생의 결과·계약 유지. 새 profile은 별도 버전과 명시적인 입력 manifest 필요.
- 실제 모델 호출은 소스·자료·기준·호출 상한을 별도 등록한 후에만 실행한다.

- 전체 BTC 오프라인 회귀: 3,501개 통과, 12개 skip. 최초 실행의 subprocess import 실패는
  필수 PYTHONPATH 누락이 원인이었으며 올바른 환경으로 전체를 다시 실행해 통과했다.
- provider·replay·dataset·tape 집중 검증: 142개 통과. 실제 288개 관측 입력의 해시와 반환값이 일치했다.
- 실제 입력의 관측/재구성 × OHLC/OLHC 네 쌍에서 고정 WAIT fixture와 frozen 결과가 일치했다.
  각 쌍은 288개 판단, 1,440개 보호 확인이며 실제 모델 호출은 0회다. 이 검사는 수익 시험이 아니다.
- 별도 경제 실행·검증 스크립트의 가짜 어댑터/임시 SQLite 회귀는 60개 통과했다.
- 독립 검토에서 발견한 미래 확정봉 시작 시각, 원응답 결측 분류, 회계 검증 전 손익 산출 문제를
  수정하고 반례 검증을 추가했다. 실제 원본 입력이나 과거 경제 판정은 수정하지 않았다.
- 변경 파일의 Ruff F/E9와 diff 검사를 통과했다. 운영 배포·경제 결과·M5 수익 입증은 별도다.
