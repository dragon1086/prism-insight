# BTC 청산 관측 보완

## 목적과 범위

최적 트레일의 검증을 위해 기존 JSONL→OTLP→ClickStack 경로에 BTC 청산 상태를
추가한다. 새 네트워크 호출·LLM·의존성·cron은 추가하지 않는다.
현재는 관측 코드이며 트레일 정책이나 주문을 변경하지 않는다.

## 이벤트

`btc.exit.snapshot`은 runner의 보호/전략 처리 전후 보유 포지션별로 발생한다.
mode·로컬 position id·진입시각·트랜치로 식별자를 만들며 stage로 전후를 구분한다.
이 식별자는 로컬 포지션 기준으로, 거래소 주문·체결과의 완전한 연결은 아직 없다.

- 전략, 방향, 수량, 진입가, 보호봉 종가와 해당 봉 시각
- 현재 로컬 스탑, 본전보호·트레일 활성 여부, 대기 진입주문 여부
- 논리 자본과 출처, 실제 노출배수, 추정 가격손익, 초기 위험 대비 R
- 실효 트레일 TF·활성 R, 코드 버전은 공통 이벤트 envelope에 포함
- 비용·펀딩 미반영 순손익 및 거래소 스탑 확인은 null/MISSING으로 유지

주의: protection bar close는 실시간 mark price가 아니다. 전후 스냅샷은
거래소 ACK/체결 증거가 아니며, before에 있고 after에 없다고 체결을 추론하면 안 된다.
동일 JSONL의 재전송은 가능하므로 event_id 기준 distinct 집계가 필요하다.

## 실패 안전성

관측 실패는 경고 로그를 남기고 매매를 계속한다. 기존 emitter의 민감정보
마스킹·이벤트 크기 제한을 재사용하며 API 응답 원문과 주문 ID를 수집하지 않는다.

## 현장 확인

db-server의 prism-observability-shipper와 tunnel 서비스는 active 상태였다.
기존 spool이 존재함을 확인했다. 신규 이벤트의 ClickStack 도착은 아직 검증하지 않았다.

## 추가로 필요한 증거

1. 보호주문 수정 intent → ACK → 거래소 재조회 확인 → fill의 exact ID 연결.
2. 트레일 계산에 사용한 확정 MA·ATR·정책 버전과 후보별 shadow 판단.
3. 포지션 생애주기 MFE/MAE, 실제 비용·펀딩, 스탑별 이익 반납량.
4. ClickStack의 distinct 수량·결측률·수집 지연·보존기간·디스크 여유 검증.

따라서 이 변경만으로 데이터 수집이 충분하다거나 최적 트레일이 적용됐다고
판정하면 안 된다. 기존 타이트한 트레일 후보들은 장기 수익을 훼손해 활성화하지 않았다.
