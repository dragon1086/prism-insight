# DART·경쟁사 보고서 배포 실행 계획

사용자 승인: 경쟁사 비교, DART 분석과 남은 오류를 해결하고 DB/app 서버 및 Telegram 봇에 배포한다. PR #752에서 필요한 변경을 선별 이식하고 역할이 끝나면 원본을 보존한 채 PR을 닫는다. 30쪽 보고서의 실제 매매 입력 여유를 검증한다. 눌림목 SHADOW 설계는 TODO만 추가한다.

## 실행 및 완료 조건

1. #752 커밋과 로컬 WIP를 운영본/현재 후보와 대조해 재사용·미이식·폐기 결정을 기록한다. TradingView와 실패한 실험을 일괄 복원하지 않는다.
2. 원문 손실 없이 기간과 표 계층을 이해할 수 있는 DART 집필 입력 및 작성 경로를 개선한다. 기존 실패를 고정 반례로 삼고 특정 종목 숫자를 코드에 박거나 PDF만 수동 수정하지 않는다.
3. 경쟁사 추출→실제 기존 수집 도구→같은 기준 비교→본문/전략/요약→PDF/BUY 연결을 검증한다. 추정치와 확정 실적, 공급자 시세 기준을 구분한다.
4. 실제 집필 결과에서 기존 오류와 주요 약정·만기 누락을 원문 대조한다. 형식·원문 해시 테스트만으로 금융 서술 정확성을 승인하지 않는다.
5. 실제 PDF 추출 및 전체 BUY 요청의 길이/토큰과 모델·실행 제한을 확인한다. 100만 토큰을 모든 실행 경로에 임의 적용하지 않는다.
6. 관련 회귀·구문·정적 검사, 정확한 PR head CI를 통과하면 병합한다. clean 운영 worktree에 Git ff-only로 배포하고 봇을 안전하게 단일 인스턴스로 재시작한다.
7. 두 서버 코드·서비스·읽기 전용 스모크·cron/보호 설정 불변을 확인한다. 첫 정규 매매 배치 관측 여부는 별도로 표시한다.
8. #752 선별 이식/보존 기록 및 후속 링크를 남긴 후 close한다. 브랜치나 로컬 WIP는 삭제하지 않는다.

## 경계

- 실제 주문으로 테스트하지 않는다. 점수·손절·규모·스크리닝·SHADOW 규칙을 이번 변경으로 바꾸지 않는다.
- 기존 공식 자료·시세·컨센서스 개선을 유지하고 새로운 의존성·유료 데이터 계약을 추가하지 않는다.
- 필요한 집필/검증에만 호출을 한정한다. 실패 원인이 남았는데 같은 전체 보고서를 무작정 반복하지 않는다.
- 프롬프트/모델 변경만으로 오류 해결을 주장하지 않고 실제 산출물 대조 후 배포한다.

## 통합 검수에서 추가한 경계

- DART 세 장을 제대로 썼더라도 기존 기업 본문과 마지막 요약이 옛 해석을 재사용하면 불일치가 남는다. 기존 마지막 요약 호출을 Astra 기반 교정·요약으로 교체한다. 정상 단계는 11개로 유지하며 추가 검수 호출을 상시 늘리지 않는다.
- 기업 현황·개요의 손익 귀속, 서로 다른 비교 기준, 자료 확보 범위를 제한적으로 교정한다. 숫자·URL·원문 단락의 일치와 중복/겹침을 코드로 확인하고 모두 통과한 후 원자적으로 적용한다. DART 원문 장·경쟁사 표·계산 근거·실제 매매 결정은 수정하지 않는다.
- 기존 거래소 달력이 휴장으로 확인한 날의 국내 종목 거래 관측 시점만 별도 제한적으로 바로잡는다. 해외 사건·공시 발표일을 휴장으로 미루거나 실제 매매 결정을 바꾸지 않는다.
- 편집 실패/미해결 충돌을 기존의 일반 요약 실패 문구로 덮어 성공 보고서로 내보내지 않는다. 검증 실패 시 발행·캐시 성공 경로로 진행하지 않는다.
- 숫자 문자열 보존 검사는 회계 의미의 정확성을 자동 인증하는 것이 아니다. 실제 최종 산출물의 귀속·기간·조건은 별도 원문 대조한다.
- 검증 실행은 같은 날 저장한 기본 초안 6개와 동일 원문/경쟁사 기준의 DART 장을 명시적으로 재사용했다. 모든 기본 초안을 매번 다시 생성한 실행이나 동일 입력 A/B 실험으로 표현하지 않는다.
