# BTC 고정 파동 백테스트

사용자 정정: 수익 개선 검증은 최근 주요 급등락 구간을 고정해 로직 변경 전후를 같은
조건으로 비교한다. 단건 AI 재검토나 배포 후 정상 작동 확인으로 대체하지 않는다.
기존 기준선·가격 지도·실제 결과를 먼저 찾고, 이후 후보마다 유리한 날짜를 다시 고르지 않는다.

## 기존 기준과 새 기준

- `BTC-20261113-fixed-v1`: 11/13 하루, 급락/반등 각4회 판단. 봉인 기준선은 종료1건·1승,
  평균 이익78.9142USDT, 손실 표본과 손익비는 없음이다. 당시 후보는0거래였다.
  알려진 개발 표본의 결과이며 실전 수익이나 지금 운영안의 성과가 아니다.
- 13/14 지도는8개6시간 영역의 큰 파동을 기록했지만, 실제 모델 비교는 하락 두 구간에
  한정됐고 중단됐다. 이를8구간 비교 완료라고 부르지 않는다.
- `BTC-20261114-16-fixed-v2`: 최근 완료3일의15분·30분·1시간·4시간별 최대 상승/하락
  24개 창을 지도에 기록하고, 하루1시간 상승/하락 두 파동씩6개를 고정한다.
  각 파동 시작부터5분 간격4회, 총24회 AI 판단이다.12시간·일·주는 runtime의 배경 입력이다.

| 고정 파동 시작(KST) | 방향 | 해당1시간 가격 변동 |
|---|---|---:|
| 11/14 10:30 | 하락 | −1.51% |
| 11/14 13:15 | 상승 | +0.91% |
| 11/15 09:45 | 하락 | −2.68% |
| 11/15 10:45 | 상승 | +4.42% |
| 11/16 20:30 | 하락 | −1.15% |
| 11/16 22:55 | 상승 | +1.73% |

파동은 사후 시세로 고른 개발 회귀 시험이다. 이 방향을 모델에 정답으로 제공하거나
진입을 강제하지 않는다. 판단 당시에는 당시까지 확정된 입력만 제공한다.

## 고정할 계약

시세·Mark·실제 펀딩·워밍업·시험 시각·초기 자본10,000USDT·비용·체결 경로·수치 실행기를
해시로 고정한다. 한 계좌의 자본과 포지션을3일간 이어가며, 기존 네이티브 주문·보호는
전 기간 실행한다. AI는 고정24회만 호출하므로 전체5분 LLM 운용 재현과 구분한다.
모델 응답 시간은 경제 시간에서 제외하되 실제 HTTP의 운영 자원·버전·시간 보호는 유지한다.

현재 로직의 기준선은 한 번 측정하고 별도 프로세스에서 저장 요청·결과를 정확히 재생한 뒤
읽기 전용으로 봉인한다. 이후에는 후보 로직만 새 폴더·등록서·호출 장부로 측정한다.
같은 benchmark hash와 engine lock hash만 같은 표에서 비교한다. 실행기·비용·시간표를
바꾸면 새 ID로 구분하며 이전 기준선을 몰래 다시 생성하지 않는다.

## 실행과 기록

로컬 실행 자료는 `tasks/btc-fixed-three-day-20261117/`에 있다.

- `selection-prereg.json`, `wave-selection.json`: 모델 결과 전 고정한 선택 규칙·시세 해시·파동·시각.
- `benchmark.json`, `benchmark.sha256`, `engine-lock.json`: 실제 펀딩을 포함해 검증한 최종 계약.
- `status.json`: 대기·실제 시작·중단·완료를 구분한다. 예약 성공은 시작/완료가 아니다.
- `day-baseline/report.json`, `frozen.json`: 실제 기준선과 별도 프로세스 재생 증거.
- `RESULT_ko.md`, `RESULT.json`: 종료 건수·승률·평균 이익·평균 손실·손익비·낙폭·비용·미청산.
- `REUSE_BASELINE_ko.md`: 후보 등록·기준선 재사용 절차.

누락 펀딩·체결·실행 실패는 모름으로 남긴다. 미청산 평가이익을 승리로 세지 않는다.
모델/기술 오류는 중단하고 재시도·예산 초기화·날짜 재선정을 하지 않는다. M5 수익성 입증과
자동 전략 배포는 별도이며 이 기준표가 승인하지 않는다.
