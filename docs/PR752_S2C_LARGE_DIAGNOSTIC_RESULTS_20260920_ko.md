# 승인된 대형 주석 진단 취득 결과

## 결과

사용자 승인, 설계 critic OKAY, 실패 회귀, 구현, 독립 코드 리뷰 APPROVE를 거친 뒤 고정된 삼성생명 연간 주석 URL을 **1회** 요청했습니다. HTTP 200으로 EOF까지 **2,833,488바이트(약 2.70 MiB)**를 확보했습니다. 재시도·다른 URL·모델 호출은 없었습니다.

- 관측 시각: 2026-09-20T10:42:10 UTC.
- receipt: `20260331004244`, dcmNo `11213317`, eleId `24`.
- SHA-256: `556ee3df6e4131bf77c72d8ca8b4a27c02c9e6cf2abf62b01ea846dbb8f724df`.
- 별도 private 진단 디렉터리 0700, body/manifest 0600이며 INCOMPLETE marker를 최종 단계에서 제거했습니다.
- 과거 불완전 fixture와 동일한 응답이라는 증명은 없습니다. 과거 fixture와 실패 기록은 변경하지 않았습니다.

## 확인된 원인과 구조

이 문서는 운영 2 MiB보다 큽니다. 현재 운영 파서에 넣으면 예상대로 `LIMIT_EXCEEDED / HTML_BYTE_LIMIT`를 반환합니다. **운영 한도는 변경하지 않았고 진단 원문을 운영 입력으로 사용하지 않았습니다.**

별도 오프라인 full DOM 진단에서 58,596개 노드, 최상위 표 1,723개를 확인했습니다. 표 기하 파서는 1,718개를 읽고 중첩 표 5개를 거절했습니다. 지원된 표의 grid는 77,808칸, 원본 셀은 35,897개입니다. 이 진단용 full DOM은 운영 파서 fallback이 아닙니다.

제목은 `15-1`, `15-2`, `15-3` 같은 하위 번호를 포함합니다. 이를 제외한 단순 정수 제목 분할은 27개 구간만 찾아 보험계약 내용을 앞의 기타자산 구간에 잘못 묶습니다. 하위 번호까지 포함하면 상위 주석 제목을 포함한 55개 제목 경계가 관측되고, 가장 큰 직렬화 구간은 709,644바이트입니다. **직렬화 크기는 원문 바이트 offset이나 공식 부분 문서 요청 tuple이 아닙니다.**

따라서 앞부분을 자르거나 번호만 보고 나누면 안 됩니다. 다음 설계는 부모 scope·제목·단위·조건·전체 원문 hash·원래 XPath와 누락 구간을 보존해야 합니다. 작은 구간으로 나눌 가능성은 확인했지만, 안전한 운영 수집·파싱·보고서 전달이 구현됐다는 뜻은 아닙니다.

## 검증과 변경 파일

- 신규 13개 및 기존 fixture 68개, 합계 81개 통과.
- 전체 연구 입력 CI 회귀 1,550개 통과, 기존 의존성 경고 4개.
- Ruff·Python 구문·diff 및 독립 코드 리뷰 통과. Python 전용 타입 검사 완료 주장은 하지 않습니다.
- 추가: `tools/capture_dart_large_section.py`, `tests/test_capture_dart_large_section.py`, 설계/결과 문서. CI에 신규 회귀를 연결했습니다.
- 기존의 경로·권한·배타적 쓰기 helper를 재사용했고 운영 모듈과 새 의존성은 추가하지 않았습니다. 이 고정 URL은 승인된 일회성 진단 범위를 제한하는 용도이며 종목별 운영 파싱 예외가 아닙니다.

## 남은 위험

대형 섹션 운영 수집, 문맥을 보존하는 분할, 중첩 표의 단위·조건 연결, 최종 6,000바이트의 필수 근거 전달은 미완료입니다. 삼성생명 원문을 후속 설계·튜닝 근거로 사용하므로 이제 개선용 회귀 사례로 취급하며, 새로운 범용성 주장에는 별도 새 검증군을 먼저 고정해야 합니다. 코스맥스 미실행과 이전 검증군 실패를 삭제하지 않습니다.

한국·미국 전체 품질 게이트가 끝나지 않았으므로 머지·배포하지 않습니다. OAuth 복구는 최소 실제 호출로 확인했지만 실제 보고서 품질 검증을 대신하지 않습니다. 보유기간·손절·재진입·주문 규칙, 운영 원문 2 MiB 및 최종 입력 6,000바이트는 그대로입니다.
