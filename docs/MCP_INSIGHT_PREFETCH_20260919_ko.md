# 기존 MCP 활용과 보고서 인사이트 prefetch: 설계·검증 계약

> 추가 감사: 원문 수집 성공과 중요한 주석 보존은 별개였다. 아래의 수집/NEWS 출력 검증을
> 공시 전체 내용의 충분성으로 해석하면 안 된다. 동일 원문 비용 비교와 구조 파서의 실패·수정은
> `FILING_EXTRACTION_EVALUATION_20260919_ko.md`에 기록했다. 신규 추출 실험은 운영 v5에 연결하지 않았다.

## 사용자 요구와 범위

2026-09-19: 새 검색 서비스부터 추가하지 않고 기존 MCP 활용법을 조사한다.
경쟁사·업종 주도주 등 보고서에 필요한 정보의 수집을 설계·구현·시험한다.
긴 MCP 결과가 곧바로 LLM 입력이 되지 않도록 큰 자료는 prefetch 단계에서 처리한다.
모든 사실을 항상 확보할 수 있다는 약속이 아니라, 필요한 질문과 자료 공백을 빠짐없이 관리한다.
매매 게이트·주문·cron은 변경하지 않는다. 기존 Draft PR #752에서 이어간다.

## 역할과 데이터 범위

1. 기업·사업 구성과 직접 경쟁관계: 회사정보/사업부 매출/공시·IR 원문.
2. 비교 가능한 사업 지표와 차별성: 기간·단위·사업 범위·실적/추정·출처를 유지한다.
3. 업종/종목 가격 주도력: 기존 시세/스크리닝/ETF 문맥을 재사용한다. 비교 모집단·관측 시각이
   없으면 순위를 만들지 않고, 선정 종목이나 업종 ETF를 전체 업종의 주도주로 확대하지 않는다.
4. 재무·밸류에이션·컨센서스: 기존 재무 prefetch를 우선하며 원문/기간 차이를 보존한다.
5. 실적·가이던스·수주·제품·고객 이벤트: 공시/보도자료/뉴스의 회사 주장과 확인 사실을 구별한다.
6. 수급·보유구조: 기존 거래량/투자자 수급/기관 보유 자료를 재사용한다. 가격 강도를 자금 유입으로 바꾸지 않는다.
7. 산업·거시·규제: 기존 시장 문맥 및 필요한 공개자료. 해당 업종 적용 범위를 명시한다.
8. 반대 근거·리스크·다음 확인 사건: 기회 설명과 독립된 질문으로 남긴다.

## 실행 순서

- 실제 기존 서버 list_tools와 고정 버전을 먼저 확인한다. 등록/문서/접속/실제 조회 성공을 구별한다.
- 큰 HTML/PDF/표/검색 결과는 모델 밖에서 수집한다. 같은 원문 재수집 대신 private cache와 source ID를 재사용한다.
- 문서 목록·동적 뷰어·PDF를 구분하여 기존 도구의 링크/HTML/actions/map 기능을 사용한다.
- 모델에는 절별로 필요한 완전한 근거와 공백만 전달한다. 단어 수 또는 글자 수를 토큰 수라고 부르지 않는다.
- 직접 붙는 보고서 연구 MCP에도 코드 수준 크기 제한을 적용한다. 긴 원문을 자른 조각으로 바꾸지 않고
  UNKNOWN/축소 조회 필요 상태를 반환한다. 주문/거래 MCP에는 이 정책을 자동 적용하지 않는다.

## 사전 검증과 상한

- 기존 v11 회귀 및 원문 스냅샷을 유지한다. 새 실험은 2026-09-18 기준 실패 원문을 고정하여 재조회/재생을 분리한다.
- 초기 live 대상: KR RF머트리얼즈·오스코텍·아모레퍼시픽의 기존 KIND/IRGO 실패,
  US LITE·GEV·CRM의 공시/경쟁 문맥, MU·삼성 양성 대조군.
- 새 탐색 경로의 cold 상한: 검색 최대 2, 문서탐색 최대 1, 원문 조회 최대 5, 전체 최대 8호출·90초.
  이 상한은 격리 opt-in 프로필에만 적용한다. 기존 운영 60초/기존 허용 범위는 보존한다.
- 모델에 공급되는 연구 자료의 UTF-8 직렬화 바이트를 보수적인 텍스트 토큰 상한으로 관리한다.
  실제 모델 usage와 구별한다. 증거 본문/JSON·지시문 overhead/도구 정의/반복 턴은 따로 계측한다.
- 직접 도구 결과: 결과별 크기와 실행별 누적 증거 예산을 검증한다. 짧은 거절 안내 overhead는 별도 집계한다.
- 표·주석·기간을 통째로 남기거나 통째로 제외한다. 같은 자료의 다른 절 중복 전달을 측정한다.
- 네트워크/권한 오류, 로딩 화면, 자료 부재, 비교 불가, 예산 부족을 별도 상태로 기록한다.
- 실제 원문 획득률과 질문 해결, 저장 원문→최종 모델 입력 생존, 토큰/시간/실패를 함께 본다.
- 신규 서비스 설치·가입·인증·권한 변경 없이 수행한다. 서버 운영 활성화는 기존 품질 게이트를 대체하지 않는다.

## 상태

## 확인한 기존 MCP와 활용 방법

- Perplexity 1.2.0: 실제 list_tools 4개. search는 문자열 질의, 도메인·국가·최근기간 필터,
  결과 1~20개, 페이지별 256~2,048 토큰 요청이 가능하다. 페이지별 요청값은 전체 응답 한도가 아니다.
  발견에는 search를 사용하며 ask의 서술·인용은 원문과 구별한다.
- Firecrawl MCP 3.23.6: 실제 list_tools 27개. markdown/html/links, waitFor, onlyMainContent,
  maxAge, actions, map, PDF 옵션 등의 스키마를 확인했다. 등록된 기능과 실제 성공은 구별한다.
  큰 HTML/PDF와 동적 뷰어는 prefetch에서 처리한다. query/directQuote는 1회 시험에서
  HTTP 200과 함께 `Query generation failed after all models` 경고만 반환했다. 성공한 기능으로 세지 않는다.
- 한국 시세 MCP 5개, Yahoo Finance 9개, time 2개: list_tools 연결을 확인했다.
  이미 수집한 시세·재무·보유구조를 재사용한다. 모든 데이터 API를 새로 호출한 시험은 아니다.
- webresearch/deepsearch는 로컬 오프라인 실행에서 확인되지 않았다. 서버 전체에서 영구적으로
  고장 났다고 단정하지 않는다. TradingView는 현재 로컬 등록·인증 연결이 확인되지 않았다.
  새 도구 설치나 새 인증은 하지 않았다.

공식 참고: [Perplexity Search](https://docs.perplexity.ai/api-reference/search-post),
[Firecrawl Scrape](https://docs.firecrawl.dev/features/scrape),
[Firecrawl Map](https://docs.firecrawl.dev/features/map),
[TradingView MCP](https://www.tradingview.com/mcp/docs).
현재 기능의 구현 여부는 최신 문서만 믿지 않고 고정 MCP의 실제 스키마와 응답을 대조했다.

## 핵심 수집 복구: 로딩 화면이 아니라 본문을 가져오기

같은 RF KIND 공시 주소에서 다음 결과를 확인했다. 모든 시험은 maxAge=0이며 각 조건 1회다.

- onlyMainContent=true, 대기 없음: 294자 로딩 안내.
- onlyMainContent=false, 대기 없음: 1,905자 뷰어 외곽.
- onlyMainContent=true, waitFor=3000: 294자 로딩 안내.
- onlyMainContent=false, waitFor=3000: 296,724자 실제 보고서와 본문 링크.

마지막 성공 조건은 앞서 확보한 응답과 비교했으므로 통계적인 반복 안정성 시험은 아니다.
그럼에도 이 사례에서는 **본문 필터 해제와 렌더링 대기의 조합**이 필요하다는 구체적 근거다.
새 검색 공급자를 추가하지 않고 기존 Firecrawl 기능으로 해결했다.

법인명은 별도 문제였다. 거래소 표시명 RF머트리얼즈와 공시 법인명 알에프머트리얼즈가 달라
본문을 얻고도 탈락했다. 종목별 별칭 특례 대신 다음 경로를 만들었다.

1. KRX 뷰어의 상단 종목코드와 HTTP 200을 확인한다.
2. 실제 본문 링크와 표지 법인명을 연결한다.
3. 직접 발견한 static 문서는 접수 경로로부터 뷰어 탐색 후보를 만들되, 후보 자체를 증거로 쓰지 않는다.
4. 실제 조회한 뷰어의 종목코드·같은 본문 backlink·표지 법인명이 맞아야 이미 받은 본문을 재사용한다.
5. 지주회사·다른 종목·HTTP 실패·HTTP 상태 미확인은 alias 승인의 근거가 아니다.

실제로 문서번호를 접수번호로 오인해 조회한 별도 시험은 한화토탈에너지스가 나왔다.
올바른 접수 경로 후보는 RF(327260)와 원래 static 문서 backlink를 반환했다. 이 실패도 보존했고,
URL을 만들었다는 이유로 회사 정체성을 확인했다고 하지 않는다.

## 구현한 수집·전달 구조

- `report_insight_prefetch.py`: 기존 두 검색과 본문/목록 탐색을 조건부로 활용한다.
  KIND 동적 뷰어 → 정확한 static 본문, IR 목록 → 문서 링크/map, 본문 → 주제별 완전한 단위로 처리한다.
  종목·문서 유형별 네트워크 상한은 8회/90초다. 기존 경로는 OFF에서 보존한다.
- 원문은 모델 밖에서 처리하고 섹션별 직렬화 UTF-8 6,000바이트 이내의 근거만 전달한다.
  동일 문단 중복을 제거하고 표·단위·주석·관계 문맥은 함께 보존한다. 빈 주제와 예산 누락을 명시한다.
- 주제 분류는 후보 선정이지 사실 인증이 아니다. 회계기준 guidance와 실적 가이던스,
  operating과 rating, 소수주주와 수주, 신용등급 정의와 기업 리스크를 혼동하던 회귀를 분리했다.
  GAAP/non-GAAP 기준은 지우지 않는다.
- `report_insight_manifest.py`: 9개 범주의 기존 입력 위치·해시·미확인 차원을 섹션별로 표시한다.
  기존 재무/차트/보유 자료를 다시 복사하지 않는다. 자료가 있다는 사실과 질문 해결을 구분한다.
- `tool_result_budget.py`: 실제 SDK call_tool 반환 경계에서 결과당 6,000바이트,
  실행당 승인된 근거 18,000바이트를 제한한다. 초과분은 잘라서 주지 않고 짧은 UNKNOWN으로 대체한다.
  거절 안내 비용은 별도 계측하며, 이 수치는 전체 프롬프트나 전체 토큰 한도가 아니다.
- 직접 연구 도구의 스키마도 축소한다. Firecrawl은 scrape/search/map, Perplexity는 search/ask만
  보고서 모델에 보인다. 벌크/브라우저/에이전트 작업은 prefetch 쪽에서만 사용한다.
  숨겨진 도구 호출은 실행하지 않는다. 다른 기존 읽기 서버에도 크기 제한을 적용할 수 있다.
- 적용은 승인된 enhanced packet에서 생성한 **개별 ReportAgent profile**에 묶었다.
  전역 환경변수만으로 허용 목록 밖 보고서를 바꾸지 않는다. 캐시 I/O·lock timeout도 작은 실패 패킷을
  반환하므로 승인 대상이 뜻하지 않게 무제한 직접 MCP 경로로 돌아가지 않는다.

## 업종 주도력: 기존 시세를 재사용하되 의미를 좁힌다

- `snapshot_price_leaders.py`: KR의 이미 수집한 snapshot/전일 가격/KIS 분류로 관측 그룹 상위 3개를 계산한다.
- 이름은 **KIS 분류별 관측 종목군의 전일 대비 가격 강세 후보**다. 좁은 산업 전체 순위,
  사업 경쟁력 순위, 시총 순위 또는 확정 종가 수익률로 부르지 않는다.
- 분류 누락, 유효 가격 수, 실제 관측일/전일, 모집단 해시, 동률과 표시에서 빠진 동률 종목 수를 보존한다.
- 후보 선별이 끝난 뒤 metadata에만 기록하며, report용 macro context에 별도 키로 전달한다.
  BUY가 소비하는 market_intelligence에 자동 추가하지 않는다. 종목 보고서에는 해당 그룹 하나만 들어간다.
- US에는 전체 분류와 실제 snapshot 시점이 충분하지 않아 같은 순위를 만들지 않는다. UNKNOWN을 유지한다.
- 이 변경은 설명용 입력 보강이다. 신규 전략·점수·진입/매도 문턱·비중·주문 변경이 아니다.

- 앞선 live 4종목을 그대로 사용한 실제 뉴스 모델 4회는 모두 응답했다.

  잘못 설명했다. 차단된 응답을 공급자 실패처럼 설명한 경우도 있었다. 이 결과는 운영 합격이 아니다.
- 이후 거절 안내를 '자료는 반환됐으나 크기 때문에 미전달'로 명확히 하고,
  URL 날짜·회계기간 종료일은 공개/제출일이 아니라는 계약을 추가했다.
- 최종 RF v5 실제 모델: **3회 요청·95.833초, 입력 22,949/출력 2,623토큰**.
  통신용 고객 RFHIC/MACOM/LUMENTUM과 경쟁사 Kyocera/NGK/SINCLAIR,
  레이저용 고객 DILAS/IPG/TRUMPF 등과 경쟁사 Kyocera/Egide를 구분했다.
  순위·수주잔고·업종 수혜·발행일을 만들어내지 않았다. URL은 유지됐으나 원래 source ID는 누락됐다.
- 이전 RF 입력 36,175토큰/5회와 최종 22,949토큰/3회는 서로 다른 live 자료의 단일 실행이다.
  비용 절감률이나 안정적인 성능 개선으로 해석하지 않는다. Perplexity ask 내부 모델 비용과 청구액은 UNKNOWN이다.
- 긴 응답을 막아도 기존 지시문·도구 정의·대화 이력이 반복되므로 전체 입력은 여전히 크다.
  기존 US 재무/차트 prefetch 전체와 근거 handoff 중복은 별도 경량화 대상이며, 이번에 전부 바꾸지 않았다.
