# 공시 구조·주석 기반 추출 평가 사전 계획

## 문제와 범위

사용자는 29만 자를 확보한 것과 중요한 정보를 잘 추린 것은 다르다고 지적했다.
기존 v5는 키워드와 앞쪽 문단/크기 제한에 의존한다. 중요한 재무 주석을 놓치지 않았는지,
같은 비용으로 더 나은 입력을 만들 수 있는지는 아직 입증하지 못했다.
이번 작업은 확보한 동일 원문에서 추출 방법을 비교한다. 신규 검색·매매·운영 설정 변경은 하지 않는다.

## 사전 고정한 자료와 기준표

- 개발 문서: RF머트리얼즈의 기존 288,845자 static 사업보고서 원문.
- 별도 기업 검증 문서: 오스코텍과 아모레퍼시픽 운영회사 공시. 지주회사 문서는 제외한다.
  이 기업들은 앞선 작업에서 다룬 적이 있지만 이번 추출 규칙 개발에는 사용하지 않는다.
- 별도 평가자가 추출 결과를 보지 않고 원문을 읽어 중요 사실 기준표를 먼저 고정한다.
  RF 12~18개, 나머지는 기업별 8~12개이며 원문에 있는 경우 절반 이상을 재무 주석에서 선정한다.
- 기준표에는 사실별 중요도(1~3), 연결/별도, 기간·단위, 원문 문장/표 행과 필요한 문맥,
  허용 해석과 금지 추론을 넣는다. 공개자료에 없는 항목을 억지로 채우지 않는다.

## 비교 방법과 예산

1. 기존 키워드 후보 생성/선택.
2. 문서 구조만 인식하고 원문 순서대로 선택하는 단순 비교안.
3. 구조·주석 문맥을 보존하고 주제 중요도/중복/예산을 고려한 선택안.

세 방법은 같은 직렬화 형식과 문서당 UTF-8 **3,000/6,000/9,000/12,000/18,000바이트**에서 비교한다.
출처·섹션·단위 등 metadata 비용도 포함한다. 바이트를 실제 토큰 수로 부르지 않는다.
기존 운영형 3개 section_notes를 합친 결과도 별도로 측정하되, 단일 6KB 결과와 같은 예산이라고 하지 않는다.

## 평가 지표

- 중요 사실의 완전 회수율과 가중 회수율. 여러 근거가 필요한 사실은 전부 충족해야 완전 회수로 센다.
- 문장/숫자만 찾은 부분 회수와 단위·기간·연결/별도까지 보존한 완전 회수를 구분한다.
- 주석 범주의 회수, 중복, boilerplate, 필요한 단위/표 헤더/조건 손실, 잘못된 연결/별도 결합.
- 표를 줄일 때는 행 선택임을 표시하고 헤더·단위·관련 주석을 함께 둔다. 합계를 재계산하거나
  선택한 행을 전체 표로 표현하지 않는다. 행/문장마다 원문 위치를 복원할 수 있어야 한다.
- raw 크기/입력 크기, 추가 provider·모델 호출 수, CPU 처리시간과 메모리를 측정한다.
- 독립 기준표는 제한된 표본의 감사 기준이지 모든 투자 정보를 망라한 정답지가 아니다.

## 선택과 중단 조건

같은 예산의 중요 내용 회수가 개선되고, 표·단위·기간·출처 훼손이 없어야 개선안으로 인정한다.
큰 예산이 항상 최적이라는 결론을 내리지 않는다. 예산 증가 대비 추가로 보존되는 중요 사실과
실제 모델 입력/답변을 비교해 비지배 비용-품질 후보(Pareto)를 제시한다.
코드 최적화와 투자 성과 개선은 구별한다. 전역 최적성이나 전 종목 품질을 증명했다고 하지 않는다.

## 현재 상태

독립 기준표 38개를 고정했다(RF 18, 오스코텍 10, 아모레퍼시픽 10). 이 중 주석 항목은 29개다.
38개는 서로 다른 정보를 묶은 검수 항목이며, 공시에 존재하는 모든 사실의 개수가 아니다.

### 실험 이력과 평가기 수정 원칙

- 첫 구조·키워드 점수 방식과 후속 점수 개선은 RF 개발 문서에서 실패했다. 실패 결과는
  `rf_v1.json`, `rf_v2.json`에 보존했다. 좋은 결과만 보고하기 위해 삭제하지 않는다.
- 표 행 선택과 주석 전체 묶음을 별도 대안으로 추가했다. 표 행 선택은 단위·헤더·주석을
  남길 수 없는 표를 거절하며, 선정 행이라는 표시와 원문 위치를 보존한다.
- 평가기에서 `100`이 `1000`에 일치하는 오류와, 한 큰 레코드 안의 다른 표에서 날짜·단위를
  빌려오는 오류를 재현하고 수정했다. `source-unit-bound-v2`부터 원문의 개별 표 또는 동일
  섹션·연결 범위의 연속 문단 안에서 평가한다. 선택하지 않은 원문을 점수에 보충하지 않는다.
- 원문 위치·순서·중복·본문 일치·연결/별도 범위를 검증한다. 기존 후보에도 같은 구조 정보를
  부여하여, 메타데이터가 새 방식에만 있다는 이유로 내용 점수가 높아지지 않도록 한다.
- 최초 고정 v3의 별도 기업 평가에서 아모레퍼시픽의 주석 묶음 방식은 18KB에서도 엄격한
  완전 보존 0/10이었다. 이를 통과로 바꾸지 않는다. XBRL의 `19-1` 주석 번호와 제목을 포함한
  분기·단위 캡션을 인식하지 못한 구조 오류가 드러났다.
- 이 오류를 확인한 뒤의 수정·재실행은 **홀드아웃을 본 뒤의 회귀검증**이다. 새 기업에 대한
  독립 합격이나 일반화 성능으로 표현하지 않는다. 최초 결과는 `evaluation_frozen_v3.json`에
  남긴다. 기준표의 원문·정답·가중치는 수정하지 않는다.

최종 수치·운영 판정은 아래 후속 결과 절에 기록한다. 신규 모듈은 오프라인 실험이며 기존
`insight_prefetch_v5` 수집/보고서 경로, 운영 MCP·cron·매매 설정에는 연결하지 않는다.

## 최종 판정: 원문 확보는 성공했지만 최적 추출은 아니다

**자동 운영 반영 불가.** 주석 단위 보존은 개선됐지만 18KB 상한에서도 독립 선정한 38개
검수 항목 중 15개만 완전히 보존했다. 나머지는 부분 보존 또는 누락이다.
전체 보고서가 15개 사실만 담는다는 뜻은 아니다. 공시 발췌 입력만 평가했으며,
다른 재무 MCP 입력과 최종 LLM 해석은 이번 수치에 포함하지 않는다.

### 동일 원문·동일 비용 조건

- RF: 2025년 사업보고서, 288,845자 / UTF-8 504,223바이트.
- 오스코텍: 2025년 사업보고서, 281,774자 / 505,065바이트.
- 아모레퍼시픽 운영회사: 2026년 1분기보고서, 339,959자 / 565,566바이트.
- 방법 5개 × 예산 5개 × 문서 3개 = 75조건을 각 5회, 총 375회 실행했다.
- 예산은 문서당 3/6/9/12/18KB(1KB=1,000바이트)다. 실제 출처 URL·범위·제목·원문 위치·주의문을
  포함한 compact JSON 전체를 측정한다. 기존 3개 보고서 절 각각 6KB와 단일 6KB는 구별한다.
- 비교용 `legacy`는 기존 `topic_blocks` 후보·2,400바이트 제한·순서를 재사용한다.
  동일 구조 정보를 붙인 비교용 형식이며 실제 운영형 3절 round-robin packet 자체는 아니다.
- **저장된 이전 RF 실제 실행은 2025년 3분기 공시를 사용했다.** 이번 연차보고서의 정답을
  그 이전 실행에 대입한 점수는 보고하지 않는다. 이번 비교는 모두 동일 연차 원문 재생이다.

### 핵심 내용 보존: 같은 18KB 상한

- RF: 기존 후보 2/18 → **주석 묶음 8/18**. 주석 항목은 0/14 → 7/14.
  실제 출력은 각각 15,093 / 17,581바이트다.
- 오스코텍: 2/10 → **4/10**. 주석 항목은 2/8 → 4/8.
  실제 출력은 10,254 / 17,666바이트다.
- 아모레퍼시픽: 1/10 → **3/10**. 주석 항목은 1/7 → 3/7.
  실제 출력은 11,364 / 17,981바이트다.
- 합계 5/38 → 15/38이며 사전 중요도 가중치를 적용하면 13% → 41%다.
  여러 곳의 근거·조건이 필요하면 모두 있어야 완전 보존으로 센다. 전체 53개 근거 묶음 중
  완전 보존은 5개 → 22개다. 숫자 일부만 있는 경우를 완전 보존으로 올리지 않았다.

단순 원문 순서 방식은 앞부분을 채우고 뒤쪽 주석을 놓쳤다. 문단별 점수·다양성 방식은
RF에서 18KB에도 완전 항목 0/18이었다. 유용한 문장이 없다는 뜻이 아니라, 함께 해석해야 할
검수 항목의 전제조건을 모두 확보하지 못했다는 뜻이다. 안전한 표 행 발췌 실험도 18KB 최종
선택에서 세 문서 모두 발췌 표 0개여서 채택 근거가 없다. 이를 모든 예산으로 일반화하지 않는다.

### 예산 증가가 최적화는 아니다

주석 묶음 방식의 완전 항목 수와 실제 직렬화 크기:

- RF: 3KB 3개(2,999B), 6KB 4개(5,703B), 9KB 5개(8,895B),
  12KB 7개(11,877B), 18KB 8개(17,581B).
- 오스코텍: 3KB 1개(2,812B), 6KB 3개(5,929B), 9KB 4개(8,977B),
  12KB 4개(11,753B), 18KB 4개(17,666B).
- 아모레퍼시픽: 3KB 1개(2,560B), 6KB 1개(5,735B), 9KB 1개(8,774B),
  12KB 1개(11,896B), 18KB 3개(17,981B).

오스코텍은 9KB→18KB에서도 이 기준의 완전 보존이 늘지 않았다. RF는 12KB→18KB에서
약 5.7KB를 더 쓰고 1개가 추가됐다. 아모레는 18KB에서야 계약 조건 묶음이 들어왔다.
가중 완전 보존율과 바이트의 경험적 비지배 후보를 결과 JSON에 남겼다. 이는 전역 최적해나
모든 콘텐츠 기준의 우월성을 증명하지 않는다. 부분 보존의 가치나 검수 항목을 달리 정하면
선택도 달라질 수 있다. 출처 URL 수십 바이트도 경계에서 선정 결과를 바꾼다.

### 중요했던 주석과 아직 남는 누락

최종 18KB 주석 묶음에 조건과 함께 보존된 정보:

- RF: 법인별 연결 실적, 주요 고객 집중, 특수관계자 매출·채권, 채권 연령·충당금,
  받은 지급보증의 방향, 결산 후 토지 취득계약, 화재 손실과 보험금 불확실성.
- 오스코텍: 기술이전의 조건부 원천징수세액 반환의무, 개발 성공에 따라 달라지는 수익,
  주요 고객 매출, 상속 후 최대주주 미확정.
- 아모레: 재고 평가·폐기손실, 코스알엑스 잔여지분 지급기한 연장과 **1개월 전 통지 시
  앞당길 수 있는 조건**, 157,335백만원 매입의무. 단순히 “2030년까지 유예”라고 하면 틀린다.

그러나 다음은 충분히 보존하지 못했다.

- RF: 이익과 현금흐름·운전자본을 함께 보는 근거, 법인세수익, 영업권 평가 가정.
  차입·담보는 4개 근거 묶음 중 3개가 남았으나 담보 예금 근거가 빠졌다. 차입 정보가 통째로
  없다고 하거나 완전히 확인됐다고 하면 둘 다 부정확하다.
- 오스코텍: 미인식 세무상결손금, 전환가격 조정, 기술이전 분배율과 수취 연도.
- 아모레: 사업부 매출·이익, 영업권 잔액, 채무보증, 일반 소송.

별도 제공하는 `content_audit_ko.md`에 38개 원문 검수 기준을 수치·단위·범위·해석 주의사항과
함께 정리했다. **검수자가 선정한 참고자료이며 자동 추출기가 모두 확보한 출력이 아니다.**

### 비용·성능과 미검증 범위

- 저장 원문 선택기의 추가 공급자·LLM 호출은 0회다. 원문 수집, 개발/검수 에이전트,
  최종 보고서 모델 비용까지 0이라는 뜻은 아니다.
- 주석 묶음의 문서별 5회 중앙값은 약 147~171ms다. 네트워크·원문 파일 읽기·평가 시간은
  제외한 로컬 선택 처리시간이다. 단일 장비·3문서의 소규모 측정이며 서비스 지연 보장이 아니다.
- 별도 warm 18KB 실행 3회씩에서 Python 추가 할당 peak 중앙값은 RF 3.97MB,
  오스코텍 3.95MB, 아모레 7.67MB였다. tracemalloc 측정이며 이미 읽어 둔 원문·전체 프로세스
  RSS·수집/모델 메모리는 제외한다. 시간 측정에는 이 계측의 오버헤드를 섞지 않았다.
- 75조건 모두 반복 해시가 같았고 실제 직렬화 응답이 해당 예산 이하였다.
- 바이트를 토큰으로 부르지 않았다. 동일 모델의 최종 보고서 A/B, 실제 입력 토큰,
  청구액·캐시 비용 절감은 **미측정**이다. 원문 선택 품질이 미달하여 자동 운영 반영이나
  “비용 대비 최적”을 승인하지 않았다.
- 기준표는 제한된 표본이고 재무 주석 비중이 높다. 미국 SEC·금융업·다른 공시 서식의 새 독립
  검증을 하지 않았다. 원문의 오류, 기업의 추정·주장을 사실로 바꾸는 문제도 별도다.

## 다음 설계 기준

새 검색 MCP보다 **이미 확보한 원문의 구조 인식과 질문별 근거 구성**이 우선이다.
이번 실패는 원문에 필요한 정보가 없어서 생긴 문제가 아니다.

1. 회사·연결 범위·보고기간·실제 제출/정정일을 확인하고 분석 기준일 이후 자료를 제외한다.
   먼저 검색된 과거 분기 공시를 최신 사업보고서의 대용으로 쓰지 않는다.
2. 원문 전체는 prefetch/cache에 두고 목차→사업→연결/별도→주석→XBRL 표·캡션까지 색인한다.
3. 문단 몇 개가 아니라 질문별 필수 근거를 묶는다. 차입 한도·실행액·만기·담보예금,
   세전이익·세금효과, 계약 본문·예외조건을 함께 요구한다.
4. 큰 주석은 안전한 소절/표+관련 조건으로 조회하고 모델에는 필요한 묶음만 전달한다.
   전체 주석 반환이나 중간 문자열 자르기를 기본 해법으로 삼지 않는다.
5. 첫 전달은 작게 유지하되 빠진 중요 질문을 명시하고 필요한 묶음만 총량 안에서 추가
   prefetch한다. 총량을 넘으면 검증 완료처럼 쓰지 않고 누락으로 남긴다.
6. 새 기업·업종에서 다시 기준표를 고정하고 추출 평가 및 동일 모델의 최종 답변·토큰 A/B를
   수행한다. 이번 홀드아웃을 다시 미공개 검증셋이라고 부르지 않는다.

## 구현·검증·운영 경계

- `prism_core/filing_structure.py`: 원문 위치·공시 계층·연결 범위·표 캡션 파서.
- `prism_core/filing_selection.py`: 동일 직렬화 예산의 비교용 선택기 5종.
- `prism_core/filing_table_projection.py`: 안전하게 처리할 수 있는 표만 행 단위 발췌.
- `tools/evaluate_filing_extraction.py`: 원문·기준표 해시, 문맥 기반 회수율, 비용·재현성 평가.
- 대응 테스트 4개 파일과 CI 경로를 추가했다. 신규 의존성은 없으며 기존 v5 운영 경로는 그대로다.
- 75개 신규 관련 테스트와 519개 기존 연구/보고서 회귀 통과(기존 의존성 경고 3건).
  별도 타입 검사기는 환경에 구성되어 있지 않다. Ruff·컴파일·diff 검사는 별도로 수행한다.

- **운영 배포·전 종목 ON·cron·주문·매매 문턱·인증키 변경 없음.** 실제 모델/최종 PDF 재검증과

## 재현

원문·기준표는 기존 로컬 검증 자료에 있으며 공개 저장소에 전체 공시를 복제하지 않는다.
최종 결과는 `filing_extraction_20260919/evaluation_final_metered.json`이다.

```bash
.venv/bin/python tools/evaluate_filing_extraction.py \
  --gold "$ARTIFACTS/gold_rf.json" --gold "$ARTIFACTS/gold_holdout.json" \
  --out "$ARTIFACTS/evaluation_replay.json" \
  --methods legacy,structure_order,structured,structured_projected,note_bundles \
  --budgets 3000,6000,9000,12000,18000 --repeats 5
```

`ARTIFACTS`는 이 세션의 `filing_extraction_20260919` 디렉터리다. 결과에 원문·기준표·구현 파일의
SHA-256을 기록한다. 시간은 환경에 따라 달라지지만 동일 원문·구현의 선정 결과·크기·점수는 결정적이다.
