# BTC 알림의 쉬운 표현과 전후 비교 (M3)

## 요청과 변경 범위
초기 진입/추가 체결/포지션 변경을 일반 사용자가 이해하도록 표시한다. 가격 수익률,
레버리지 단순 환산 수익률, 증거금 비중, 계좌 대비 계획 손실을 구분한다.
주문·위험 한도·전략·LLM 프롬프트·채널 라우팅은 바꾸지 않는다. 알림용 증거는 기존
대조 결과만 사용하며 새 거래소 조회나 주문을 추가하지 않는다. 과거 공지를 재발송하지 않는다.

## 숫자 정의
- 1배 수익률: LONG은 (목표-평단)/평단, SHORT는 (평단-목표)/평단.
- 레버리지 환산: 위 비율×확인된 레버리지. 거래소의 실제 ROI와 같다고 주장하지 않는다.
  증거금·수수료·펀딩에 따라 실제 비율은 다르며, 미확인 배율을 확정값으로 표시하지 않는다.
- 예상 가격 손익: 해당 목표에서 정리할 수량×방향별 가격 차이. 달러 손익에 레버리지를
  또 곱하지 않는다. 부분 익절은 실제 목표 수량(계획이면 명시한 가정 수량)만 계산한다.
- 증거금 비중: 같은 계좌·대조 시점의 실제 positionIM / equity. 총 거래금액/레버리지로
  실제 증거금을 가공하지 않는다. 교차마진 증거금은 손실 상한이 아니다.
- 손절 예상: 남은 포지션이 표시 가격에 체결됐다고 가정한 비용 전 손익과 현재 equity 대비 비율.
- 시나리오 전체 한도: 원래 initial_equity 기준2% 예산. 현재 포지션의 손절 예상액과 분리한다.
- 비용/미체결 포함 위험 예약: 기존 risk_snapshot과 확인된 회계·현재 미체결로 산출한 경우만
  표시한다. 알 수 없는 비용을0으로 채우지 않으며 절대 최대손실 보장으로 표현하지 않는다.

## 첨부 사례의 확인된 뜻
체결84750/0.1BTC, SL84500, TP85200에서60% 정리, 거래소확인10배.
체결 직후 관측 증거금851.847125 / 같은 계좌 equity9613.09241435 =8.86%다.
이는 증거금 비중이며 계좌 전체 손실 한도가 아니다.
- TP: 1배+0.53%, 10배 단순환산+5.31%; 0.06BTC만 정리하면 비용 전+27USDT, 계좌+0.28%.
- SL: 1배-0.29%, 10배 단순환산-2.95%; 0.1BTC 전량이면 비용 전-25USDT, 계좌-0.26%.
- 전체 시나리오 예산192.27USDT는 별도의2% 계획 한도다.

## 전후 비교의 증거 계약
position_before/position_after는 각각 자기 시점에 확인된 같은 시나리오의 상태다.
현재 평균 진입가·잔량·실제 SL·확인된 LIVE TP/부분SL 가격과 수량을 비교한다.
옛 계획을 과거 실제 상태로 바꾸지 않는다. 이전 상태가 없으면 최초 확인/이전 자료 없음으로
표시한다. 이전 기록은 과거 시각 자체로 유효하며 현재 시각과120초 이상 차이 난다고 버리지 않는다.
반면 오래된 체결에 현재 계좌 자료를 당시 자료처럼 붙이지 않는다.
첫 체결에 이미 보호 상태가 담겼다면 동일 내용을 '변경'으로 다시 알리지 않는다.
SL뿐 아니라 TP/평단/수량만 바뀐 경우도 알리되, 시각·증거금·equity·주문 ID만 바뀐 조회는
새 포지션 변경으로 취급하지 않는다. 모든 전후 상태는 알림용이며 주문 권한이 아니다.

## 검증 기준
원래 수치·롱/숏·부분 익절·추가 진입 평균단가·수익 보호 SL·자료 부재/오래된 시각/
타 계좌·TP만 변경·동일 상태 반복·재시작·알 수 없는 주문/회계의 반례를 검사한다.
공개/운영자 채널 구분과 기존 체결/보호/정산 증거 검사를 유지한다. 전체 BTC 격리 테스트,
최종 head CI, 서버 격리 테스트, 배포 후 자연 실행을 각각 확인한다.

## 구현 검증
scenario_notice.py는 계산/표시만 담당하고, scenario_notice_evidence.py는 이미 확인된
거래소·회계 자료를 알림용으로 묶는다. broker에는 알림 비교 기준만 저장하며 실행 권한으로
사용하지 않는다. runtime의 PLAN에는 현재 보유량과 추가 요청 수량, 이전SL을 따로 전달한다.
최초 미체결 상태의 flat 기준이 저장된 뒤 체결되는 경우까지 검사해 중복 보호 공지를 막았다.
알림 생성/렌더링/상태 저장 오류는 별도 SAVEPOINT로 격리해 검증된 주문·회계·보호 결과를
롤백하지 않는다. 알림만 실패하면 미완료 알림 상태를 성공으로 꾸미지 않는다.
