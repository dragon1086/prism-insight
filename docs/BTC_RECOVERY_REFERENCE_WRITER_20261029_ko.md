# 복구 요청·응답 중복 제거: writer 후보

계산형 판단에서 이미 기록된 같은 slot·sequence의 review 이벤트와 recovery 모델 요청·응답이 정확히 같을 때, recovery 기록을 review 원본에 대한 해시 참조로 저장한다. 원래 저장보다 작을 때만 선택하며 review 기록은 유지한다. 대상이 없거나 중복·불일치·변경됐거나 코덱이 실패하면 기존 압축 원문으로 되돌린다. 기록은 기존 트랜잭션 안에서 쓰고 참조 대상은 쓰기 잠금 아래 다시 검증한다.

`#1196` reader의 CI·병합·배포 및 실제 첫 정기 실행 확인이 선행돼야 한다. 이 writer가 먼저 적용되면 기존 복기·감시·외부 백업이 새 형식을 읽지 못할 수 있다. 이 후보는 기존 DB를 바꾸지 않으며 90일 보존이나 디스크 반환도 구현하지 않는다. review 이벤트가 recovery의 원본이 되므로 두 기록의 삭제·이동·백업은 함께 검증해야 한다.

기존 16행 개발 표본에서 recovery 저장은 903,645바이트였고 참조 후보는 4,248바이트였다. review 원본은 그대로 필요하므로 이 수치를 전체 DB 절감률로 사용하지 않는다. Mac 합성 DB에서 약 96KB 요청과 응답을 한 트랜잭션에 기록한 각 1회 측정은 기존 압축 4.17ms, 후보 4.16ms였고 쓰기 잠금 포함 구간은 각각 3.07ms, 2.58ms였다. 이는 서버 경쟁·최악 지연·매매 판단 기한의 보증이 아니다.

관련 검증은 실제 런타임 저장·원문 복원, 같은 slot의 정확한 순서, 원본 부재·불일치·중복·변경 및 코덱 예외의 fallback, 복기, 감시를 포함한다. 전체 CI, 선행 reader 배포, writer 배포, 첫 정기 실행과 실제 절감 관측은 별도다. 기존 기록 정리나 운영 주문은 이 문서로 승인되지 않는다.
