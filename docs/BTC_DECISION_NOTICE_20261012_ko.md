# BTC 5분 판단 유지보수방 알림

## 범위와 연결

사용자가 5분마다 왜 관망하는지 알 수 있도록 유지보수 Telegram방에 짧은 판단 요약을 요청했다.
M3 관측·운영성 변경이다. 매매 정책·프롬프트·모델·주문·위험·기존 스케줄은 변경하지 않는다.

1. 기존 판단의 기록된 결과만 사용한다. 추가 LLM·거래소 호출이나 별도 cron을 만들지 않는다.
2. runner의 현재 호출 input_id·slot과 저장된 context·outcome을 대조한다. 최신 과거 행을 빌려 쓰지 않는다.
3. 판단 완료 후 기존 outbox에 PRIVATE 종류로 등록하고 거래 잠금 밖에서 보낸다. 공개방 fallback은 금지한다.
4. 같은 5분 슬롯은 한 번만 전송하되 다음 슬롯의 같은 WAIT는 새 판단으로 알린다. 오래된 요약을 몰아서 보내지 않는다.
5. 미확인 ACK는 재전송하지 않는다. 요약·발송 실패가 주문 실행 결과를 바꾸거나 새 매매를 만들면 안 된다.
6. 테스트·CI·배포·첫 정규 전송 영수증은 구분한다. 완료 근거가 없는 단계를 완료라고 표시하지 않는다.

## 표시 계약

시각, 행동, 핵심 이유, 다음 재평가를 짧은 문장과 이모티콘으로 구분한다.
WAIT는 관망과 기존 포지션/계획 유지를 구분하고, 주문 요청은 체결과 구분한다.
WAIT side=null에서 롱·숏 방향을 추측하거나 confidence를 승률로 표시하지 않는다.
검증 거절된 모델 설명은 정상 판단 근거로 내보내지 않는다. 조기 차단은 해당 실행의 안전한 상태 문구만 쓴다.
재평가 조건은 검증된 기록만 표시하며 자동 진입을 약속하지 않는다. 없으면 다음 5분 재평가로 안내한다.
설명은 결정론적으로 줄이고 민감정보·내부 경로·ID·원시 오류·과도한 개행을 제거한다.

## 검증과 배포

슬롯·입력 불일치, 이전 설명 혼입, 거절된 제안, 보호 전용 루프, 중복·오래된 큐,
공개방 오배달, 미설정, 네트워크 실패와 상태별 렌더링을 주문·네트워크 없는 테스트로 검사한다.
서버 기준 b547b2f6의 범위만 변경한다. 무관한 main 변경을 함께 배포하지 않는다.
선별 배포는 별도 사용자 확인을 기다리며, 실제 채널 시험 발송 대신 배포 후 첫 자연 판단의 영수증을 확인한다.

## 구현·검증 결과

- 현재 슬롯 요약 모듈과 회귀 테스트를 추가하고 runner 완료 경계·notice 렌더러·PRIVATE outbox에 연결했다.
  기존 발송기를 재사용하며 runtime·broker·프롬프트를 수정하지 않았다.
- 기존 outbox의5열 스키마를 유지하고 판단 알림에만 만료 메타데이터를 붙였다. 체결 공지의 보존·재전송 규칙은 바꾸지 않았다.
- 로컬 BTC 전체3,442개 통과·12개 skip, 독립 집중290개 통과. F/E9 정적 검사·컴파일·diff 검사 통과.
- 관찰 문장 추출은 WAIT에만 사용한다. 진입·수정·청산 설명은 원문 순서를 유지한다.
- 전송 누락을 완전히 방지하지는 않는다. 잠금 충돌·슬롯을 넘긴 지연·미확인 ACK에는 중복 방지를 우선한다.
- CI, 선별 배포 승인, 서버 배포, 첫 자연 전송 영수증은 아직 별도 확인 단계다.
