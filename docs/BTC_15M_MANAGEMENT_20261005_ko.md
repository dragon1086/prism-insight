# BTC 최소 15분봉·보유 관리 변경 계약

## 승인과 범위

2026-10-05 사용자는 최소 판단 봉을 15분으로 지정하고 30분·1시간·4시간·12시간·1일·1주를 요청했다.
응답 유효기간 교정, 저항 돌파 실패 대응, 보유 대안 비교와 상황별 프레이밍 검토도 승인했다.
M0 응답 계약과 M2 입력·재생 정합성을 먼저 검증하고 M4 정책 변경을 별도 버전으로 기록한다.
M5 수익 개선은 미입증이며 이번 손절 한 건에 맞춘 수치 최적화를 하지 않는다.

## 사전 가설과 충돌 해소

- 15분은 최소 판단·타이밍 봉, 30분·1시간은 주요 판단 봉이다. 상위 봉은 맥락이지 만장일치 진입 조건이 아니다.
- 판단 5분 주기와 보호 1분 주기는 봉 주기와 다르다. 기존 스케줄·보호 집행은 유지한다.
- 5분봉 및 5분봉 거래량 파생 정보는 모델의 판단 입력에서 제외한다. 미완성 15분 이상 봉의 관측 시간과 불확실성은 유지한다.
- 유리한 국면에서는 비용 후 기회비용을 비교하되 강제 진입·추격하지 않는다. 하락장에서도 유효한 숏에는 대칭적으로 적용한다.
- 저항 도달은 무조건 청산 조건이 아니다. 돌파 지속과 돌파 실패를 구분해 부분 목표·보호·잔여 추세 추종을 비교한다.
- 단기 약화는 추가 진입 보류뿐 아니라 기존 보유의 유지·감축·보호·종료 비교에 사용한다. 즉시 부분 시장가 청산처럼 미지원 행동을 만들어내지 않는다.
- 매 응답의 유효기간은 기존 주문 만료와 다르다. WAIT가 기존 주문 수명을 연장하지 않지만, WAIT 응답 자체도 반환 후 유효해야 한다.
- 원래 시나리오 시작 순자산 2%, 수익으로 위험 예산 보충 금지, 10배, 손절 확대 금지, 체결 확인과 데모 전용을 유지한다.

## 사전 검증 계획

입력 생성 → 모델에 실제 전달되는 JSON → 응답 계약 → 검증기 → 실행·보호의 연결을 확인한다.
최소 봉과 누락된 주봉, 형성 중 봉, UTC 주봉 경계, 재생의 미래 정보 차단을 검사한다.
만료된 기존 계획을 보유한 WAIT, 요청 직후 만료, 과도한 만료, 정상 미래 만료를 비교한다.
롱·숏의 유리/불리/혼조, 저항 돌파 지속/실패, 위험 차단 중 보호와 부분 익절 후 잔여 물량을 반례로 검토한다.
같은 입력 비교는 행동 계약 검증이며 수익성 증거가 아니다. 기존 하루 결과와 새 정책 결과를 합치지 않는다.

## 상태

구현·독립 논리 검토와 로컬 전체 테스트를 완료했다. 배포·자연 실행·수익성 입증은 아직 완료하지 않았다.
운영 주문이나 기존 포지션을 실험 목적으로 변경하지 않는다.

## 구현 경로와 검토 결과

`scenario_preview.collect_snapshot` → `engine/scenario_snapshot` →
`scenario_runtime.snapshot_input_time` → `scenario_llm.propose` → wire/경제 검증기 → 기존 실행 경로를 확인했다.
입력은 7개 봉이며 15분·30분·1시간의 신선도를 필수 검사한다. 실제 공개 주봉 시작 시각은
2026-10-05 및 09-28 월요일 00:00 UTC로 확인했다. API 주기는
[Bybit 공식 Kline 문서](https://bybit-exchange.github.io/docs/v5/market/kline)를 대조했다.

검토 중 거래량 문구의 3개 봉 비교와 실제 1개 봉 비교 불일치를 수정했다.
새 재생 데이터셋은 주초부터 원본을 확보하여 형성 중 주봉을 구성한다.
기존 자료의 누락은 그대로 미확인으로 남긴다. 백테스트의 1분 원본은 체결 모의와
15분 이상 집계에 쓰이며 1분 매매 신호를 모델에 전달하지 않는다.

과거 rationale를 모델 전달용 복사본에서만 제외했다. 원본 감사 기록·구조화 주문·수량·위험은
변경하지 않는다. 새 판단 설명도 다음 입력에 반복되지 않는 절충이 있으므로 매번 현재 시장
증거로 가설을 재평가한다. recommended expires_at=now+300은 응답 지연을 허용하는 도움값이다.
OPEN/ADJUST의 주문 수명에도 영향을 줄 수 있어 단순 문구 정리나 수익성 무변경으로 취급하지 않는다.

주문 없는 모델 비교는 공개 시장 snapshot 하나를 고정하여 flat·합성 LONG 보유·합성 SHORT 보유·
합성 신규 위험 차단 LONG의 4조건 × 기존/신규 프롬프트 1회씩, 총 8회로 제한했다.
두 프롬프트에 새 7개 봉 입력과 새 응답 계약을 동일하게 주며, 프롬프트 이외의 효과나 수익성을
분리 추정하는 실험이 아니다. 오류와 응답 지연도 결과에 포함한다. 실제 과거 거래를 재구성한 결과가 아니다.

배포 전 전체 테스트와 정확한 head CI를 확인하고 새 정책 구간을 시작한다.
기존 주간 점검에서 새 구간을 따로 검토하며 추가 스케줄은 만들지 않는다.
안전 우회·반대 방향 강제·불필요한 주문 반복·입력 차단이 발생하면 해당 변경을 검증된 되돌림 PR로
복귀한다. 이미 체결된 포지션이나 기존 보호 주문을 삭제·재실행하지 않는다.
성과 판정은 기존 M5 기준을 유지하며, 한 번의 손절이나 수익만으로 정책을 다시 튜닝하지 않는다.

## 사전 검증 결과

로컬 전체 BTC 테스트 3,247개 통과·12개 skip, 네트워크 시도 0회. Ruff F/E9 및 diff 검사를 통과했다.
실제 공개 7개 봉 입력은 모두 정상이며, 모델 입력 크기는 52,572~52,714바이트로 100,000바이트 한도 이내다.
OAuth 비교 8개 모두 wire·반환 지연 반영 경제 검증을 통과했다. 기존 4 WAIT, 신규 3 WAIT·1 ADJUST였다.
신규 ADJUST는 합성 숏 보유의 손절 강화와 절반 익절을 제안했고 신규 진입은 없었다.
신규 LONG도 WAIT를 선택했으므로 단기 악화 시 항상 조기 청산한다거나 이번 과거 손절을 피했을 것이라고
주장할 수 없다. 모두 응답 TTL 300초였으며, 새 OPEN 표본이 없어 진입 주문 수명 편향은 검증하지 못했다.
만료된 기존 계획의 보유 WAIT는 정상 응답했지만 4조건 1회씩의 작은 계약 점검이며 수익성 증거가 아니다.
