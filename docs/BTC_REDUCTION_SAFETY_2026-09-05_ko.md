# BTC 메인 청산 안전성 교정

## 수정 범위

- 포지션·주문 조회가 실패하거나 응답이 불완전하면 무포지션으로 해석하지 않고
  원장과 기존 보호주문을 유지합니다.
- 청산 의도를 요청 전에 저장하고 고유 orderLinkId를 사용합니다.
- 시장가 감축 요청을 자동으로 재시도하지 않습니다.
- 주문과 연결된 중복 제거된 실제 Trade 체결 합계가 요청 수량에 도달하기 전에는
  장부 수량을 감소시키거나 포지션을 제거하지 않습니다.
- 미확인 상태는 재시작 후에도 유지하며 신규 진입과 중복 감축을 차단합니다.
- 미확인 청산 중에도 10분 보호 경로에서 누락된 스탑 복구는 계속 시도합니다.
- 공통 OTLP 전송 시 서비스·버전·환경·호스트가 다른 이벤트를 별도 resource로
  분리합니다. 첫 이벤트의 서비스명으로 전체 배치를 덮어쓰던 오류를 고칩니다.

## 안전성과 운영 대가

거절·부분체결·응답 유실 상태에서 추측으로 주문을 다시 내지 않습니다.
확정 체결 증거가 모두 도착하지 않으면 pending_reduce 상태가 유지됩니다.
운영자는 거래소 주문·체결을 대조한 뒤 해소해야 하며, 단순 메타 삭제로
강제 재개하면 안 됩니다. 체결 조회 첫100건 밖의 기록도 보수적 보류를 만들 수 있습니다.
누락 스탑 복구 요청 ACK를 실제 작동 중인 보호주문 확인으로 간주하지 않습니다.

## 변경하지 않은 것

메인·스윙 진입 신호, 트레일 파라미터, 레버리지/위험 설정, cron은 변경하지 않습니다.
스윙 신규 보호 복구 초안은 정산 연결 검토가 남아 있어 이 배포에서 제외합니다.
기존 통합 스탑 취소·재발행, 첫 부분진입 보호, 양방향 합산 위험,
백테스트 데이터 복원·펀딩·MTM NAV는 후속 작업입니다.

## 검증

실패 재현 후 회귀 테스트를 추가했습니다. 거절, ACK만 수신, 부분체결,
응답 유실, 재시작, 체결 중복, 정상 완전체결, 감축, 보류 중 스탑 복구를 검사합니다.
추가한 가짜거래소 테스트는 실제 계정·주문을 사용하지 않습니다.
배포 결과는 채팅으로 별도 보고합니다.
