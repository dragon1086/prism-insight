# BTC 신규 지정가의 마디가격 보정

## 사전 검토·승인 범위

- 사용자 승인: 2026-10-05, 다음 신규 진입·새 TP 가격만 5~10 USDT 간격으로 보정한다.
- 기준선: `540102081d921271b5eea6fbf2a81a6b9f6b21c1`.
- 분류: 오류 수리가 아니라 제한적인 **경제적 집행 가격 변경**이다. M4 사전 비교와
  M0/M1 안전성 회귀, M3 감사 기록을 병행한다. 신규 실자금·다른 전략 승격은 승인하지 않았다.
- 기존 demo MAIN, 10배, 시나리오 전체 2%, 하루 4%, 3연속 손실 중단을 유지한다.
- SL·부분 SL·수량·익절 비중·현재 미체결 주문·추격 설정을 이 정책으로 변경하지 않는다.

## 1. 가설·반증 조건

같은 방향의 지정가 대기 주문이 마디에 몰릴 때 작은 가격 양보로 가격 우선순위를 개선할
가능성이 있다. 반대쪽 유동성이 많은 경우도 있으므로 둥근 숫자가 항상 불리하다고 가정하지 않는다.
체결 가능성 증대와 수익성 개선은 다르다. 더 불리한 진입·익절 가격, 비용, 역선택이 이점을 없앨 수 있다.
효과는 대기열·당시 호가 자료 없이는 검증할 수 없으며 OHLC 재생으로 대기열 효과를 입증하지 않는다.

결과를 보기 전에 고정한 규칙:
- 원래 신규 지정가가 **정확히 10 USDT 배수**일 때만 후보로 삼는다. 50/100/500/1000 배수를 포함한다.
- 기본 간격은 **7.3 USDT**, 실제 tick 정렬 후 원래 가격과의 차이는 **5~10 USDT**로 제한한다.
- LONG 진입·SHORT TP는 매수이므로 위로, SHORT 진입·LONG TP는 매도이므로 아래로 보정한다.
- 이미 세분화된 가격은 그대로다. 무작위 끝자리·성과에 맞춘 파라미터 탐색은 사용하지 않는다.
- 5~10은 **원래 선택한 마디**로부터의 간격이지 모든 10 단위 가격에서 그만큼 떨어진다는 뜻이 아니다.
- 보정 대상은 주문 지정가다. 거래소가 더 좋은 가격에 체결하거나 여러 체결을 평균하면
  **실제 체결가·평단은 여전히 둥근 숫자**일 수 있다. 그 값을 알림에서 인위적으로 바꾸지 않는다.

## 2. 기존 경로와 궁합

실제 경로: `scenario_llm.propose` strict wire → `ScenarioRuntime._tick` 원본 제안 저장 →
모델 호출 뒤 재조정/최신 context → 원본 `validate_scenario` → 가격 보정 → 재검증 →
durable intent → `ScenarioExecution._preflight` → 거래소 주문/복구/실제 체결 알림.

- 원본 LLM 제안은 보존한다. 원본 경제 검증 이전에 가격을 고쳐 잘못된 제안을 정상화하지 않는다.
- 보정은 최신 broker context의 명시적인 정책과 tick·bid/ask로만 수행한다. ticker는 이미 조회하는
  자료를 재사용하며 새 API·모델 호출·상주 프로세스는 추가하지 않는다.
- 최종 가격으로 현재 위험·확신도 한도·최소 주문·담보·청산 여유를 검증한다. SL을 좁히거나
  수량을 늘려 보정된 주문을 억지로 통과시키지 않는다.
- 현재 코드에는 고정 RR 최저값이 없다. 기존 TP 방향 검사와 위험 한도를 유지하고,
  기존 비용률·슬리피지 가정으로 보정이 양의 예상 가격차를 비용 후 비양수로 만드는지 확인한다.
  새 RR 숫자를 임의로 추가하지 않는다.
- 같은 가격의 LIVE TP를 다시 적은 ADJUST는 ID가 달라도 보정하지 않는다.
- 현재 전략은 ADJUST 시 TP 취소·재생성을 할 수 있다. 이번 정책은 그 행동을 새로 유발하지 않으며,
  유지하려는 기존 TP의 **가격**을 바꾸지 않는다.
- 기존 저장 계획, 재시작 복구, 부분체결 후 수량 동기화, 미체결 추격에는 다시 보정하지 않는다.
  신규 보정 진입의 이후 추격 한도는 실제 durable intent에 저장된 최초 주문 가격 기준이다.

## 3. 보정 실패와 원래 계획 보존

다음 조건에서는 해당 보정을 생략하고 이미 검증한 원래 가격을 유지하며 사유를 기록한다.
- tick·호가·현재성 근거가 없거나 원래 가격이 tick 규격에 맞지 않는다.
- tick 정렬 후 간격이 5~10 밖이거나 가격이 비양수가 된다.
- 대기 주문이 보정 때문에 반대쪽 최우선 호가를 넘어 새롭게 즉시 체결 가능해진다.
  원래 전략이 이미 시장성 GTC를 제안했다면 그 의도 자체를 금지하지 않는다.
- TP의 방향·비용 후 수익 여유·원래 손절 방향을 잃는다.
- 보정된 전체 제안이 시나리오 2% 또는 확신도 위험 한도를 넘는다.

보정 실패로 기존 보호 강화 전체를 버리지 않는다. 최종 조합을 다시 검증하며,
검증되지 않은 전체 제안은 기존 fail-closed 경로로 중단한다.

## 4. 모델 프롬프트 논리

신호·국면·MA10/35·형성봉 해석은 그대로다. 모델은 근거가 되는 원래 구조 가격을 제안하고,
명시적 호스트 정책이 한 번만 집행 가격을 보정한다는 역할을 설명한다. 모델이 이 간격을
미리 더하거나 audit 메타데이터를 응답 스키마에 복사하지 않도록 한다.
현재 보정 가격을 그대로 유지하는 요청에는 추가 보정을 하지 않는다.
SL 완화 금지·이미 체결된 TP 재생성 금지·최초/추가/감축 구분과 충돌하지 않아야 한다.

## 5. 검증·부진 원인 구분

검증 전에 다음 반례와 비교를 고정한다.
- LONG/SHORT 신규 진입/TP 부호, tick 0.1/0.5/1, 보정 불가능 tick, 이미 세분화된 가격.
- WAIT/EXIT·정책 없는 context·기존 SL/partial SL/수량/비중/추격 설정 불변.
- 원본 malformed/위험 초과는 선행 거절. 새 가격의 방향·비용·시장성·위험 초과는 보정만 생략.
- SL-only ADJUST의 동일 TP 유지, ID 변경 재진술, partial fill·복구·재시작의 중복 보정 없음.
- raw proposal·감사 기록·최종 intent·PLAN 알림·실제 fake broker request 가격 일치.
- 동일한 제안·시세·비용 아래 기준선과 보정 후보를 비교한다. 기대 동작과 불리한 경우 모두 남긴다.

전진 관측은 기존 감사 기록으로 적용/생략, 원래/최종 가격, 비용·체결을 구분한다.
최초 7일의 전진 관측도 작은 표본이면 불충분으로 남기며, 체결률 개선을 인과적으로 확정하지 않는다.
보정이 한도 밖·SL 변경·중복 적용·저장 가격 불일치를 만들면 신규 보정을 중단하고 기존 가격 정책으로
되돌린다. 기존 포지션 보호와 이미 제출된 주문의 복구는 유지한다. 최근 손익에 따른 자동 정책 전환은 없다.
이는 운영자의 검증된 되돌림 절차이며, 새 자동 정책 전환기를 추가한 것이 아니다.
되돌릴 때도 이미 저장된 보정 intent·실제 주문 가격은 소급해 되돌리지 않는다.

## 6. 현재 결론과 완료 조건

사용자가 승인한 좁은 demo 집행 보정의 구현·안전 검증 후 적용을 진행한다.
전체 전략 수익성·호가 대기열 효과 입증이나 M0/M2/M4/M5 전체 완료가 아니다.
로컬/서버 격리 테스트, 정확한 head CI, ff-only 배포, 다음 정규 실행, 최초 실제 보정 주문을 따로 기록한다.
검증 목적으로 실제 주문·runner 강제 실행·과거 알림 재발송을 하지 않는다.

### 배포 전 구현·검증 근거

- 기존 관련 47개를 먼저 통과시키고 신규 모듈 부재 실패를 확인한 뒤 구현했다.
- 신규 가격 단위 35개, 실제 runtime→broker→fake exchange 통합 3개, 프롬프트/strict wire
  소유 경계 회귀를 추가했다. 단위·통합 파일은 기존 CI 실행 목록에 연결했다.
- 최종 전체 격리 BTC: **3,107 passed / 12 skipped / network attempts 0**(Python 3.12.12).
- Ruff F/E9, Python 컴파일, diff check, 독립 설계·최종 읽기 검토를 통과했다.
  별도 Python 타입검사 설정은 없다.
- 같은 제안·같은 호가의 4가지 방향/가격 예와 시장성 전환·비활성 반례의 순수 비교를 통과했다.
  비교 입력은 합성 자료이며 실제 주문·DB·모델·채널 전송은 없었다.
- `scenario_execution.py`와 기존 위험 검증기는 변경하지 않았다. 원본 proposal는 보존하고
  최종 intent의 `execution_pricing`에 버전·관측 호가·원래/최종 가격·적용/생략 사유를 남긴다.
- 위 결과는 호가 대기열·체결률·수익 개선의 증명이 아니다. CI·운영 Python·배포·첫 정규 실행·
  최초 실제 보정 주문 관측은 각각 별도 확인한다.
