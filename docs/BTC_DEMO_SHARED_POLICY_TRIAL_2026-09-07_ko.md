## 설정·활성화 계약

1. 기존 자격증명 파일과 cron은 수정하지 않습니다. 공통 원장의 BTC 전용 설정 키를
   검증된 관리 명령으로 관리하고, 데이터베이스를 임의 SQL로 편집하지 않습니다.
2. 두 세션 모두 Bybit demo endpoint인지 확인한 뒤 반환 UID를 읽고 서로 다른 계정으로
   고정합니다. UID 자체는 CLI 출력·로그·보고서에 넣지 않습니다.
3. enable은 공통 실행 잠금 안에서 두 계정의 fresh 자본·포지션·미체결 주문·로컬 미확정
   상태를 확인합니다. flat/미체결 없음이 확인되지 않으면 설정을 바꾸지 않습니다.
4. 설정은 엄격히 검증하고 원자적으로 저장합니다. 기존 환경 설정과 충돌하면 자동으로
   덮어쓰거나 몰래 우선순위를 바꾸지 않고 신규 진입을 차단합니다.
5. pause는 신규 진입을 멈추는 기능입니다. 기존 보호·청산·미확정 주문 복구와 영속 예약은
   그대로 유지합니다. "검사를 끄고 무제한 진입"하는 우회로로 만들지 않습니다.
6. 정상 demo tick에 비밀값 없는 유효 정책 상태를 기록합니다. 설정 읽기 실패도 기존
   보호를 막지 않으며, 실제 새 주문 경계에서 다시 정책을 검증합니다.

## 관리 명령

`prism-btc` 디렉터리에서 실행하며, 비율은 퍼센트 숫자가 아닌 소수로 입력합니다.

```bash
python -m live.shared_entry_policy status --root-db ../stock_tracking_db.sqlite
python -m live.shared_entry_policy probe --root-db ../stock_tracking_db.sqlite --heat 0.065 --slippage 0.001 --demo
python -m live.shared_entry_policy enable --root-db ../stock_tracking_db.sqlite --heat 0.065 --slippage 0.001 --demo
python -m live.shared_entry_policy pause --root-db ../stock_tracking_db.sqlite
```

- 설정 키는 `btc_meta`의 demo / `shared_entry_policy_v1`입니다. 계정 연결 정보는
  이 비공개 운영 데이터에만 보관하며 상태 명령과 관측 이벤트에는 UID를 제외합니다.
- `probe`는 운영 DB를 읽기 전용으로 열고 주문 없이 준비 상태만 확인합니다.
- `enable`은 명시적 `--demo`와 수치가 필요하며 같은 정책의 반복 적용은 중복 생성하지 않습니다.
- `pause`는 거래소 연결 없이 새 진입을 차단합니다. 예약·체결 기록이나 보호 주문을 삭제하지 않습니다.
- 정상 종료된 예전 진입이 ACK 상태로 남아 있으면, 정확한 terminal 부모 주문과
  체결 증거로 확인합니다. ACK를 완료로 간주하거나 원래 기록을 지우지 않습니다.
- 과거 TP는 실제 종료 상태인 `FULFILLED`/`FLAT_TERMINAL`만 허용하며,
  잔여 포지션·미체결 주문·정리 대기 주문이 있으면 활성화를 거부합니다.
- 관리 변경과 UID를 제외한 `shared_policy_control` 이벤트는 같은 transaction에 기록합니다.
  이후 demo tick은 `shared_entry_policy_observed_v1`로 실제로 읽은 설정과 코드 버전을 남깁니다.
- 원래 환경변수 방식은 호환합니다. 다만 runtime 설정과 `.env`/프로세스의 기존
  `BTC_SHARED_ENTRY_*`가 함께 있으면 오류로 표시하고 새 진입을 차단합니다.

## 증거 구분

관리 명령의 `active`는 설정 저장, 정상 tick의 `active`는 런타임이 설정을 읽었다는 증거입니다.
어느 쪽도 실제 신규 체결, 계획 대비 슬리피지, 수익성 향상을 증명하지 않습니다.
거래소 과거 이력이 없거나 상충하면 재활성화를 막으며 임의의 이력 추정으로 우회하지 않습니다.
