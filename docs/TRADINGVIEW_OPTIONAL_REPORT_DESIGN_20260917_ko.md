# TradingView 선택형 보고서 보강 설계

## 상태

사용자는 Essential 구독 완료를 알리고 선택형 도입·자유로운 MCP 테스트를 요청했다.
후속 승인: 충분한 로컬 검증을 통과하면 이번 기능은 별도 운영 SHADOW 기간 없이
사용자의 PRISM 운영 배포에서 ON으로 활성화한다. 다른 사용자의 기본값은 계속 OFF다.
보고서와 매매 판단의 근거 품질 개선이 목적이며, 보고서 구조 변경도 허용하되 최소한으로 접근한다.
후속 상태(2026-09-18): 사용자가 SSH 터널과 맥북 브라우저로 서버 OAuth 승인을 완료했다.
서버 도구35종 확인, 읽기 도구22종 실호출 및 인증 갱신을 확인했다.
실측 한계와 결과는 TRADINGVIEW_CAPABILITY_AUDIT_20260918_ko.md를 따른다.
설계와 오프라인 입력 검증만 진행했으며, 실행 프롬프트·매매 정책·운영 보강 ON은 아직 변경하지 않았다.

## 기존 사용자 보존 계약

1. 기본값 OFF. 미가입·미설정 사용자는 기존 yfinance/KIS/Perplexity/Firecrawl 경로를 그대로 사용한다.
2. OFF에서는 TradingView import·도구 발견·인증·네트워크·캐시 조회·관련 프롬프트 추가가 모두 0이다.
3. 공통 필수 의존성·공통 필수 자격증명으로 추가하지 않는다. 기존 YAML은 수정 없이 읽혀야 한다.
4. ON이어도 TradingView는 보강 자료다. 기존 데이터를 덮어쓰거나 누락을 0으로 대체하지 않는다.
5. 미인증·토큰 만료·429·timeout·부분 응답은 상태로 기록하고 제한된 대기 후 기존 경로를 유지한다.
   이미 끝난 Perplexity/Firecrawl 조사를 실패 때문에 다시 실행하지 않는다.
6. 신규 가입 권유나 API 키 누락 메시지를 기존 사용자의 공개 보고서에 삽입하지 않는다.
7. 킬 스위치 하나로 보강만 중단한다. 기존 보고서 생성·주문·보유·매도는 그대로 남는다.

OFF의 동등성은 LLM 최종 문장이 우연히 같다는 의미가 아니다. 기존 함수 호출·도구 목록·
모델 입력·비용을 추가하지 않는 경계가 동일해야 하며, 이를 고정 fixture로 검증한다.

## 단계와 권한

- OFF: 기존 경로만 실행.
- EVALUATE: 별도 읽기 전용 시험. 정규 보고서·매매 입력에 미반영.
- ENRICH: 로컬 품질·비용·호환성 검증, 필수 CI 및 이용권한 확인 후 PRISM에 ON 배포.
  별도 운영 SHADOW 단계는 요구하지 않는다. 배포 후 정상 실행과 중단 스위치는 확인한다.

위 이름은 제안된 설계 상태이며 아직 존재하는 환경변수나 구현된 모드가 아니다.
승인은 읽기 도구 탐색과 검증을 통과한 선택형 운영 보강이다. 효용 검증을 이유로 관심목록을
임의 편집하거나 알림·시험 주문을 만들고 유료 추가상품을 구매하지 않는다.
get_active_watchlist도 기본 목록을 생성·활성화할 수 있어 최초 시험 허용 목록에서 제외한다.

## 연결 경계

현재 McpServerSpec은 command 기반이며 backend는 MCPServerStdio를 만든다.
TradingView는 Streamable HTTP + OAuth이므로 URL을 기존 YAML에 붙여 넣는 것만으로 호환되지 않는다.
기존 stdio 계약을 깨지 않는 별도 선택형 transport/prefetch adapter가 필요하다.
Codex 데스크톱에서의 로그인과 PRISM 서버의 무인 인증·갱신은 별도로 검증한다.
토큰·쿠키·비밀번호를 프로젝트·보고서·Telegram·로그에 저장하지 않는다.

## 비용 우선 구조

기존 데이터 prefetch → 선택형 TV 수집 → 출처·날짜·법인 검증 → 압축된 공통 근거 → 기존 에이전트.

- LLM에게 전체 도구 목록을 상시 노출해 자율 순회시키지 않는다.
- 보고서 질문에 필요한 자료를 코드가 고정 순서로 수집한다.
- 종목·사업범위·자료 기간·공개시점·정책 버전을 cache key에 포함한다.
- 같은 원문은 뉴스/기업분석/최종 종합에서 공유한다. 실패·권한 부족도 구분해 짧게 재사용한다.
- 원문에 권한이 있는 범위에서 hash와 보관 참조를 남기고, 모델에는 핵심 발췌와 미해결 사항만 보낸다.
- 예산은 호출 수·시간·입력 크기·retry 합계로 강제한다. 초기 수치는 실측 후 확정한다.
- 이전 competitive_prefetch 프로토타입의 텍스트 대응 검사는 사실·법인·수치의 의미 검증이 아니다.
- MCP 호출을 코드로 옮겨도 제공자 요금과 최종 분석 토큰은 남는다. 비용 절감을 미리 단정하지 않는다.

## 인증 후 시험할 범위

우선 KR2·US2의 적은 표본에서 진행하고 한도가 확인되면 확대한다.
종목 식별, 실제 제공 도구/schema, 응답 기준시각·지연, 누락/권한 오류부터 기록한다.

1. 뉴스 목록/원문: 중복·발표시각·제목과 본문 대응·유료기사 접근 제한.
2. 공시/실적발표: 올바른 법인·분기와 원문 대응. 과거자료가 현재 수정본인지 구분.
3. 재무/전망: KIS/yfinance/공식 IR와 값·단위·기간·GAAP·actual/estimate 대조.
4. 경제/실적/배당 일정: 예상일/확정일·시간대·업데이트 상태.
5. 가격/지표/스크리너: 기존 팩트와 정의·기준봉·수정주가·거래량 출처 비교.

기사 수나 페이지 수가 많다는 이유로 통과시키지 않는다. 특정 도구의 미국 성공을 한국 성공으로 확대하지 않는다.
Essential 구독을 실시간 시세·모든 뉴스·무제한 과거 데이터의 권한으로 해석하지 않는다.

## 보고서 개선 가설

- 회사 설명을 되풀이하기보다 새 정보가 투자 논리를 어떻게 바꾸는지 설명한다.
- 실적/가이던스/시장 기대를 구분하되 과거 컨센서스가 없으면 기대 변화 추세를 만들지 않는다.
- 경쟁사 비교는 같은 기간·사업 범위·단위에서만 한다. 전체 기업 매출을 제품 점유율로 바꾸지 않는다.
- 긍정 근거와 가장 강한 반대 근거, 확인할 사건, 판단을 바꿀 조건을 함께 제시한다.
- TV에 없는 시장점유율·가격결정력·제품 경쟁력은 기존 검색·공식 자료 검증으로 보완한다.

## 필수 회귀와 진입 조건

- 설정 없음/OFF: 기존 KR·US factory 입력·도구 목록·호출 순서 동등, TV 호출0.
- ON 미인증/만료/429/timeout/빈 응답: 기존 보고서 정상, 반복 fallback·추가 LLM 폭주 없음.
- 부분 성공: 확보된 자료만 출처와 함께 주입. 결측을 실패 점수로 사용하지 않음.
- 올바른 설정: 기존 숫자와 충돌하면 자동 우선 덮어쓰기 대신 불일치 표시.
- 재실행: 공유 cache 사용, 날짜·법인·권한 경계 분리, 비밀값 유출 없음.
- 같은 종목·시점·모델에서 기존 보고서와 보강안의 근거 일치·공백 해결·토큰·시간 비교.
- 보고서·매매 에이전트에 제공하는 근거의 품질을 높이되, 기존 숫자와 판단을 몰래 덮어쓰지 않는다.
  점수 문턱·선발·손절·비중·집행 정책 자체를 바꿔야 한다면 매매 변경 하네스로 별도 근거를 검토한다.
  SHADOW 생략 승인이 테스트·CI·운영 스모크 생략을 뜻하지 않는다.
- 이용약관의 자동 처리·저장·채널 배포 허용 범위를 확인한 뒤 운영 보강을 검토한다.

## 로컬 검증 후 바로 활성화하기 위한 추가 조건

- 미국·한국의 문서상 읽기 도구를 기능군별로 실제 호출하고 성공/권한부족/자료없음/오류를 분리한다.
- 기존 도구만 사용한 입력과 보강 입력을 같은 후보·기준시점·모델로 비교한다.
- 틀린 법인·인용·단위·시점, 출처 충돌, 확정되지 않은 전망의 실적 둔갑을 점검한다.
- 회사/뉴스/최종 보고서/PDF/매매 에이전트 입력까지 근거와 미확인 상태가 보존되는지 확인한다.
- 토큰·시간·API 호출은 실제 측정값만 비교한다. 원문 길이 감소를 비용 절감률로 부르지 않는다.
- 새 도구 실패 시 기존 경로가 정상 동작하고, 기능 OFF에서 기존 입력/호출이 동일해야 한다.
- 본문 구조는 우선 유지하고 필요한 근거·반론·판단 변경 조건만 보강한다. 구조 변경은 별도 diff로 검토한다.
- 정확한 검증 커밋을 배포하고 PRISM 전용 설정에서만 활성화한다. 미가입 사용자 설정은 변경하지 않는다.

## 사용자 인증

### 확정한 진행 순서

초기 계획은 사용자가 집에서 승인할 때까지 대기하는 것이었으며, 이후 맥북과 SSH 터널로 서버 승인을 완료했다.
운영 서버는 최초 승인 시에만 맥 브라우저와 SSH 로컬 포워딩을 사용하고, 이후에는 서버가
독립적으로 HTTP MCP에 접속하는 방향으로 계획한다. 실제 callback/포트 호환성은 구현 시 검증한다.
서버용 승인은 서버에서 시작한 OAuth 요청에 대해 수행하고, 승인 결과와 갱신 자격증명은
서버의 제한된 저장소에 보관한다. Mac Codex의 연구용 인증과 자동 공유된다고 가정하지 않는다.
공개 인증 포트·Telegram 토큰 전달·맥미니 상시 중계는 사용하지 않는다.
SSH 터널을 이용한 인증과 읽기 시험은 완료했다. 운영 어댑터 통합·활성화는 별도이며 아직 실행하지 않았다.

사용자 Mac의 터미널에서 아래 명령으로 공식 MCP를 등록하고 브라우저에서 로그인한다.

```bash
codex mcp add tradingview --url https://mcp.tradingview.com/mcp
# 위 명령에서 인증이 끝나지 않은 경우
codex mcp login tradingview
```

새 세션에서 도구가 노출되는지 확인한다. API key 발급은 필요 없으며 비밀번호/토큰을 전달하지 않는다.

공식 문서: https://www.tradingview.com/mcp/docs
