# TradingView P3b / 공시 선택 P4a 진행 기록

## 사용자 질문: 제한하는 것이 주문 기능인가, 데이터를 쓰는 용도인가?

확인해야 한다고 설명한 것은 **데이터를 사용하는 용도**다.
TradingView 안에서 주문하는 기능만을 뜻하지 않는다. TV 자료를 PRISM에 넣고 PRISM이
매수·매도 판단을 한 뒤 KIS에서 주문하는 경우도 검토 대상이다.
[일반 약관 3절](https://www.tradingview.com/policies/)은 TV 데이터에 의존한 자동매매·
알고리즘 의사결정과 비표시 용도를 제한한다고 명시한다. 주문이 다른 증권사에서 나가는지만으로
이 제한을 벗어난다고 확정할 수 없다.

다만 [공식 MCP 출시 안내](https://www.tradingview.com/blog/en/tradingview-mcp-server-public-beta-60864/)는
AI 스크리닝·보고서 분석·코드에서 데이터를 분석하는 사용례를 소개한다. 따라서 모든 AI 처리나
자동 조회가 금지라고 해석하지 않는다. 공식 MCP에 별도 허용 조건이 있는지, 개인 분석과
무인 매매 연결/보고서 재배포의 경계가 무엇인지는 별도 확인이 필요하다. 확정적인 법률 판단이 아니다.

이 불확실성은 운영 이용범위 확인 사항이며 독립 모듈 개발을 멈출 이유로 삼지 않았다.
이번에도 실거래 연결·운영 ON·실제 인증파일 접근/갱신 없이 후속 모듈을 개발했다.

## PRD와 설계

P3b는 기존 P2 수집/P3a HTTP adapter가 필요할 때만 호출하는 credential supplier다.
사용자 데이터·주문·프롬프트를 건드리지 않는다. 신규 의존성 없이 기존 HTTPX와 POSIX 파일 잠금을 쓴다.

- 기본 OFF에서는 경로 검사·lock 파일·인증·HTTP가 모두 발생하지 않는다.
- 소유자 전용 디렉터리/파일만 읽고 심볼릭 링크·하드 링크·잘못된 권한을 거절한다.
- 교체되는 credential inode가 아닌 별도 안정적인 파일에 프로세스 간 잠금을 잡고 다시 읽는다.
- 충분히 유효한 토큰은 그대로 반환하며 credential/state 파일을 다시 쓰지 않는다.
- 갱신 전 비밀값이 없는 IN_FLIGHT 표식을 내구성 있게 저장한다. 응답 유실 등으로 결과가
  불분명하면 같은 인증값으로 재시도하지 않는다. 메타데이터나 만료일만 바꿔도 차단이 풀리지 않는다.
- 성공 응답을 받으면 임시 파일 fsync → 원자적 교체 → 디렉터리 fsync까지 마친 후 반환한다.
- 취소가 와도 소유한 갱신/저장 작업을 방치하지 않고 정리를 마친 뒤 취소를 전달한다.
  따라서 안전한 정리 때문에 명목상 timeout을 넘을 수 있다. 프로세스 강제 종료와 공급자 측
  토큰 회전 후 응답 유실까지 복구를 보장하지 않는다.
- HTTP 응답은 64KiB 제한이며 압축을 요청하지 않는다. 압축 응답이 오면 본문 소비 전에 거절한다.
- 공개 OAuth metadata에서 현재 issuer와 refresh endpoint를 무인증 읽기로 확인했다.
  실제 사용자의 OAuth를 갱신하거나 TradingView 자료 조회 권한을 시험한 것은 아니다.

P4a는 검증된 메타데이터를 입력받는 순수 선택기다. 기존 `filing_selection.py`의 문서 내부
발췌 기능과 역할을 구분하며, 문서부터 잘못 선택하는 문제를 별도 계층에서 다룬다.

- 기준시각 이전 공개된 자료 중 최신 보고기간을 기본 후보로 선택한다.
- 과거 사업보고서는 세부 내용 보완 자료로 분리한다. 과거 연차의 최근 정정일이 더 최신 반기를 밀어내지 않는다.
- 당일 기사/공시의 공개시각이 없으면 임의로 자정을 넣지 않는다. 날짜만 확인된 이전 날짜 자료는
  그 날짜의 공개시간 범위를 보존한다.
- 정정본 연결·법인·연결/별도·기간이 충돌하거나 현재 정정본 공개시각이 미확인이면 이전 본문을
  현재 자료로 조용히 되돌리지 않는다. 최신 본문을 확보하지 못해도 연차로 대체하지 않는다.
- 전체 목록을 확인하지 못했으면 '현재 확보한 후보'와 '최신임이 확인된 자료'를 구분한다.

TV 문서 정규화는 category·회계연도/분기 라벨·중첩 종목코드·reported·정확한 view ID와
provider total을 보존하도록 보완했다. `reported`를 제출일로, Q2를 무조건 6월 말로 바꾸지 않는다.
전체 건수와 몇 개 항목을 받았다는 것만으로 공식 공시 목록 완전성을 인증하지 않는다.

## RF머트리얼즈: 실제 공식 원문 확인

[DART 반기보고서](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260814001631)와
그 페이지에서 실제 반환한 viewer 인자로 열린 표지에서 확인했다.

- 법인명: 알에프머트리얼즈 주식회사.
- 대상기간: 2026-01-01 ~ 2026-06-30, 제20기 반기보고서.
- 제출일: 2026-08-14. 정확한 접수 시각은 공식 원문에서 확인하지 못했다.
- 이 자료는 2025년 사업보고서보다 새로운 정기공시 후보임이 확인됐다.
- 공식 전체 목록/정정 이력을 완전히 수집하지 않았으므로 기준시점의 절대적인 최신 공시라고
  확정하지 않았다. 다른 사이트의 분·초 표시는 공식 검증 시각으로 사용하지 않았다.

[회사 Financial 목록](https://www.rf-materials.com/41?sca=Financial)은 확인 시 2025년 사업보고서가
가장 최근 항목이었다. 따라서 회사 IR 목록 하나만 확인하는 방식으로는 위 반기를 놓칠 수 있다.
이 관측은 공식 원문 존재 확인이며 RF의 새 완성 보고서나 자동 공시 수집기 검증은 아니다.

## 검증과 피드백

- 구현 전 기존 초기 기반 150개 테스트 통과.
- P3b: 모듈 미구현 RED 후 synthetic store/MockTransport GREEN. 실제 두 프로세스의
  잠금·다시 읽기 시험에서 갱신 POST 1회. 실제 인증값은 사용하지 않았다.
- 보안 리뷰에서 압축 해제 후 크기를 재는 문제가 발견됐다. 8MiB로 팽창하는 gzip 응답을
  스트리밍 테스트로 재현하고, 본문 소비 0회로 거절하도록 수정했다.
- P4a: 미확인 scope/kind를 단순 제외해 오래된 연차가 최신으로 승격되는 오류,
  연결된 정정본의 다른 법인/범위 충돌을 무시하는 오류를 RED→GREEN으로 수정했다.
- 날짜 overflow를 안전하게 처리하고, 빈 분류/종목 컨테이너만 있는 응답이 자료 확보로
  처리되는 회귀도 수정했다. 모든 기준은 supplied metadata의 정확성을 별도로 요구한다.
- 최종 코드 리뷰에서 빈 view/provider와 공백 ID도 자료로 세는 경로를 추가로 발견했다.
  문서 ID·제목·원문 위치 또는 유효 view ID를 요구하도록 문서 도구에 한정해 수정했다.
- 신규 테스트: credential 61개, 공시 선택 48개, 문서 탐색 6개, 합계 115개 통과.
  CI 연구/보고서 전체 명령을 로컬 실행한 결과 **830개 통과**, 기존 경고 3건.
- 아키텍처(P4a)·보안(P3b)·코드(P3b/P4a) 독립 리뷰 후 수정·재검증을 마쳤다.
  Ruff·compileall·diff 검사가 통과했다. Python 전용 타입 검사와 pip-audit는 환경에 없어
  미실행이며 TypeScript 기반 LSP의 무진단을 Python 타입 안전성으로 주장하지 않는다.

## 변경 파일과 남은 작업

신규: `prism_core/tradingview_credentials.py`, `prism_core/filing_catalog.py`와 대응 테스트.
수정: `prism_core/tradingview_evidence.py`, 문서 탐색 회귀 테스트, CI 테스트 등록.
기존 normalizer·URL sanitizer·HTTP adapter·비밀 로그 격리를 재사용했다.
실제 보고서/스크리닝/BUY/SELL 실행 코드는 바꾸지 않았다.

P3의 실제 OAuth/공급자 실측 검증, P4의 전체 공시 목록 수집·뉴스 중요도/Perplexity 복구,
P5 서술형 보고서와 PDF→BUY/보유 이후 사실→SELL, P6 스크리닝 대조, P7 운영 적용은 남아 있다.
구현된 옵션은 아직 운영 앱의 설정으로 연결되지 않았다. 보고서의 중요성을 낮추거나
매매 정책을 대신 변경하지 않는다. 전체 도입 완료·실제 수익 개선을 주장하지 않는다.
