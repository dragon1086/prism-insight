# 보고서 재발 장애: 수정 전 계획과 인수 기준

## 관측과 한계

배포 후 새 샘씨엔에스 요청은 20:03:25부터 20:18:43까지 실행되어 기본 여섯 장,
DART 세 장, 투자전략까지 생성했으나 첫 최종 검수의 일반 오류에서 중단됐다.
기존 운영 로그에는 실제 검수 응답이 없어, 결합된 조건 중 어느 항목이 실패했는지는
확정할 수 없다. 이전의 초안 재사용 검증 성공을 신규 운영 요청 성공으로 일반화하지 않는다.

## 변경 전에 확인한 구조적 문제

1. 읽기 전용 장의 충돌도 보고하라는 지침과 이를 형식 오류로 거절하는 수신 범위가 다르다.
2. 충돌 진단 전에 아직 발행하지 않을 요약·수정안까지 검사해 유효한 진단을 잃을 수 있다.
3. 운영에는 세부 원인을 재현할 안전한 기록이 없지만, 검증 도구에만 캡처 기능이 있다.
4. 주요 통합 테스트가 요약과 복구 함수를 함께 대체하여 실제 경계 연결을 검증하지 못한다.

## 실행 계획

- 단계별 상태·JSON 형식·진단 가능한 장·수정 권한을 분리한다. 장별 권한은 한 목록에서 정의한다.
- 기존 SDK의 구조화 출력 경로를 사용하고 실제 OAuth 경로에서 지원 여부부터 확인한다.
- 충돌 응답에는 발행용 요약이나 편집을 요구하지 않는다. READY에서만 요약·편집 보호를 적용한다.
- 모든 알려진 장의 충돌을 표현할 수 있게 하되, 원문·계산표·peer·macro 근거는 자동 수정하지 않는다.
- 모델이 쓴 기본 장·DART 장은 기존 작성자와 같은 원문으로 제한적으로 복구한다. 전략은 수정한
  근거에서 새로 합성한다. 무제한 재생성·새 자료 수집·보호를 끄는 성공 처리는 금지한다.
- 전략 작성 전에 사실 충돌을 평가하고 최종 검수도 유지한다. 초안 복구와 전략 재합성의 횟수는
  각각 제한하며, 남은 충돌·형식 위반·원천 부족은 서로 다른 사유로 명시적으로 종료한다.
- 오류 코드와 안전한 비공개 재현 자료를 크기·개수·기간 제한으로 저장한다. 비밀값·환경 설정은
  기록하지 않으며 기록 실패가 원래 오류를 덮어쓰지 않게 한다.

## 인수 기준

- 형식 오류, 알려진 비복구 충돌, 전략 단독, 근거 부족, 수치·기간·부호·용량 문제를 구별한다.
- 실제 구조화 응답 → 검증기 → 복구 → 새 전략 → 실제 재검수 연결을 시험한다.
- 실패·시간 초과·취소에서 부분 PDF·정상 캐시·채널 메시지가 발행되지 않음을 확인한다.
- 동일 입력 회귀와 신규 전체 생성을 분리한다. 최종 후보에서 초안/캐시를 주입하지 않는
  한국 report 경로를 실제 앱 환경으로 실행하고 별도 표본을 확인한다.
- 한국·미국 진입점과 캐시·전달 계약을 함께 확인한다. 실제 주문은 만들지 않는다.
- PR의 정확한 head와 CI를 확인한 뒤 clean ff-only로 배포한다. 운영 소스·서비스 점검과
  첫 운영 요청 또는 첫 정규 배치의 관측 여부를 구분해서 보고한다.

손절·매수 점수·주문 수량·매매 정책 변경, 데이터가 불충분한 보고서의 정상 발행은 범위 밖이다.

## 9월 25일 후속 수정 범위

- 신규 앱 진입 테스트의 교정 사유에 코드와 설명이 섞인 응답을 확인했다. 사유를
  기존 네 코드의 enum으로 제한하고 로컬 검증도 같은 목록을 사용한다. 임의 문자열을
  접두사만 보고 정상 사유로 바꾸지 않는다.
- 뉴스 작성자가 만든 Competitive Evidence와 코드가 복사한 overview Handoff의
  소유권을 구분한다. 원문 공시·계산표는 계속 불변이다. 정확한 내용·ID·경계를 확인한
  파생 복사본만 분리하고, 기존 뉴스 복구 후 ID와 복사본을 한 번 재생성한다.
- 검수 입력에서는 검증된 중복 복사본만 생략한다. 뉴스 원본과 독립적인 개요 본문은
  검수하며, 복사본 불일치는 숨기지 않고 실패시킨다. 새 ID는 사실 인증이 아니다.
- 미국 PDF의 공통 시장 근거에서 측정값이 전혀 없는 선택 지표 행은 생략하고
  미확인 범위를 묶어 안내한다. SPY 기준·부분 측정·국면·관측 모집단의 한계는 유지하며
  원시 수치·국면 판정·매수 게이트는 변경하지 않는다.
- 밤사이 미국 매수보류 분석은 별도 Evidence Packet으로 수행한다. 거래량 필터 추가는
  이번 장애 수리와 분리하며, 표본과 시점 정의 검토 없이 전역 조건으로 승격하지 않는다.

추가 인수 기준은 CE 교정 후 뉴스와 복사본 일치, 멱등성, 변조 거절, 실제 PDF의
미측정 행 정리, 정확한 최종 코드의 신규 앱 진입 테스트다. 이전 실패 기록은 보존한다.
