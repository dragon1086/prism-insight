# Telegram 리포트 데이터 경로 변경

## 사전 계획

- app-server의 KIS 자격증명은 복사하거나 변경하지 않습니다. DB 서버의 기존 KIS 조회 기능을 인증된 읽기 전용 API로 사용합니다.
- 기존 archive API의 인증과 localhost SSH 터널을 재사용합니다. 주문 API, 임의 함수 호출, 공개 포트 추가는 금지합니다.
- Telegram 프로세스와 그 리포트/MCP 자식 프로세스만 원격 경로를 선택합니다. 연결 실패 시 로컬 KIS나 KRX로 우회하지 않습니다.
- 날짜·종목·기능·응답 크기를 제한하고, 출처와 관측일 메타데이터를 보존합니다. 실패 응답에는 내부 경로나 예외 원문을 넣지 않습니다.
- 리포트 생성 실패는 정상 Markdown/PDF로 저장하지 않고, 기존 오류 캐시도 전달하지 않습니다. 이용 횟수 환불 동작은 유지합니다.
- 먼저 격리 회귀 테스트를 실행하고, DB API와 app 터널에서 실제 SK하이닉스 가격·지수 조회를 확인한 뒤 봇을 재시작합니다.

## 배포 경계

DB 서버는 최신 main이지만 app-server는 이전 릴리스에 머물러 있습니다. app-server에 무관한 변경 수백 개를 함께 배포하지 않습니다. 필요한 변경만 이전 서버 커밋 위에 백포트하고, 해당 커밋과 통합 main을 각각 검증합니다. 서버는 clean 상태에서 검증된 후속 커밋으로만 fast-forward합니다. 기존 비밀 설정·운영 DB·보고서 파일과 다른 서비스는 보존합니다.

## 완료 증거

- 최초 통합 테스트의 11개 실패는 테스트용 환경변수가 다음 테스트로 남는 격리 문제였습니다. 테스트가 실제 환경 대신 독립된 사전을 사용하도록 수정한 뒤 동일 조합 216개가 통과했습니다.
- 요청 본문은 4KB, 응답은 2MB로 제한합니다. API는 대기 5초와 별도 프로세스 25초 제한을 두며, 시간 초과 프로세스를 종료·회수합니다. 클라이언트 제한은 35초입니다.
- 가격·지수·시총·수급·수급 추정·재무 현재값·종목명·상장시장 등 8개 조회만 허용합니다. 상장시장 확인 실패 시 임의의 비교 지수를 선택하지 않고 RS 패널을 생략합니다.
- 최초 보안 검토에서 발견한 서버 작업 시간 제한 문제는 별도 프로세스 종료 방식으로 보강했습니다. 두 번째 검토에서 확인된 차단 사유는 없었습니다.
- 오류 표시가 포함된 부분 보고서도 보수적으로 거부하므로, 일부 섹션 장애 때 가용성이 낮아질 수 있습니다. 기존 진단 파일은 삭제하지 않고 캐시 재사용만 거부합니다.
- 운영 배포와 실제 데이터 확인은 아직 미완료입니다. 아래에 검증 결과를 추가하기 전에는 완료로 간주하지 않습니다.
