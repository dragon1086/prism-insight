# BTC 간결한 알림과 잔여 실행 검증

## 범위와 정리 계획

기준선은 PR #891 배포본 `c96b6976`이다. M3.1/M3.2 알림 의미·가독성 개선과
M0 실행 가용성 오류 수정을 구분한다. 전략·프롬프트·위험 한도·데모 MAIN·스케줄은 유지한다.

1. 체결·정산·시나리오 원장을 읽기 전용 대조해 중복 진입인지 알림 문제인지 구분한다.
2. 기존 증거 검증과 계산은 보존하고, 반복 상세 설명을 이벤트별 핵심 문장으로 줄인다.
   먼저 길이·의미 회귀를 고정한다. 내부 원본 근거는 삭제하지 않는다.
3. 첫 진입, 같은 매매의 추가 체결, 기존 포지션 상태, 일부 청산, 전량 체결 후 정산 대기,
   정산 완료를 구분한다. 이전 상태가 없는데 변경 전 값을 만들지 않는다.
4. 별도 실행 회귀로 활성 매매의 새 OPEN 금지, 미확정 정산 중 새 매매 금지,
   완전 정산 이후 새 시나리오 허용을 확인한다.
5. 모델 응답 후 잠금 경합은 제한된 획득 재시도로 보완하되, 잠금 본문·주문은 반복하지 않는다.
6. 전체 격리 테스트·정확한 PR head CI·운영 Python 검증 뒤 clean/ff-only 배포한다.
   수동 테스트 주문 없이 자연 예약 실행을 확인한다.

## 인용한 메시지의 사실관계

2026-10-04 00:16 KST까지 보존된 거래소 체결 증거를 중복 제거해 대조했다.
해당 시나리오의 진입은 10/03 21:42:49 KST, 84,750 USDT에서 0.1 BTC 한 건이다.
그 뒤 ADJUST는 추가 진입 수량 없이 SL을 84,620으로 조정했다.
TP 주문 교체는 익절 주문 변경이지 신규 포지션이 아니다. 정산 완료 기록도 없다.
23:07:20 공지는 새 버전이 기존 포지션의 비교 기준을 처음 저장한 PROTECTION 알림이었다.
따라서 이 공지를 새 진입으로 해석하면 안 된다. 이 관측만으로 미래 거래까지 보증하지 않는다.

## 공개 표현 계약

- 대표 진입·상태·변경 알림은 650자/11줄 이하를 회귀로 검증한다.
- 첫 상태 확인은 **기존 포지션 · 신규 진입 아님**으로 표시하고 원래 진입시각을 연결한다.
- 추가 체결은 **같은 매매**임을 명시한다. 같은 주문의 나누어진 체결도 포함하므로
  별도 신규 주문이었다고 추측하지 않는다.
- 변경 알림은 바뀐 수량·평단·SL·TP의 전후 차이를 우선한다. 변하지 않은 모든 항목을
  줄줄이 반복하지 않는다.
- TP/SL은 가격, 정리 비율, 1배/확인 레버리지 단순환산 수익률, 해당 수량 손익과 계좌
  영향을 짧게 표시한다. 수량으로 계산한 손익에 레버리지를 다시 곱하지 않는다.
- 증거금 비중은 같은 계좌 순자산 기준이다. 현재 손절 예상과 전체 매매 2% 목표 한도는
  별개다. 비용 전·단순환산·계획 초과 가능성은 짧은 주의문으로 남긴다.
- 검증된 잔량이 0이면 전량 청산 체결과 정산 완료를 구분한다. 잔량을 모르면 일부 청산으로
  단정하지 않는다. CLOSED의 flat·정산·주문 종료 근거 검사는 그대로 유지한다.
- 공개/운영자 채널 분리, 과거 공지 불변, 전송 중복 방지, 선택적 알림 오류 격리를 유지한다.

## 실행 검토 하네스

변경 유형은 경제적 전략 변경이 아닌, 잠깐의 후모델 잠금 경합으로 판단을 버리는 구현
결함 수정이다. 보호 점검·위험 한도·시나리오 조건·LLM 호출 빈도는 유지한다.
변경 전 운영 기록에는 최근 한 시간 보호 확인 60건, WAIT 완료 2건, lock_busy 7건,
별도 일반 오류 4건이 있었다. 저장된 WAIT 제안은 검증 완료된 판단과 다르다.

잠금 획득만 최대 8초 시도한다. 대기 중 다른 작업의 잠금을 빼앗거나 풀지 않는다.
획득 후 기존 거래소 재대조와 계좌·시나리오 버전, 입력 120초 신선도, 제안 만료 및 위험
검증을 모두 통과해야 한다. 영구 경합은 제한시간 후 안전하게 건너뛴다.
LLM 재호출·주문 재실행·WAIT의 검증 전 성공 처리는 금지한다.

검증 반례는 일시/지속 경합, 계좌·시나리오 변화, 입력/제안 만료, 잠금 본문 오류,
프로세스 간 실제 파일 잠금이다. 수익성·전략 승격·백테스트 개선 증거로 부르지 않는다.
일반 오류는 잠금 문제와 원인이 같다고 단정하지 않으며 별도 조사 결과를 기록한다.

별도 15분 간격의 실패는 당시 snapshot/context/proposal이 모두 미보존이었다.
정상 합성 데이터의 00/05/10/.../55분 수집은 모두 통과하므로 15분 경계 버그로 단정하지
않는다. 후속 관측을 위해 고정된 실패 단계와 정확한 허용 목록의 수집/입력 검증 오류만
기존 감사 결과에 남긴다. 임의 예외 문구·API 응답·계좌 정보는 출력하지 않는다.
수집 시각 경계를 넘거나 입력이 오래된 경우 거부하는 안전 조건은 완화하지 않는다.

## 완료 근거의 구분

소스·격리 테스트 결과와 배포·자연 실행·새 실제 체결 관측을 분리한다.
최종 테스트 수, CI, 배포 커밋과 자연 실행 관측은 PR 및 전달 보고서에 기록한다.
전량 청산부터 다음 신규 진입까지의 실제 전진 관측이 없으면 격리 검증으로만 표시한다.
