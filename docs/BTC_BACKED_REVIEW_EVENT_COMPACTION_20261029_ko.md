# 백업과 일치하는 판단 이벤트 압축

BTC review 이벤트를 안전하게 압축하기 위한 수동 도구다. 기존 문자열을 이미 배포된 review gzip 형식으로 바꾼다. 원문 복원이 확인되지 않으면 저장하지 않으며, rowid·slot·sequence를 바꾸지 않는다. 미확정 주문·포지션·보호·정산 기록을 삭제하지 않는다.

1. 먼저 복원 검증된 전체 백업의 receipt·manifest, archive와 복원본의 크기·SHA, 파일 권한을 확인하고 `btc_review_backup_manifest.py`로 백업된 review 이벤트의 위치·저장 타입·바이트 SHA만 비공개 목록에 기록한다. 원문을 목록에 넣지 않는다. receipt와 목록은 같은 사용자 영역에 있으므로 악의적인 동시 변경을 막는 독립 서명은 아니다.
2. `btc_review_manifest_batch.py`는 고정된 목록 SHA·원본 파일 식별을 검증하고 20행 이하의 배치만 고른다. 서버 `btc_review_event_compaction.py`는 명시적 실행 플래그와 같은 파일 식별을 요구하며, 각 행의 rowid·slot·sequence·저장 타입·SHA가 백업 목록과 일치하는 경우에만 압축한다. 기존 내용을 압축한 행은 원문 SHA가 같을 때만 재시작 시 그대로 둔다.
3. 서버는 매분 25~49초, BTC 판단 프로세스 부재, 여유 4GiB 이상, WAL 128MiB 미만 조건을 준비 전과 쓰기 잠금 중에 다시 확인한다. SQLite 쓰기 잠금은 대기하지 않는다. 기준 미충족·변경·오류가 발생하면 그 행을 넘기지 않고 중단한다. 한 행이 commit되는 순간 WAL은 상한을 넘을 수 있으므로 정확한 하드 상한이나 다른 프로세스의 디스크 사용 보장은 아니다.

배포만으로 실행되거나 예약되지 않는다. 실제 적용 전 정확한 배포 commit, 백업 영수증·목록 SHA, 대상 서버 상태와 첫 소량 배치 결과를 확인한다. 운영 DB에 이전·삭제·변환을 시작하면 복원과 후속 변경 보존을 함께 고려해야 한다.

이 도구는 행 내부 빈 공간을 만들어 이후 SQLite 쓰기에 재사용할 수 있게 할 뿐이다. `auto_vacuum=NONE`인 기존 파일의 운영체제 표시 크기를 줄이거나 90일 삭제를 수행하지 않는다. 일반 VACUUM·파일 교체는 rowid와 ClickStack 출처 식별 및 백업 후 기록을 해칠 수 있어 별도 검증 전 수행하지 않는다.
