# 한국·미국 공시의 범용성 검증 결과

## 먼저, 미국은 무엇을 분석하는가

이번 미국 작업은 TradingView MCP 검증이 아닙니다. 이전 세션의 미국 테스트는 고정된 PDF 내용이 실제 BUY 입력까지 전달되는지 확인한 것이었고, 실제 미국 기업 분석의 성공 사례로 세면 안 됩니다.

현재 저장소의 미국 자료 경로는 다음과 같습니다.

- 가격·기본 재무제표·기업 정보·주주·애널리스트 추정치: `prism-us/cores/data_prefetch.py`의 yfinance 사전 수집.
- 일부 부문 매출: yfinance의 공시 목록과 Yahoo Finance CDN에 제공된 SEC 공시 사본의 inline XBRL.
- 뉴스·경쟁사·기사 원문: Perplexity와 Firecrawl. 기사·검색 요약과 원문을 같은 수준의 근거로 취급하지 않습니다.
- TradingView: 별도 선택형 보완 경로이며 이번 실조회에 사용하지 않았습니다. 기본 OFF와 권한 미확인 상태를 바꾸지 않았습니다.

미국의 공식 공시 원천은 SEC EDGAR입니다. 10-K/10-Q와 외국 발행사의 20-F/40-F, 8-K/6-K 및 XBRL 자료를 구분해서 다뤄야 합니다. 공개 제출 이력 API는 별도 API key가 필요하지 않지만 접근 정책과 속도 제한을 지켜야 합니다. [SEC 공식 API 설명](https://www.sec.gov/search-filings/edgar-application-programming-interfaces), [개발자 접근 정책](https://www.sec.gov/about/developer-resources).

## 이번에 수정한 일반 규칙

### 미국 수치의 잘못된 추정을 제거했습니다

기존 부문 매출 파서는 추출한 숫자를 일괄적으로 ‘백만 USD’로 표시하고, 분기·누적 기간도 연도만 남긴 FY 표기로 바꿨습니다. 일부 누락 값을 0으로 채우고 가장 큰 값을 총액으로 고르는 코드도 있었습니다. 종목별 예외가 아니라 이 공통 파서를 교체했습니다.

- 통화·unit, scale, sign, decimals/precision, 정확한 기간, 발행사, 사업·지역 등 차원을 분리합니다.
- 수치를 합치거나 환산하지 않습니다. CNY와 USD, 분기와 누적, 다른 사업 차원을 서로 바꾸거나 더하지 않습니다.
- 표기 순서나 namespace prefix가 달라도 실제 namespace를 확인합니다. 원문 해시와 namespace 재정의에도 복원할 수 있는 위치를 보존합니다.
- nil·누락·충돌·해석 불가 변환은 0으로 바꾸지 않습니다. 같은 의미의 중복 그룹에 해석 불가 값이 섞이면 정상 값 하나만 골라 내보내지 않습니다.
- tuple, 중첩 inline 구조, 알 수 없는 context 범위, 발행사 불일치는 임의로 평탄화하지 않습니다. 끝까지 검증할 수 없는 개수 한도 초과도 앞부분 성공으로 처리하지 않습니다.
- 기존 Yahoo 경로는 16 MiB 읽기 제한, 정확한 HTTPS 호스트·CIK·접수번호 경로, redirect 금지를 적용합니다. 경로 CIK와 본문의 CIK가 다르면 거절합니다. 이 대조는 공식 ticker 식별이나 최신성 검증을 대신하지 않습니다.
- 10-K/10-Q와 20-F/40-F를 같은 일반 처리 규칙으로 지원합니다. 8-K/6-K를 임의의 정기보고서 대체물로 고르지 않습니다.

구현은 기존 lxml을 사용했으며 새 의존성을 추가하지 않았습니다. 완전한 XBRL 검증 엔진은 아닙니다. 회사별 확장 taxonomy, typed dimension, 지원하지 않는 숫자 변환이나 잘못된 XML 등은 여전히 명시적 미지원입니다. [Inline XBRL 명세](https://www.xbrl.org/specification/inlinexbrl-part1/rec-2013-11-18/inlinexbrl-part1-rec-2013-11-18.html).

### 공식 SEC 목록의 선택 경로를 추가했습니다

공식 ticker→CIK와 submissions의 ticker를 대조하고, 공개 수락 시각·공시일·회계기간 말일을 구분합니다. 정정이 기존 문서를 전부 대체한다고 가정하지 않으며, 확인되지 않은 정정은 해당 기본 자료의 승격을 막습니다. 회계기간 시작일과 연결 범위도 metadata만으로 만들지 않습니다.

선택한 원문과 수치가 실제 보고서 입력까지 연결되는 경로를 네트워크 없는 실제 모듈 테스트로 확인했습니다. 새로운 경로는 명시적 `sec_inline_v1`·`latest_periodic_filings` 옵션과 적절한 User-Agent가 있어야 작동하며 기본 OFF입니다. 수시 공시의 본문까지 읽은 것은 아니므로 `SEC_EVENT_BODIES_NOT_ACQUIRED`를 표시합니다.

**실제 공식 SEC 목록 요청은 프로젝트의 공개 연락처를 사용하는 식별 가능한 User-Agent로 1회 시도했으나 HTTP 403이었습니다.** 재시도·IP/프록시 전환·다른 호스트를 통한 차단 우회는 하지 않았습니다. 따라서 아래 Yahoo 사본 결과를 공식 SEC 최신성 검증으로 표시하지 않습니다.

### 한국의 수집 예산과 보고서 전달을 개선했습니다

- 기존 공시 선정·정정 검증을 끝낸 뒤, 선택한 기본·연간 보완 주석을 미사용 과거 주석보다 먼저 수집합니다. 요청 한도를 늘려 해결하지 않습니다.
- 선택형 수집에 요청 간격과 제한적인 GET 전송 오류 재시도를 추가했습니다. 재시도도 원래 호출·바이트·시간 예산에 포함합니다. POST, 403/429, timeout은 재시도하지 않습니다.
- 후보가 0개여도 선택 본문의 해시·크기·URL이 남습니다. 원문 확보 실패와 파서 탈락을 구분합니다.
- 반복 공시 메타데이터는 출처별로 한 번만 전달하고 레코드에서 참조합니다. 같은 출처의 metadata가 충돌하면 결합하지 않으며, 감사 시 원래 값으로 정확히 복원합니다. 섹션별 6,000바이트 한도와 조건·원문 값은 유지합니다.
- 평가기는 기업 확인→공시 선택→본문→추출 후보→최종 전달을 분리합니다. 전송 장애가 연속되면 추가 요청을 멈추되 미실행 기업도 전체 분모에서 빼지 않습니다.

## 사전 고정한 표본과 실제 결과

`filing_generalization_round3_20260920.json`에 한국·미국 각각 개발군 6개와 별도 검증군 4개를 원문 파서 출력을 보기 전에 고정했습니다. 기업 이름에 따른 코드 분기는 추가하지 않았습니다.

### 미국: 개발군 4/6, 별도 검증군 3/4에서 수치 추출

개발군은 MSFT, JPM, XOM, PLD, REGN, COST입니다. 6개 사본 원문의 총 크기는 33,950,113바이트였고, 최종 재실행에서 6개 해시가 모두 기준 실행과 같았습니다. 같은 원문에서 기존/신규 파서를 비교했습니다.

- MSFT 76개, JPM 21개, REGN 40개, COST 44개로 합계 181개 fact를 추출했습니다.
- XOM·PLD는 공급자 경로 CIK와 본문 발행사가 맞지 않아 0개입니다. 이를 성공으로 만들기 위해 발행사 검증을 완화하지 않았습니다.
- 기존 파서가 출력한 5개 사례는 모두 백만 USD·FY 표기를 가정했습니다. 실제 이 표본에서 누락 0 채우기가 관측됐다는 증거는 없으며, 해당 오류는 별도 합성 회귀로 차단했습니다.
- 공급자 목록에는 MSFT 2026-04-29, JPM 2025-02-14처럼 오래된 공시가 첫 후보로 남아 있었습니다. 첫 후보를 오늘의 최신 공시라고 부르지 않습니다.

별도 검증군은 TSM, BABA, NVO, DE이며 파서를 고정한 뒤 처음 한 번만 실행했습니다. 결과를 보고 파서를 수정하지 않았습니다.

- TSM: 20-F에서 6개 fact, TWD를 보존했습니다.
- BABA: 20-F에서 85개 fact, CNY와 USD를 분리했습니다.

- NVO: 해당 공급자 문서에서 지원되는 매출 fact가 없어 0개입니다. 공시나 매출이 없다는 뜻이 아닙니다.

별도 검증군 합계는 387개 fact입니다. 개발군·검증군 모두 실행 전후 파서 해시가 동일했습니다. **지원된 7개도 모두 PARTIAL이며, 수치 추출을 기업 분석·중요 근거 회수·최종 모델 보고서의 합격으로 확대하지 않습니다.**

### 한국: 처음 발견한 실패를 보존했고 최종 독립 검증은 통신 장애로 막혔습니다

개발군은 셀트리온·삼성물산·POSCO홀딩스·카카오·LG에너지솔루션·HMM입니다. 첫 실행은 161회/28,581,979바이트였고 기업 확인과 기본 공시 선택은 6/6, 선택 본문 완전 확보는 4/6이었습니다. 모두 PARTIAL입니다.

- LG에너지솔루션: 주석은 수집됐지만 범위 처리에서 후보가 모두 제외됐습니다. 이후 원문 재조회가 막혀 이유를 추측해 파서를 고치지 않았습니다.
- 카카오: 연간 주석이 예산 소진으로 빠졌습니다. 선택된 연간 주석 우선순위는 일반 규칙과 실패 회귀로 수정했지만, 수정 후 실측 복구는 아직 증명하지 못했습니다.
- HMM: 기본·연간 주석 전송 오류가 있었습니다. 실제 복구됐다고 표시하지 않습니다.
- POSCO홀딩스: 일부 표 크기 제한이 남았습니다.

최종 개발군 재실행과 고려아연·두산에너빌리티·삼성생명·코스맥스의 첫 검증군 실행은 DART 전송 장애로 막혔습니다. 각 실행에서 요청 2회가 실패한 뒤 나머지를 미실행 처리했습니다. 총 HTTP 4회/0바이트, 성공 단계 0건입니다. 코드 해시는 동일했지만 본문이 없어 원문 A/B는 비교 불가입니다. **한국의 범용성 통과를 주장할 수 없습니다.**

## 검증과 변경 파일

- 연구·보고서 CI 목록 회귀: 평가기 실행 경계 수정 후 최종 1,433개 통과했습니다. 앞선 1,427개와 중간 1,431개 실행도 보존합니다.
- 별도 US 경계·보고서 소비·BUY gate·주문 수량 묶음: 64개 통과. 일부는 위 묶음과 중복이므로 합산 성공 수로 표시하지 않습니다.
- 실제 KR 소비자·US 오전/오후 batch→JSON의 공급자 shape 회귀 46개, KR/US 수급·KIS 원천 회귀 77개도 별도 통과했습니다. 가격 공급자나 주문 경로를 바꾸지 않았음을 확인하는 회귀이며 공시의 내용 품질을 대신하지 않습니다.
- 신규 모듈·공유 수정부·새 테스트 Ruff, compileall, diff 검사 통과. 기존 US data_prefetch 전체 Ruff는 기준선 52건에서 36건이며, 코드·메시지·원문 행 기준 새 진단은 없었습니다. 파일 전체 lint가 0이라고 주장하지 않습니다.
- 기존 KR BUY 해시 snapshot 2개 실패는 재현했고 기대 hash를 바꾸지 않았습니다. Python 전용 타입 검사 및 전체 취약점 감사 완료도 주장하지 않습니다.
- 독립 리뷰에서 수치·식별자·namespace·중복·기간·원문 위치 관련 반례를 먼저 재현하고 수정한 뒤 이번 구현 단계의 승인을 받았습니다.

주요 파일: `sec_inline_evidence.py`, `sec_public_filings.py`, `sec_report_evidence.py`, 기존 US `data_prefetch.py`, DART 수집·보고서 어댑터, 공통 report prefetch, 평가기 2개, 사전 고정 manifest와 관련 테스트·CI입니다. 기존 정규식 기반 수치 추정과 출력용 가정은 삭제하고 공통 보수적 파서로 통합했습니다.

### 평가기 실행 경계 수정

첫 커밋 e438413b의 원격 정적 분석은 평가기의 동적 기준선 코드 실행과 명령줄 프로세스 호출을 지적했습니다. 검사를 끄거나 예외 처리하지 않고 해당 경로를 제거했습니다. 이제 평가기는 고정된 Python 함수만 격리 프로세스에서 실행하며, 결과는 크기가 제한된 JSON 바이트로 전달합니다. 메시지 헤더만 도착하고 본문이 멈추는 경우까지 전체 제한 시간으로 감시하고 프로세스와 읽기 스레드를 정리합니다.

후속 비교는 저장된 기준선의 코드 버전·같은 원문 해시·결과 파일 해시를 확인한 경우에만 지표를 참조하며, 예전 코드를 새로 실행한 것처럼 표시하지 않습니다. 위 실제 동일 원문 A/B 결과는 수정 이전 실행 당시의 해시와 함께 보존합니다. 운영 파서와 검증군 결과는 바꾸지 않았습니다.

## 남은 조건과 배포 판단

아직 전체 범용 사용 승인 상태가 아닙니다. 공식 SEC 접근 403, DART 전송 장애, 기존 모델 OAuth 재로그인 문제를 코드 성공으로 숨기지 않습니다. 특히 다음이 필요합니다.

1. 정상 공개 원문 접근이 가능해진 뒤 한국의 실패 원문을 로컬 검증용으로 안전하게 고정하고 파서 범위·대형 섹션·표 제한을 다시 검증합니다. 해시만 남겨서는 원문을 재현할 수 없으므로 후속 원문 검증에서는 별도의 제한된 보존 절차가 필요합니다.
2. SEC 공식 목록·본문 최신성 경로를 실제로 검증합니다. 공급자 목록이 오래됐거나 발행사가 다르면 다른 회사 자료를 대신 쓰지 않습니다.
3. NVO 같은 미지원 원문 형식, 외국 발행사 공시의 문서 구성과 확장 taxonomy를 일반 규칙으로 평가합니다. 이번 검증군 결과를 향후 튜닝에 쓰면 그 군은 회귀군으로 전환해야 합니다.
4. 실제 모델의 서술·출처·중요 조건·반대 근거·PDF 품질, 최신 공시의 SELL 전달을 검증합니다. 수치 몇 개를 읽었다는 사실만으로 분석을 완료했다고 하지 않습니다.
