## 1. 목적과 기준 문서

목표는 **실행과 측정을 신뢰할 수 있고, 비용 차감 후 개선을 입증하며,
지속적으로 유지보수할 수 있는 BTC 매매 시스템**입니다. 수익 보장은 목표/완료 기준이 아닙니다.

이 문서가 방향·우선순위·진행 상태의 유일한 기준 문서입니다.
agentmemory와 과거 채팅은 이 문서로 찾아오는 안내일 뿐, 현재 완료 상태의 근거가 아닙니다.
운영 코드·실제 체결 증거가 문서와 다르면 문서를 최신 근거에 맞춰 정정합니다.

확인된 기반:

  테스트 통과는 실환경 예외·수익성 전체의 증명이 아닙니다.

  주문→체결→보호→정산의 완전한 연결이 확보된 것은 아닙니다.
- 기존 트레일 후보들의 우열은 불완전 기준선의 영향 때문에 확정하지 않았습니다.

아래 마일스톤은 이 기반과 별개로 **미완료 항목을 기준으로 관리**합니다.
계획 날짜가 지났거나 PR이 머지됐다는 이유만으로 완료 처리하지 않습니다.

## 3. 진행 순서

**M0 실행 안전 → M1 공통 자본·원장 → M2 신뢰할 수 있는 재생 →
M4 전략 실험 → M5 전진 검증 → M6 제한적 운영 승격** 순서입니다.
**M3 관측·운영성**은 M0부터 병행하며 M5 이전에 필수 조건을 충족해야 합니다.

### M0. 보호·체결 안전성 — 진행 중, 최우선

다음 작업:
- [ ] M0.1 최초/부분 진입 체결 직후 실제 체결 수량에 보호가 붙도록 보완합니다.
- [ ] M0.2 스탑 가격이 같으면 주문을 건드리지 않고, 변경 시 취소 선행 공백을 없앱니다.
- [ ] M0.3 부분청산·응답 유실·정체성 누락·오래된 주문의 재조정 절차를 완성합니다.
- [ ] M0.4 시장 수집·선택적 연구·LLM 장애와 무관하게 보호/조회가 작동하도록 분리합니다.
- [ ] M0.5 중복 tick·프로세스 재시작·동시 주문에 대한 잠금/멱등성을 검증합니다.

완료 근거:
- reject, ACK-only, partial fill, timeout-after-accept, stale data, restart,
  취소·변경 실패의 fault injection과 회귀 테스트를 첨부합니다.
- 미확정 체결을 실적으로 기록하지 않고, 감축 요청이 반복 노출을 만들지 않습니다.
- 보호 불가 상태를 숨기지 않으며 경보·진입 제한·운영자 복구 절차가 명시돼야 합니다.
- 수정 전 재현/수정 후 통과, 배포 커밋, 실제 관측 결과를 각각 기록합니다.

## 5. 매번 확인하는 개발 규칙

BTC 코드·백테스트·관측·배포 작업 시작 시:
1. 이 문서를 읽고 대상 ID(M0.1 등), 선행 조건, 현재 증거를 적습니다.
2. 작업 범위와 성공 테스트를 정합니다. 관련 없는 미래 단계 규칙을 함께 추가하지 않습니다.

작업 종료 시:
1. PR/커밋, 재현·테스트, 배포 여부, 실제 관측, 남은 위험을 구분합니다.
2. 새로운 검증 근거가 생긴 항목만 이 문서의 상태와 변경 기록을 갱신합니다.
3. 코드만 작성되거나 테스트만 통과한 항목을 운영 완료/수익성 입증으로 표시하지 않습니다.
4. 다음 작업은 이 문서에서 다시 선택합니다. 일탈하면 이유와 복귀 조건을 기록합니다.
