# BTC 진입 메뉴의 기존 근거 보존 (M4 입력 품질)

1. 유형/기준선: fe6012de의 기존 진입 후보 입력을 보존하는 수정이다. PR1403 후보는 기존 예시를 계획당 하나로 줄였고 실제 개발 수익 입력에서 OPEN→WAIT가 관측되어 미배포 보류했다. 예시 축소가 판단 변화의 원인이라고 단정하지 않는다.
2. 가설/반증: 기존 6개 선택지·순서·가격·전체 비용 예시·지시문을 보존하고, 12KB 안에서만 내부에 이미 계산된 추가 손절 대안을 붙인다. 기존 자료가 줄거나 입력 한도 초과로 전체 메뉴가 사라지거나, 알려진 수익 진입 반례를 잃으면 채택하지 않는다. 확정 손절이 더 낫다는 규칙은 도입하지 않는다.
3. 호환성: snapshot/context→prepare→동적 schema→DRAFT→계산→SELECT→실행의 prepare 계층만 변경한다. 기존 prefix는 완전히 같아야 한다. 추가 후보는 최대12개/12KB이며 출력 후보2·선택1·위험·수량·비용·보호·수렴·회복·분석시간축은 그대로다. 여유가 없으면 기존 메뉴를 반환하며 기존 과대 입력의 fail-closed는 유지한다. 새 후보 가격은 만들지 않는다.
4. 비교: 동일 고정 개발 입력 3개에서 전 항목 보존과 모의 전체 경로·별도 프로세스 재생을 먼저 확인한다. 실제 모델은 동일 7구간 안의 손실06:45/기존수익23:30 두 입력만 최대4HTTP, 기존44+최대4=48로 등록한다. 과거 원응답은 동일 기준 요청의 증거이며 후보 재사용 응답을 실제 새 판단으로 세지 않는다. 합성 계좌·개발 반례이며 holdout/전체 수익성 검증은 아니다.
5. 진단/중단: 예시를 삭제하지 않는지, 예산 때문에 전체 메뉴가 UNAVAILABLE이 되지 않는지, 원 지시문·시장·계좌가 같은지 검사한다. 초안과 선택의 실제 운영 시간 여유/활성 모델 장애를 호출 전 확인한다. 실패하면 봉인하고 재시도하지 않는다. 기존 수익 입력이 다시 WAIT이거나 손실 입력에 실행 가능한 대안이 없으면 채택 보류한다. 같은 관망 표본을 더 호출하지 않는다.
6. 현재 결정: 사전 등록 후보. 이전 손절 대안 후보와 일반 진입 문구 완화는 미배포 유지한다. 비용 후 승률 개선·M5·SHADOW/LIVE 승격을 주장하지 않는다. 배포는 기능 비교와 전체 CI 성공을 확인한 뒤 별도 판정한다.

로컬 검증: 기존 코드에서 대안 노출 회귀 검사 1건이 실패했고 수정 후 관련 170건이 통과했다. 개발 입력 3개는 기존 6개 계획 전체 prefix와 모든 비용 예시·지시문·시장/계좌가 일치한다. 모델 메뉴는 각각 8/7/7개, 11175/11224/11225바이트로 12KB 안이며 두 손실 입력의 기존 CURRENT 형성/확정 손절 대안이 함께 노출된다. 원 정상 OPEN은 모의 응답으로 전체 검토 경로를 통과했다. 실제 모델 검토와 전체 CI는 별도 확인한다.
