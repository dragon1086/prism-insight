# BTC 매매 메시지의 포지션·계좌 정보 계약

## 문제와 범위

복구 진입 공지에서 체결 수량·가격·손절만 보여 주고, 기존 상세 알림의 마진 방식,
거래소 레버리지, 증거금과 계좌 대비 비중을 빠뜨렸다. 또한 일부 기존 fallback은
전략 노출배수를 거래소 레버리지로 쓰거나, 논리적 전략 자본을 실제 거래소 계좌
평가액으로 표현할 수 있었다. 이번 변경은 BTC 메시지의 정보·출처 정합성 교정이다.
매매 규칙·마진 방식·레버리지 설정·위험 예산 자체는 변경하지 않는다.
로드맵 범위는 M3 관측·운영성 후속이며, M0 보호·체결 선행 조건을 유지한다.

## 모든 BTC 매매 이벤트에서 확인할 항목

- 메인/스윙, demo/live, 종목·방향, 신규/추가/감축/청산/복구 구분, 실제 체결시각.
- 계좌의 교차/격리/포트폴리오 마진, 단방향/헤지 모드, 거래소 설정 레버리지.
- 이번 체결과 현재 총수량, 체결가/현재 평가가격의 구분, 명목 포지션 금액.
- 거래소가 제공한 해당 포지션 초기증거금과 **같은 거래소 계좌** 평가액 대비 비중.
- 해당 계좌 평가액·지갑잔고·가용액·전체 초기/유지증거금과 자료 기준시각.
- 손절 가격·보호 확인·손절 위험과 비중, 익절/추세 청산 계획, 제공되는 경우 청산가.
- 청산/감축은 확인된 실현손익·비용·청산 비율·남은 노출과 이전/현재 snapshot을 구분한다.

## 숫자 해석 원칙

1. 스윙 `pos.leverage`의 전략 노출배수와 거래소 설정 leverage를 구분한다.
   메인 원장 필드는 기록 경로에 따라 의미가 다르므로 일괄적으로 전략 배수라고 부르지 않는다.
2. Bybit 계좌 `marginMode`가 마진 방식의 출처다. 폐기된 position `tradeMode`로 추측하지 않는다.
3. `positionIM`은 거래소의 초기증거금 값이며 mark 기준으로 변할 수 있다. 특히 교차마진에서는
   고정적으로 떼어 둔 원금이나 최대 손실이 아니다. 명목금액/레버리지를 실제 납입 증거금으로
   위장하지 않는다. 제공되지 않으면 확인 불가로 남긴다.
4. 논리적 전략 자본과 스윙/메인 실제 거래소 계좌를 섞지 않는다. 금액과 비중에 분모·통화·
   자료시각을 붙인다. 서로 다른 계좌 잔고를 근거 없이 합산하지 않는다.
5. 지연 공지에서 지금 조회한 값은 현재 snapshot으로 명시한다. 현재 마진·평가액을
   과거 진입 시점의 값으로 소급해서 부르지 않는다. 청산 후 flat 자료를 진입 증거금으로 쓰지 않는다.
6. 실제 읽기 전용 조회를 제한적으로 재사용하고 렌더러에서는 네트워크 호출하지 않는다.
   부가 계좌 정보 조회 실패 때문에 매매/보호/원장 처리를 중단하지 않는다.
   선택적 알림 보강 GET은 공유 주문 잠금을 잡은 채 실행하지 않는다.
7. 과거 청산의 거래소 상세를 현재 같은 방향의 다른 포지션으로 채우지 않는다.
   체결과 연결된 상세 자료가 없으면 확인 불가로 남기고 현재 계좌 자료만 별도로 표시한다.
   손상된 선택적 snapshot 필드 때문에 체결 메시지 자체를 누락시키지 않는다.

## 검증·운영 적용

기존 상세 본문을 유지하면서 공통 포지션 블록을 적용한다. 정상/복구, 메인/스윙,
진입/추가/감축/청산과 결측·타계좌·오래된 자료·포트폴리오 마진을 회귀 검증한다.
검증·배포 후 누락됐던 기존 본 채널 공지는 같은 메시지를 수정하며, 새 매매처럼
중복 공지하거나 주문·마진·레버리지 설정을 변경하지 않는다.
