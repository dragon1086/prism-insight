# BTC 매매 메시지의 포지션·계좌 정보 계약

## 문제와 범위

복구 진입 공지에서 체결 수량·가격·손절만 보여 주고, 기존 상세 알림의 마진 방식,
거래소 레버리지, 증거금과 계좌 대비 비중을 빠뜨렸다. 또한 일부 기존 fallback은
전략 노출배수를 거래소 레버리지로 쓰거나, 논리적 전략 자본을 실제 거래소 계좌
평가액으로 표현할 수 있었다. 이번 변경은 BTC 메시지의 정보·출처 정합성 교정이다.
매매 규칙·마진 방식·레버리지 설정·위험 예산 자체는 변경하지 않는다.
로드맵 범위는 M3 관측·운영성 후속이며, M0 보호·체결 선행 조건을 유지한다.

## 공개 메시지와 내부 진단을 구분한다

2026-10-06 M3 체결 알림 보완: 전체 포지션 관측이 아직 검증되지 않아 간소 알림을
보내더라도 TP를 조용히 누락하지 않는다. 체결 자식 주문의 intent ID·시나리오·방향·
진입 ID가 일치하는 원래 요청의 TP만 `진입 당시 TP 계획`으로 표시한다. 이는 현재
거래소 주문 확인이 아니며 최신 다른 수정 계획을 과거 체결에 붙이지 않는다.
원래 계획의 빈 목록은 `고정 TP 없는 계획`, 결측·손상은 `자료 미확인`으로 구분한다.
나중에 전체 검증 관측이 있으면 그 관측의 현재 TP를 우선하되 기존 체결 이벤트를
다시 발송하거나 고쳐 저장하지 않는다. 체결 하나로 전체 보유·손익·계좌를 역산하지 않는다.
원래 시작 순자산을 함께 전달해 기존 0.5% 또는 2% 위험 목표의 분모를 명시한다.
주문·보호·정산·위험 한도와 스케줄은 변경하지 않는다.

2026-10-04 사용자 승인: 공개 알림은 제목/한국 시각, 이번 체결, 누적 보유,
계좌 순자산·증거금, TP/SL 금액·계좌 비율의 짧은 이모티콘 블록을 사용한다.
부분 청산 가격손익은 비용 전이며 순손익 미확정 경고를 유지한다. 이전→현재 수량은
관측 범위와 개별 체결 범위를 혼동하지 않는다. 금액과 분모는 다음을 따른다.

- 이번 체결 금액은 `실제 체결 수량 × 체결가`인 명목금액이다. 추가 납입 증거금으로 부르지 않는다.
- 총 증거금과 현재 순자산은 같은 계좌·같은 관측의 거래소 자료만 쓴다.
- TP/SL은 해당 수량의 가격손익과 현재 순자산 대비 비율을 우선하고, 가격 1배와 레버리지 환산을 구분한다.
- 부분 청산의 이번 가격손익은 exact execution ID로 검증된 거래소 cashFlow만 쓰고 **비용 전**이라고 표시한다.
- 누적 실현손익에 잔여 TP/SL 가격손익을 더한 예상 결과는 **향후 수수료·펀딩 전**이며 이익 보장이 아니다.
- 근거 없는 금액은 0이나 확정손익으로 만들지 않는다.

사용자 추가 요청: 필요한 숫자는 유지하되 원시 계좌 스냅샷을 공개 채널에 그대로 붙이지 않는다.

- **진입/추가 진입:** 데모/실거래 구분, 방향·가격·수량·시각, 확인된 마진 방식과 레버리지,
  운용 기준자금·증거금·사용 비중, 손절 위험·목표/청산 계획을 짧게 표시한다.
- **청산/감축:** 청산 사유, 확인된 순손익과 비용, 진입→청산 가격, 정리 수량·보유 시간·한국 시각을
  우선 표시한다. 끝난 포지션에 현재의 큰 데모 계좌 잔고나 빈 포지션 상세를 붙이지 않는다.
  사용자 요청에 따라 전량 종료는 **그 종료에 연결된** 검증된 청산 후 순자산과 조회 시각만
  짧게 추가한다. 마지막 청산 체결 후 120초 이내·같은 계좌·잔량 0으로 확인된 거래소 관측값만 쓰고,
  시작 자산+확정 손익으로 종료 자산을 추정하지 않는다. 자료가 없으면 미확인으로 둔다. 현재 새 포지션의 자산을 소급하지 않는다.
- `손실 -0.9배`처럼 레버리지·수익률과 혼동되는 위험 단위는 공개 제목에서 제거한다.
- 확인되지 않은 정산은 반드시 짧은 경고로 구분한다. 선택적 자료 누락을 여러 줄의
  `확인 불가`로 반복하지 않는다. 핵심 결측은 한 문장으로 묶는다.
- 거래소 확정 청산 행의 leverage가 있으면 해당 거래 표시로 전달한다. 선택적 leverage가
  잘못됐다는 이유로 유효한 손익 정산을 버리지 않는다. 과거 포지션에 현재 값을 대신 쓰지 않는다.
- 전체 원본 스냅샷·정산 근거·위험 단위·누락 사유는 내부 진단으로 보존한다.
  압축은 공개 표현 변경이지 데이터 삭제나 원장 변경이 아니다.

## 전체 데이터 계약에서 확인할 항목 (모든 항목의 공개 출력은 아님)

- 메인/스윙, demo/live, 종목·방향, 신규/추가/감축/청산/복구 구분, 실제 체결시각.
- 계좌의 교차/격리/포트폴리오 마진, 단방향/헤지 모드, 거래소 설정 레버리지.
- 이번 체결과 현재 총수량, 체결가/현재 평가가격의 구분, 명목 포지션 금액.
- 거래소가 제공한 해당 포지션 초기증거금과 **같은 거래소 계좌** 평가액 대비 비중.
- 해당 계좌 평가액·지갑잔고·가용액·전체 초기/유지증거금과 자료 기준시각.
- 손절 가격·보호 확인·손절 위험과 비중, 익절/추세 청산 계획, 제공되는 경우 청산가.
- 청산/감축은 확인된 실현손익·비용·청산 비율·남은 노출과 이전/현재 snapshot을 구분한다.

## 숫자 해석 원칙

사용자 요청에 따라 **운용자금 대비 증거금 사용 비중**을 먼저 표시한다.
스윙의 분모는 해당 진입에 사용한 `swing_entry_logical_capital`이며 메인은 해당 계좌 평가액이다.
데모 스윙 지갑의 여러 자산을 합친 큰 평가액 대비 비율은 참고 항목으로 분리한다.
예: 운용 기준 9,600 USD, 증거금 약 1,388 USDT라면 조회 환율 환산 후 약 14.5%다.
운용 기준자금·공식 증거금·환율이 없거나 과거 청산 포지션 자료가 연결되지 않으면
비중을 확인 불가로 표시한다. 9,600을 상수로 고정하거나 계좌 간 송금으로 설명하지 않는다.

1. 스윙 `pos.leverage`의 전략 노출배수와 거래소 설정 leverage를 구분한다.
   메인 원장 필드는 기록 경로에 따라 의미가 다르므로 일괄적으로 전략 배수라고 부르지 않는다.
2. Bybit 계좌 `marginMode`가 마진 방식의 출처다. 폐기된 position `tradeMode`로 추측하지 않는다.
3. `positionIM`은 거래소의 초기증거금 값이며 mark 기준으로 변할 수 있다. 특히 교차마진에서는
   고정적으로 떼어 둔 원금이나 최대 손실이 아니다. 명목금액/레버리지를 실제 납입 증거금으로
   위장하지 않는다. 제공되지 않으면 확인 불가로 남긴다.
4. 논리적 전략 자본과 스윙/메인 실제 거래소 계좌를 섞지 않는다. 금액과 비중에 분모·통화·
   자료시각을 붙인다. 서로 다른 계좌 잔고를 근거 없이 합산하지 않는다.
5. 지연 공지에서 지금 조회한 값은 현재 snapshot으로 명시한다. 현재 마진·평가액을
   과거 진입 시점의 값으로 소급해서 부르지 않는다. 청산 후 flat 자료를 진입 증거금으로 쓰지 않는다.
6. 실제 읽기 전용 조회를 제한적으로 재사용하고 렌더러에서는 네트워크 호출하지 않는다.
   부가 계좌 정보 조회 실패 때문에 매매/보호/원장 처리를 중단하지 않는다.
   선택적 알림 보강 GET은 공유 주문 잠금을 잡은 채 실행하지 않는다.
7. 과거 청산의 거래소 상세를 현재 같은 방향의 다른 포지션으로 채우지 않는다.
   체결과 연결된 상세 자료가 없으면 확인 불가로 남기고 현재 계좌 자료만 별도로 표시한다.
   손상된 선택적 snapshot 필드 때문에 체결 메시지 자체를 누락시키지 않는다.

## 검증·운영 적용

기존 상세 본문을 유지하면서 공통 포지션 블록을 적용한다. 정상/복구, 메인/스윙,
진입/추가/감축/청산과 결측·타계좌·오래된 자료·포트폴리오 마진을 회귀 검증한다.
검증·배포 후 누락됐던 기존 본 채널 공지는 같은 메시지를 수정하며, 새 매매처럼
중복 공지하거나 주문·마진·레버리지 설정을 변경하지 않는다.
