# BTC 재평가 적용 경계 기록 보완

사전 기준: M3 기록 정합성. PR #993 독립 검증기는 실제 적용 직전/직후가 없으면
INSUFFICIENT로 남긴다. 이를 미래 관측만 기다려 해결할 수 없으므로 기존 감사 경로에
bounded 전이 기록을 추가한다. 수익성 연구와 별도인 실행 근거 보완이다.

## 변경하지 않는 것

모델 입력·프롬프트·판단·조건 슬롯3개·주문·보호·위험 한도·회복 절차를 바꾸지 않는다.
새 DB 테이블·상주 배치·모델 호출·외부 의존성을 추가하지 않는다.

## 기록 계약

- 경제 검증 후 정확한 원본 제안/input/action/scenario와 적용 시각을 연결한다.
- 모델에 제시된 조건과 최신 적용 직전 조건을 분리해 before/presented/after와 receipt를 보존한다.
- 수량/길이/크기 경계를 넘거나 감사 자체가 실패하면 감사 공백으로 남기고 보호 EXIT를 막지 않는다.
- 메모리상 관측과 커밋 증거를 분리한다. 별도 flush에서 정확한 저장 제안/입력/결과 영수증을
  확인하고, intent가 필요한 경로는 정확한 커밋 intent까지 대조한다.
- outcome 누락·rollback·다른 action·다른 영수증은 성공 전이가 아니다. 거래소 주문 성공으로
  해석하지 않는다. 이후 상태나 현재 계좌를 당시 적용 경계로 대신 쓰지 않는다.

## 통과 조건

독립 오프라인 verifier와 원래 runtime의 격리 통합으로 용량 부족·중복·교체·새 hit 거절·
불량 메타·WAIT/ADJUST/EXIT·감사 예외·state/outcome rollback을 검사한다. 원래 주문/보호
결과가 감사 유무에 따라 달라지면 실패다. 정확한 head의 전체 테스트·CI·운영 Python 스모크와
첫 자연 실행을 구분한다. 실제 비어 있지 않은 조건 등록은 관측 전까지 미관측이다.

## 수익 개선과의 구분

이 보완 자체는 수익 개선이 아니다. 기존 정책과 개선 정책의 경제 비교는 별도 사전등록으로
구간·비용·모델 호출 수·초기 계좌·중단 기준을 고정한다. 각 정책의 자체 계좌 상태에서 판단하고
타 정책의 응답을 재사용하지 않는다. 미래 독립 표본이 쌓이기 전 수익 개선 입증으로 승격하지 않는다.

## 구현 검증

관련188개, 독립 capture/provenance/review_memory66개와 replay identity/audit3개를 통과했다.
사전/사후 레코드는 최대16KiB, 기존3개 슬롯/메타 경계를 유지한다. 감사 기록은 기존 테이블만
사용하고 공개 알림·외부 관측 전송의 허용 목록은 늘리지 않았다. 운영 배포와 실제 조건 관측은
별도 영수증으로 확인한다. 커밋 확인은 현재 전체 state나 거래소 체결 성공을 뜻하지 않는다.
