# 최초 수량에 가능한 호스트 가격 보정 위험 반영

## M0 계산 순서 수리

보존된 5975310 LONG 후보는 원가격 83,890에서 0.025 BTC를 배분했다. 원가격 위험 17.6205는 배분 한도 17.7334015276899 안이지만, 호스트 가격 보정 83,897.3 적용 후 위험 17.803365가 되어 마지막 검증에서 올바르게 기각됐다.

원가격과 기존 가격정책의 정적으로 가능한 보정가격을 각각 최악 허용 chase의 기준으로 계산하고, 더 큰 단위 위험으로 최초 수량을 한 번 내림 계산한다. 해당 수치 회귀의 수량은 0.024 BTC가 된다. 실제 가격정책을 먼저 실행하거나 가격 보정 뒤 다시 수량을 줄이지 않는다.

## 불변 조건과 한계

- 기존 7.3 USDT/tick 정렬 산식을 공유한다. 실제 가격정책의 quote·edge·최소금액·경제 검증은 그대로 둔다.
- 가능한 보정가격은 실행가격이 아니다. 현재 quote가 없거나 오래됐거나 가격정책이 보정을 생략하더라도, 이후 신선한 검증에서 보정될 가능성까지 보수적으로 예약한다.
- receipt의 model_price·possible_policy_price·risk_anchor_price·worst_chase_price를 구분한다. price_policy_anchor_is_execution_price는 false다.
- 조건부 명시 가격, 비마디 가격, 가격정책 부재 또는 정적 보정 불가능 시 기존 수량 경로를 유지한다.
- 모델 원가격·SL·confidence·분수와 초기자본·위험 한도를 바꾸지 않는다. 보유/예약/소비 위험과 각 진입별 최종 한도 검증을 유지한다.
- 기존 core는 estimated_cost_rate > 0.1을 거부한다. SHORT의 cost>=1 미분 방향은 순수 산식 반례로만 검사하고 실제 허용 범위를 늘리지 않는다.

일부 조건에서 실제로 필요했던 수량보다 조금 작아질 수 있다. 이는 위험 상한의 보수성이지 수익 개선 증거가 아니다. 실제 모델 재검증·전체 테스트·CI·배포·자연 관측은 별도이며 기존 모델 HOLD 결과를 바꾸지 않는다.
