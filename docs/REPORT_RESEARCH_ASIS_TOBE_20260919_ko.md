## 2. 이전 경로와 개발 경로를 구분한 확인 결과

### Perplexity와 당일 급등 설명

`git show 69505dc0^:cores/agents/news_strategy_agents.py`에서 확인한 이전 프롬프트는
네이버 뉴스 목록을 읽고, Perplexity에 같은 업종 주도주와 업종 동향을 나누어 질문했다.
기사별 원문 조회는 금지했고, 날짜 확인은 프롬프트 지시였다. 따라서 이전 경로를
원문 검증까지 보장한 정상 기준선으로 부를 수는 없다. 이전 실제 응답과의 동일 입력 비교는 미완료다.

운영 기준 `f586cc9`에는 이미 `_competitive_evidence_contract`가 있었다.
`git diff f586cc9..796d4336 -- cores/agents/news_strategy_agents.py`는 비어 있다.
즉 이 파일의 경쟁근거 지시를 이번 개발 브랜치가 처음 도입했다고 설명하면 틀린다.

현재 계약은 최대 두 통합 질의 중 첫 질의에 사업·경쟁사·주가 주도주·추세·지표를 요구한다.
당일 변동 원인 최우선 지시도 남아 있지만, 경쟁 비교 질문을 반드시 완료하라는 지시와
같은 도구 예산을 사용한다. 질문의 비대화 가능성은 코드에서 확인되지만, 품질 저하의
각 원인별 기여도는 아직 분리 측정하지 않았다.

개발의 `cores/llm/tool_result_budget.py`는 SDK 반환 경계에서 큰 응답을 거절한다.
`refuse()`는 반환됐으나 크기로 미전달된 상태를 공급자 실패와 구분한다.
그러나 안내문 자체가 축소 재수집을 실행하는 것은 아니다.
인수인계의 RF 실행은 23,096B 응답이 6,000B guard에서 미전달된 사례다.
이는 이전 실행 기록이며 이번에 재실행한 값이 아니다.

**목표:** 시세는 기존 신뢰 가능한 입력을 재사용하고, 당일 사건 발견과 장기 경쟁 비교를
서로 구분한다. 긴 검색 응답은 모델 밖에서 발견 URL·기사별 근거를 선정하고 원문을 제한적으로
읽는다. 크기 제한을 늘리거나 검색 답변 전체를 검증된 사실로 주입하지 않는다.
수집 성공·모델 전달·원문 확인·원인 설명을 별도로 기록한다.

### 최신 공시와 기준시점

`prism_core/report_insight_prefetch.py`의 `collect` 경로는 연도 검색과
`search_recency_filter='year'`를 사용한다. 이는 공식 제출 목록에서 최신 보고기간과
정정본을 판정하는 selector가 아니다.

`prism_core/report_research_prefetch.py::_source`는 공개 메타데이터의 날짜를
`reference_date`와 비교한다. 시간대가 있으면 실행 당시 UTC 시각보다 미래인지도 확인하지만,
역사적 분석의 정확한 판단 시각과 비교하지는 않는다. 같은 날 장후 기사 배제와
시장 시간대로 날짜가 달라지는 사례는 이 검사만으로 보장되지 않는다.
메타데이터는 이미 `SOURCE_METADATA_UNVERIFIED`로 표시하므로 확정 제출일로 승격하면 안 된다.

`prefetch_report_research` 캐시 키는 시장·종목·일자·프로필 등을 포함하지만 판단 시각은 없다.
유효 입력은 최대 6시간 재사용한다. 오전·오후 같은 날짜에 새 공시가 추가되는 상황과,
나중에 만든 캐시를 이른 시점 재생에 사용하는 상황을 별도로 시험해야 한다.
이 구조적 위험을 실제 운영 누출이 발생했다는 주장으로 확대하지 않는다.

**목표:** 배치에서 한 번 정한 시간대 포함 `decision_at`을 모든 수집·검증·요약에 전달한다.
재실행은 원래 판단 시각을 보존하며, 수집 시각과 혼동하지 않는다. 날짜만 주어진 과거 입력은
임의로 장 마감 시각을 만들어 정밀 검증에 합격시키지 않는다.
공식 목록의 실제 공개/접수 시각과 보고기간으로 최신 기본 보고서를 고른다.
정정 여부·연결/별도·법인을 확인하고 과거 연차는 상세 보완으로만 쓴다.
접근 실패한 최신 보고서를 과거 보고서로 조용히 대체하지 않는다.

### 본문과 내부 근거 전달

`news_strategy_agents.py::_competitive_evidence_contract`와
`prism_core/report_research_context.py::apply_section_research`의 도구 없는 분기는
공개 본문에 `Competitive Evidence`와 기술 필드를 요구한다.
`prism_core/competitive_evidence.py::attach_competitive_evidence`는 그 제목을 파싱해
뉴스에 CE ID를 삽입하고 기업 개요에 기록을 복사한다.
`cores/analysis.py`는 해당 handoff 이후 요약/최종 합성을 진행한다.

**목표:** 감사 기록과 공개 서술을 별도 전달하되 근거 참조는 유지한다.
공개 본문은 사실 → 의미 → 반대근거·중요 한계 → 다음 확인점으로 쓴다.
제목/기술 필드만 삭제하면 현재 handoff 파서가 `RECORD_ABSENT`가 되므로,
프롬프트만 바꾸는 수정은 하지 않는다. KR/US, 요약, PDF 추출, BUY 실제 입력에서 함께 검증한다.
현재 문서는 BUY 전체 경로 검증 완료를 주장하지 않는다.

### TradingView

`prism_core/tradingview_evidence.py`는 스스로 오프라인 payload 분류기이며 사실 검증기가
아님을 명시한다. 이번 검색에서 KR/US 분석 모듈과 `report_research_context.py`의 직접

**목표:** 실제 등록·인증·이용권한·허용 도구와 운영 호출 경로를 따로 확인한다.
기존 KIS 가격/주문 소스를 교체하지 않는다. 이번 재개 감사에서는 실호출하지 않았다.

## 3. 할루시네이션 방지: 유지할 규칙과 추가할 검증

기존 원문 확인·날짜 검증·모르면 모른다고 표시하는 규칙은 삭제하지 않는다.
다만 규칙이 프롬프트에 있다는 것과 실행 경계에서 보장된다는 것은 구분한다.

1. 출처 URL뿐 아니라 해당 주장을 뒷받침하는 원문 위치와 기간·단위·대상을 보존한다.
   검색 요약/인용 링크/HTTP 200/자료 존재만으로 검증 완료라고 하지 않는다.
2. 배치 판단 시각 이전에 이용 가능했던 자료만 당일 판단 근거로 사용한다.
   보고기간 종료일·공개일·정정일·수집일·주가 관측시각을 분리한다.
3. 수집 실패, 예산 때문에 미전달, 조사 범위 내 미발견, 실제 부재를 구분한다.
   “확보한 자료만으로 직접적인 상승 원인을 확인하지 못했습니다”는 가능하지만,
   실패한 검색을 근거로 “당일 뉴스가 없습니다”라고 하지 않는다.
4. 사실, 회사의 주장, 전망, 해석을 분리한다. 동시 보도를 인과관계로 바꾸지 않는다.
5. 출처 간 수치가 충돌하면 기간·연결 범위·단위·정정 여부부터 대조한다.
   해소하지 못한 충돌은 남기고, 유리한 수치만 선택하거나 평균내지 않는다.
6. 외부 원문은 신뢰되지 않은 자료다. 문서 안의 명령문으로 시스템 지침을 바꾸지 않는다.
7. 의미 있는 한계는 자연어로 본문과 BUY 입력에 함께 남긴다.
   내부 실패 코드와 반복 UNKNOWN은 공개 설명을 대신하지 않는다.

## 4. 구현 전 고정할 실패 사례와 통과 조건

- 같은 회사의 연차/반기/분기: 실제 공개된 최신 보고기간 선택, 연차 상세 보완.
- 같은 날 배치 이후 공시·장후 기사: 이전 시점 판단 근거에서 제외.
- UTC/KST/뉴욕 날짜 경계와 DST: 같은 절대 시각으로 비교.
- 정정본이 판단 이후 공개: 이전 판단에 소급 적용하지 않음.
- 날짜만 있거나 공개일 미확인: 시각을 만들어내지 않음.
- 다른 법인/지주사/연결·별도: 잘못 결합하지 않음.
- 최신 원문 차단: 과거 자료를 최신으로 표시하지 않음.
- 빈 뉴스 화면·도구 실패·큰 응답: 뉴스 부재로 바뀌지 않음.
- 중복 기사·재보도: 신규 사건 수와 중요도를 부풀리지 않음.
- 캐시 생성시각/판단시각 역전 및 같은 날 새 공시: 미래 자료 혼입·갱신 누락 검사.
- 서술형 변경: 출처·반대근거·조건이 최종 PDF 텍스트와 BUY 입력에서도 유지.

먼저 저장된 RF 실패 입력으로 회귀를 만들고 최신 공시 목록 수집을 별도로 검증한다.
이후 동일 입력으로 기존/수정 경로를 비교한다. 미사용 기업·업종/US는 따로 고정한다.
호출 수·바이트·실제 토큰·지연·청구 비용을 구분하고 미측정 값은 추정 성과로 쓰지 않는다.
