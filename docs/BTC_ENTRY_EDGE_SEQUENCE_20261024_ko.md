# 진입 우위와 수량 결정의 순서 정리

## 범위: M0·M3/M4, M5 수익성 증거 아님

SYSTEM·FLAT·DRAFT·SELECT·allocation의 기존 문구를 대체했다. 작은 탐색 진입을 반복 권유하던 표현을 제거하고, 현재 가격 진행과 목표 접근성/장애 → 비용 불확실성과 구조적 무효화 → 수량의 순서를 맞췄다. 기계적인 후보 적격과 선택할 만한 진입 우위를 구분한다.

5976088의 OPEN 자체를 오류로 고정하지 않는다. 그 사례의 가격·결과를 코드에 넣거나 WAIT를 강제하지 않는다. 작은 수량·허용 예산만으로 진입을 정당화하는 설명을 방지하려는 판단 지침이다. 모델이 지침을 항상 따른다는 보장은 아니다.

## 보존한 경계

- schema·수량 계산·위험 한도·강제 청산·주문 실행은 변경하지 않는다.
- 비용 UNKNOWN은 0이나 확정 손실이 아니며 자동 WAIT도 아니다. 구조적으로 정당화한 후보는 호스트 비용 계산까지 전달한다.
- 강한 진행의 즉시 진입, MA10→MA35 구간, 수렴 중 돌파, 독립적인 새 근거가 있는 반대 방향 진입을 허용한다.
- 확정봉/재시험의 일률적 요구, 손실 한 건의 벌점, 새로운 숫자 게이트를 도입하지 않는다.
- 첫 recovery 관측 WAIT, 15분 제외, 기존 보유의 판단과 신규 진입 심사의 구분은 유지한다.

## 검증과 남은 작업

변경 전 실제 조립 경로의 새 회귀 5개가 실패했고, 호환 경계 1개는 통과했다. 단일 제안·legacy/할당/경제 거부형 DRAFT/SELECT의 실제 생성 요청을 가짜 응답으로 검사한다. 프롬프트 해시 핀도 함께 갱신한다.

실제 모델의 개선 여부는 별도 고정 사례·호출 상한을 사전등록한 뒤 검증해야 한다. 기존 B 설명 오류 v1/v2 보류 결과는 보존한다. 출력 설명 계약 수리·나머지 보유/REDUCE 문구 정리는 별도 변경이며, 이 커밋으로 배포 완료나 수익 개선을 주장하지 않는다.
