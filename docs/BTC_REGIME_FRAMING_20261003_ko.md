# BTC 국면별 프롬프트 프레이밍 비교

## 사전 변경 계약 (M4)
1. 유형: 경제적 판단 프롬프트 변경. 기준선은 운영1364bc40이다. 사용자 요청은
   좋은 국면에서 관망의 기회비용을 검토하고, 불리한 국면에서는 위험 관리를 우선하는 것이다.
2. 가설: 30m/1h 단기 방향성이 유리할 때 WAIT만 기본값으로 삼지 않고 작은 선진입과
   관망을 비교하게 하면, 위험 한도를 늘리지 않고 기회 참여를 개선할 수 있다.
   횡보·급반전·비용 초과에서는 성과가 악화될 수 있으며 해당 반례를 숨기지 않는다.
3. 연결 경로: scenario_snapshot의 관측값→scenario_framing의 결정론적 프레이밍→
   scenario_llm→기존 JSON/위험 검증→ScenarioRuntime/ScenarioDemoBroker다.
   프레이밍은 새 진입 하드 게이트가 아니다. 4h+는 맥락, 5m은 속도 참고다.
   합성 경계는 최근 확정봉을 사용하고, 이후 관측이나 최종봉을 앞당겨 사용하지 않는다.
   롱/숏 방향을 구분하며 보유 방향에 역행하는 국면은 방어적으로 다룬다.
4. 비교: 기존과 같은 2026-10-02 00:00–06:00 UTC 자료에서 기준선 fresh1회,
   후보 fresh1회를 실행한다. 각72개 판단 시점, OHLC 기본 비용, 가상10,000 USDT다.
   후보는 frozen 재생으로 재현성을 확인한다. 실행마다 모델 판단은 독립적이므로
   차이를 프레이밍의 순수 인과효과로 주장하지 않는다. 기존+70.45USDT도 과거 참고값이다.
5. 비용·체결·정산·위험 제약은 변경하지 않는다. 10배/시나리오 계획2%/하루4%/3연패,
   비용 예약·보호 주문·중단 잠금·엄격한 출력 계약은 그대로다. 기회비용은 잠재적
   대안 비용일 뿐 실현 손실이나 위험 예산 추가분이 아니다. 강제 거래 수를 목표로 삼지 않는다.
6. 판정: 사전등록 탐색 비교. 수익성 입증·실자금 전환이 아니다. 이번 재사용6시간에서
   거래·수익이 늘었다는 사실만으로 우월성을 입증하지 않는다. 상승/하락/혼조·보유 역행·
   회계 미확정 반례는 회귀 테스트로 고정한다. 위험/데이터/형식 검증 실패나 재현 불일치는
   배포 차단 사유다. 조건을 결과에 맞춰 재조정하지 않고, 다음 튜닝은 별도 실험으로 남긴다.

## 주식 구현과의 관계
주식 코드에서 기회비용을 고려한 보유/매도 문구와 강세장 신규 진입 하한 완화 기록
(`BULL_DISTRIBUTION_ENTRY_FLOOR_20260930_ko.md`)을 확인했다. 주식과 동일한 국면별
프롬프트 모듈이 존재한다고 단정하지 않는다. BTC의 30m/1h 관측과 롱/숏 수명주기에
맞추어 적용하며 주식 소스는 변경하지 않는다.

## 검증 기록
구현 파일은 `live/scenario_framing.py`, `scenario_llm.py`, `scenario_runtime.py`다.
관측 시각·데이터 출처·선택 이유를 `context.decision_framing`에 저장하고, 모델 호출 전
다시 계산한다. 외부 문자열을 시스템 지시로 붙이지 않고 고정된 세 프롬프트 중 하나를
선택한다. 기존 구조 응답 스키마·위험 검증·주문 실행 코드는 변경하지 않았다.
`analysis/scenario_replay.py`에는 기본 프롬프트와 국면별 프롬프트 조각 해시를 구분해
저장한다. CI에 프레이밍 회귀 테스트를 추가했다. 새로운 의존성이나 상주 프로세스는 없다.
구체적인 테스트 수·호출 원응답·비교 손익·배포 여부는 PR 검증 기록과 전달 보고서에서
각각 보고한다. 유리한 국면에서 실제 진입이 늘었는지는 실행 결과로만 판정한다.

## 최초 비교에서 발견한 공통 실행 결함
기준선과 후보 모두 26회 모델 호출 후 미체결 취소·재배치 ADJUST가 PENDING에 남아
추가 판단을 막았다. 기존 주문은 취소 확정, 새 ADJUST의 자식 주문은0개, 실행 배치는
ABORTED, 계좌는flat이고 미체결0이었다. 원본 결과/응답은 보존하고 이 중단된 비교를
프레이밍의 우열이나 전체6시간의 매매 성과로 해석하지 않는다.
자식 주문 전 영속 기록 불변조건에 근거해, 명시적 중단·정확한 취소 확인·완전한
flat/무주문·미확정 근거 없음이 모두 확인된 경우에만 미집행 ADJUST를 종료시킨다.
실제 체결/알 수 없는 제출/중단된 프로세스의 미확정 작업을 성공으로 바꾸지 않는다.
같은 실행 계층 교정을 기준선과 후보 모두에 적용한 뒤 새 fresh 비교를 사전 등록한다.
이는 프레이밍이나 수량/위험 파라미터 재조정이 아니며 원본 tape 해시는 고치지 않는다.
