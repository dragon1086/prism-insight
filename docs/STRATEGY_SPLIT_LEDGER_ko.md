# 분할진입 전략 원장 v1

## 구현 범위와 경계
독립 회계 엔진, 기존 이벤트의 별도 DB 재생, 계좌 집행 상태 overlay, 정수 주문 계획,
Telegram 메시지 미리보기를 제공합니다. 기존 보유 DB를 교체하거나 실제 분할 주문을
활성화하지 않습니다. 운영 전략 자본 프로필은 사용자가 확정해야 하며 예시 금액을
운영 기본값으로 쓰지 않습니다.

### 세 가지를 분리합니다
- 전략 장부: 기준 자본·현금·누적 투입원금·가상 수량·손익.
- 실계좌 집행: 요청·접수·거절·부분/전체 체결·UNKNOWN과 예약 원금.
- 이벤트 재생 결과: fail-open 관측 자료에서 만든 불완전한 검증용 projection.

실계좌 실패가 전략 장부를 되돌리지 않습니다. 관측 projection은 commit과 이벤트
append 사이 누락 가능성이 있어 완전한 운영 원장이라고 부르지 않습니다.

## 회계 계약
- StrategyBook → Campaign → 불변 Leg/Event 구조입니다.
- Decimal 가상 분수 수량을 사용하며 브로커 정수 수량과 구분합니다.
- 가중평단은 잔여 원가/잔여 가상 수량입니다. 부분청산은 평균원가를 비례 배분합니다.
- 매수 비용은 원가·현금에, 매도 비용은 대금에 반영합니다. 누적 목표 한도는 원금 기준입니다.
- 현금+마지막 관측 가격의 보유 평가액=평가자산, 평가자산−초기자본=실현+평가손익입니다.
- v1은 외부 입출금과 FX 합산을 지원하지 않습니다. KR/KRW와 US/USD 장부를 분리합니다.
- 평가 가격은 마지막 원장 관측값이며 최신 시세라고 주장하지 않습니다.

### 50%와 초분할
새 원장 target_pct는 **고정 단위예산 대비 누적 투입원금 한도**입니다.
10→30→60→100의 추가 투입은 10·20·30·40이고, 50→100은 추가50입니다.
동일 목표를 가격 하락 때문에 다시 제출해도 신규 leg가 생기지 않습니다.
원가 아래 물타기는 거절하며, 일반 레짐100%, 강세 레짐 최대300% 및 총 목표10단위
제한을 따릅니다. 한 종목은10%만 진입해도 종목 슬롯 하나입니다.

기존 micro_split.py의 '현재가격 기준 목표 평가액' projection과 다른 의미이므로
기존 SHADOW를 새 회계로 소급 재해석하지 않습니다. 100% 초과 실제 계좌 집행도
이번에 활성화하지 않습니다.

예: 초기1000, 단위100, 가격100에50% 진입은 가상0.5주입니다. 가격110이면 손익5,
가격수익률10%, 전체 장부 수익률0.5%입니다. 이후50%를110에 추가하면 별도 leg를
기록해 가중평단을 계산합니다.

## 계좌 연결
계좌 주문 계획은 계좌별 단위예산×목표비율에서 확인된 매수 원금과 예약 원금을 차감하고
최종 지정가로 수량을 내립니다. UNKNOWN 예약은 임의 해제하지 않으며 동일 목표를
가격 하락만으로 재주문하지 않습니다. 이 함수는 주문하지 않습니다.

execution_profile_ref/intent_ref로 정확히 연결합니다. 원문 계좌번호를 기록하지 않습니다.
FILLED/PARTIAL에는 수량·가격·증거를 필수로 요구합니다. 접수만으로 체결을 추정하지 않습니다.
과거 프로필 미확인 주문의 알려진 REJECTED 상태는 미해결 overlay로 남기며 원장은 유지합니다.
실제 체결조회 adapter 전체가 연결됐다고 주장하지 않습니다.

## 재생 안전성
- entry.executed+simulator_recorded=True만 원장 진입으로 사용합니다. candidate 선택은 진입이 아닙니다.
- exact position_id만 연결합니다. ticker/날짜로 여러 계좌·기존 추가진입을 추정 병합하지 않습니다.
- 프로필 없는 과거 포지션은 각각 격리된 검증 장부이며 전체 포트폴리오로 합산하지 않습니다.
- 같은 프로필·종목의 기존 추가진입은 캠페인 연결 부재로 보호 조건에서 보류될 수 있습니다.
- 같은 ID/내용은 no-op, 같은 ID/다른 내용은 충돌입니다. 실패·충돌·고아 이벤트를 보고합니다.
- 이벤트·leg·현금 갱신은 한 SQLite transaction입니다. book 전체의 시각 순서를 검사해
  미래 청산금을 과거 다른 종목 진입에 쓰는 것을 차단합니다.
- 원본 파일과 운영 stock_tracking_db.sqlite는 출력 경로로 사용할 수 없습니다.

## 명령과 메시지
```bash
python tools/replay_strategy_ledger.py \
  --input logs/prism_events.jsonl \
  --ledger runtime/strategy-ledger-validation.sqlite \
  --capital-profile /absolute/path/to/explicit-capital.json \
  --message-preview
```

자본 설정 예시(검증 예시이며 운영 기본값 아님):
```json
{"US":{"currency":"USD","initial_capital":"10000","unit_budget":"1000"},
 "KR":{"currency":"KRW","initial_capital":"10000000","unit_budget":"1000000"}}
```

명령은 별도 DB와 JSON만 생성합니다. 메시지 미리보기는 Telegram/Redis/GCP에 전송하지 않습니다.
표시는 전략 목표·가상 수량·평단·미투입예산·장부 손익과 실계좌 증거를 나눕니다.
개별 과거 포지션 검증 장부는 전체 포트폴리오가 아니라는 표시를 포함합니다.

## 운영 승격에 남은 일
사용자 기준자본 확정, 명시적 캠페인/leg 이벤트, transactional outbox, 기존 추가진입
매핑 감사, 실제 체결조회 adapter, 메시지 중복 전달 제어와 전량 종료 경로 검증이 필요합니다.
그 전에는 기존 운영 원장·매매 정책을 교체하거나 초분할 실주문을 켜지 않습니다.
