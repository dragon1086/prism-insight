# BTC 경보의 과거 집계와 현재 상태 구분

2026-09-15 사용자가 전달한 2시간 오류 7건·처리 지연 105분 경보는 10:15 KST에
생성된 것으로 로그에서 확인했다. 당시에는 실제 진입 복구 장애가 진행 중이었고,
10:22 이후 정상 완료 tick이 이어졌다. 10:57 읽기 전용 재점검에서는 price_stale이
없고, 과거 2시간의 오류 누적 7건만 남아 있었다.

## 변경 범위

- 과거 경보를 현재의 새 장애로 오해하지 않도록 점검 생성 시각을 메시지에 표시한다.
- 오류 집계에는 마지막 오류 시각/경과 시간, 그 이후의 완료 tick 관측 여부를 붙인다.
- 오류 개수·2시간 창·경보 임계값·severity는 유지한다. 완료 tick을 보았다는 이유로
  모든 위험이 해결됐다고 판정하거나 과거 오류를 삭제하지 않는다.
- 처리 지연의 기준은 마지막 처리된 30분봉 시각임을 명확히 한다. 마지막 프로세스
  실행 시각과 혼동하지 않으며 기존 임계값은 바꾸지 않는다.
- 실제 매매·시세 수집·보호·주문·스케줄·LLM 호출은 변경하지 않는다.

## 검증

고정 시각에서 복구 이후 완료 tick, 아직 복구 중인 skip heartbeat, 후속 재발 오류,
과거/미래 timestamp, 경보 생성 시각과 기존 임계값을 검사한다. 실제 운영 원장은
읽기 전용으로 재점검하고, 모니터링방에 현재 확인 결과를 전달한다.
