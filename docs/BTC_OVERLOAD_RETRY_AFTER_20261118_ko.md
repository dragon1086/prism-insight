# BTC AI 서버 혼잡과 대기 안내 처리 (M0)

같은 OAuth 경로의 연구 응답에서 HTTP200 / status=failed / error.code=server_is_overloaded / error.type=service_unavailable_error / retry-after=321초를 확인했다. 원문은 비공개 로컬 증거에 보존했다. 11:05 운영 오류의 원응답은 저장되지 않았으므로 동일 원인이라고 단정하지 않는다.

두 가지 처리를 고친다. 알려진 과부하를 일반 incomplete나 형식 오류로 뭉개지 않고 안전한 overloaded 분류로 전달한다. HTTP200이어도 error가 있으면 성공 응답으로 채택하지 않는다. 연구의 중복 terminal 검사를 제거하고 동일 OAuth 검증에 맡겨 원인 분류를 보존한다. 즉시 재시도·키/모델 대체는 없다.

검증된 숫자 Retry-After(최대24시간)만 초/밀리초에서 보수적으로 읽는다. 실패 이벤트에 안전한 대기시간·실패시각만 추가하며 헤더/메시지 원문을 공개하지 않는다. 운영의 다음 정기 판단은 최신 오류 이벤트의 기한을 읽어 아직 이르면 모델을 호출하지 않고 기존 protect-only 경로로 보호·정산 점검을 계속한다. 보호 불확실성은 대기 상태로 가리지 않으며, 보호 확인만으로 모델 오류가 복구됐다고 알리지 않는다. 기한 뒤에는 새로운 입력의 정상 정기 판단으로 복귀한다. 기존 DB 스키마·cron·위험/주문 권한은 변경하지 않는다.

로컬 검증: 변경 전 과부하 분류·성공+오류 혼합응답·연구 원인전달3개 검사와 대기/보호3개 검사가 실패했다. 수정 후 OAuth·운영 runner·알림·실패 이벤트·원 프롬프트 해시·연구 보호 관련510개가 통과했다. 안내시간 직전에는 모델 없이 보호만 실행하고, 정확한 기한 이후 정상 판단으로 복귀하며, 보호 불확실성·잘못된 메타데이터를 대기로 가리지 않는 경계를 포함한다. CI·배포·첫 정기 실행·실제 후속 과부하에서의 대기는 별도다.
