# 미국 실데이터 파이프라인 통합 검증

## 목적과 검증 범위

사용자는 단위 테스트가 아니라 로컬에서 미국 `run_full_pipeline()`을 운영 cron과 유사한
환경으로 실제 실행하고, 이전 보고서와 비교하도록 요청했다. 새 전용 worktree와 Python 3.11
가상환경을 만들고 실제 시세·검색·LLM·PDF 생성 경로를 실행했다. 종목을 임의로 고정하거나
선정 수를 줄이지 않았다. 이 문서의 실행 완료 여부는 마지막 결과 절로 구분한다.

**안전 경계:** 실제 `run_full_pipeline`의 매크로 → 전체 스크리닝 → 선정 보고서 → PDF →
텔레그램 요약 생성은 그대로 실행한다. tracker의 `run`만 private 빈 가상계좌에서 실제
`_analyze_report_core`와 `_evaluate_production_buy_gate`를 실행하는 어댑터로 바꾼다.
원래 `process_reports`의 계좌별 처리, 후속 시세 재조회, 현금·주문 예산 검사, 보유종목 SELL,
브로커 집행까지 검증한 것은 아니다. 기존 격리 실행 차단 장치를 해제하지 않았다.
공개 채널·아카이브·Redis/GCP 발행은 차단했다. 다국어 방송 전송 경로도 제외했다.

## 운영 환경과의 대조

실제 db-server crontab에서 해당 항목 앞의 `CRON_TZ`까지 확인했다.

- 미국 오전: **America/New_York 10:15**, 월~금.
- 미국 오후: **America/New_York 14:30**, 월~금.
- 이번 실제 실행은 오후 모드, 분석일 `20260917`이다. 현재 장중 자료를 사용하는 운영형
  실행이며 과거 시점 재현이나 백테스트가 아니다.
- 보고서: `gpt-5.6-luna`, effort medium; 보조·요약: Luna low.
- BUY: `gpt-6-astra`, high, 240초; SELL 설정 high/120초는 유지하되 빈 계좌라 실행하지 않는다.
- BUY 동시성 3, 보고서 병렬 설정, 매매일지 기능, 국면 최소 점수, 초분할 SHADOW 설정을 반영했다.
- 시장 문맥 ON, 경쟁근거 prefetch OFF, TradingView OFF를 실제 운영 설정과 맞췄다.
- 로컬의 기존 보고서 OAuth 인증은 실패해, 로컬에 바인딩한 SSH 터널로 서버의 임시 OAuth
  프록시를 사용했다. 오케스트레이션·수집·PDF는 로컬에서 실행했다. 유료 API-key fallback은 쓰지 않았다.
- BUY Codex는 로컬의 기존 인증을 사용하되 사용자 도구 설정을 읽지 않는 검증용 실행기로
  읽기 전용 SQLite·시간 도구만 제공했다. 읽기 전용 DB의 쓰기·ATTACH 금지는 유지했다.
- 운영 계좌·거래내역·비밀키를 복제하지 않았다. 매매일지는 운영과 같은 공유 테이블 구조만
  생성했으며 실제 행은 없다. 따라서 과거 거래 경험이 BUY 점수에 주는 영향은 비교 대상이 아니다.

## requirements와 MCP 설치

새 가상환경에서 `requirements.txt`를 실제 설치하고 의존성 일관성 검사를 통과했다.
서버는 Python 3.11.11, 로컬은 3.11.15이며 OS는 각각 Linux/macOS다.

- `openai==2.43.0`, `openai-agents==0.7.0`: 기존 pin 유지.
- `mcp==1.26.0`: 새 코드가 직접 쓰는 SDK를 간접 의존성에 맡기지 않고 명시했다.
- `yfinance==1.2.0`, `pandas-market-calendars==5.3.1.2`, `playwright==1.58.0`:
  운영에서 사용 중인 버전으로 고정했다. 수정 전 새 설치는 각각 다른 최신 버전을 가져왔다.
- pandas는 양쪽 2.2.3이다. Chromium 설치와 실제 PDF 생성도 확인한다.
- Node MCP는 Python requirements에 넣지 않는다. 추적되는 레지스트리의
  Perplexity `@perplexity-ai/mcp-server@1.2.0`, Firecrawl `3.23.6`,
  Yahoo Finance MCP `0.1.2` 및 내부 시간 서버를 실제 시작해 도구 목록을 확인했다.
- TradingView는 원격 OAuth MCP이므로 별도 Python 전용 패키지를 임의로 추가하지 않았다.
  이번 테스트에서도 운영 OFF이며, 자동 판단·공개 채널 이용권한 문제를 해결했다고 하지 않는다.

## 실제 실행에서 찾고 수정한 문제

### 1. 호스트별 매크로 MCP 설정 불일치

US 매크로만 무시된 로컬 설정 파일에 의존했다. 서버는 과거 커스텀 Perplexity 프로세스를,
보고서는 새로운 고정 레지스트리를 사용했다. 새 checkout에는 설정 파일 자체가 없었다.

`cores/llm/macro_mcp_app.py`에서 추적되는 레지스트리의 Perplexity만 명시적으로 구성한다.
활성 OAuth 프록시 주소와 환경변수 키를 유지하며 설정 파일에 비밀값을 쓰지 않는다.

### 2. 원문이 긴 뉴스 분석의 HTTP 413

첫 실제 실행에 **최대 1,048,576바이트 / 실제 1,080,797바이트**라는 프록시 오류가 기록됐다.
뉴스 재시도로 보고서는 만들어졌지만 오류 없는 통합 실행은 아니었다.

aiohttp의 암묵적 1 MiB 요청 제한을 **유한한 8 MiB**로 바꿨다. Chat와 Responses 양쪽에서
1.1 MiB 수용·본문 보존, 8 MiB 초과 거절·upstream 미호출을 테스트했다.
이는 프록시의 전송 한도이며 모델 토큰 예산이나 다른 upstream 제한을 없애는 변경이 아니다.

### 3. 같은 배치에서 시장 LLM을 세 번 호출

첫 실행의 동시 보고서 3개가 모두 전역 캐시를 빈 상태로 보고 같은 시장 분석을 생성했다.
`generate_reports()`가 배치 전용 `MarketReportCache`를 공유하도록 바꿨다.
같은 배치·날짜·언어는 생성 작업 하나를 공유하며, 다른 배치에는 재사용하지 않는다.
실패·빈 결과는 캐시하지 않고 한 호출자의 취소가 다른 호출자의 작업을 취소하지 않도록 했다.

### 4. Nasdaq-100 구성종목 15개 누락

실제 로그에서 기존 Nasdaq 페이지에 구성종목 표가 없어 S&P 500의 503개만 조회하는 문제가
확인됐다. 구성종목 전용 페이지로 이전된 것이 원인이었다.

새 고정 주소를 우선 사용하고 기존 페이지는 한 번만 fallback한다. 현재 구성종목 표,
문자열 종목코드, 중복·과거 변경표·모호한 표를 검사한다. 실제 조회는 Nasdaq 102개와
S&P 503개, 합집합 **518개**였다. 이는 원래 의도한 두 지수의 합집합 복원이며
TradingView를 이용한 신규 후보군 확장이 아니다. 각 요청 제한시간 10초를 유지한다.

### 5. 공개 보고서의 출처 연결과 제목

첫 신규 보고서 세 개에는 거시 수치 뒤에 `[1]`·`[4]` 등이 있지만 대응하는 참고문헌이 없었다.
새 시장 문맥이 켜진 경우 공개 HTTPS 연결이 없거나 번호 참조가 해결되지 않는 별도 거시 서술을
그대로 게재하지 않고 출처 연결 미확인 사실을 표시한다. 추가 실제 검증에서는 시장 분석
본문도 같은 문제를 가진 것을 발견해, **전략·요약 입력 조합 전** 미해결 숫자 인용을 걸러냈다.
지수 사전 수집 경로는 별도 매크로가 있으면 가격·거래량·VIX만 분석하고 중복 뉴스 조사를
하지 않는다. standalone 보고서는 기존 뉴스 조사 경로를 유지한다. 구조화된 매크로 판단·순위는 바꾸지 않는다.
프롬프트에는 실제 링크와 발행일을 요구했다. URL 연결 검사는 내용의 진실성 검증이 아니다.

또한 한국어 개행 정리가 공통 시장 제목과 첫 문장을 합치던 문제를 빈 줄로 교정했고,
분석가의 설명·점수가 공식 매매 국면을 대체하지 않는다는 구분을 추가했다.

### 6. 테스트 환경과 종료 검증

첫 검증기는 실제 반환형인 `Path`를 문자열이 아니라는 이유로 잘못 거절했다. PathLike를
허용하되 실재·크기 검사는 유지했다. 빈 가상 DB에는 공유 매매일지의 빈 스키마도 생성한다.
첫 Codex 시험에서 읽기 전용 도구의 승인 설정이 빠져 다른 모델로 fallback한 사실을 확인했다.
수정 후 검증기는 **모든 선정 보고서의 Astra primary 성공**까지 요구한다.

첫 실행은 결과 파일을 쓴 뒤 프로세스 종료가 지연돼 해당 검증 프로세스만 종료했다.
마지막 엔트리포인트에 기존 MCP 로거의 명시적 종료를 추가했다. 최소 재현에서는 원래도
정상 종료했으므로 로거가 유일한 원인이었다고 단정하지 않는다. 최종 실행에서는 실제 종료까지 확인해야 한다.

## 보고서 비교: 첫 산출물과 기존 MRNA

기존 MRNA 9월11일 보고서와 새 9월17일 보고서를 비교했다. 날짜·시세·뉴스가 달라
판단 변화 모두를 코드 효과라고 해석하지 않는다.

- 기존 28,283자 → 첫 신규 27,689자(이미지 base64 제외), 약 2.1% 감소.
- 신규 세 보고서에 같은 시장 근거 ID와 16 ETF의 5/20/60거래일 성과가 전달됐다.
- 관측군 상승313·하락188·보합2, 유효503/503·누락0이 표시됐다. 이는 초기 실행의
  축소된 관측군 수치이며, Nasdaq 누락을 수정한 최종 실행의 분모와 구분해야 한다.
- ARE 전략은 XLRE의 상대약세를 실제 접근 판단에 사용했다. 숫자 부록만 추가한 것은 아니다.
- 신규 MRNA는 기관 보유량을 지연 스냅샷으로, CMF 등을 가격·거래량 대용치로 더 명확히 설명했다.
  이를 모든 향후 보고서에서의 보장으로 일반화하지 않는다.
- 직접 경쟁사의 동기간·동일 사업 비교는 여전히 불완전하다. 회사 지표를 산업 전체 근거로
  넓히거나 비교 불가 표기와 본문 우위 서술이 충돌할 가능성도 남는다.
- 이번 조사는 전체 보고서의 사실 무오류나 수익성 개선을 증명하지 않는다.

## 실행 기록

- run1: 실제 503개 관측, MRNA·ARE·SMCI 선정, 보고서/PDF/요약 각각3개 생성,
  BUY 분석3개 수행. 413 재시도와 Codex fallback, 잘못된 테스트 반환형 검사,
  종료 지연이 있어 합격으로 세지 않았다.
- run2: 보고서 생성 전 Nasdaq 구성종목 누락을 확인해 중단했다. 성공 표본이 아니다.
- run3: 518종목, 보고서/PDF/요약 각3개, Astra primary3개 및 프로세스 종료0을 확인했다.
  하지만 시장 분석 본문의 미연결 인용이 남아 콘텐츠 검증은 탈락했다. 시간 도구의
  초기 실패 후 재호출도 기록됐다. 가드 적용 위치를 교정한 후 다시 실행했다.
- **run4: 최종 실제 실행 성공.** 관측518/518·누락0, MRNA/MU/SMCI 선정,
  보고서3개·PDF3개·요약3개, Astra high BUY3개, 결정론적 게이트3개를 완료했다.
  검증 오류0, 표준 로깅 degraded0, primary fallback0, cleanup 성공,
  프로세스 종료코드0이다. 실주문과 외부 발송은0이다.
  단, 시간 도구의 초기 요청1건이 필수 timezone 없이 실행되어 실패한 뒤 올바른 인자로
  재시도됐다. `status=failed, error=null`이라 error 필드만 보면 놓치는 사례였다.
  상태도 함께 집계하도록 검증기를 고쳤으며 **저수준 도구 오류까지0건이라고 주장하지 않는다.**
- 총 소요 약 **18분35초**. 매크로67초·스크리닝220초·보고서380초·PDF5초·요약361초,
  Astra 호출은 각각 약62/64/69초였다. BUY 준비와 종료 시간도 총 시간에 포함된다.
- 최종 BUY는 세 종목 모두 미진입이었다. 정상적인 미진입을 분석 실패로 보지 않으며,
  실제 진입·주문 통과를 검증한 것으로도 보지 않는다. 목표 근거와 보유기간·청산 모델이
  `target_provenance`에 실제 기록됐다.
- 실행 중 사용한 ON 가격 분석 프롬프트의 한·영 SHA를 고정한 회귀로 이후 standalone
  호환성 보완이 ON 입력을 바꾸지 않았음을 확인했다. 전체 실행과 별개인 이 경계 검증을 구분한다.

## 최종 보고서 품질·비용 관측

- 세 보고서의 시장 본문은 종목별 차트 태그를 제외하면 동일하다. 시장 보고서 생성 작업은
  배치당1회였고, 최종 가격 분석 작업은 추가 MCP 호출 없이 완료됐다.
- 이전 미연결 시장 인용 **9개→0개**, 검증되지 않은 연준25bp·3.75~4.00% 서술 제거,
  지수 단위 **USD→포인트**, 제목 줄바꿈 교정을 확인했다.
- `MI-1eb34b6019ca1ff6`, 완료 일봉2026-09-16, 상승344·하락174·보합0,
  유효518/518·누락0이 세 보고서와 PDF 텍스트에 보존됐다. PDF는 각각18/18/17쪽이다.
- 이미지 제외 본문: MRNA28,283→25,530자(-9.7%), MU26,770→27,261자(+1.8%),
  신규 SMCI24,930자. 분량이 늘었다는 이유로 품질 향상으로 판단하지 않는다.
- 보고서 SDK에서 측정한 부분은 최초24작업·1,253,815토큰에서 최종22작업·560,216토큰이었다.
  시세·뉴스·모델 출력이 달라진 순차 관측이며 코드의 단독 인과 효과가 아니다. 별도 macro·
  legacy 요약·검색 비용은 포함하지 않아 전체 토큰/청구액 감소율로 사용하면 안 된다.

**경쟁사 조사는 개선 완료가 아니다.** 이전 MU 보고서는 최신 동일 기간의 DRAM 점유율을
비교했지만 최종 보고서는 오래된 자료와 UNKNOWN을 사용해 비교 정보가 줄었다.
기존 인용 URL을 실제 재조회한 결과 Counterpoint의 2026-09-02 공개 자료에서
2026 Q2 DRAM Samsung38%·SK hynix25%·Micron24% 표를 확인했다.
즉 이 사례에서는 원문 자체가 없는 것이 아니라 조사 선택·근거 재사용이 불안정한 문제가 남는다.
[확인한 원문](https://counterpointresearch.com/en/insights/global-dram-and-hbm-market-share)

이 판단을 HBM 전 수치·모든 경쟁자료의 독립 검증으로 확대하지 않는다. 경쟁근거 prefetch는
계속 OFF이며, 검증된 출처·peer·기간을 재사용하는 별도 보완이 필요하다.
