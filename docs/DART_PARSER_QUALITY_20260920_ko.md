# DART 파서 적용 및 보고서 입력 품질 검증

## 판단

**원문 추적성과 일부 위험 근거의 전달은 개선됐지만, 운영 전환 기준에는 미달했습니다.**
독립 파서와 명시적 옵션을 구현했고 기존 PR #752에 이어서 반영합니다. 기본 OFF는 유지하며 이번 결과로 머지·배포하지 않습니다. 최종 생성 보고서의 정확도가 향상됐다고 주장하지 않습니다.

이번 작업은 참고 저장소의 구조화 아이디어를 독립 구현한 것입니다. OpenDART API·증분 DB·MongoDB·Redis를 도입하거나 참고 코드를 복사하지 않았고, 의존성도 추가하지 않았습니다.

## 구현한 내용

1. **섹션과 원문 위치:** 목차를 본문으로 오인하지 않고 섹션 경로·연결/별도 범위·원문 표현의 SHA-256·DOM 위치를 보존합니다. 모호한 중복 대제목은 거절합니다. 혼합 텍스트와 inline 숫자는 실제 블록 경계까지 묶고 여러 원문 위치를 기록합니다.
2. **표와 주석:** 원래 셀 좌표, rowspan/colspan, 다단 헤더, 단위·기간 문구와 각주를 보존합니다. `-`나 빈칸을 0으로 바꾸지 않습니다. 실패한 표의 각주를 이전 표에 붙이지 않습니다. 숨김·대체 콘텐츠와 잘못된 병합, 제한 초과는 명시적으로 제외합니다.
3. **보고서 입력:** 기존 발행사·시점·URL 필터를 통과한 KRX 본문에만 선택적으로 적용합니다. 이 필터가 법인·발행시각을 모두 독립 검증한다는 뜻은 아니며 미확인은 유지합니다. 기존 구조화 Markdown 선택기를 재사용하고 새 증거의 출처·scope를 실제 section_notes까지 전달합니다. 기존 경쟁사 문단을 유일한 완전 원문 블록으로 확인한 경우 보존합니다.
4. **자원과 실패 경계:** HTML/Markdown 각각 2 MiB, HTML 30,000노드·깊이·레코드 제한, 표 행/열/셀 제한을 적용합니다. 실패한 HTML을 안전하지 않은 평탄화 표로 조용히 대체하지 않습니다. 정제 HTML과 원본 응답의 해시는 구분합니다.

### 옵션과 영향 범위

연구 기능이 켜진 KR `insight_prefetch_v5`에서 `filing_parser: "structured_v1"`라는 정확한 값만 새 경로를 선택합니다. Boolean true는 활성화 값이 아닙니다. 캐시를 분리하고 기존 OFF·US 요청은 보존합니다. 이 옵션에서는 같은 KRX 본문 scrape에 `html` 형식을 추가하며 추가 호출을 만들지는 않습니다.

**중요:** 38개 항목 점수는 HTML이 없는 기존 Markdown 응답 재생에서 측정했습니다. HTML 경로는 원본·Markdown 구조 대응을 보완하여 2문서에서 발췌 전달을 확인했지만, 한 문서의 제한 실패와 실제 Firecrawl HTML 응답 검증이 남았습니다. 설정 예시를 활성화 권고로 해석하면 안 됩니다. 운영 설정은 변경하지 않았습니다.

Firecrawl 공식 문서는 여러 형식의 동시 요청과 `html`이 정제된 표현이라는 점을 명시합니다. 원본 응답 바이트와 동일하다고 취급하지 않습니다. [공식 문서](https://docs.firecrawl.dev/features/scrape)

## 실제 보고서 입력 전후 비교

기존에 고정한 RF머트리얼즈 2025 사업보고서, 오스코텍 2025 사업보고서, 아모레퍼시픽 2026년 1분기보고서의 **3문서·38개 검증 항목**을 사용했습니다. 이미 사용한 회귀군이며 새로운 holdout이 아닙니다. 최신 보고서를 새로 선택한 실험도 아닙니다.

이전·이후 모두 같은 원문과 같은 기준일, **섹션별 6,000 UTF-8 바이트 한도**를 사용했습니다. 선택기 중간 결과가 아니라 최종 `news_analysis`·`company_overview`·`company_status` 패킷에 들어간 발췌를 평가했습니다. 서로 다른 표나 범위에서 가져온 조각을 합쳐 정답 처리하지 않습니다.

- RF머트리얼즈: 완전한 근거 항목 **1/18 → 1/18**.
- 오스코텍: **1/10 → 2/10**.
- 아모레퍼시픽: **1/10 → 1/10**.
- 합계: **3/38 → 4/38**. 분모 전체 대비 7.9%에서 10.5%이지만, 이를 보고서 정확도나 매매 성과 개선률로 부를 수 없습니다.

추가된 완전 근거는 **오스코텍 공시의 IPO 공모가에 따른 전환가격 조정과 기존 전환가격 70% 하한 조건**입니다. 투자자가 희석 가능성을 검토할 때 빠뜨리기 쉬운 조건을 전달한다는 의미가 있습니다. 다만 이 정보가 실제 생성 본문의 판단을 개선했는지는 아직 측정하지 못했습니다.

RF의 고객·경쟁사 역할 구분, 오스코텍의 주요 고객 집중, 아모레퍼시픽의 매출 10% 이상 외부고객 여부는 기존 완전 근거를 유지했습니다. 이들 내용은 해당 과거 공시의 서술이며 오늘의 상태나 독립 검증된 사실을 뜻하지 않습니다.

### 추적성과 비용

- 평가기가 원문을 읽어 scope를 추론한 점수는 위의 **3 → 4**입니다.
- 보고서에 실제 전달된 scope까지 요구하면 **1 → 4**입니다. 서로 다른 지표이므로 섞어 개선률을 부풀리지 않습니다.
- 처리 후 발췌의 선언된 원문 위치·해시 검증 실패는 **0건**입니다. 기존 경로의 3건은 평가용 위치를 유일하게 복원하지 못한 발췌이며, 곧바로 허위 사실 3건이라는 의미는 아닙니다.
- 실제 전달량은 9개 섹션 합계 **29,709 → 50,652바이트**, 약 **70.5% 증가**했습니다. 상한은 같지만 여유 예산을 더 사용했습니다. 토큰 수·요금은 별도이며 바이트 증가를 비용 절감으로 포장하지 않습니다.
- 완전 근거는 여전히 **34/38개가 미충족**입니다. 근거 추적 개선만으로 충분한 보고서가 됐다고 판정할 수 없습니다.

## 피드백 후 수정 이력

최초 구조화 경로에서는 RF의 기존 경쟁사 문단이 탈락했습니다. 이 실패를 보존하고 두 가지 일반 규칙을 수정했습니다.

1. 예전의 topic당 2개 제한이 새 구조화 후보를 불필요하게 잘랐습니다. 구조화 후보만 최대 24개까지 검토하되 최종 섹션 바이트 상한은 그대로 유지했습니다.
2. 짧은 문단 위주 순위가 서로 다른 제품군의 경쟁사 문단을 밀어냈습니다. 기존 경쟁사 발췌가 유일한 완전 원문 블록일 때 보존하도록 했습니다. 회사명·종목별 예외를 추가하지 않았습니다.

중간 결과: 최초 합계 3→3, 후보 제한 수정 후 3→4이지만 RF 1→0, 경쟁사 보존 수정 후 최종 RF 1→1·합계 3→4. 실패 파일은 삭제하거나 최종 성공으로 덮어쓰지 않았습니다.

## 실제 HTML 검증: 구조 대응을 수정했지만 전체 합격은 아님

같은 3문서의 공식 KRX 공개 HTML을 제한된 GET 3회로 확보했습니다. HTTP 200은 내용 품질 합격이 아닙니다.

- RF: 파서가 기록을 추출했습니다.
- 오스코텍: 일부 표가 지원하지 않는 구조여서 부분 추출했습니다.
- 아모레퍼시픽: 35,477노드로 현재 30,000노드 제한을 넘어서 거절했습니다.
- 첫 adapter 재생에서는 **3문서 모두 최종 전달 레코드 0개**였습니다. 원문 HTML과 Markdown의 섹션 계층·문단 경계 차이가 원인이었습니다.
- 이 실패 후 회사별 예외 없이 보고서 제목 앞부분과 한글 소제목 표현 차이를 처리했습니다. Roman 대목차·숫자 절/주석·연결/별도는 같아야 하며, 산문 결합은 원래 경로와 범위가 같은 인접 문단에만 허용합니다. 제목이나 표를 건너뛰지 않고, 중복되는 대응은 거절합니다.
- 수정 후 RF는 **57개 후보 → 최종 11개 발췌**, 오스코텍은 **53개 후보 → 최종 12개 발췌**를 기존 섹션 예산 안에서 전달했습니다. 이는 23개 사실을 독립 검증했다는 뜻이 아닙니다. 아모레퍼시픽은 노드 제한 때문에 여전히 0개입니다.

이 재생은 실제 Firecrawl의 정제 HTML 응답을 새로 받은 검사가 아닙니다. 따라서 Firecrawl가 반드시 같은 결과를 낸다고 단정하지도, 운영 HTML 반입이 검증됐다고 주장하지도 않습니다. 다른 표에서 숫자를 모으거나 다른 숫자 주석·연결 범위의 문장을 대응시키는 방식은 금지합니다. `10`과 `100`, 다른 대목차, 중복 표·산문을 거절하는 반례 테스트를 추가했습니다. HTTP 바이트 해시는 CRLF를 정규화하지 않고 확인했습니다.

## 최종 생성 보고서 및 PDF

실제 보고서 agent factory와 SDK backend, 동일 모델 설정을 사용하는 고정 입력 전후 비교를 준비하고 실행했습니다. MCP 검색·매매·채널 발송은 제거했습니다. 그러나 **18개 섹션 실행 시도 모두 AuthenticationError로 종료**되어 생성 본문을 얻지 못했습니다. 모델 사용량도 측정되지 않았습니다.

따라서 자연스러운 서술, 환각 감소, 사실→의미→한계 전달, 새 본문의 PDF 보존은 **미측정**입니다. 기존 PDF/보고서 소비자 회귀 테스트 통과는 새 생성 본문의 전후 품질 비교를 대신하지 않습니다. 실패 후 실행기는 첫 인증 오류에서 남은 비교를 중단하도록 고쳤고, 인증정보를 다른 계정에서 가져오거나 설정을 수정하는 우회는 하지 않았습니다.

## 변경 파일과 검증

- `prism_core/filing_html.py`, `filing_html_tables.py`: 독립 HTML 섹션·표 파서.
- `prism_core/filing_report_evidence.py`: 출처를 보존하는 표현별 adapter.
- `prism_core/filing_selection.py`: 기존 선택기에 owner별 topic 필터를 추가하여 중복 구현을 피했습니다.
- `prism_core/report_insight_prefetch.py`, `report_research_prefetch.py`: 명시적 옵션·캐시 분리·출처 메타데이터 전달.
- `tools/evaluate_filing_report_quality.py`: 실제 최종 패킷의 출처 기반 비교 평가.
- 신규 테스트 4개 파일과 `.github/workflows/ci.yml`: 회귀를 기존 CI에 연결했습니다.

불필요한 새 DB·새 SDK·새 파서 의존성을 도입하지 않았습니다. 구조화 Markdown 선택과 보고서 패킷 생성은 기존 구현을 재사용했습니다. 형식 오류·미확인 수치를 추정으로 메우는 기능은 넣지 않았습니다.

최종 코드에서 연구·보고서 회귀 **1,050개**, 별도 KR/US 공급자 및 기존 PDF/렌더러 회귀 **66개**가 통과했습니다. Ruff·compileall·diff 검사를 통과했고 새 테스트를 CI에 연결했습니다. 정확한 commit/원격 CI 정보는 함께 전달하는 완료 기록으로 연결합니다. 독립 HTML 기능 리뷰, 보안 리뷰, 최종 코드 리뷰는 **비활성 실험 범위**에서 승인됐습니다. Python 전용 타입 검사는 설정되지 않았고, 제공 LSP의 TypeScript 결과를 Python 검증으로 세지 않았습니다. 의존성 취약점 감사 도구도 없어 해당 감사는 미완료입니다.

최종 재현 영수증은 `filing_report_quality_release_candidate_20260920.json`, `filing_raw_html_release_candidate_20260920.json`입니다. 앞선 실패 영수증과 모델 인증 실패 기록도 함께 보존했습니다.

## 다음 합격 조건

1. 원문/정제 HTML/Markdown 간 섹션·문단 대응을 실제 응답으로 검증하고 기존보다 안전한 전달을 확인해야 합니다. 전역 크기 상한만 올리거나 출처 대조를 완화해서 통과시키지 않습니다.
2. 38개 회귀 항목의 낮은 완전 근거 확보율과 추가 전달 비용을 개선하고, 수정에 쓰지 않은 별도 표본으로 확인해야 합니다.
3. 보고서 생성 인증 경로가 정상화된 뒤 동일 입력으로 최종 본문과 PDF를 비교해야 합니다.
4. 최신 정기공시 선정·기사 원문 검증·TradingView 비사용자 무영향·BUY/SELL 소비 경계 등 기존 PR의 미완료 게이트까지 통과한 뒤에만 같은 PR을 머지·배포합니다.
