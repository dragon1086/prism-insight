# BTC 모델 오류와 연구 호출 격리 (M0)

11/18 11:05:25의 운영 후보 생성 요청은 약2.72초 뒤 incomplete로 종료됐다. 당시 보유·미체결은0, 보호 확인은True였고 주문 판단은 미반영됐다. 11:10·11:15 정기 WAIT가 정상 완료됐으며 운영 모델 incident는 해제됐다. 읽기 전용 Bybit 데모 조회로11:17:35 보유0·주문0과11:04~11:11 체결0을 확인했다. 서비스는 active/running·재시작0이었다. 원응답의 상세 terminal 이유는 저장되지 않아 근본 원인을 단정하지 않는다. 타임아웃 확대·응답 채택·모델/키 대체·운영 판단 재실행은 하지 않는다.

기존 연구 보호는 코드·cron·현재 실행 여부·시각 여유를 확인했지만 운영 모델 incident의 활성 상태는 확인하지 않았다. 오류 이후 연구가 불안정한 AI 경로를 추가 사용하지 않도록, 매 HTTP 직전 운영의 incident 해제 상태를 읽기 전용으로 확인한다. 활성 또는 상태 MISSING이면 연구 요청을 보내지 않는다. 판단·주문·보호 권한과 운영 정기 판단은 변경하지 않는다.

R9 연구는 운영 점검을 우선하려고 전용 로컬 연구 프록시만 종료했다. 원장의9회 요청과 성공/실패 원문을 보존하며 기존 봉인 장부를 재개하지 않는다. 후속 연구가 필요하면 새 등록서·장부를 쓰고 성공한 요청은 전체 요청 일치 검증으로만 재사용한다. 실제HTTP 재시도는 없으며 총 호출 한도를 유지한다.

수정 전 신규3검사가 실패했고, 활성/비활성/결측·읽기전용DB·양쪽 시계·시간 여유·실제HTTP전 차단을 포함한 관련101검사가 통과했다. 실제 오류 응답 자체를 성공/WAIT로 바꾸지 않는다. 후속 실제 HTTP의 readiness 영수증에 model_healthy=True가 없으면 전송하지 않는다. 새 검사를 기존PR CI에 함께 연결한다. 수익성·회복 권한·주문/cron 변경은 없다.
