# 범용 경쟁사 조사 사전 평가 계획

## 범위와 변경 전 기준

2026-09-18 재개. 운영은 f586cc9, 연구 활성화는 MU/005930만이다.
개발 기준은 최신 main 47b58e15이며 기존 요약 근거 개선을 보존한다.
매매 점수·주문·cron·TradingView 권한은 변경하지 않는다.

## 결과를 보기 전에 고정한 표본

- US 개발: MU(양성), LITE(실패), TMO(다각화), JPM(금융), MRNA(바이오), GEV(산업재).
- KR 개발: 005930 삼성전자(양성), 327260 RF머트리얼즈(실패),
  051910 LG화학(다각화), 105560 KB금융(금융), 039200 오스코텍(바이오), 005380 현대차(자동차).
- 미사용 검증: US COST, CRM / KR 035420 NAVER, 034020 두산에너빌리티.
- 기준일 2026-09-18. 각 live cold 수집 1회와 warm 재호출 1회.
  실패를 삭제하지 않으며 재시도는 별도 run으로 집계한다.
- 기존 v6와 신규에 동일한 저장 원문/검색 응답을 재생한 비교는 live 검색 비교와 분리한다.

## 구현 순서

1. 기존 회귀를 실행한다. 실제 원문·검색 결과의 법인/사업/출처 연결 실패를 기록한다.
2. 기존 prefetch 메타데이터를 재사용하는 범용 조사 입력과 출처 선정·공개 공시 URL 처리를 구현한다.
3. 구조화 관측의 차원 일치와 기간별 산술을 검증한다. 원문 일치와 사실 검증은 분리한다.
4. 실패·빈 응답·타임아웃·예산 초과를 기존 뉴스 조사/최종 소비 경계까지 검증한다.
5. 명시적인 전 종목 설정 전환을 추가하되 통과 전 운영 범위는 유지한다.

## 고정 상한과 판정

- 수집: 검색 1회 + scrape 최대 2회, 총 60초. warm 추가 호출 0회.
- 뉴스 입력 3,500자, 회사 절 각각 1,200자. 표/문장/차원은 통째로 보존하거나 통째로 생략한다.
- 신규 상시 LLM 호출과 의존성 추가 없음. 모델 검증은 기존 뉴스 경로에서
  gpt-5.6-luna/기존 effort를 유지하고 실행당 300초, 실패 포함 실제 usage를 기록한다.
- 잘못된 법인·수치·기간·출처를 검증된 사실로 제시하면 불합격이다.
- 단순 수집 수가 아닌 주입된 원문, 직접 peer 적합성, 비교 질문 해결,
  UNKNOWN/INCOMPARABLE 유지, 본문-요약 모순을 개별 평가한다.
- 자료가 부족한 사실과 탐색 실패를 구분한다. UNKNOWN만 늘어난 결과는 범용 효용 입증이 아니다.
- MU/삼성 기존 완전한 비교표가 후퇴하지 않고 실패군과 미사용 업종에서도
  실제 질문 해결 개선을 확인해야 전 종목 ON을 허용한다.
- 전체 표본의 최종 뉴스/요약/PDF→BUY 경계, CI, 운영 Python 스모크까지 통과해야 배포한다.
  미달 시 미완료 항목과 재현 증거를 남기며 운영 범위를 임의로 넓히지 않는다.

## 상태

## 이번 세션 결과: 구현은 진행했지만 전 종목 활성화는 불합격

운영 허용 목록은 MU/005930 그대로이다. 이 문서는 범용 품질 합격이나 배포 승인이 아니다.
원문 존재, 주입 성공, 모델 응답 성공, 질문 해결, 전체 보고서 사실 정합성은 구별한다.

### 변경한 코드

- `report_research_prefetch.py`: 기존 회사 메타데이터 재사용, 짧은 공시 중심 검색,
  정확한 원문 링크로 남은 scrape를 사용하는 경로, 문서 목록/탐색 메뉴의 일부 배제,
  사업 경쟁 설명 우선 발췌, 두 자료의 예산 분배, 실패 사유 및 실제 timeout 호출 수 보존.
- 공개 DART/KIND 문서 ID만 제한적으로 허용한다. URL을 변형하지 않으며 토큰·중복 ID·
  로컬 호스트·DNS 마지막 점·제어문자 주소를 배제한다. 잘못된 검색 URL 하나가 나머지를 중단시키지 않는다.
- 링크형 표 헤더, 여러 문장의 주석, Markdown 강조/이스케이프된 반올림 안내,
  경쟁사 목록의 관계 문맥은 원자적으로 보존하거나 통째로 생략한다.
- 캐시는 버전·시장·종목·기준일·필수 구조를 검사한다. 회사 조사 입력이 바뀌면 재사용하지 않는다.
- `research_comparison.py`, `research_table_observations.py`: 구조화된 관측의 차원 대조와
  제한적인 명시적 점유율 표 추출/Decimal 산술이다. 임의 업종·공시를 자동 이해하는 범용 파서가 아니다.
  미확인 실제치/추정치·사업 범위는 미확인으로 남으며, 계산 결과도 조건부 산술일 뿐 사실 인증이 아니다.
- KR/US 분석 호출부와 US prefetch는 기존 조회의 서술 필드만 재사용한다. 추가 회사정보 조회는 없다.
- `configure_report_research.py`: 명시적인 `--all-symbols`를 추가했다. 생략하면 기존 범위를
  보존하고 `{}`는 전부 제외하며, 시장 문맥과 OFF는 독립적으로 유지한다. 운영에서 실행하지 않았다.
- `.github/workflows/ci.yml`에 새로운 오프라인 회귀를 연결했다.

### 실제 소스 수집: 실패 실험도 보존

모든 값은 동일한 기준일의 별도 live 탐색이며 동일 응답 A/B로 오해하면 안 된다.
각 cold 뒤 warm을 실행했고 모든 warm은 신규 외부 호출 0이었다.

  자체 투자점수, IR 문서 제목이 실제 비교자료로 들어가는 문제가 재현됐다.

  알려진 집계 사이트를 제외해도 다른 AI 집계물이 대신 들어왔다. 이 버전은 실패이다.

- v9: 개발 12개 + 기존 검증 재평가 4개 + 새 미사용 검증 4개, 총 20개.

  20개 모두 60초·3호출·입력 길이 상한을 지켰다. 가장 느린 신규 표본은 54.346초였다.

정량 점유율 비교는 기존 메모리 양성 두 종목에서 확인했다. 모든 기업에 시장점유율 수치를

호출 단가/실제 청구액은 응답에 없어 UNKNOWN이다. 비용 절감이나 수익 개선을 주장하지 않는다.

### 검증 버전과 남은 작업

- v9 live 동결 뒤 코드 리뷰에서 링크형 표 헤더/주석/비정상 URL 문제를 추가 수정해
  collector를 v10으로 올렸다. v9 측정값을 v10의 새 live 실행값으로 부르지 않는다.
- 고정 원문 모델 비교는 MU·삼성·LITE·RF의 두 입력군, 도구 없는 gpt-5.6-luna/medium으로
  실행했다. 이는 전체 뉴스 조사·최종 요약·PDF·BUY 파이프라인 A/B가 아니다.
- 모델 8회 모두 응답했고 SDK 합계 31,820토큰, 합산 477.745초였다. 기존/신규 입력의
  선택 원문이 다르고 각 1회이므로 비용·속도 개선률을 주장하지 않는다. 두 응답의 보고 출력 토큰이
  설정값 4,000을 넘었으므로 이 설정의 강제 상한도 입증되지 않았다.
- 고정 모델 시험의 신규 입력은 당시 v8이다. LITE/RF는 부적절한 집계 수치를 되풀이하지 않았으나
  경쟁 비교를 해결한 것이 아니라 응답을 유보했다. 탈락 사유를 실제로 주입된 요약자료처럼 부르는
  표현과 장황한 빈 비교표가 남았다. 삼성의 101% 합계 서술 등 단일 응답 개선을 결정론적 수정으로 세지 않는다.
- v10 안전 수정은 저장된 v9의 20개 응답으로 별도 strict offline replay한다. 알려지지 않은 URL은
  외부에서 보충하지 않고 실패 처리한다. 첫 replay에서 URL 우선순위의 대소문자 회귀가 드러나
  원문 URL은 보존하면서 비교 문자열만 소문자로 만드는 회귀 수정을 했다. 실패 기록도 남겼다.
- 최종 v11은 링크로 확보한 실제 공시 본문을 mirror보다 먼저 주입한다. 이전 replay에서
  LITE의 SEC 본문을 확보하고도 예산 때문에 버리는 문제가 드러났기 때문이다.
  Unicode/PDF 경쟁자 목록은 문장·관계 머리말과 묶고 큰 목록은 통째로 생략한다.
  자체 가치평가 표가 경쟁 서술로 대체되는 등 의도적인 정보 선택도 있어 모든 내용의 무손실을 주장하지 않는다.
- 최종 v11의 20건 strict offline replay는 저장 응답 59개만 사용했고 미등록 요청/외부 호출은 0이었다.
  수집 28개·주입 25개·주입 0인 종목 3개이며 LITE는 SEC 본문만 주입하고 mirror를 제외했다.
  MU/삼성의 두 사업 표·차원·반올림 주석을 보존했다. 현대차 자체 가치평가 표 2개는 통째로 생략됐다.
  collector SHA256: `1480e1b66081d7b12b1f47d809b0611770d446f9ccf0fce9ef01a3bbbdb9e261`.
- 현재 원문 수집 품질 게이트가 미달이므로 모든 표본의 비싼 전체 보고서 생성, 운영 배포,
  전 종목 ON, 첫 전 종목 정규 배치 검증을 완료했다고 표시하지 않는다.
- 다음 해결 대상은 한국 공시/IR 목록에서 정확한 본문을 얻는 경로, OCR/메뉴 판별,
  사업별 peer 관계와 동일 기준 지표를 실제 소비 구간에 전달하는 방법이다.
  문서 이동 단계가 기존 예산으로 부족하면 실패율·지연 실측에 근거한 별도 예산안을 먼저 정한다.

### 운영 안전

db-server는 확인 시 f586cc9, clean, crond active였다. cron·매매 문턱·주문·운영 설정은 변경하지 않았다.
오늘 KR 오전 정규 배치는 09:55:52에 본 파이프라인 완료를 기록했지만, 선택 종목은 대원전선과
SK하이닉스로 기존 연구 허용 두 종목은 아니다. 따라서 연구 기능 적용 후 첫 해당 종목 보고서
완료의 증거로 세지 않는다. 일본어 번역 PDF 한 건의 timeout은 별도 미해결 오류이며 이번에 수정하지 않았다.
