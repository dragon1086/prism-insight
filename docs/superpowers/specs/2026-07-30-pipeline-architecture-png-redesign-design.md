# 파이프라인 아키텍처 PNG 전면 개편 설계

## 목적

`docs/PIPELINE_ARCHITECTURE_ko.md`의 아키텍처 이미지를 일반 한국인 투자자가
쉽게 읽을 수 있도록 전면 개편한다. 기존 그림의 작은 글자, 영어 중심 용어,
과도한 정보 밀도, 기능 중복, 코드에 없는 개념을 없앤다.

최종 산출물은 모두 PNG다. SVG 파일은 만들거나 문서에 연결하지 않는다.

## 독자

- 주식 경험은 있으나 개발 지식은 없는 투자자
- 영문 금융 용어에 익숙하지 않은 투자자
- 작은 글자를 읽기 어려울 수 있는 고령 독자
- 시스템의 전체 흐름과 매매 원칙을 먼저 이해하려는 사용자

## 표현 원칙

- 밝은 미색 배경을 사용한다.
- 화면 비율은 16:9, 기본 해상도는 1920×1080으로 통일한다.
- 제목은 52px 이상, 소제목은 38px 이상, 본문은 30px 이상으로 그린다.
- 한 장에는 핵심 상자 3~6개만 둔다.
- 스크리닝은 파랑, 분석은 보라, 매매는 초록, 피드백은 주황으로 구분한다.
- 경고와 차단에만 빨강을 사용한다.
- 색만으로 뜻을 구분하지 않고 제목, 아이콘, 선 모양을 함께 사용한다.
- 영어는 첫 등장에만 한글 뒤에 병기한다.
- 어려운 용어에는 한 줄짜리 풀이를 붙인다.
- 수치, 조건, 기능 상태는 코드에서 확인된 것만 쓴다.
- 선택 기능은 `기본 꺼짐`, 로그 전용 기능은 `관찰 중`, 실주문 기능은
  `운영 설정 필요`로 표시한다.
- 운영 문서의 LIVE 표기와 코드 기본값이 다르면 두 값을 함께 밝힌다.

## 이야기 구조

그림은 다음 네 단계로 읽힌다.

1. 종목 스크리닝: 시장을 살피고 후보를 찾는다.
2. 종목 분석: 후보 한 종목을 여섯 방향과 CAN SLIM으로 조사한다.
3. 매매: 신규 매수, 추가 매수, 보유, 매도를 결정한다.
4. 피드백: 거래를 기록하고 다음 판단에 과거 경험을 제공한다.

기존 9장을 모두 교체하고 4장을 추가해 총 13장으로 구성한다.

### 1. `market-pulse-batch-control-overview.png`

제목: `윌리엄 오닐의 M: 지금은 주식을 사기 좋은 시장인가`

Market Pulse를 “대표지수의 매수 환경을 살피는 장치”라고 설명한다.

- 입력: KOSPI 또는 S&P 500의 종가와 거래량
- 상태: `상승 흐름`, `매도 압력 증가`, `시장 조정`
- 배치 정책:
  - 상승 흐름: 오전·오후 실행
  - 매도 압력 증가: 오전·오후 실행
  - 시장 조정: 오전 휴지, 오후 실행
- 계산 실패: 배치를 막지 않고 실행
- 코드 기본값: `shadow`
- 운영 문서 기록: `live`

시장 폭, 업종 흐름, VIX, 이벤트 플래그, 신뢰도 태그, 컨텍스트 태그는
Market Pulse 입력이나 출력으로 그리지 않는다.

### 2. `distribution-day-state-transitions.png`

제목: `분산일: 거래량이 늘면서 대표지수가 하락한 날`

분산일은 “기관성 매도 압력이 의심되는 날”이지 기관 매도의 확정 증거가
아니라고 밝힌다.

- 당일 종가가 전일보다 0.2% 이상 하락
- 당일 거래량이 전일보다 증가
- 최근 25거래일 안에서 센다.
- 해당 분산일 종가보다 이후 지수가 5% 이상 오르면 그 분산일은 지운다.
- 0~3개: 상승 흐름
- 4~5개: 매도 압력 증가
- 6개 이상: 시장 조정
- 기준 고점에서 10%를 초과해 하락해도 시장 조정에 진입한다.
- 시장 조정은 분산일 수가 줄었다는 이유만으로 풀리지 않는다.
- 상승 확인일 또는 조정 전 고점 돌파로 상승 흐름에 복귀한다.

상승 확인일은 “조정 저점 뒤 시작된 반등의 4일 차 이후, 지수가 하루
1.25% 이상 오르고 거래량도 증가한 날”로 풀이한다. 거래량이 없을 때
가격 조건만 사용하는 코드의 예외도 작은 주석으로 표시한다.

### 3. `screening-six-triggers-overview.png`

제목: `오전·오후에 종목을 찾는 6가지 방법`

기본 트리거 여섯 개를 오전과 오후 두 줄로 나눈다.

오전:

1. 거래량 급증: 전일보다 거래량이 30% 이상 증가한 상승 종목
2. 갭 상승 후 강세 유지: 전일 종가보다 시초가가 1% 이상 높고 장중 상승 유지
3. 시가총액 대비 자금 집중: 거래대금이 기업 크기에 비해 큰 상승 종목

오후:

4. 하루 상승률 상위: 전일 종가 대비 3~15% 상승
5. 장 마감 무렵 강세: 종가가 당일 고가에 가깝고 거래량도 증가
6. 거래량이 늘어난 횡보 종목: 거래량 50% 이상 증가, 하루 등락 ±5% 안,
   20일 이동평균선 아래로 크게 밀리지 않은 종목

KR에서 공통으로 적용되는 거래대금 100억 원 이상과 일부 트리거의
시가총액 5,000억 원 이상 조건을 하단 공통 조건으로 표시한다.
US는 금액 단위와 상한이 다르므로 “미국 시장은 동일한 구조, 별도 금액 기준”
이라고 구분한다.

### 4. `candidate-screening-reranking-overview.png`

제목: `많은 후보에서 최종 1~3종목을 고르는 과정`

다음 흐름만 그린다.

`기본 6개 발견 조건 + 상황별 추가 조건 → 중복 제거 → 네 가지 점수 →
주도 업종 후보와 개별 강자 배분 → 최대 3종목`

상황별 추가 조건:

- 주도 업종 대표주
  - KR: 시장 체제와 관계없이 거시 정보가 있으면 실행
  - US: 강한 상승장을 제외하고 실행
- 역발상 가치주
  - 횡보장, 약한 하락장, 강한 하락장에서 실행

네 가지 재정렬 점수:

- 발견 조건 자체 점수
- 예상 수익과 손실의 비율
- 후보군 안에서의 상대강도
- 20일선에서 지나치게 멀리 오른 정도

시장 체제별 실제 가중치는 문서 표로 연결하고 그림에는 상대적인 강조만
표시한다. 재무·뉴스·AI 적합성·신뢰도 가중치가 스크리닝 하드 필터인 것처럼
그리지 않는다.

### 5. `trading-regime-entry-overview.png`

제목: `두 가지 시장 판단은 서로 하는 일이 다릅니다`

왼쪽에는 Market Pulse 3상태, 오른쪽에는 스크리닝용 시장 체제 5상태를 둔다.

- Market Pulse:
  - 상승 흐름
  - 매도 압력 증가
  - 시장 조정
  - 분석 배치를 쉴지 결정
- 시장 체제:
  - 강한 상승장
  - 완만한 상승장
  - 횡보장
  - 완만한 하락장
  - 강한 하락장
  - 후보 점수 가중치와 주도 업종/개별 종목 슬롯을 결정

`parabolic`은 공통 여섯 번째 시장 상태가 아니다. 매수 프롬프트가 강한
상승장에 추가 조건을 적용할 때만 쓰는 “과열 가속 상승” 행이라고 별도
주석으로 표시한다.

### 6. `screening-analysis-deep-dive.png`

제목: `선별된 종목을 여섯 방향에서 조사합니다`

KR의 여섯 분석을 큰 카드로 표시한다.

1. 주가와 거래량
2. 투자자별 매매 동향
3. 기업 실적과 재무 상태
4. 사업 내용과 경쟁력
5. 최근 뉴스와 같은 업종 주도주
6. 시장과 업종 환경

US는 2번이 기관 보유 분석으로 바뀐다고 표시한다. KRX/yfinance 사전 수집,
웹 조사 보완, 분석 실패 시 폴백을 하단에서 짧게 설명한다.

스크리닝의 여섯 트리거, 후보 재점수, 시장 체제는 이 그림에서 반복하지 않는다.

### 7. `can-slim-seven-questions.png`

제목: `CAN SLIM: 좋은 성장주를 찾는 7가지 질문`

각 글자를 일반 투자자의 질문으로 바꾼다.

- C: 최근 분기 실적이 좋아지고 있는가
- A: 여러 해에 걸쳐 이익이 성장했는가
- N: 신제품, 새 사업, 새로운 상승 계기가 있는가
- S: 거래량과 주식 수급이 상승을 뒷받침하는가
- L: 같은 업종에서 앞서가는 주도주인가
- I: 기관투자자의 관심과 보유가 뒷받침되는가
- M: 전체 시장이 주식을 사기에 유리한가

현재 구현 강도를 함께 표시한다.

| 요소 | 구현 판정 | 근거 |
|---|---|---|
| C | 부분 구현 | 분기 실적 보고서와 프롬프트 평가. 고전적 EPS 성장률 하드 게이트는 없음 |
| A | 부분 구현 | 다년 실적·ROE·매출 성장 조사. 고전적 연간 EPS 기준을 코드로 강제하지 않음 |
| N | 부분 구현 | 뉴스·신제품·신고가·촉매를 조사하고 LLM이 판단 |
| S | 비교적 강함 | 거래량 트리거, 수급 보고서, 매집 신호, 분산일 |
| L | 비교적 강함 | 주도 업종, 후보군 상대강도, 선택형 오닐 RS Rating |
| I | 부분 구현 | KR 기관·외국인 순매수, US 기관 보유 자료. 데이터가 없을 수 있음 |
| M | 강함 | 5단계 시장 체제와 별도의 오닐 Market Pulse |

“CAN SLIM 전체를 완전히 자동화했다”는 표현은 쓰지 않는다. “일곱 요소를
모두 조사하지만 코드 강제 수준은 서로 다르다”고 설명한다.

### 8. `entry-gates-overview.png`

제목: `신규 매수: 최종 결정 전에 확인하는 조건`

하나의 AI 프롬프트와 여러 코드 게이트를 일곱 개의 독립 AI 모듈처럼
그리지 않는다. 다음 세 층으로 단순화한다.

1. 보고서를 읽는 CAN SLIM 매수 판단
   - 기업 기초 체력
   - 종목 자체 추세
   - 상승 동력과 시장 환경
   - 목표가·손절가·손익비
2. 코드가 다시 확인하는 안전 조건
   - 반복 손절과 재진입 제한
   - 보유 종목 중복과 추가 매수 조건
   - 포트폴리오 자리와 업종 집중
   - 주문 진행 상태
3. 최종 결과
   - 매수
   - 매수하지 않음

현재 매수 프롬프트에는 “다음 기회를 기다리는 관심종목” 기능이 없으므로
관심·보류를 별도 결과로 그리지 않는다.

### 9. `pyramiding-portfolio-overview.png`

제목: `수익 중인 종목을 추가 매수할 때`

피라미딩은 “수익이 난 종목에만 제한적으로 한 칸을 더 쓰는 방식”이라고
풀어 쓴다.

- 기본 포트폴리오 최대 10칸
- 동일 종목을 이미 보유했는지 확인
- 수익 중인지 확인
- 허용된 시장 체제인지 확인
- 동일 종목 추가 횟수와 전체 자리 확인
- 업종 집중 상태 확인
- 조정 종료 직후 파일럿 기능이 켜져 있으면 중복 추가 매수 동결

부분 금액 매수, 헤지, 독립된 행 단위 청산이라는 표현은 제거한다.
데이터베이스에 보유 건이 여러 행으로 저장될 수 있다는 구현 세부는 문서
설명으로 돌린다.

### 10. `trading-exit-overview.png`

제목: `언제 팔 것인가: 손실은 짧게, 수익은 오래`

우선순위를 다음처럼 표시한다.

1. 기업 생존이나 상장에 영향을 주는 중대 사건
2. 매수가 대비 절대 손절과 시나리오 손절
3. 50일선 이탈, 고점 대비 추적 손절, 약한 시장에서 목표가 도달
4. AI가 뉴스·기업·시장·기술 변화까지 종합해 보유 또는 매도 판단

실제 최종 결과는 기본적으로 보유 또는 청산이다. 임의의 헤지와 포지션
전환은 그리지 않는다. 피라미딩된 보유 건의 개별 처리 가능성은 문서에서
설명한다.

### 11. `position-protection-loops.png`

제목: `정규 분석 배치와 별도로 움직이는 보호 장치`

세 도구를 각각 설명한다.

- 긴급 손절: 시나리오 손절가 또는 절대 -7% 확인
- 추세 이탈 매도: 50일선, 추적 손절, 목표가를 연속 확인 또는 종가 확인
- 미체결 주문 관리: 실제 미체결 수량 조회 후 가격 정정 또는 취소

“항상 가동”이라고 쓰지 않는다.

- 배치와 독립적으로 실행되도록 설계됨
- 별도 cron 등록이 필요함
- 긴급 손절과 추세 이탈 매도의 코드 기본값은 SHADOW
- 운영 문서에는 두 기능이 LIVE로 기록됨
- 미체결 주문 관리는 운영 문서에서도 SHADOW
- 저장소 `docker/crontab`에는 세 루프가 등록되어 있지 않음

### 12. `feedback-reentry-overview.png`

제목: `매매가 끝난 뒤 기록은 다음 판단에 어떻게 쓰이나`

실제 흐름은 다음과 같이 그린다.

`거래 완료 → 매매일지·회고 저장 → 반복되는 교훈 추출 → 다음 종목 판단에
관련 경험 제공 → 재진입 제한 확인`

다음을 구분한다.

- 거래 이력: 매수·매도 가격, 수익률, 청산 이유
- 회고: 계획과 실제 결과, 잘한 점, 개선점
- 직관·교훈: 반복 패턴을 짧은 문장으로 저장하고 관련 종목 판단에 제공
- 재진입 제한: 최근 매도 결과와 시간 조건을 코드가 확인

시스템이 스스로 매매 규칙이나 프롬프트를 고쳐 배포하는 자율 강화학습으로
표현하지 않는다.

## CAN SLIM 감사 기준

CAN SLIM “구성됨”은 다음 세 수준으로 나눠 판단한다.

1. 데이터 수집: 해당 정보를 보고서가 실제로 가져오는가
2. 프롬프트 판단: 매수 에이전트가 해당 요소를 반드시 검토하도록 지시받는가
3. 코드 강제: LLM 판단과 별개로 수치나 상태를 코드가 직접 계산·차단하는가

일곱 요소의 이름이 프롬프트에 존재한다는 사실만으로 완전 구현이라고
판정하지 않는다.

## PNG 제작 방식

- Pillow로 1920×1080 PNG를 직접 그리는 생성 스크립트를 작성한다.
- 저장소에 이미 있는 `Pillow>=10.0.0`만 사용하며 새 의존성을 추가하지 않는다.
- macOS의 Apple SD 산돌고딕 Neo를 우선 사용하고, 사용할 수 없으면
  Arial Unicode MS로 대체한다.
- 글상자 높이는 실제 폰트 바운딩박스로 계산해 잘림을 막는다.
- PNG에는 검색 가능한 텍스트가 없으므로 그림과 동일한 문구를
  `PIPELINE_ARCHITECTURE_ko.md`에도 요약한다.
- 기존 PNG 아홉 장은 같은 파일명으로 교체한다.
- 새 PNG 네 장은 위 목록의 새 파일명으로 추가한다.
