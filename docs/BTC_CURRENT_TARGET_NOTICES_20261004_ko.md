# BTC 변경 알림: 현재 TP/SL과 추세 추종 표시

## 범위와 선행 조건

M3.1/M3.2 관측·알림 후속이다. M0의 확정 체결·보호 증거 조건과 최초 기준 무알림,
동일 이벤트 중복 발송 금지를 유지한다. 주문·LLM 판단·위험 예산·5분/1분 스케줄은 바꾸지 않는다.

사용자는 SL 변경 메시지에서 TP와 수익 시나리오가 사라지고 중복 설명이 길다고 지적했다.
19:51 KST에 발송된 원본은 TP 목록이 확인된 빈 배열인 상태였지만, 이전 목록과 같다는 이유로
TP 블록 전체를 생략했다. 결과적으로 남은 물량의 고정 TP가 없다는 사실도 표시되지 않았다.
숫자를 임의로 추가하거나 이미 체결된 TP를 현재 목표처럼 재사용하지 않는다.

## 수정 전 작업 계획

1. 기존 렌더링·증거 검증 테스트를 먼저 실행해 동작을 고정한다.
2. SL만 바뀐 경우의 기존 TP 유지, 확인된 빈 TP, 미확인 TP를 구분하는 실패 회귀를 추가한다.
3. 변경 내역과 현재 청산 계획을 분리한다. 보유량·평단·계좌는 짧게, 현재 TP/SL은 항상 보인다.
4. 중복 조회 시각·첫 진입 설명·SL 손익 반복은 줄인다. 변경 전→후 가격과 근거 있는 금액은 보존한다.
5. 롱/숏·다중 TP·부분 체결·결측·stale snapshot·실제 plain-text 전송 경계와 길이를 검증한다.
6. 정확한 PR head CI 이후 db-server에 ff-only 배포한다. 공개 테스트 메시지·과거 재발송은 하지 않는다.

## 표현 계약

- TP가 있으면 변경되지 않았더라도 현재 가격·해당 수량·보유 비율·예상 USDT·현재 계좌 비율을 표시한다.
- 확인된 빈 TP는 **고정 TP 없음**으로 표시하고, 남은 물량은 추세 추종·SL 보호 상태임을 설명한다.
  이는 미래의 SL 인상이나 수익을 보장하지 않으며, 고정 청산 시각·확정 수익 목표를 만들어 내지 않는다.
- TP 자료가 미확인이면 **미확인**이다. 빈 TP 또는 전량 추세 추종으로 바꾸지 않는다.
- SL은 변경 전→후 가격, 남은 물량 손익, 확인된 누적 실현손익과 합친 시나리오 예상 결과를 구분한다.
- 수량·평단이 그대로여도 보유 요약을 표시해 알림 하나만으로 읽을 수 있게 한다.
- 같은 이벤트의 계좌·증거금·레버리지·마진 방식과 가격 1배/레버리지 단순환산을 유지한다.
- 총 손실 목표와 계획 위험은 시나리오 시작 계좌 기준이다. 현재 계좌 대비 TP/SL 손익과 혼동하지 않는다.
- 미래 체결 비용과 가격 차이로 예상 결과가 달라질 수 있다는 짧은 경고를 남긴다.
- 원본 이벤트·스냅샷·정산 증거는 삭제하지 않는다. 보내는 본문만 줄인다.

## 검증·배포 상태

구현과 로컬 검증은 완료했다. 기존 renderer 75개 통과 후 신규 회귀를 먼저 실행해
동일 TP·빈 TP 누락 2개 실패를 재현했고, 수정 후 renderer/progress 103개가 통과했다.
마지막 plain-text 전송 경계에서 동일/빈 TP가 보존되고 정확히 한 번 발송되는 2개 사례도 추가했다.
전체 격리 BTC 테스트는 **3,033 passed / 12 skipped / network attempts 0**(Python 3.12.12)이다.
Ruff F/E9·컴파일·diff check와 독립 읽기 검토도 통과했다. 별도 타입검사 설정은 없다.
19:51 원본 형태의 로컬 재구성은 현재 보유·TP 상태를 추가하고도 **608자→523자**로 줄었다.
원본 계좌 자료는 저장소에 넣지 않았다.

CI·운영 Python 스모크·첫 정규 실행 및 자연 변경 공지 관측은 로컬 검증과 별개다.
이 문서의 사전배포 기록만으로 운영 배포·실제 새 알림 발송 완료를 주장하지 않는다.
오래된 메시지를 새 메시지로 재발송하거나, 형식을 시험하기 위해 매매를 실행하지 않는다.
이 작업은 M3 전체 완료 또는 전략 수익성 개선을 뜻하지 않는다.
