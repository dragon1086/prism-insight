# 미국 개별주 대상 확대: 구현 전 계약

## 범위와 승인 경계

기준선 a4dafd3. 무료 yfinance·공개 종목 목록만 사용하고 15~20분 지연을 허용한다. 사용자는 한국과 비슷한 관리 구조와 ETF 등 비개별주 제외를 요청했다. 기존 지수 모드는 그대로 두고 격리된 opt-in 확대 경로를 구현한다. 운영 활성화·새 시총 금액·대량 외부 호출은 아직 하지 않는다. 미국 시총 5억 USD는 사용자에게 제안한 미확정 값이며 기본값으로 몰래 적용하지 않는다.

## 전략 채택 검토: 여섯 항목

1. 유형: 대상·기본 선발 기준의 경제적 의사결정 변경. 데이터 누락 버그 수리와 구분한다.
2. 가설: 단일 기업 보통주 범위를 넓혀 지수 밖 후보를 발견하되 상품형 증권·비정상/불명확 자료는 후보로 전달하지 않는다. 수익 개선은 주장하지 않는다. 정상 개별주 누락 또는 비개별주 통과는 분류 가설의 반증이다.
3. 기존 전략: 트리거별 상승률·거래대금·후보 cap 및 보고서→BUY→주문→SELL 정책을 바꾸지 않는다. 한국 공통 관리 방식만 참고하며 원화 금액을 달러 숫자로 복사하지 않는다. 확대가 순위·평균 거래량 모집단을 바꾸는 효과를 명시한다. 상세 소비 경계 검토는 검증 결과로 보완한다.
4. 비교: 같은 snapshot에서 허용 개별주가 유지되고 ETF/ETN/펀드/우선주/워런트/권리/유닛 등이 제거되는 양방향 테스트, 미확인 분류 제외, 날짜·시세 결측, 기존 지수 모드 회귀 및 KR/US 실제 모듈 통합. 주문·네트워크·발송은 차단한다. 미래 수익·실체결 자료를 가공하지 않는다.
5. 유지·중단: 기존 모드 기본 유지. 확대 모드 오류를 지수 축소 성공으로 숨기지 않는다. 데이터/종목 분류 실패와 정상 후보 없음 구분. 시총·유동성 경계와 시점성 실측을 통과하기 전 운영 전환하지 않는다. 수익성 관측 기간은 아직 정하지 않았으므로 수익 개선 또는 LIVE 적합성 승인으로 해석하지 않는다.
6. 현재 결론: 격리 구현·사전등록 비교. 무료 소스 실제 전시장 처리 시간, 시총 금액, ADR/REIT 세부 운영 범위 등 미확인 항목은 문서에 남긴다. 전시장 운영 활성화는 보류한다.

## 구현 순서

- 공개 목록 parser와 보수적 증권 유형 분류를 독립 테스트한다.
- 동일 응답에서 당일/전일을 추출하는 제한된 분할 수집을 추가하고 기존 수집 경로는 유지한다.
- 확대 경로에서 Yahoo EQUITY 및 기업 metadata를 확인하고, 명시된 시총 기준을 적용한다. 결측은 우량 판정으로 통과시키지 않는다.
- 실패/제외 사유와 요청·수집·정책 통과 종목 수를 JSON에 별도로 남긴다.
- 기존 JSON/보고서 소비 경계를 보존하고 격리 통합 회귀로 검증한다.

## 실제 한국 기준 및 소비 경계 확인

한국 기본 거래대금은 100억 원, 특정 오후 추가 레인은 50~100억 원에서 최대 1개다. 주요 6개 트리거는 시총 5,000억 원 하한을 적용하지만 매크로·역발상은 같은 전역 시총 하한을 갖지 않는다. 상대 거래량은 20일 평균이 아니라 해당 입력 집합 평균의 20%다. 한국 마스터도 우선주·SPAC·REIT 완전 제외를 보장하지 않는다. 따라서 미국의 전체 기본 적격성 필터는 새 정책이며 한국과 숫자까지 동일한 전략이라는 뜻이 아니다.

근거: trigger_batch.py의 SCREENING_MIN_TRADE_VALUE, apply_absolute_filters, 주요 6개 트리거 및 macro/contrarian; cores/kis_market_snapshot.py의 마스터 필터.

US run_batch → us_stock_analysis_orchestrator.py의 선정 JSON·보고서 → us_stock_tracking_agent.py의 BUY/보유 SELL → 공통 cores/buy_gate.py → KIS strict quote/ExecutionService 경계를 검토했다. 이번 변경은 입력 적격성에만 적용하며 BUY 점수·R/R·위험 예산·정수주식·보유 SELL 판단을 수정하지 않는다. 신규 후보가 없으면 이 배치의 report 기반 tracking을 생략하는 기존 동작도 유지한다. Yahoo 지원은 KIS 주문 가능성 보증이 아니며 확대 종목의 broker quote 대조는 미실행이다.

## 구현 상태와 제한

- 기본 major_indices 경로는 동일하게 유지한다. listed_common 모드는 명시적 시총 설정이 없으면 수집 전에 거절한다.
- 목록의 명시적 common/ordinary/ADR 유형과 ETF·증권 종류·거래소·Nasdaq 재무 상태를 먼저 확인한다. 개별 기업 ADR 및 기업형 REIT 보통주는 허용하며 펀드형 수익증권은 제외한다. Yahoo EQUITY, 거래소, USD, 업종·섹터·시총을 다시 확인하고 shell/fund를 제외한다. 분류 제공자의 오기까지 완전히 보장하는 방식은 아니다.
- 당일/전일을 같은 묶음 응답에서 추출한다. 50종목 묶음, 2개 yfinance 동시 요청, 새 묶음 시작 예산 600초, metadata 새 조회 시작 예산 300초다. 진행 중 요청의 완전한 벽시계 timeout은 보장하지 않는다. 이 값은 데이터 신선도 20분 보증이 아니다.
- metadata 조회 전에 거래대금으로 잘라내는 최적화는 상대 거래량 평균까지 바꾸므로 제거했다. 당일·전일이 유효한 대상 전체의 metadata 확인 비용이 남는다. 지속 캐시·전시장 소요시간·미확인 자료 재조회는 아직 구현/검증하지 않았다.
- 시세 coverage와 적격성 제외를 분리한다. 참여도는 정책 제외 전 시세로 계산한다. metadata 결측은 PARTIAL 및 trigger_errors로 기록하고 정상 무신호로 표시하지 않는다. 일부 정상 자료가 있으면 해당 후보를 계속 계산하는 기존 형태를 유지하므로 전시장 전체 비교 완료를 의미하지 않는다. 운영 전 부분 수집의 후보 발송·매매 허용 정책도 확정해야 한다.
- 공개 목록 parser의 초기 실제 조회는 13,277행 중 5,064개 1차 통과였다. 이후 회사명 오탐 교정이 있어 이 수치를 최종 현재 종목 수로 고정하지 않는다. 시총·metadata·시세까지 통과한 수는 미측정이다.

## 활성화 전 남은 조건

미국 시총 하한 사용자 확정, ADR/기업형 REIT 포함 범위 확인, 전체 대상 metadata 수집·캐시 비용 검증, 장중 양일 시세와 원천 지연 확인, 부분 수집 처리 정책, 실제 KIS 읽기 전용 quote 및 종목 매핑 대조가 남는다. 격리 테스트 통과는 이 실측들을 대체하지 않는다. 이번에는 PR 병합·서버 배포·운영 활성화·계정 변경을 하지 않는다.

## 검증 기록

- 공개 목록 read-only parser smoke 1회 성공. 시세·주문 호출은 하지 않았다.
- 새 분류/분할 수집/확대 batch→JSON + 기존 snapshot/status 계약: 133개 통과.
- 기존 KR/US provider-shape, KIS corporate-action, KR/US full-batch integration: 71개 통과. 모델·주문·채널은 격리 경계로 차단했다.
- Ruff 치명적 오류 규칙 E9/F63/F7/F82, 변경 Python 6개 구문 검사, git diff --check 통과. 전체 리포지터리 lint/typecheck·원격 CI는 미실행이다.
- 변경 파일: prism_core/us_stock_universe.py, prism-us/cores/us_surge_detector.py, prism-us/us_trigger_batch.py, 신규 테스트 3개, .env.example, .github/workflows/ci.yml, 이 문서.
- 단순화: 확대 적격성을 입력 경계 한 곳에서 적용하고 기존 트리거·보고서·BUY/SELL 로직을 재사용한다. 새 의존성·상주 서비스·스케줄은 없다.
