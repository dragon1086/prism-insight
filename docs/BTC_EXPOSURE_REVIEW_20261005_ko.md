# BTC 부분익절 후 비중 재평가 프롬프트

## 1. 변경 유형과 사용자 승인

2026-10-05 사용자는 작은 잔량만 보유한 채 강세를 놓치는 문제를 지적하고,
Luna가 유지·추가 진입·감축·전량 청산을 비교하도록 보강하는 방향을 승인했다.
기준선은 `4f4d59f233361fd08563e79eb7498c592e0061c7`이다.
이 작업은 M4의 제한적 **경제적 판단 프롬프트 변경**이며 실행 오류 수리나 수익성 입증이 아니다.

변경 범위는 BTC demo MAIN의 기존 5분 판단 프롬프트, 회귀 테스트와 검토 문서다.
기존 스키마·호스트 위험 검증·실행기·가격 보정·주문 유형·모델·스케줄은 유지한다.
새로운 즉시 부분 시장가 청산 기능이나 임의 목표 비중을 추가하지 않는다.

## 2. 가설과 반례

기존 문구는 유효한 추세의 보호 잔량을 유지하도록 강조하지만, 잔량의 **크기 자체가
현재 근거에 적절한지** 비교하도록 요구하지 않는다. 검증된 부분익절 후에도 계속 관망하는
습관이 있다면 추가 기회를 놓칠 수 있다. 반대로 비중 회복을 강제하면 추격·과매매와 비용이 늘 수 있다.

따라서 다음 네 선택을 비교하되 작은 물량·실현 이익·남은 위험예산 자체는 진입 신호가 아니다.
현재 30분/1시간 근거와 무효화 기준·비용 후 추가 진입의 타당성이 있어야 한다.
새 확정봉이나 모든 시간대의 동의를 필수로 요구하는 별도 진입 gate는 만들지 않는다.

## 3. 실제 경로와 프롬프트 논리

### 입력과 권한
- `ScenarioDemoBroker.context()`의 검증된 `positions`, `pending_entries`, 비용·손실·위험 차단을 사용한다.
- `ScenarioRuntime._context()`가 같은 시나리오의 원래 순자산, 과거 요청 계획과 실제 target 상태를 전달한다.
- `current_plan`의 수량·risk는 현재 체결·현재 잔여 위험의 증거가 아니다. 계산 기준을 섞지 않는다.
- 활성 시나리오라도 OPEN만 접수되고 실제 보유가 0이면 이번 노출 재평가 문구의 대상이 아니다.
- 모델은 기존 strict wire를 제안하고, 호스트가 최신 재조정→마디가격 보정→위험 검증→영속 intent→
  실행 직전 재검증을 한다. 모델에게 직접 주문 권한을 주지 않는다.

### 선택지의 실제 매핑
- 유지: WAIT. 불필요한 ADJUST나 TP 재생성은 하지 않는다.
- 추가 진입: 같은 시나리오의 ADJUST에 **증분 수량만** 제안한다.
- 조건부 감축/보호: ADJUST의 허용된 TP·부분 SL·hard SL 계획을 사용한다.
  즉시 부분 시장가 REDUCE 기능은 없으므로 가짜 트리거나 새 action을 만들지 않는다.
- 전량 청산: EXIT. 새 OPEN은 잔량·주문·비용 정산이 끝난 뒤 다음 별도 판단에서만 가능하다.
- ADJUST는 출구 계획 전체를 대체한다. 유지할 미체결 TP와 새 출구를 의도적으로 구성하며,
  이미 체결된 TP를 복제하거나 예전 수량을 다시 주문하지 않는다.

### 모순과 해결
- “유효하면 잔량 유지”를 무조건 HOLD로 읽는 문제: 보호 잔량 유지는 선택지이지 필수 결론이 아님을 명시한다.
- “기회비용”이 매수를 강제하는 문제: 현재 추가 진입 근거와 위험 조건을 우선하며 정해진 비중·거래 횟수를 요구하지 않는다.
- “전량 익절 후 새 출발”로 예산을 재충전하는 문제: 같은 방향 증액이면 기존 유지+추가와 먼저 비교한다.
  예산·평단 초기화만을 위한 청산/재진입은 하지 않되, 유효한 EXIT 후 새 기회 진입까지 금지하지 않는다.
- SL 완화·수량 증가로 주문을 끼워 맞추지 않는다. 원래 시나리오 2%, 이익 재사용 금지,
  pending 위험 예약, 10배 고정, 하루/연속 손실 차단은 그대로다.
- 감축을 즉시 부분 시장가와 혼동하지 않는다. 새 스키마나 주문 유형을 만들지 않는다.
- 공개 알림 형식은 바꾸지 않는다. 기존 rationale에는 선택·핵심 근거·추가하지 않는 이유 또는
  재평가 조건을 짧게 쓰도록 한다. 긴 사고 과정이나 별도 출력 필드는 요구하지 않는다.

## 4. 사전 고정 검증

1. 기존 관련 테스트 통과를 먼저 확인하고, 신규 문구 누락 실패를 재현한다.
2. 같은 active 후보에서 WAIT·유효 ADD·조건부 감축·EXIT가 기존 wire/경제 검증을 통과하는지 검사한다.
3. 손절 완화·같은 시나리오 중 새 OPEN·예산 초과·pending 위험 누락·차단 중 추가 진입은 계속 거절되어야 한다.
4. 기존/신규 프롬프트만 바꾼 도구 없는 Luna OAuth 제안을 주문 없이 비교한다.
   입력은 사전에 고정한 보존 시세와 합성 계좌 조건으로 만들며 운영 주문 기록으로 부르지 않는다.
5. 강세 재평가·약한 근거·신규 위험 차단·회계 결측의 4조건을 전부 보고한다.
   각 조건 A/B 2회, 총 16응답을 고정한다. 오류·거절도 버리지 않는다.
6. 강세라고 무조건 ADD를 정답으로 채점하지 않는다. 작은 표본의 선택 변화는 프레이밍 점검이지
   수익·체결·장기 인과 효과의 증명이 아니다. 안전 제약 위반이나 노골적 수량 복원 강제가 있으면 배포를 보류한다.

## 5. 유지·중단과 전진 관측

### 사전 계획에 따른 첫 비교와 안전 의미 교정

첫 A/B 16응답은 모두 wire·경제 검증을 통과했다. 기존은 WAIT 6/보호 ADJUST 2,
후보 v1은 WAIT 7/보호 ADJUST 1이며 양쪽 모두 추가 진입 0회다. 이것을 증액·수익 개선으로 해석하지 않는다.
다만 기존과 후보 일부 사유가 TP 한 건의 종료/체결과 전체 포지션 종료를 혼동해
남은 물량을 불일치로 설명했다. 실제 target의 잔량 0과 현재 포지션 잔량은 양립할 수 있다.

수익이나 ADD 횟수를 맞추는 변경이 아니라 이 자료 해석만 명확히 하는 후보 v2를 추가한다.
v1의 코드·입력·16응답은 그대로 보존한다. 같은 4조건·2회씩 v2 응답 8개를 추가해,
원래 기준선 8개와 동일 입력으로 비교한다. 새 위험 gate·목표 비중·사후 시장 선택은 하지 않는다.
전체 호출 수는 24개이며 이 작은 표본으로 일반적 모델 오류율이나 수익성을 추정하지 않는다.

고정 시세 입력은 2026-10-05 06:15 KST와 08:05 KST의 보존된 공개 시세 snapshot이다.
계좌·체결 목표·호가는 합성 조건이며 실제 거래를 복원한 것이 아니다. 과거 입력용 가상 clock을 썼다.
호출은 도구 없는 기존 localhost ChatGPT OAuth 경로만 사용하고, broker·주문·채널 발송은 하지 않는다.

새 위험 한도·새 트리거·새 상주 모니터링은 추가하지 않는다. 기존 결정/주문 기록으로
추가 진입을 선택/보류한 근거, 단계별 거절, 실제 비용·순손익을 구분해 관찰한다.
최초 7일 뒤에도 표본이 작으면 불충분으로 남긴다. 가격 보정 효과와 프롬프트 효과를 혼동하지 않는다.
위험 우회·반복 왕복 매매 유도·비용 악화가 확인되면 검증된 되돌림으로 프롬프트만 원복한다.
기존 포지션 보호와 이미 승인된 주문은 유지하며 최근 손익에 따라 자동 정책 전환하지 않는다.

## 6. 현재 상태

최종 v2 비교 8개는 WAIT 5/ADJUST 3이며, 강세 재시험 사례 1회에서만 증분 0.001 BTC를
제안했다. 약해진 거래량 사례는 증액 없이 보호·목표를 조정했고, 위험 차단·회계 결측은
모두 WAIT였다. 해당 8개에는 v1에서 발견한 부분 TP/전체 보유 불일치 설명이 다시 나타나지 않았다.
이는 작은 자료 해석 점검이며 일반적 오류 제거 또는 추가진입·수익 증가의 입증이 아니다.
기준선 8/v1 8/v2 8, 총 **24응답 모두 strict wire·경제 검증 통과**, 실제 주문 0회다.
새 매수 제안 수를 늘리려고 사례를 추가하거나 강제 목표 비중을 넣지 않았다.

최종 로컬 전체 **3,122 passed / 12 skipped / network attempts 0**, 서버 Python 3.11.11
격리 전체 **3,133 passed / 1 skipped / network attempts 0**이다. Ruff F/E9·컴파일·diff check,
독립 논리 검토를 통과했다. 프롬프트 상수를 제외한 운영 모듈 AST가 기준선과 같음을 확인했다.
별도 Python 타입검사 설정은 없다. 모델은 기존 gpt-6-luna/high/priority, 도구 없는 ChatGPT OAuth만 사용했다.

사용자가 승인한 좁은 demo 판단 보강을 구현·검증한다. M0/M2/M4/M5 전체 완료가 아니다.
로컬·서버 격리 테스트, 같은 입력 A/B, 정확한 head CI, ff-only 배포,
첫 정규 판단·실제 추가 진입·수익성 전진 증거는 각각 따로 기록한다.
