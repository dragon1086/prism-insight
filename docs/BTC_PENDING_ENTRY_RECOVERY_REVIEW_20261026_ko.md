# M0.3 신규 미확정 진입의 추가 격리 검토

후속 상태(2026-10-26 10:44 KST): 별도 #1133으로 구현·검증·배포·전환까지 완료했다.
원본 두 사건은 미정산으로 보존했고 정기 판단이 재개됐다. 24시간 무경보는 관측 중이다.
실제 구현·근거는 [추가 격리 복구](BTC_ENTRY_EPOCH_RECOVERY_20261026_ko.md)를 따른다.

아래는 후속 구현 전 검토 기록이다. 작성 당시 상태: 설계 검토만 수행했다. 추가 격리 코드 구현·상태 변경·신규 매매 재개는 하지 않았다.
원본 UNKNOWN을 취소·거절·미전송으로 소급 확정하지 않는다. 실자금은 대상이 아니다.

## 기존 격리 함수를 다시 실행하지 않는 이유

`scenario_incident_epoch.receipt()`는 영수증을 한 건만 허용하고, 원 사건·UNKNOWN ID·봉인 snapshot을
고정한다. 기존 영수증을 수정하거나 `cutover()`를 새 주문에 그대로 재사용하면 원 사건의
승인 결박·봉인 검증을 깨뜨린다. 이전 승인은 Sell reduceOnly 0.001 BTC 한 건의 잔여 위험을
수용한 것이다. 이번 Buy 0.025 BTC의 늦은 체결은 새 포지션을 만들 수 있어 같은 권한이 아니다.

## 추가 격리를 구현한다면 필요한 최소 범위

1. 기존 영수증·봉인 원본은 그대로 두고, 새 사건 전체 행의 해시와 원 영수증 해시를 결박한
   append-only 추가 영수증을 별도로 둔다. UNKNOWN과 PENDING은 역사 미정산으로 남기며 성과에서 제외한다.
2. intent 조회·children 조회·historical 표시·새 위험 가드·건강 점검의 제외 범위는 이 영수증의
   정확한 시나리오/주문 집합만 사용한다. 모든 UNKNOWN을 제외하는 조건은 만들지 않는다.
3. 기존 두 사건 모두 정확한 link와 금융 구간을 계속 감시한다. 새 Buy의 늦은 주문·체결이나
   조회 공백은 새 진입을 차단하고 보호·소유 수량 확인을 우선한다. 증거를 격리 밖으로 버리지 않는다.
4. 구버전 worker가 새 격리 상태를 이해하지 못한 채 전송할 수 없도록 launcher/control 호환성을
   별도로 막는다. 단순히 active=None으로 바꾸거나 새 epoch 문자열만 넣어서는 안 된다.
5. 전환은 전체 계좌 두 번 완전 조회, 두 scheduler의 정지/복원 원문, 실제 worker 부재,
   진행 중 전송 없음, 원본 재검증과 상태 전환의 원자성을 요구한다. 위험0.5%·10배·자동 승격 금지는 유지한다.
6. 위 구현의 오프라인 정상/누락/변조/늦은 Buy/구버전 worker/부분 전환 실패 검증과 PR CI가 끝난 뒤,
   이 신규 Buy의 잔여 위험을 포함한 실행 승인을 받아야 활성화할 수 있다.

## 현재 유지하는 상태

추가 격리를 승인·구현·활성화한 것으로 간주하지 않는다. 보호 점검과 원 주문의 정확 조회는 계속하고,
신규 판단 보류를 숨기지 않는다. 추가 격리의 상태 전환과 새 24시간 무경보 관측은 아직 시작하지 않았다.
수익성 오프라인 연구는 이 의사결정과 분리해 계속할 수 있다.
