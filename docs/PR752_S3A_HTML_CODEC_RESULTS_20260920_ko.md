# S3a 결과와 입력 예산 결정 요청

## 완료한 제한 범위

전체 HTML 표의 row/col/rowspan/colspan/text를 모두 보존하는 무손실 tuple 표현을 추가했습니다. 행·열 선택, 숫자 변환, 조건 절단, 후보 정렬이나 24개 cap 변경은 없습니다. 분류·Markdown 대조 이후 material HTML에만 적용하며, encoding metadata까지 포함한 전체 block이 실제로 작아질 때만 사용합니다. 기본/OFF·Markdown·SEC·structured 경로는 유지합니다.

기존 표 파서·분류·routing·provenance를 재사용했습니다. 새 의존성은 없습니다. 새 codec 모듈, adapter/revision, fingerprint/CI와 DOM 감사·회귀를 변경했습니다. decoder는 파싱 전 구조·바이트 제한과 복원 전 크기·좌표·겹침 검사를 수행합니다.

## 검토와 검증

- 설계 critic가 전체 block 비용, JSON 할당 전 한도, encoding 표식의 원문 연결을 요구했고 보완 후 OKAY를 받았습니다.
- 독립 코드 리뷰에서 양쪽 표식 삭제와 shape 변조가 감사를 통과하는 반례를 재현했습니다. RED 후 원래 legacy text 및 원본 shape를 직접 대조하도록 고쳤습니다. 최종 APPROVE입니다.
- 전체 연구 입력 회귀 **2,025개 통과**, 기존 경고 4개입니다. codec 59개와 전달 감사 25개를 포함합니다. 독립 관련 143개 및 Unicode/제어문자/escape 200사례도 통과했습니다. Ruff·구문·diff 검사를 통과했으며 Python 타입 검증 완료를 주장하지 않습니다.
- SHA를 확인한 실제 저장 원문 6개에서 후보 805개의 순서·분류·provenance를 C5 기준선과 대조했습니다. encoding 표식과 excerpt 표현 외에는 같았습니다.
- 인코딩된 후보 686개, 원본 셀 **40,878개**를 byte-exact 복원했습니다. 해당 excerpt 합계는 **2,746,217→1,220,936바이트**입니다. 이것은 후보 전체의 합계이며 단일 모델 입력량이나 모델 품질 점수가 아닙니다.
- 격리 packet에서 실제 전달된 codec 33개도 원문 해시·위치·셀·shape와 대조했습니다. 모든 담당자 입력은 6,000바이트 이하였습니다. 이 격리 검증은 발행사/최신성 전체 수집 검증을 대체하지 않습니다.
- 추가 HTTP·모델·주문·운영 메시지 호출은 없습니다. 원문은 비공개이고 첨부하지 않습니다.

## S3 내용 품질은 아직 불합격

실제 C4에서 선택한 source들을 동일 원문으로 재구성했습니다. 전체 네트워크 replay가 아닙니다. 최종 news/overview/status는 **5,776/5,664/5,821바이트**, 근거 2/1/2개입니다. 필수 표 781과 1018, 연간 fragment는 최종 전달되지 않았습니다. 압축으로 앞쪽의 더 큰 표가 새로 들어오면서 전달 집합도 바뀌었으므로 근거 수나 압축률을 품질 개선으로 단정하지 않습니다.

필수 충당부채 표 781은 **7,957→4,821바이트**, 별도 자회사 소송 표 1018은 **1,229→783바이트**입니다. 단위·조건·출처 metadata와 JSON 문자열 비용을 합치면 전자는 기존 6,000바이트 입력에 단독으로도 들어가지 않습니다. 두 표는 후보 순서상 index 31/46으로, 현재 앞 24개 제한도 별도로 해결해야 합니다.

## 실제 예산 충돌을 분리한 진단

다른 후보를 제거하고 **이 두 필수 표만** 넣은 별도 프로세스의 진단을 수행했습니다. 종목별 운영 선택 규칙을 만든 것이 아니며 설정·코드의 운영 한도도 바꾸지 않았습니다.

- 6,000바이트 가정: 작은 표만 전달, 3,638바이트.
- 8,000바이트 가정: 큰 표만 전달, 7,779바이트.
- 10,000/12,000바이트 가정: 두 표와 원래 문맥·출처를 모두 전달, **9,636바이트**.

이 결과는 오직 두 표의 완전한 표현 비용을 보여줍니다. 예산을 늘리기만 하면 범용 품질이 통과한다는 뜻은 아닙니다. 아직 후보 정렬·주제 다양성·최신/과거 구분·새 검증군·모델 해석을 검증해야 합니다.

다른 업종도 확인했습니다. POSCO PF 표 447은 전체 excerpt가 64,169→20,435바이트로 줄었지만 각주 570바이트와 metadata를 더하기 전부터 12,000바이트를 넘습니다. 따라서 삼성생명 사례만 보고 12,000이면 충분하다고 권고하지 않습니다.

## 사용자 지원이 필요한 다음 결정

현재 6,000바이트 계약 아래에서는 **현재 표현으로 전체 표를 보존하는 방식**이 이 필수 기준을 충족하지 못합니다. 가능한 모든 안전한 표현·선정 방법이 불가능하다고 단정하지 않습니다. 다른 열에도 불확실성·진행 중 소송이 있어 특정 두 열만 우대하는 규칙을 이 종목에 맞춰 넣지 않았습니다. gold를 완화하거나 운영 입력 한도를 몰래 늘리지 않습니다.

**사용자 결정 요청:** 운영 6,000바이트는 유지한 채, 로컬에서 담당자별 **6,000·12,000·24,000·32,000바이트**의 제한된 비교 실험을 허용할지 확인합니다. 원문·조건·출처와 기존 gold는 유지하며 모델 호출이나 운영 적용은 포함하지 않습니다. 32,000바이트에서도 범용 품질을 보장하지 않습니다. 기존 주문 규칙·2 MiB 응답 한도도 변경하지 않습니다.

먼저 기존 후보·순서·24개 제한을 고정해 예산 효과만 측정하고, 일반 선정·주제 다양성 규칙은 별도 설계합니다. gold 표만 넣은 진단과 실제 선정 성공을 구분합니다. 32,000에서도 실패하면 자동 증액하지 않고 보고합니다. 실제 전체 packet 비용과 필수 근거·조건·출처의 공동 보존을 함께 평가합니다. 이 지원 요청은 독립 critic 검토에서 OKAY를 받았으며 특정 회사만의 성공에 맞춘 12,000 권고는 폐기했습니다.

사용자 결정 전에는 이 비교용 확대를 구현하거나 운영에 적용하지 않습니다. 기존 Draft PR #752, 머지·배포 보류를 유지합니다. 한국 범용성, 미국 공식 공시 검증, 실제 모델→Markdown→PDF→BUY/SELL·뉴스와 기존 snapshot 실패는 아직 남아 있습니다.
