# BTC 매매 알림의 짧은 블록·금액 표시

## 범위와 작업 계획

M3.1/M3.2 알림 후속이다. 기존 M0 보호·체결 검증을 유지하며 매매 판단·위험·주문·스케줄은 바꾸지 않는다.
사용자는 이모티콘·개행으로 이번 체결과 전체 보유, 계좌와 TP/SL 결과를 구분하는 형식을 승인했다.

1. 기존 렌더러 회귀로 증거 조건·미확정 경고를 고정한다.
2. 이번 체결, 누적 보유, 계좌, TP/SL, 정산을 짧은 블록으로 분리한다.
3. 부분 청산에도 남은 물량 TP/SL와 계좌 영향을 표시한다. 확인된 회계 자료만 보강한다.
4. 실제 plain-text 전송 경계에서 개행·길이·비밀정보 비노출·중복 금지를 검사한다.
5. 전체 격리 테스트와 정확한 PR head CI 이후 배포하며, 신규 자연 공지 관측은 별도 보고한다.

## 금액과 분모

- 이번 체결 금액은 `실제 체결 수량 × 체결가`인 **명목금액**이다. 실제 추가 납입 증거금으로 부르지 않는다.
- 총 증거금과 현재 순자산은 같은 계좌·같은 관측의 거래소 자료만 사용한다.
- 관측 전후 수량/평단은 그 관측 사이 변화다. 같은 배치의 여러 체결을 한 번 체결의 직전/직후로 위장하지 않는다.
- TP/SL는 해당 수량의 가격손익과 현재 순자산 대비 비율을 우선하며, 가격 1배/레버리지 단순환산을 구분한다.
- 부분 청산의 이번 가격손익은 exact execution ID로 검증된 거래소 cashFlow만 사용하며 **비용 전**이라고 표시한다.
- 누적 실현손익에는 이미 기록된 모든 수수료·펀딩(잔여 물량 진입 수수료 포함)이 반영된다.
  누적 금액에 잔여 TP/SL 가격손익을 더한 예상 결과는 **향후 수수료·펀딩 전**이며 이익 보장이 아니다.
- 최종 종료는 확정 순손익과 당시 시나리오 시작 순자산 비율이다. 종료된 거래에 현재 새 계좌/포지션 값을 붙이지 않는다.
- 근거 없는 금액은 0이나 확정손익으로 만들지 않는다. 미확정 경고를 짧게 유지한다.

## 단순화와 보존

긴 한 줄을 체결/보유/계좌/보호/정산 블록으로 나눈다. 부분 청산 렌더링의 조기 반환을 없애
검증된 잔여 TP/SL 표시를 재사용한다. 별도 회계 계산 엔진 대신 이미 검증한 거래소 값을 전달한다.
기존 공지 ID·전송 claim·최초 기준 무알림은 그대로다. 과거 전체 재공지나 누락 종료 공지 복구는 실행하지 않는다.

## 검증 기준

신규/추가 진입, 부분/전량 청산, 롱/숏, SL 이전→변경, 다중 TP, 다중 체결 한 배치,
비용/펀딩 결측, 오래된/타계좌 snapshot, add-after-reduction의 평균 원가를 검사한다.
테스트·배포·실제 자연 발송을 구분하며 수익성 검증이나 과거 복구 승인으로 해석하지 않는다.
