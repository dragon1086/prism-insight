# 최종 입력 예산 비교: 승인 범위와 고정 조건

사용자는 핵심 근거가 최종 입력까지 도달하도록 개선하자는 설명에 “그러자”라고 답했습니다. 앞서 제안한 **무모델·오프라인 6,000/12,000/24,000/32,000바이트 비교와 제한 원인 분리**부터 진행합니다. 운영 6,000바이트, 원문 취득 한도, 모델 호출·운영 활성화·미국 진행의 기존 검증 조건은 유지합니다.

## 실험 계약

- 기준 코드 `00855f1c15dde1c90aa7fb3a555b8231393d05b1`과 이미 SHA 검증된 원문을 재사용합니다. 새 원문·모델·주문 호출은 하지 않습니다.
- 실제 packet builder를 별도 로컬 프로세스에서 사용합니다. 실험 동안만 `SECTION_BYTES`를 승인된 네 값으로 바꾸고 복구합니다. 후보·순서·source/topic 24개 제한·gold·문맥·source role은 고정합니다. 원문이나 필수 표만 강제로 고르는 비교가 아닙니다.
- 현재 일반 source 구성과 연간 전체 주석 component 대체를 구분합니다. 후자는 전체 네트워크 replay나 연간 보완의 필요성 증명이 아닙니다.
- 고정된 G1/G2/G3 평가기의 원문 셀·조건·기간·단위·주체·출처 판정은 재사용합니다. 실험 예산 통과 여부는 운영 6,000바이트 판정과 별도로 보고합니다. 평가기 gold를 바꾸지 않습니다.
- 실제 후보 frontier에서 필수 표의 위치와 제외 이유를 추적해 24개 cap의 영향과 byte-fit 실패를 분리합니다. 이 단계에서는 cap을 늘리지 않습니다.
- 이전 7개 원문의 다른 업종은 동일 원문 component 스트레스 비교이며, 독립 gold나 새 홀드아웃으로 부르지 않습니다. 실제 전달 record는 원문 provenance 감사로 검증합니다.
- 후보/순서 SHA, source hash, 코드 SHA, 고정 observation 시각, 정확한 UTF-8 bytes와 문자 수, 최종 포함/누락, processing time을 기록합니다. 같은 예산 반복 결과가 같고 입력·상수가 복구되는지 검사합니다.

## 최종 입력 경계

packet 생성만 통과했다고 실제 보고서 입력 성공으로 세지 않습니다. 실제 `apply_section_research`를 도구 없는 ReportAgent 정의에 적용해 note가 온전히 들어갔는지 검사하고, coverage manifest가 같은 근거를 가리키는지도 확인합니다. SDK·모델 실행은 없습니다.

현재 adapter의 `len(note)>6000`은 문자 단위인 반면 packet/manifest는 UTF-8 바이트 단위입니다. 먼저 이 차이를 측정합니다. 운영 한도를 올리지 않고 UTF-8 바이트로 일치시키는 안전 수정은 별도 실패 회귀를 먼저 고정합니다. 큰 실험 packet이 기본 guard에서 거절되는 결과도 보존합니다.

## 판정

source/candidate 도달, packet의 필수 근거 통과, 최종 agent 입력 통과, 실제 모델/문서 품질을 각각 구분합니다. 32,000에서도 실패하면 자동 증액하지 않습니다. 연간 후보 전달 개수 자체를 목표로 삼거나 primary의 최신 상태를 오래된 annual로 대체하지 않습니다. 이 결과만으로 운영 한도 변경·한국 전체 품질·미국·배포 완료를 주장하지 않습니다.

## 후속 구현 경계: 기본값과 실험 전달을 분리

첫 고정 비교에서 24,000/32,000은 packet의 G1~G3를 보존했지만 기본 agent/manifest guard가 전체를 거절했습니다. 따라서 범위를 다음과 같이 한정한 공통 계약을 독립 architect가 조건부 승인했습니다.

- 공통 UTF-8 정책에 기본값6,000과 허용값6,000/12,000/24,000/32,000을 정의합니다. `type(value) is int`와 허용 목록을 검증합니다.
- packet builder, agent injection, manifest source scan에 **명시적인 keyword-only `source_budget_bytes`**를 추가합니다. 기본값은 모두6,000입니다. 실제 KR/US factory·orchestration·cache 호출부는 변경하지 않습니다.
- budget을 packet/receipt/source/env에서 읽지 않습니다. 오직 호출자가 명시한 실험 인자만 적용됩니다. 실험 runner는 전역 상수 변경 대신 같은 인자를 세 단계에 전달합니다.
- 기본 경로는 여전히 큰 packet을 전체 생략합니다. 명시적 실험 경로만 source note를 정확히 전달하는지 검증합니다. 두 결과를 별도로 보고하며 실험 helper 성공을 운영 factory나 실제 모델 성공으로 부르지 않습니다.
- manifest 전체6,000/섹션1,800/참조 record8개 제한 및 도구 결과6,000/18,000 제한은 별도이며 변경하지 않습니다. 보고서 지침/envelope 바이트도 source note와 분리해 계측합니다.

## 실제 경쟁 항목의 오분류 수정

최초12,000 비교에서 표781보다 먼저 들어간 것은 다른 주제의 가이던스가 아니라, 같은 위험 queue로 잘못 분류된 **정식 연결재무상태표**였습니다. 독립 원문 검토가 이를 확인했고 정식 포괄손익계산서·자본변동표의 지배구조 오분류도 확인했습니다.

material HTML 표의 가장 가까운 section title이 번호/공백 변형을 제외한 정식 재무제표 명칭 전체와 정확히 일치할 때만 `financial_quality_valuation / company_status`로 배치합니다. 상위 재무제표 제목이나 단순 substring으로 하위 위험 주석까지 이동시키지 않습니다. 원문·셀·조건·출처·scope는 그대로이며 기존 non-material/Markdown/SEC 경로는 변경하지 않습니다. 특정 gold 공간 확보 규칙이 아니라 문서 유형의 소유 섹션 교정입니다. 효과는 별도 동일예산 재측정으로 확인합니다.
