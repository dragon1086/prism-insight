## 진행 원칙과 PR

사용자 요청에 따라 기존 Draft PR #752, `feat/general-competitive-research`에서 이어간다.
전체 작업·내용 품질·통합·정확한 HEAD CI 검증이 끝나면 같은 PR을 머지하고 정해진 운영 절차로
배포한다. 지금은 전체 완료가 아니므로 일부 테스트 통과만으로 머지하지 않는다.
TradingView에 관한 사용자의 진행 의사는 기록하되, 가공·개인 사용·낮은 적발 가능성을
공급자의 허가 확인으로 쓰지는 않는다. 같은 논의를 반복하며 기술 검증을 중단하지 않는다.

## 결과를 보기 전에 고정한 표본

모든 DART 조회의 판단시점은 2026-09-18 15:30 KST, 조회기간은 2025-01-01~2026-09-18,
요청 범위는 연결 재무제표로 고정했다. RF는 이미 개발에 사용한 대조군이다.

- 개발 일반화 5개: 삼성전자, 현대차, KB금융, 오스코텍, LG화학.
- 첫 별도 검증 3개: 유한양행, 메리츠금융지주, 에스엠.
- 첫 검증의 실패를 본 뒤 새로 고정한 2차 검증 3개: 한국전력, NAVER, 신한지주.

업종·규모·지주/운영회사 차이를 포함했다. 이 표본은 DART 수집기 기준 미사용 표본이며
프로젝트 전체에서 한 번도 언급하지 않은 회사라고 주장하지 않는다. 실패 회사를 빼거나
쉬운 회사로 대체하지 않았다. 결과를 보고 고친 첫 검증군은 이후 회귀군으로 표시했다.

## 실제로 드러난 일반화 문제와 수정

개발 5개 최초 실행에서 기본자료를 선정한 것은 **2개**뿐이었다. RF 성공만으로 충분하지 않았다.

1. **종목명과 공시 법인명이 달랐다.** 현대차 이름 검색만으로는 공식 법인코드를 찾지 못했다.
   회사별 별칭을 하드코딩하지 않고, DART가 제공하는 종목코드 검색과 기업개황의 실제 종목코드를
   대조했다. 고유 법인코드·종목코드가 일치해야 수집한다.
2. **정정본 표지 날짜와 실제 제출일을 혼동했다.** KB금융·LG화학의 정정 문서는 표지에 원래
   제출일을 유지했다. 정정 공시의 접수일을 가용 시점으로 보존하고 표지 날짜를 별도로 저장했다.
3. **오래된 정정이 더 최신 반기까지 막았다.** 공식 `family` 목록과 실제 확보한 원문들의
   기간·연결 범위를 대조해 정정 관계를 검증했다. 과거 미확인 항목은 명시적으로 남기되,
   검증된 더 최신 기간의 기본자료까지 무조건 숨기지 않는다. 같은 기간·더 최신·미확인 기간은
   여전히 보수적으로 막는다. 같은 날 정정은 시각 없이 순서를 만들지 않는다.
4. **첨부 정정을 본문 정정과 혼동했다.** 첫 별도 검증에서 메리츠의 감사보고서·정관 첨부가
   사업보고서 본문으로 취급됐다. 공식 `[첨부정정]` 표지를 구분하여 본문 판본으로 쓰지 않고
   미확인 첨부로 보존했다. 오래된 첨부와 같은 기간 첨부의 차단 범위를 구분한다.

수정 중 공식 목록의 `+본문선택+` placeholder를 오류로 처리하는 회귀도 실제 실행에서
발견했다. 해당 실패 실행도 보존했고, 정확한 정상 placeholder만 허용하는 테스트를 추가했다.
예산을 늘리거나 회사 코드별 예외로 통과시키지 않았다.

## 현재 확인된 결과와 남은 검증

- 개발 5개 재검증: **5개 모두 기본자료 선정**, 4개 완전 수집, KB금융은 과거 일부 미확인으로 부분 수집.
- RF 대조군: 기본자료·연차 보완자료 선택 유지.
- 첫 별도 검증: 최초 **2/3 기본자료 선정**, 실패를 반영해 일반 규칙을 수정했다.
  수정 후 메리츠의 2026 반기 기본자료도 선택됐다. 에스엠의 마지막 재조회는 기업 식별 요청 단계에서
  통신이 종료되어 미완료이며, 이전 실행에서 확보한 결과를 새 실행 성공으로 옮겨 쓰지 않았다.
- 2차 검증 3개: 본문을 받기 전에 통신 오류가 발생했다. 같은 환경의 DART 홈 조회도
  `RemoteProtocolError`로 실패했다. 원인이 점검·접속 제한인지 확인하지 못했으므로 추정하지 않는다.
  이 결과를 회사별 데이터 부재나 일반화 합격으로 계산하지 않았다. 연결 정상화 후 같은 표본으로 재검증해야 한다.

따라서 **전 종목 일반화 검증 완료가 아니다.** 기본자료 선정 성공과 모든 과거 공시·첨부 검증,
보고서 품질, 미국 SEC 지원, BUY/SELL 판단 검증은 별개다. 조회는 같은 조건의 새 실조회이며
고정 응답 A/B라고 하지 않는다. 결과 JSON에는 표본·수집기 해시·실패 사례·미확인 항목을 보존했다.

## 다음 작업: Perplexity 결과가 통째로 사라지는 문제

큰 결과를 무제한 허용하지 않고, 활성 연구 프로필의 Perplexity 두 도구에 한해 **출처 탐색용
URL만 제한적으로 복구**하도록 기존 MCP 반환 경계에 연결했다.

- 성공한 텍스트 결과가 개별 크기 한도를 넘었을 때만 적용한다.
- 원래 답변·숫자·인과 설명은 검증된 사실로 복사하지 않는다. 제목·날짜를 URL에서 만들어내지 않는다.
- 원 응답 hash·크기·미전달 사유를 보존한다. 원문 확인/법인 일치/공개시각은 미확인 상태다.
- 새 MCP 결과 전체를 기존 누적 예산에서 차감한다. URL을 중간에서 자르거나 한도를 늘리지 않는다.
- 기존 작은 응답, 다른 서버, 오류, 비텍스트 결과, 연구 비활성 경로는 유지한다.

실제 RF 저장 응답을 SDK 두 출력 모드로 재생했다:
**23,096B 원 결과 → 1,475B 반입 예산 / 1,408B SDK 표시**, 후보 10개 중 URL 9개 복구.
한 URL은 기존 안전 규칙에 따라 제외했다. 잘못된 회사인 RF Industries 링크도 포함돼 있었으므로
출처 목록을 기업 사실로 승격하지 않았다. 새 네트워크·모델 호출은 0회다.
기존 모델에는 원래 23KB 답변이 아니라 짧은 거절 안내만 전달됐다. 따라서 위 수치를
실제 입력 토큰 절감률로 해석하지 않는다. 필요한 출처 위치를 다시 전달한 품질 개선이다.

이는 **출처 위치 전달 복구**다. 기사 원문 검증·당일 상승 원인 분석·서술형 보고서 완성을
뜻하지 않는다. 원문 수집과 회사·시점 확인을 연결하는 다음 단계가 남아 있다.

## 변경 및 검증

- DART 수집기와 대응 회귀: 정정 관계·첨부 역할·날짜 보존을 일반화했다.
- 다종목 진단 도구·고정 표본·대응 테스트를 추가했다.
- `search_discovery_fallback.py`와 기존 `tool_result_budget.py`: 탐색 URL 복구와 실제 SDK 경계 회귀.
- 기존 선택기·URL 안전 검사·SDK wrapper를 재사용했다. 새 의존성·매매 점수·손절·주문·cron 변경은 없다.
- 관련 연구/보고서 회귀 **974개 통과**, 기존 경고 3건. Ruff·compileall·diff 검사 통과.
  독립 코드/보안 리뷰 후 상충 참조번호 표기와 오류 분류까지 수정했다.
- 원격 Codacy는 진단 도구의 Git 버전 조회 subprocess를 지적했다. 검사를 우회하지 않고
  프로세스 호출 자체를 제거했다. 도구는 소스 해시만 기록하며 커밋 정보는 별도 검증 기록에서 연결한다.
- Python 전용 타입 검사/의존성 취약점 감사는 도구 미구성으로 미완료다. 테스트가
  실제 내용 품질·미실행 검증군·배포 성공을 대신하지 않는다.
