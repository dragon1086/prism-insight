# BTC 보유 중 후속 진행과 수익 반납 비교 후보

1. **범위:** M4 보유 판단 프레이밍의 경제적 의사결정 변경 후보다. 기준선은 `8f08bdbe`이다.
   현재코드의 고정3일/6시점 가상계좌 재생은 종료1건·0승1패·비용후−7.1819USDT였고 독립 재생이 일치했다.
   실제사고epoch/계좌 복원이 아닌 명시적 합성복구상태의 개발자료다.
2. **가설:** 첫 익절 뒤 11:05 입력에서 확정누적순이익2.4740USDT와 잔여0.014BTC가 있었다.
   모델은 반등 위험을 인지하면서 1시간 하락구조와 미도달 무효화선을 이유로 WAIT했다.
   느린 방향이 유지되는 것과 잔량을 그대로 보유할 이점을 구분하면 수익 반납을 줄일 가능성이 있다.
   단순히 이익이 났거나 15분봉이 반등했다는 이유만으로 청산하는 규칙은 아니다.
3. **호환성:** 기존 `HOLDING_MANAGEMENT_PROMPT`에서만 1h/30m 방향 안의 15m 반응을 비교하고,
   첫 익절 후 이미 제공되는 거래전체 mark/stop 순손익을 사용하도록 정리한다.
   새 계산·지표·임계값·상주 작업을 넣지 않는다. 비용충당액과 관측수수료의 구분,
   정상눌림의 추세보유·native SL·원위험예산·stop_policy/stop_revision 관문은 유지한다.
   무포지션/예약/미확정/격리 입력과 진입·원목표·손절 허용가격·수량상한은 바꾸지 않는다.
4. **동일 조건과 반례:** 위 재생 손실 입력과 실제수익거래 `s_38b8d7d08dffbcd7e4c862d4`의
   첫 TP 이후 최초 WAIT(slot5979610)를 고정한다. 실제 원장부터 확인하고 보유 원문을 보충한다.
   양쪽 보유 설명카탈로그는 각 시각의 원문으로 구성한다. 누락된 실행권한을 만들지 않는다.
   현재코드의 가상손실 입력 기준응답을 정확한 요청 일치 시 재사용하고,
   실제수익반례의 현기준안과 두 후보입력은 최대6새HTTP/입력30만·출력8천토큰으로 제한한다.
   건강한 진행을 이익실현 자체만으로 자르거나 실패관측을 꾸며내면 채택하지 않는다.
5. **판정과 중단:** 손실입력에서 감소/보호/청산의 근거와 상태일관성을 확인하고, 건강한 수익반례에서
   정상눌림과 계속보유의 이점을 유지하는지 본다. 동일행동/효과미확인은 반복호출하지 않는다.
   유망하면 같은 고정3일·6시점에서 후보의 계좌·보유·체결·비용·펀딩을 처음부터 연속 재생한다.
   해당 비교주기는 기존기준선7+기능확인6+후보최대12=최대25HTTP로48상한 안이며,
   입력최대1.6M/출력40k의 사전 총량을 지킨다. 개발상승만으로 M5 수익성 판정을 내리지 않는다.
6. **현재 결론:** 연구 후보이며 자동 승격하지 않는다. 프롬프트·스키마·수학·기존 권한의 모순을
   대조하고 보유 전용 해시만 갱신한다. 테스트·CI·배포·첫정기실행·실수익성은 별도 상태로 보고한다.
